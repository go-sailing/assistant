## 1. 背景与目标

### 1.1 背景

用户在日常工作与生活中需要记录和跟踪大量待办事项，但传统任务管理工具存在两个痛点：

1. **操作成本高**：新增、修改、查询任务需要在表单和列表间多次点击，录入负担重，导致用户放弃记录；
2. **缺乏灵活性**：固定的界面操作无法支持模糊表达（如"把下周所有和房租有关的事都推后三天"），批量操作困难。

大语言模型（LLM）的自然语言理解与 Function Calling（工具调用）能力，可以让用户通过对话完成全部任务管理操作，同时保留传统任务列表视图作为可视化管理入口。

### 1.2 产品目标（MVP）

- **核心目标**：验证"对话 + 列表"双入口的任务管理体验，帮助用户低成本地记录、组织和完成任务。
- **MVP 成功假设**：用户愿意通过自然语言录入任务，且聊天中完成的任务操作与手动操作具有完全一致的效果。

### 1.3 非目标（MVP 不做）

- 不做原生 App（iOS / Android 安装包），MVP 首发仅提供**移动端 Web（H5）**；
- 不做 PC 端专门适配；
- 不做本地通知/消息推送提醒（任务仅记录截止时间，不主动触达）；
- 不做本地存储与离线能力：数据与业务逻辑全部在云端，端上仅做展示与交互，断网不可用；
- 不做多人协作、任务指派与共享清单；
- 不做日历、习惯打卡、笔记、记账等任务以外的功能；
- 不做第三方服务集成（邮箱、IM、日历账号等）；
- 不做语音输入与多模态（图片/文件）；
- 不做插件市场与自定义 Agent。

## 2. 目标用户与使用场景

### 2.1 目标用户

- 有日常待办管理需求、但觉得传统待办 App 操作繁琐的个人用户；
- 习惯用聊天方式表达需求、希望"说一句话就把事记下"的用户。

### 2.2 核心使用场景

| 场景 | 描述 |
| --- | --- |
| 快速记录 | 用户对助手说"周五下午 3 点提醒我交季度报告"，系统自动创建任务并解析截止时间。 |
| 晨间查看 | 用户打开 App，在任务首页查看今日到期、已逾期任务。 |
| 对话查询 | 用户问"我这周还有哪些没完成的事？"，助手以自然语言 + 任务卡片列表回答。 |
| 批量修改 | 用户说"把本周的工作任务全部标为高优先级"，助手调用工具批量更新并反馈结果。 |
| 状态推进 | 用户说"季度报告做完了"，助手将对应任务标记为已完成。 |
| 随手整理 | 用户说"把'买牛奶'加到生活清单，截止周六"，助手创建并归类任务。 |

## 3. 产品整体说明

### 3.1 产品形态

- **移动端 Web（H5）**：用户通过手机浏览器访问，MVP 不发布、不依赖原生 App；
- 采用云端一体化架构：前端为瘦客户端，仅负责展示与交互；任务数据存储、业务规则校验、LLM 调用与工具执行全部在服务端完成；
- 页面内采用底部两个核心 Tab：**任务**、**助手（聊天）**。

### 3.2 信息架构

```
个人助手 App
├── 任务 Tab
│   ├── 任务列表（支持按清单/状态/时间筛选）
│   ├── 任务详情页
│   ├── 新建/编辑任务（表单）
│   └── 清单管理（内置清单 + 自定义清单）
└── 助手 Tab
    ├── 对话列表（会话历史）
    └── 对话页（消息流 + 任务卡片 + 工具执行确认）
```

### 3.3 双入口关系（关键设计原则）

1. **数据同源**：手动操作与对话操作读写同一套任务数据，任一入口的变更在另一入口实时可见；
2. **能力对等**：LLM 聊天具备任务管理的**全部能力**——凡手动可完成的任务操作，对话均可完成（详见第 5 章能力对照表）；
3. **结果可追溯**：聊天中发生的任务变更以结构化卡片展示，并同步反映在任务列表中。

## 4. 功能需求一：任务管理

### 4.1 任务数据模型

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string | 是 | 任务唯一标识，系统生成 |
| title | string | 是 | 任务标题，最长 200 字符 |
| note | string | 否 | 备注/描述，最长 2000 字符 |
| status | enum | 是 | `todo`（待办）/ `completed`（已完成），默认 `todo` |
| priority | enum | 否 | `none` / `low` / `medium` / `high`，默认 `none` |
| due_at | datetime | 否 | 截止时间（含日期，可选具体时间） |
| list_id | string | 否 | 所属清单 ID，未指定时归入"默认清单" |
| created_at | datetime | 是 | 创建时间 |
| updated_at | datetime | 是 | 最近更新时间 |
| completed_at | datetime | 否 | 完成时间 |

### 4.2 功能清单

| 编号 | 功能 | 优先级 | 描述 |
| --- | --- | --- | --- |
| T-01 | 创建任务 | P0 | 手动填写标题（必填）、备注、优先级、截止时间、所属清单后保存。 |
| T-02 | 查看任务列表 | P0 | 按清单浏览；支持筛选（全部/未完成/已完成）、按截止时间或创建时间排序；展示逾期、今日、即将到期标识。 |
| T-03 | 查看任务详情 | P0 | 展示任务全部字段及创建/完成时间。 |
| T-04 | 编辑任务 | P0 | 修改标题、备注、优先级、截止时间、所属清单。 |
| T-05 | 完成/取消完成 | P0 | 勾选切换完成状态；完成时记录 `completed_at`，取消时清空。 |
| T-06 | 删除任务 | P0 | 删除前二次确认；删除后不可恢复（MVP 不做回收站）。 |
| T-07 | 清单管理 | P0 | 系统内置"默认清单"；用户可新建、重命名、删除自定义清单（删除清单时其内任务移至默认清单）。 |
| T-08 | 任务搜索 | P1 | 按标题、备注关键词搜索任务。 |

### 4.3 任务列表交互要求

- 列表项展示：标题、清单名称、优先级标记、截止时间、完成态（划线置灰）；
- 逾期未完成任务截止时间标红；
- 支持左滑快速完成/删除；
- 下拉刷新；列表数据实时从云端拉取，端上不做本地持久化与离线缓存；网络异常时展示错误状态与重试入口（账号体系见 6.3）。

### 4.4 任务管理业务规则

- 标题去除首尾空格后不能为空；
- 截止时间允许早于当前时间（保存时提示"已过期"但允许创建，由用户确认）；
- 删除清单不允许级联删除任务，统一迁移至默认清单；
- 默认清单不可重命名、不可删除。

## 5. 功能需求二：LLM 聊天

### 5.1 功能概述

助手 Tab 提供对话界面，用户以自然语言完成任务的增、删、改、查及批量操作。LLM 通过 Function Calling 调用任务服务工具，执行结果回写任务数据库并以卡片形式在对话中呈现。

### 5.2 功能清单

| 编号 | 功能 | 优先级 | 描述 |
| --- | --- | --- | --- |
| C-01 | 多轮对话 | P0 | 支持上下文连续对话，可基于上一轮结果追问（如"那把它改成高优先级"）。 |
| C-02 | 对话式任务管理 | P0 | 通过自然语言完成任务的创建、查询、编辑、完成、删除、清单归类与批量操作（能力对照见 5.3）。 |
| C-03 | 任务卡片渲染 | P0 | 对话中涉及的任务以结构化卡片展示（标题、清单、优先级、截止时间、状态），卡片可点击跳转任务详情。 |
| C-04 | 写操作确认 | P0 | 对**删除**和**影响多条任务的批量修改**，在执行前展示操作预览并要求用户确认；单条创建/编辑/完成可直接执行。 |
| C-05 | 信息抽取与追问 | P0 | 创建/编辑任务时自动从语言中解析标题、截止时间（"下周五"等相对时间）、优先级、清单；关键必填项（标题）缺失时向用户追问澄清。 |
| C-06 | 执行结果反馈 | P0 | 每次工具调用后用自然语言反馈成功/失败及影响范围（如"已将 3 个任务标记为完成"）。 |
| C-07 | 会话历史 | P0 | 保存历史会话，可重新打开查看；会话内任务数据始终展示最新状态。 |
| C-08 | 通用问答 | P1 | 与任务无关的问题可正常对话回答，但助手应主动引导回到任务管理场景。 |
| C-09 | 新建会话 | P1 | 手动开启新会话，清空当前上下文。 |

### 5.3 聊天与手动操作能力对照表（能力对等要求）

> 验收标准：下表每一行，聊天入口必须能达到与手动入口**相同的数据效果**。

| 任务管理能力（手动） | 聊天中的表达示例 | LLM 工具 |
| --- | --- | --- |
| 创建任务（T-01） | "下周一上午 10 点提醒我做体检，加到生活清单" | `create_task` |
| 查看任务列表（T-02） | "看看我今天要做什么" | `list_tasks` |
| 搜索任务（T-08） | "找一下和报销有关的任务" | `search_tasks` |
| 查看任务详情（T-03） | "季度报告那个任务具体什么时候截止？" | `get_task` |
| 编辑任务（T-04） | "把体检改到下周二，备注要空腹" | `update_task` |
| 完成/取消完成（T-05） | "体检做完了" / "把体检恢复成未完成" | `update_task_status` |
| 删除任务（T-06） | "把买牛奶那个任务删掉"（需确认） | `delete_task` |
| 新建/重命名清单（T-07） | "新建一个叫'装修'的清单" | `create_list` / `rename_list` |
| 删除清单（T-07） | "把装修清单删掉"（需确认，任务迁移默认清单） | `delete_list` |
| 批量操作 | "把本周逾期的任务全部延到明天" | `batch_update_tasks` |

### 5.4 LLM 工具（Function Calling）定义

| 工具名 | 入参（主要） | 说明 |
| --- | --- | --- |
| `create_task` | title, note?, priority?, due_at?, list_id? | 创建单条任务，返回任务详情 |
| `update_task` | task_id, title?, note?, priority?, due_at?, list_id? | 修改任务字段 |
| `update_task_status` | task_id, status | 完成/取消完成 |
| `delete_task` | task_id | 删除单条任务（调用前需对话确认） |
| `get_task` | task_id | 查询单条任务 |
| `list_tasks` | list_id?, status?, due_before?, due_after?, sort? | 按条件查询任务 |
| `search_tasks` | keyword | 关键词搜索 |
| `batch_update_tasks` | filter 条件, 更新字段 | 批量更新（调用前需对话确认并预览影响条数） |
| `create_list` / `rename_list` / `delete_list` | list_id?, name | 清单管理 |

工具返回统一的结构化 JSON（任务对象或任务对象数组 + 操作结果摘要），由模型组织为自然语言 + 卡片输出。

### 5.5 对话交互要求

- 消息类型：用户文本气泡、助手文本、**任务卡片**（单条/列表）、**操作确认条**（取消 / 确认）、系统错误提示；
- 工具执行中显示"正在处理…" loading 态；
- 模型无法确定操作对象时（如"把那个事删了"但存在多个候选），必须先列出候选让用户选择，**禁止猜测执行写操作**；
- 用户否认或取消后不执行，并可继续对话修正。

### 5.6 异常与边界处理

| 情况 | 处理方式 |
| --- | --- |
| LLM 服务超时/不可用 | 提示"助手暂时不可用，请稍后重试"，不影响任务 Tab 正常使用。 |
| 工具调用失败（网络/服务端错误） | 在对话中告知失败原因，任务数据保持原状，支持重试。 |
| 模型返回非法参数 | 服务端校验拦截并要求模型重新生成；连续失败则降级为错误提示。 |
| 用户表达超出任务管理范围 | 正常应答（C-08），不触发任何任务工具。 |
| 含敏感/不合规内容 | 按 LLM 安全策略拒绝，不执行工具。 |
| 时间表达无法解析 | 向用户追问具体日期，不自行猜测截止时间。 |

### 5.7 模型选型与调用方式（评审确认）

- **LLM 提供方**：DeepSeek（官方 API）；
- **模型**：`deepseek-flash`（原记录为 `deepseek-flush`，API 实测该名称不存在，已按官方 `/models` 接口返回值更正）；
- 调用方式：由**服务端统一代理调用**，API Key 仅保存在服务端，不下发到 Web 前端；
- 使用 DeepSeek 的 Function Calling 能力承载 5.4 节全部工具；对话回复采用流式输出（SSE）逐字返回到前端；
- 系统提示词、工具定义、会话上下文组装、工具参数校验与实际执行均在云端完成；前端只负责消息与卡片渲染；
- 若 DeepSeek 服务不可用，按 5.6 节降级提示；模型相关配置（模型名、超时、重试）通过服务端配置管理，便于后续替换。

## 6. 非功能性需求

### 6.1 性能

- 任务列表首屏加载 ≤ 1.5s（云端接口、正常网络环境）；
- 手动创建/编辑任务保存响应 ≤ 800ms；
- 聊天场景：用户发送消息到首字返回 ≤ 3s（DeepSeek 流式输出）。

### 6.2 可用性与兼容性

- 兼容主流移动端浏览器近两个大版本：iOS Safari、Android Chrome，以及微信等主流 App 内置 WebView；
- 页面按移动端视口自适应（移动优先），PC 浏览器可打开但不做专门适配；
- **不支持离线**：所有读写均需联网；断网或请求失败时展示错误状态与"重试"入口，端上不产生本地数据，也不做写操作暂存。

### 6.3 账号与数据

- MVP 采用**邮箱 + 密码**方式注册和登录，不提供短信/邮箱验证码功能；未登录可浏览引导页，登录后使用；
- 密码在服务端加盐哈希存储，不明文保存；注册时校验邮箱格式与密码强度（具体规则在详细设计中定义）；MVP 不做邮箱激活验证、找回密码流程（如需要，可通过客服/后台处理，或列入后续版本）；
- 瘦客户端架构：任务数据仅在云端数据库持久化，Web 端不做本地持久化（不含 LocalStorage/IndexedDB 业务数据缓存）；
- 任务数据按用户隔离；同一账号多设备、多浏览器登录后均从云端读取，数据一致；
- 用户可注销账号，注销后任务数据删除。

### 6.4 隐私与安全

- Web 端与服务端、服务端与 DeepSeek API 之间的通信全程 HTTPS；
- DeepSeek API Key 仅保存在服务端，严禁出现在前端代码或响应中；
- 发送给 DeepSeek 的内容仅包含对话所必需的上下文与任务结构化信息，不附带其他用户数据，并遵循 DeepSeek 服务条款的数据使用约定；
- 明确告知用户对话由 AI 生成、可能出现错误，写操作（尤其删除/批量）以用户确认为准。

### 6.5 可观测性

- 埋点记录：任务创建来源（手动/对话）、工具调用类型与成功率、对话轮次、确认弹窗的接受/取消率；
- 记录 LLM 工具调用失败、参数校验失败等异常日志用于优化。

## 7. 关键业务流程

### 7.1 对话创建任务

```
用户输入自然语言
  → 服务端将消息 + 工具定义 + 用户任务上下文发给 LLM
  → LLM 解析意图与字段（时间/优先级/清单）
    ├─ 标题缺失 → 返回追问 → 用户补充 → 重新解析
    └─ 信息完整 → 调用 create_task
  → 服务端执行工具、写入任务库
  → 返回任务对象 → LLM 生成确认话术
  → 客户端渲染：文本 + 任务卡片
  → 任务 Tab 列表同步出现该任务
```

### 7.2 对话执行删除/批量操作

```
LLM 解析出删除/批量意图
  → 先调用查询工具预取受影响任务
  → 对话中展示操作预览（影响对象与条数）+ 取消/确认
  → 用户确认后才执行写工具
  → 反馈执行结果；任务列表同步更新
```

## 8. 验收标准

### 8.1 任务管理

1. 可完成任务的增、删、改、查、完成状态切换，字段与第 4.1 节数据模型一致；
2. 可新建/重命名/删除清单，删除清单时任务正确迁移至默认清单；
3. 筛选、排序、搜索结果准确；逾期标识正确。

### 8.2 LLM 聊天

1. 第 5.3 节能力对照表中**全部 10 项能力**均可通过对话完成，且写入结果与手动操作完全一致（字段级校验）；
2. 单条创建类指令在信息完整时一句话即可完成，无需二次填写表单；
3. 删除、批量操作 100% 经过确认条，取消后数据无变化；
4. 操作对象不明确时 100% 出现候选澄清，不发生误写；
5. 对话中创建的任务在任务 Tab 实时可见，反之任务 Tab 的变更在助手查询时返回最新数据；
6. LLM 或网络异常时有明确错误提示；断网状态下端上不产生本地数据，恢复联网后无数据冲突；
7. 在 iOS Safari、Android Chrome 及微信内置浏览器中核心流程（注册登录、任务增删改查、对话任务管理）可用。
