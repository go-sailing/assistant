## 1. 背景与目标

### 1.1 背景

MVP v0.3 验证了"对话 + 列表"双入口的**任务（待办）管理**体验：任务以"是否完成"为核心，只有一个截止时间点（`due_at`）。但用户的另一类时间管理需求——**日程（事件）管理**——在 MVP 中被明确排除：

- 日程关心"**什么时间、持续多久、在哪、和什么事冲突**"，有明确的开始与结束时间，需要按日历形态浏览；
- 用户的典型表达天然是日程式的："帮我约个周五下午 3 点到 4 点的产品评审"、"我明天上午有什么安排？"——这类需求无法用任务准确承载。

v0.1.0 在不改变 MVP 技术架构（H5 瘦客户端 + Node 云端 + PostgreSQL + DeepSeek）的前提下，新增独立的**日程领域**，并延续"双入口、数据同源、能力对等"原则：**凡手动可完成的日程操作，LLM 对话均可完成**。

同时，本版建立日程与任务之间的**关联关系**：日程分为"普通日程"与"任务日程"两类。**任务日程是任务的执行载体**——它链接一个具体任务，代表"在某个确定的时段执行该任务"，从而让任务从"有截止日的待办"落到"有明确执行时段的安排"，并在日历上获得时间冲突保护。

### 1.2 产品目标（v0.1.0）

- **核心目标**：验证"对话 + 日历"双入口的日程管理体验，用户可低成本地安排、查询和调整自己的时间；
- **成功假设**：
  1. 用户愿意用自然语言录入日程，聊天中完成的日程操作与手动操作具有完全一致的数据效果；
  2. 用户在安排时间时信赖助手提供的**时间冲突提示**；
  3. 用户愿意为重要任务安排明确的执行时段（任务日程），被安排执行时段的任务完成率不低于未安排任务。

### 1.3 非目标（v0.1.0 不做）

延续 MVP 边界，并明确以下日程相关能力不在本版范围：

- **不做任何主动触达**：不做本地通知、短信/邮件/微信提醒；日程只记录时间，不做开始前提醒推送（提醒能力列入后续版本）；
- 不做重复/周期性日程（每天、每周、每月等循环规则），v0.1.0 仅支持单次日程；
- 不做多人协作：不做参会人、邀请、共享日历、日程指派；
- 不做第三方日历账号同步（Google Calendar、Outlook、系统日历、企微/飞书日历等），不做日历订阅（ics/节假日/生日订阅）；
- 不做会议室/资源预订、空闲忙闲查询；
- 日程与任务**保持独立建模、不做字段合并**；二者仅通过"任务日程"建立关联（链接，而非复制/转换）：不做普通日程一键转任务、不做普通日程与任务日程的事后互相转换，**日程类型创建后不可变更**；
- 不做拖拽改期、手势缩放周视图等重交互（日历视图仅支持点击与表单编辑）；
- 延续 MVP：不做原生 App、PC 适配、离线/本地持久化、语音与多模态输入。

## 2. 目标用户与使用场景

### 2.1 目标用户

- 已有待办管理习惯、同时需要安排"有明确时间段"事务的个人用户（工作会议、就医、缴费、聚会等）；
- 希望像和助理说话一样安排时间，并期望助手主动发现时间冲突的用户；
- 希望把重要任务"排进日历"、在具体时段专注执行的用户。

### 2.2 核心使用场景

| 场景 | 描述 |
| --- | --- |
| 口语建日程 | 用户对助手说"明天下午 3 点到 4 点产品评审，在 3 楼大会议室"，系统自动解析开始/结束时间、地点并创建**普通日程**。 |
| 给任务排期 | 用户说"把季度报告安排在明天下午 3 点到 4 点写"，系统命中该任务后创建一条**任务日程**链接它，日历与任务详情中均可见。 |
| 冲突改约 | 用户说"周五下午 3 点帮我约个体检"，助手发现该时段已有"季度复盘"，先提示冲突并给出候选时段，由用户决定。 |
| 日历浏览 | 用户在"日程"Tab 月视图中查看哪天有安排，点击某天查看当日全部日程时间轴；任务日程以关联样式区分展示。 |
| 晨间查看当日安排 | 用户问"我今天有什么安排？"，助手按时间顺序返回当日日程卡片列表（含任务日程及其任务完成态）。 |
| 到点执行并完成 | 用户在当日视图的任务日程上直接勾选，关联任务被标记完成；或对助手说"下午的季度报告我做完了"。 |
| 对话改期 | 用户说"把明天的产品评审推迟到后天上午 10 点"，助手更新日程并再次做冲突校验。 |
| 范围查询 | 用户问"我这周下午都安排了什么？"，助手按日期范围查询并汇总回答。 |
| 取消安排 | 用户说"周五的体检不去了，删掉"，助手命中唯一对象后经确认删除日程；多个候选时先澄清。 |
| 任务日程混合查询 | 用户问"下周三我有什么安排、有什么要交的？"，助手同时返回当日日程（含任务日程）与当日到期任务（P1）。 |

## 3. 产品整体说明

### 3.1 产品形态（延续 MVP）

- 仍为**移动端 Web（H5）**瘦客户端：日程数据存储、业务规则校验、时间冲突计算、LLM 调用与工具执行全部在服务端完成，端上仅展示与交互；
- 全部读写需联网，断网展示错误占位与重试入口，端上不产生本地日程数据、不做写操作暂存；
- 账号体系沿用 MVP（邮箱 + 密码注册登录，JWT 鉴权，数据按用户隔离）。

### 3.2 信息架构（v0.1.0 调整）

底部导航由 MVP 的两个 Tab 扩展为**三个 Tab**：

```
个人助手 App
├── 日程 Tab（新增）
│   ├── 月视图（日历网格，有日程的日期显示圆点标记）
│   ├── 当日视图（时间轴/Agenda，按开始时间排序）
│   ├── 日程详情页（普通日程 / 任务日程两种形态）
│   └── 新建/编辑日程（表单：选择日程类型；任务日程需选择关联任务）
├── 任务 Tab（沿用 MVP，新增排期入口）
│   ├── 任务列表 / 任务详情页（详情内新增"安排日程"入口）
│   └── 清单管理（内置清单 + 自定义清单）
└── 助手 Tab（能力扩展）
    ├── 对话列表
    └── 对话页（消息流 + 任务卡片 + 日程卡片 + 工具执行确认）
```

### 3.3 双入口关系（关键设计原则，扩展至日程领域）

1. **数据同源**：手动操作与对话操作读写同一套日程数据，任一入口的变更在另一入口实时可见；
2. **能力对等**：LLM 聊天具备日程管理的**全部能力**——凡手动可完成的日程操作，对话均可完成（见第 5 章能力对照表）；
3. **结果可追溯**：聊天中发生的日程变更以结构化日程卡片展示，并同步反映在日历视图中；
4. **领域关联而非合并**：日程分普通日程与任务日程。**任务日程链接且仅链接一个任务，是该任务的执行时段载体**。任务仍在任务体系内管理（完成态、优先级、清单、截止时间），日程提供时间视图与冲突保护；删除任务日程只取消安排、不删除任务。

## 4. 功能需求一：日程管理

### 4.1 日程数据模型

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string | 是 | 日程唯一标识，系统生成（UUID） |
| event_type | enum | 是 | `normal`（普通日程）/ `task`（任务日程），默认 `normal`；**创建后不可变更** |
| task_id | string | 条件必填 | 任务日程必填，且必须为当前用户拥有的任务；普通日程为 `null` |
| title | string | 是 | 日程标题，最长 100 字符。普通日程由用户填写；**任务日程的标题以关联任务标题为准**（见 4.6，不冗余存储任务标题副本） |
| note | string | 否 | 备注/描述，最长 2000 字符（任务日程可填写日程备注，与任务备注相互独立） |
| location | string | 否 | 地点，最长 200 字符（自由文本，不做地图选点） |
| all_day | boolean | 是 | 是否全天日程，默认 `false` |
| start_at | datetime | 是 | 开始时间（带时区存储，见 4.5）；全天日程时为某日 00:00 |
| end_at | datetime | 是 | 结束时间（带时区存储）；全天日程时为结束日 00:00（按日期左闭右开） |
| status | enum | 是 | `scheduled`（正常）/ `cancelled`（已取消），默认 `scheduled`；v0.1.0 取消即删除，该字段为扩展预留，列表默认不展示已删除数据 |
| source | enum | 是 | 创建来源：`manual`（手动）/ `chat`（对话），用于埋点 |
| created_at | datetime | 是 | 创建时间 |
| updated_at | datetime | 是 | 最近更新时间 |

> 与任务模型的区别与联系：任务只有 `due_at` 一个时间点且核心状态是完成/未完成；日程有 `start_at` + `end_at` 时间段，无独立"完成"概念。普通日程独立存在；任务日程通过 `task_id` 链接任务，作为任务的执行时段载体，其完成态随关联任务展示。

### 4.2 功能清单

| 编号 | 功能 | 优先级 | 描述 |
| --- | --- | --- | --- |
| S-01 | 创建日程 | P0 | 手动选择日程类型（普通日程/任务日程）：普通日程填写标题（必填）、起止时间、全天、地点、备注；任务日程选择一个已有任务并设定起止时间。保存前统一进行冲突校验（4.4）。 |
| S-02 | 月视图浏览 | P0 | 月历网格展示，有日程的日期显示标记圆点与日程条数（任务日程使用区别化标记）；可翻月；"今天"按钮回到当月今日；点击日期进入当日视图。 |
| S-03 | 当日视图（Agenda） | P0 | 按开始时间顺序展示某日全部日程：时间段、标题、地点；任务日程显示任务链接标识、优先级与完成态；支持左右切换/点选日期；空状态引导新建。 |
| S-04 | 查看日程详情 | P0 | 普通日程展示标题、起止时间、地点、备注、来源、创建时间；任务日程展示关联任务信息（标题、优先级、所属清单、完成态，可跳转任务详情）及该时段、地点、备注。 |
| S-05 | 编辑日程 | P0 | 普通日程可修改标题、时间、地点、备注；任务日程可修改时间、地点、日程备注（任务字段在任务详情中修改）。**日程类型与关联任务不可变更**；保存时重新做冲突校验。 |
| S-06 | 删除日程 | P0 | 删除前二次确认；删除后不可恢复（不做回收站）。**删除任务日程只取消该安排，不删除关联任务**；任务被删除时的反向处理见 4.6。 |
| S-07 | 时间冲突提示 | P0 | 创建/编辑保存时，若与该用户已有日程（含普通日程与任务日程）时间段重叠，弹层列出冲突日程，用户可选择"仍要保存"或返回修改（见 4.4）。 |
| S-08 | 日程搜索 | P1 | 按标题、备注、地点关键词搜索日程（任务日程同时匹配关联任务标题），结果按开始时间倒序排列。 |
| S-09 | 日历聚合到期任务 | P1 | 当日视图中以分区形式展示"当日到期任务"（只读，点击跳任务详情），与任务日程分区展示，不改变任务数据模型。 |
| S-10 | 任务排期 | P0 | 在任务详情点击"安排日程"，或新建日程时选择"任务日程"并选择任务，为任务创建关联的执行时段；同一任务可被多次排期（分段执行）。 |
| S-11 | 从任务日程完成任务 | P0 | 任务日程卡片/详情上提供勾选入口，勾选后将**关联任务**标记完成（写任务 `status=completed` 与 `completed_at`），日程本身不产生完成状态。 |

### 4.3 日历视图交互要求

- **月视图**：7 列网格；今日高亮；有日程日期显示圆点（普通日程与任务日程用区别化样式，≥3 条显示聚合点）；非当月日期置灰但可点击；
- **当日视图**：从上至下时间轴，全天日程置顶独立分区；进行中日程（当前时间落在时间段内）高亮，顶部显示"当前时间"参考线；任务日程带链接标识与任务优先级标记，关联任务已完成时整条划线置灰；
- 列表项展示：时段（"15:00–16:00"，全天显示"全天"）、标题、地点图标 + 地点文本；
- 移动端适配沿用 UXUI 设计规范：375pt 基准、44pt 最小热区、安全区适配、软键盘顶起处理；
- 下拉刷新；数据实时从云端拉取，无本地缓存；网络异常展示错误占位（不展示旧数据）与重试入口。

### 4.4 时间冲突规则

- **判定**：同一用户的两条日程（不区分普通日程/任务日程），时间段**左闭右开**且存在交集即判为冲突（A.end > B.start 且 A.start < B.end）；端点相接（A.end = B.start，如 15:00–16:00 与 16:00–17:00）**不判冲突**；
- **全天日程**：与该日期内任何日程互相标记为"时间重叠提醒"，提示强度低于硬冲突（文案区分"全天安排"与"时段冲突"）；
- 冲突**不阻止保存**：仅提示，用户明确选择"仍要保存"即可创建/更新（用户可能确实需要并行安排）；
- 冲突校验范围：与目标时间段有交集的**全部已有日程**（包含跨多日的长日程）；
- 编辑时，校验排除日程自身；
- 删除日程无需冲突校验。

### 4.5 时间、时区与日期规则

- 服务端以带时区时间（timestamptz，UTC）持久化；全天日程存储约定的日期边界，返回时附带 ISO 8601 时间与用户时区偏移；
- 前端一律按**设备当前时区**展示；跨时区使用时以设备时区为准（v0.1.0 不做手动切换时区）；
- 表单支持选择日期 + 时分；快捷选项："全天"开关、开始时间默认取下一个整点或半点，结束时间默认开始时间 + 1 小时；
- `end_at` 必须晚于 `start_at`（全天日程按日期比较，结束日 ≥ 开始日），否则表单校验不通过；
- 允许创建开始时间早于当前时间的日程（保存时提示"开始时间已过"，用户确认后保存，规则与任务"已过期"提示保持一致）；
- 标题去除首尾空格后不能为空；地点、备注去除首尾空格后存储；
- 任务日程不自动回写任务的 `due_at`：排期与截止时间相互独立（后续版本可再评估联动）。

### 4.6 任务日程业务规则

1. **类型固定**：`event_type` 创建后不可变更；不支持普通日程事后改挂任务，也不支持任务日程解绑为普通日程。需要调整时删除后重建。
2. **关联校验**：任务日程的 `task_id` 必须存在且属于当前用户；不允许为**已删除**或**已完成**的任务创建任务日程（为已完成任务排期时拦截并提示"请先将任务恢复为未完成"）。
3. **关联基数**：一条任务日程链接**且仅链接**一个任务；同一任务允许关联**多条**任务日程（用于分段、多次执行），时段之间仍参与冲突检测。
4. **展示以任务为准**：任务日程的标题、优先级、所属清单、完成态均实时取关联任务数据（接口内嵌最新任务对象，历史卡片按云端刷新机制回查），不存储冗余副本；任务被改名、调整优先级后，日程展示同步变化。
5. **完成动作落在任务上**：任务日程没有独立完成状态；从日程侧勾选完成等价于在任务列表勾选（写任务状态与 `completed_at`）。取消完成同样操作任务本身。
6. **删除联动（单向级联）**：
   - 删除任务日程：仅删除日程，关联任务保留；
   - 删除任务：该任务关联的**全部任务日程级联删除**；任务删除确认文案中须明示"将同时删除 N 条任务日程"。
7. **入口**：手动可从"任务详情 → 安排日程"或"新建日程 → 任务日程 → 选择任务"进入；对话入口能力对照见 5.3。
8. **备注与地点独立**：任务日程的地点、日程备注属于日程字段，与任务备注互不影响。

## 5. 功能需求二：LLM 日程助手

### 5.1 功能概述

助手 Tab 在 MVP 任务工具集之上新增**日程工具集**。用户以自然语言完成日程的增、删、改、查（含日期范围查询）、批量操作以及**为任务排期**；LLM 通过 Function Calling 调用日程服务工具，执行结果回写日程数据库，并以日程卡片在对话中呈现。任务与日程工具同时对模型可用，由模型按用户意图选择。

### 5.2 功能清单

| 编号 | 功能 | 优先级 | 描述 |
| --- | --- | --- | --- |
| E-01 | 多轮对话 | P0 | 支持上下文连续追问（"那把它改到下午 4 点"），指代消解规则沿用 MVP（对象不明先澄清）。 |
| E-02 | 对话式日程管理 | P0 | 自然语言完成普通日程与任务日程的创建、查询、改期、编辑、删除与批量操作（能力对照见 5.3）。 |
| E-03 | 日程卡片渲染 | P0 | 对话中涉及的日程以结构化卡片展示（普通日程/任务日程两种样式：任务日程含任务链接标识、优先级与完成态，可跳任务详情），卡片点击跳转日程详情。 |
| E-04 | 写操作确认 | P0 | 对**删除日程**和**影响多条日程的批量修改**，执行前展示预览并要求用户确认；单条创建/编辑在无冲突时可直接执行。 |
| E-05 | 时间信息抽取与追问 | P0 | 自动解析自然语言中的日期与时段（"明天下午 3 点"、"下周五上午 10 点到 11 点半"、"全天"）；开始时间缺失或日期有歧义时必须追问，禁止猜测。 |
| E-06 | 冲突告知与协助改期 | P0 | 创建/改期命中冲突时，助手必须在回复中**先告知冲突日程**，再询问"仍要安排 / 换个时间"；用户给出新时间后重新校验，直到无冲突或用户明确坚持。 |
| E-07 | 执行结果反馈 | P0 | 每次工具调用后用自然语言反馈成功/失败及影响范围（如"已取消明天 3 个日程"）。 |
| E-08 | 混合意图处理 | P1 | 同一问题涉及任务与日程时（"下周三我有什么安排、要交什么"），分别调用两类工具并分区作答。 |
| E-09 | 通用问答 | P1 | 与任务/日程无关的问题正常回答，并主动引导回时间管理场景（沿用 MVP C-08）。 |
| E-10 | 对话为任务排期 | P0 | 用户表达"把某个任务安排到某时段执行"时，模型先在任务库中确认目标任务（唯一命中/多候选澄清/不存在则询问是否新建任务），再创建 `task` 类型任务日程；**禁止猜测或编造 task_id 关联**。 |

### 5.4 LLM 工具（Function Calling）定义

| 工具名 | 入参（主要） | 说明 |
| --- | --- | --- |
| `create_event` | title, start_at, end_at, all_day?, location?, note?, event_type?, task_id? | 创建单条日程。`event_type=task` 时 `task_id` 必填，服务端校验任务归属与状态（已删除/已完成拦截），标题等展示以任务为准；服务端执行冲突校验，返回新日程（任务日程内嵌关联任务对象）及冲突列表 |
| `update_event` | event_id, start_at?, end_at?, all_day?, location?, note?, title? | 修改字段；时间字段变更时重新做冲突校验。**不允许修改 `event_type` 与 `task_id`**；任务日程的 title 入参忽略（以任务标题为准） |
| `delete_event` | event_id | 删除单条日程（**调用前需对话确认**，复用 MVP pending_actions 门控机制）；删除任务日程不影响关联任务 |
| `get_event` | event_id | 查询单条日程详情（任务日程内嵌关联任务最新对象） |
| `list_events` | date?, date_from?, date_to?, task_id?, event_type?, limit?, sort? | 按日/日期范围查询，支持按关联任务与日程类型过滤；时间窗口左闭右开；返回按开始时间排序的日程数组及每日分组信息 |
| `search_events` | keyword | 标题/备注/地点关键词搜索（任务日程同时匹配关联任务标题） |
| `batch_update_events` | filter 条件（日期范围/关键词/event_type/task_id 等）, 更新字段 | 批量改期/修改（**调用前需确认并预览影响条数**）；批量删除以 filter + 删除动作承载，同样需确认 |

工具返回统一结构化 JSON：

- 日程对象 / 日程对象数组 + 操作结果摘要；任务日程对象固定内嵌 `task`（id、标题、优先级、状态、所属清单）；
- 写操作响应固定携带 `conflicts`（冲突日程数组，含标题与时段）与 `conflict_level`（`none` / `overlap` / `all_day`）；
- 由模型组织为自然语言 + 日程卡片输出；冲突非空时系统提示词强制模型先陈述冲突再询问，**不得静默强存**；
- 关联任务类错误（不存在 / 不属于该用户 / 已完成 / 已删除）返回明确业务错误码与原因，模型必须如实告知并引导，**不得编造 task_id**。

### 5.5 自然语言时间解析规则（服务端 + 模型协同）

| 表达情况 | 解析与处理规则 |
| --- | --- |
| 明确日期 + 时段 | "明天下午 3 点到 4 点" → start/end 完整，直接创建 |
| 只有开始时间 | "明天下午 3 点产品评审" → end 默认 +1 小时，并在回复中明示"默认安排 1 小时"，用户可纠正 |
| 全天表达 | "全天 / 一整天 / 请假一天" → all_day=true，按日期边界存储 |
| 相对日期 | "今天/明天/下周五/这周末" → 以**服务器当前日期**为基准换算；模型上下文中注入当前日期与星期 |
| 时间歧义 | "周五"无法判断本周还是下周、"早上"无具体时间 → **必须追问**，不得猜测 |
| 无法解析 | "过两天有空的时候"等无确定时间 → 追问具体日期 |
| 过去时间 | 解析结果早于当前时间 → 创建前提示"开始时间已过"，请用户确认 |
| 结束早于开始 | 服务端校验拦截，要求模型修正或追问 |
| 时区/节假日 | 按设备/服务器时区处理；不做节假日推断（"节后上班第一天"需追问具体日期） |
| 为任务排期 | 先确认任务对象：唯一命中直接关联；多候选列出候选任务；任务库无匹配时**先询问用户是否新建任务**，确认后依次 `create_task` → `create_event(task)`，不得自行猜测关联 |

### 5.6 对话交互要求

- 消息类型在 MVP 基础上新增：**日程卡片**（普通日程/任务日程两种样式）、**多日日程列表卡片**（按日分组）、**冲突提示块**（冲突日程 + "仍要安排 / 换个时间"按钮）、操作确认条（取消/确认，复用 MVP 组件）；
- 普通日程卡片字段：标题、时段（"9月18日 周四 15:00–16:00"，全天显示"全天"）、地点、冲突/进行中标记；
- 任务日程卡片字段：时段、关联任务标题、任务优先级标记、所属清单、完成勾选态、地点；卡片可跳转日程详情，任务信息区可跳转任务详情；
- 工具执行中显示"正在处理…" loading 态（沿用 MVP）；
- 模型无法确定操作对象时（"把那个会删了"且存在多个候选，或"把它排到明天"但任务不明确），必须先列出候选（日期 + 时段 + 标题 / 任务候选）让用户选择，**禁止猜测执行写操作**；
- 批量操作先预取受影响日程 → 展示条数与列表预览 → 用户确认后才执行（沿用 MVP 危险操作门控：删除/批量写操作即使模型调用工具，服务端也不直接执行，而是写入 pending_actions 并下发 confirm 事件，TTL 300s）；
- 用户取消确认后数据保持原状，可继续对话修正；
- 历史会话中的日程卡片在拉取消息时按日程 ID 批量回查云端最新状态覆盖快照（沿用 MVP 卡片刷新机制，改期、删除、关联任务改名/完成后历史卡片不陈旧）。

### 5.7 异常与边界处理

| 情况 | 处理方式 |
| --- | --- |
| LLM 服务超时/不可用 | 提示"助手暂时不可用，请稍后重试"，不影响日程 Tab 正常使用（沿用 MVP 3001 错误码与友好文案，不透传上游错误） |
| 工具调用失败 | 对话中告知具体失败原因，日程数据保持原状，支持重试；禁止模型对同一失败工具无提示连续重试 |
| 模型返回非法参数（时间格式/结束早于开始/越权 ID） | 服务端 zod 校验拦截并回灌错误原因要求模型重新生成；连续失败降级错误提示 |
| 时间表达无法解析或有歧义 | 按 5.5 追问，不自行猜测 |
| 命中时间冲突 | 按 E-06 处理：告知冲突 → 用户决策；用户坚持则携带"强制保存"意图执行 |
| 为已完成/已删除任务排期 | 工具返回业务错误，模型提示"任务已完成/不存在，可先恢复任务或新建"，不得写入脏关联 |
| 幻觉日程 ID / 引用已删除日程 | 工具返回 1004，模型须如实告知"未找到该日程"并引导查询，不得编造 |
| 编造或误猜 task_id | 服务端按归属校验拦截；模型必须先经任务查询/搜索确认或向用户澄清，禁止凭名称猜测关联 |
| 表达超出任务/日程范围 | 正常应答（E-09），不触发任何工具 |
| 含敏感/不合规内容 | 按 LLM 安全策略拒绝，不执行工具 |
| 批量操作预览 0 条命中 | 明确告知"没有找到符合条件的日程"，不产生确认条 |
| 删除任务级联影响 | 对话中删除任务时，确认文案须包含"将同时删除 N 条任务日程"（与手动入口一致） |

### 5.8 模型与调用方式（延续 MVP）

- LLM 提供方：DeepSeek，模型 `deepseek-flash`，由**服务端统一代理调用**，API Key 不下发前端；
- Function Calling 同时承载任务工具集与日程工具集（含既有 `list_lists` 等全部任务工具，不在工具列表上做意图裁剪）；
- 对话回复采用 SSE 流式输出（事件类型沿用 meta/text_delta/tool_call/cards/clarify/confirm/done/error，日程卡片走 cards 事件，冲突块新增结构化卡片类型）；
- 系统提示词新增日程领域说明：普通日程与任务日程的区别、任务日程作为任务执行载体的关联规则（类型不可变更、标题以任务为准、删除日程不删任务、删除任务级联删日程）、时间段左闭右开、冲突必须先告知、时间解析与追问规则、默认 1 小时时长约定、关联任务必须先查证不得猜测；
- 服务端配置可替换模型；新增工具参数校验、工具执行与任务领域共用同一 executor 框架。

## 6. 非功能性需求

### 6.1 性能

- 月视图首屏（含当月每日日程聚合）加载 ≤ 1.5s；
- 当日视图切换日期响应 ≤ 800ms；
- 手动创建/编辑日程保存（含冲突校验）响应 ≤ 800ms；
- 对话场景：用户发消息到首字返回 ≤ 3s（DeepSeek 流式输出，服务端自身开销目标 ≤ 50ms，含冲突查询与关联任务查询）；
- 冲突校验查询在单用户 3000 条日程数据量下 P95 ≤ 20ms（建议对 `user_id + start_at/end_at` 建索引，`task_id` 建外键索引以支持任务排期查询与级联删除）。

### 6.2 可用性与兼容性

- 沿用 MVP：兼容 iOS Safari、Android Chrome 近两个大版本及微信内置 WebView；页面内返回导航、软键盘顶起处理不依赖浏览器导航；
- 月视图网格在小屏（≥320pt 宽）可正常点按，日期格热区 ≥ 44pt；
- PC 浏览器可打开但不专门适配；不支持离线，错误态展示占位而非旧数据。

### 6.3 账号与数据

- 沿用 MVP 邮箱 + 密码体系，日程数据按用户隔离，不做任何跨用户共享；
- 日程数据仅在云端 PostgreSQL 持久化，端上不做本地持久化；
- 用户注销账号时日程数据随账号删除（与任务数据同一策略）；任务日程与任务的外键关系限定在同一用户内。

### 6.4 隐私与安全

- 全程 HTTPS；DeepSeek API Key 仅在服务端；
- 发送给 DeepSeek 的上下文仅包含对话所必需的日程/任务结构化信息（标题、时间、地点等用户主动输入内容），不附带其他用户数据；
- 地点字段为自由文本，前端明确提示"请避免填写敏感精确位置"（非强制校验）；
- 对话由 AI 生成、可能出错，删除/批量改期以用户确认为准（沿用 MVP 安全告知）。

### 6.5 可观测性

- 埋点：日程创建来源（manual/chat）、日程类型（normal/task）分布、各日程工具调用类型与成功率、时间解析追问率、冲突提示发生率与"仍要保存"率、任务排期率（被安排过任务日程的任务占比）、任务日程对应任务的完成率、确认条接受/取消率、对话轮次；
- 异常日志：时间解析失败、参数校验失败、task_id 关联失败（不存在/越权/已完成）、工具执行失败、长上下文指代失败（对照 MVP TC-CHAT-015 遗留问题，新工具上线需同步回归）。

## 7. 关键业务流程

### 7.1 对话创建普通日程（含冲突分支）

```
用户输入自然语言
  → 服务端组装消息 + 工具定义 + 当前日期/星期上下文发给 LLM
  → LLM 解析意图与时间字段
    ├─ 开始时间缺失/日期歧义/无法解析 → 返回追问 → 用户补充 → 重新解析
    ├─ 仅有开始时间 → 默认 1 小时，回复中明示
    └─ 信息完整 → 调用 create_event（event_type=normal）
  → 服务端校验字段 + 执行冲突查询 + 写入日程库（source=chat）
  → 返回日程对象与 conflicts
    ├─ 无冲突 → LLM 生成确认话术 → 渲染文本 + 日程卡片
    └─ 有冲突 → LLM 先陈述冲突日程 → 冲突提示块
                  ├─ 用户选"换个时间" → 给出新时间 → 重新校验
                  └─ 用户选"仍要安排" → 完成创建
  → 日程 Tab 月视图/当日视图同步出现该日程
```

### 7.2 对话为任务安排日程（任务日程）

```
用户："把季度报告排到明天 15:00–16:00 做"
  → 模型先在任务库查证目标任务（search_tasks / get_task）
    ├─ 唯一命中 → create_event（event_type=task, task_id, start_at, end_at）
    ├─ 多候选   → 列出候选任务（标题/清单/截止时间）请用户选择，禁止猜测
    └─ 无匹配   → 询问"还没有'季度报告'这个任务，要顺便创建吗？"
                   └─ 用户确认 → create_task → create_event(task)
  → 服务端校验：任务归属、任务未删除且未完成、时间字段合法、冲突查询
  → 返回任务日程（内嵌任务对象）与 conflicts → 按 7.1 冲突分支处理
  → 日历当日视图出现任务日程（链接标识）；任务详情出现该排期记录
后续：
  ├─ 用户在日程上勾选完成 → update_task_status → 任务与任务日程同时展示完成态
  ├─ 删除任务日程 → 仅日程消失，任务保留
  └─ 删除任务 → 确认文案明示"同时删除 N 条任务日程" → 级联删除
```

### 7.3 对话删除/批量改期

```
LLM 解析出删除/批量意图
  → 先调用查询工具预取候选日程
    ├─ 0 条 → 告知未找到，不产生确认
    ├─ 多条且对象不明确 → 列候选（日期+时段+标题）请用户选择
    └─ 对象明确 → 展示操作预览（影响对象与条数）+ 取消/确认
  → 用户确认（pending_actions，TTL 300s）后才执行写工具
  → 反馈执行结果；日历视图同步更新；确认超时按 3003 提示重新发起
```

### 7.4 手动与对话的数据同源

```
日程 Tab 表单保存（冲突提示 → 仍要保存）
  → 同一 EventService 写入（source=manual）
  → 助手对话中查询（"我今天有什么安排"）返回该日程最新数据
反之：对话创建的日程立即出现在月视图/当日视图；
     对话历史卡片在再次拉取时回查云端，反映后续手动改期/删除、关联任务改名/完成的结果。
```

## 8. 验收标准

### 8.1 日程管理

1. 可完成日程的增、删、改、查，字段与 4.1 节数据模型一致；全天日程、跨日日程存储与展示正确；
2. 日程类型字段生效：普通日程/任务日程创建、展示、样式区分正确；**类型创建后不可变更，关联任务不可更换**；
3. 任务日程关联规则正确：task_id 归属校验通过；为已删除/已完成任务创建被拦截；标题/优先级/完成态实时取关联任务数据；同一任务可关联多条任务日程；
4. 月视图标记、当日视图排序正确；今日、进行中、全天分区、任务日程链接标识与完成态展示正确；
5. 冲突检测准确：普通日程与任务日程统一参与检测，重叠必报、端点相接不报、全天日程提示文案正确、编辑排除自身、冲突不阻止保存；
6. 时间校验生效：结束早于开始被拦截、过去时间有提示、时区存储与跨时区展示正确；任务排期不回写任务 due_at；
7. 删除联动正确：删除任务日程不影响任务；删除任务级联删除其全部任务日程，且确认文案明示条数；日程删除经二次确认且不可恢复；
8. 可从任务详情"安排日程"、新建表单选择任务两种入口完成任务排期；任务日程勾选完成等价于任务完成（含 completed_at）；
9. 下拉刷新与错误占位符合云端无缓存要求。

### 8.2 LLM 日程助手

1. 第 5.3 节能力对照表中**全部 P0 能力**均可通过对话完成，写入结果与手动操作**字段级完全一致**，冲突校验与任务关联规则一致；
2. 单条创建指令信息完整时一句话完成，无需二次填写表单；默认 1 小时时长在回复中明示；
3. 为任务排期时：唯一任务可直接关联；多候选 100% 澄清；任务不存在 100% 先询问再新建；**不存在任何猜测/编造 task_id 的误关联**；
4. 删除、批量操作 100% 经过确认条（pending_actions 门控），取消/超时后数据无变化；对话删除任务时确认文案包含级联日程条数；
5. 对象不明确 100% 出现候选澄清；时间有歧义 100% 追问；不发生误写、误删；
6. 命中冲突时 100% 先告知冲突日程再询问用户，不存在静默强存；
7. 对话中创建的日程在日程 Tab 实时可见；手动改期/删除、关联任务改名/完成后，助手查询与历史卡片均展示最新状态；
8. 任务与日程工具共存：同一会话内两类操作互不干扰，任务日程关联数据一致，P1 混合查询可分区作答；
9. LLM/网络异常有明确友好提示且不透传上游错误；断网下端上不产生本地数据；
10. 在 iOS Safari、Android Chrome、微信内置浏览器中核心流程（建日程、任务排期、日历浏览、对话日程管理、冲突改期、删除确认与联动）可用；
11. 长会话稳定性：新工具集上线后，须连同 MVP 遗留的 TC-CHAT-015/018（长上下文指代）连跑 ≥5 轮回归，无新增间歇失败。

## 11. 评审决议

| # | 议题 | 决议 | 已落地章节 |
| --- | --- | --- | --- |
| 1 | 日程与任务的模型关系（2026-09-16 修订） | **独立建模、通过任务日程关联**：日程作为任务执行的载体；日程新增 `event_type`（normal 普通日程 / task 任务日程）与 `task_id`；任务日程链接且仅链接一个任务；删除日程不删任务，删除任务级联删除其任务日程 | 1.1、3.3、4.1、4.6 |
| 2 | 底部导航形态 | 扩展为**日程 / 任务 / 助手三个 Tab**，日历为独立一级入口；任务详情新增"安排日程"入口 | 3.2、4.6 |
| 3 | 主动提醒/通知 | v0.1.0 **不做任何提醒触达**（延续 MVP 无推送约束），仅记录日程时间 | 1.3 |
| 4 | 重复/周期日程 | v0.1.0 **不做**，仅支持单次日程；周期规则（含编辑整条/单条的语义）列入后续版本 | 1.3 |
| 5 | 冲突处理策略 | 冲突**只提示不阻止**：端点相接不判冲突，全天日程弱化提示；普通日程与任务日程统一参与检测；用户可坚持保存；对话中必须先告知冲突再询问 | 4.4、5.6、E-06 |
| 6 | 结束时间缺省 | 语言/表单只给开始时间时，结束时间默认 **+1 小时**，助手须在回复中明示可纠正 | 4.5、5.5 |
| 7 | 时区策略 | 服务端 UTC（timestamptz）存储，按**设备时区**展示，v0.1.0 不提供手动切换时区 | 4.5 |
| 8 | 第三方日历/协作 | 不做日历账号同步、共享、参会人、会议室预订 | 1.3 |
| 9 | LLM 工具集策略 | 日程工具与任务工具**同时全量**挂载给模型（含 list_lists），由模型按意图选择；复用 SSE、pending_actions 确认门控与卡片刷新机制 | 5.4、5.6、5.8 |
| 10 | P1 范围 | 日程搜索（S-08）、日历聚合到期任务（S-09）、混合意图查询（E-08）作为 P1，随版本进度裁剪，不影响 P0 发布 | 4.2、5.2 |
| 11 | 日程-任务关联细则（2026-09-16 新增） | 日程类型**创建后不可变更**、不可事后转换或换挂任务；任务日程标题/优先级/完成态以关联任务实时数据为准，不冗余存储；同一任务可有多条任务日程；不允许为已完成/已删除任务排期；排期不自动回写任务 `due_at`；对话关联任务必须先查证、禁止猜测 task_id | 4.1、4.5、4.6、5.4、5.5、5.7 |
