## 1. 测试概述

### 1.1 测试对象与规模

v0.1.0 在 MVP（任务管理）基础上新增**日程领域**，本期执行**测试用例文档全部 144 项**：

| 模块 | 编号区间 | 用例数 |
| --- | --- | --- |
| EVENT（日程） | TC-EVENT-001～070 | 70 |
| CHAT（对话日程能力） | TC-CHAT-040～078 | 39 |
| SYNC + SEC + AUDIT | TC-SYNC-006～011 / TC-SEC-012～020 / TC-AUDIT-005～008 | 19 |
| NFR（性能/时区/兼容/A11y） | TC-NFR-006～038 | 16 |
| **合计** | | **144** |

同时执行 **MVP 冒烟集回归**（10 组断言，覆盖 AUTH/LIST/TASK/CHAT/SYNC/SEC 的 P0 项）验证任务域无回退。

### 1.2 测试环境与数据

- 后端：Node 18 + Express + TypeScript，`localhost:3000`（本次测试将 `RATE_LIMIT_AUTH_PER_MIN`/`RATE_LIMIT_CHAT_PER_MIN` 临时提升至 500，避免批量用例被限流；生产默认值 20 不变）
- 数据库：PostgreSQL 15 容器 `assistant-pg`，迁移 001/002/003 已应用
- 前端：Vite dev server `localhost:5173`（`/api` 代理到后端），浏览器移动端模拟 375×812
- LLM：**真实 DeepSeek**（模型 `deepseek-flash`），未使用任何 mock
- 测试账号：每用例独立注册（`qa_*@test.com`）；UI 用例使用预置账号 `uidemo_*@test.com`
- 浏览器：桌面 Chromium 设备模拟（**无 iOS Safe ria / Android 真机 / 微信 WebView 环境**，相关 3 项标注环境阻塞）

## 3. 缺陷清单（全部已修复并复验）

| # | 严重度 | 缺陷 | 根因 | 修复 | 复验 |
| --- | --- | --- | --- | --- | --- |
| 1 | **P1（阻断）** | 编辑任意已存在日程**必保存失败**，弹出「日程类型与关联任务创建后不可更改」 | 前端 `buildPayload` 创建/编辑共用，PATCH 恒下发 `event_type`；服务端只要 `event_type !== undefined` 即抛 4003 | 前端编辑态不下发 `event_type/task_id`；服务端改为仅在**值真的发生变化**时拒绝 | API 5 组用例全通过（同值回传 0 / 不下发 0 / 真改类型 4003 / 任务日程同值 0 / 换绑 4003） |
| 2 | **P1** | 当日视图**完全不显示冲突标记** | 列表接口 `GET /events?date=` 的 DTO 不带 `conflicts`，前端 `hasConflict()` 恒为 false（详情接口才有） | 列表返回时在结果集内两两比对标注冲突（避免 N+1） | 列表 API：重叠 2 条各 `conflicts=1`、相接 `conflicts=0`；浏览器复验 09-17 三枚、09-16 四枚胶囊 |
| 3 | **P1** | 从当日视图返回月视图后**选中日期丢失** | `eventSync.setFocusDate()` 全仓无调用点，`takeFocusDate()` 恒为空 | 返回时携带 `?date=`，月视图从路由 query 恢复选中日期 | 浏览器复验：返回后 URL `/calendar?date=2026-09-17`、标题 2026年9月、`aria-current` 在 17 日 |
| 4 | P2 | 非法时区参数导致 **500「服务器内部错误」**（有信息泄露风险） | `tz` 直接拼入 `AT TIME ZONE`，PG 报错冒泡 | 白名单正则 + `pg_timezone_names` 校验，非法值回退默认时区 | `tz=../../etc`、`tz=NoSuchZone` 均返回 `code=0` 正常回退 |
| 5 | P2 | 对话说「把…日程都取消」时**无法进入批量确认流程** | 模型只表达删除意图、不传 `update` 也不传 `delete`，服务端按「未指定修改字段」报参数错误 | 与工具描述对齐：不给 `update` 即视为批量删除 | TC-CHAT-055 复验：确认条 1 个、预取 3 条、确认后 3→0 |
| 6 | P2 | 历史卡片中**已删除日程**仍显示陈旧快照，无法辨识 | 刷新逻辑对查不到的日程保留原快照，未做标记 | 后端标记 `missing: true`，前端渲染「该日程已删除」占位（灰底划线） | TC-CHAT-076 通过：改期后时间已刷新、已删除日程 `missing=true`；TC-SYNC-009 通过 |
| 7 | P2 | 对话给出**过去时间**时直接创建，未提示确认（PRD 5.5 要求） | 系统提示词缺少该规则 | 提示词新增「时间早于当前时间须先提示确认」 | TC-CHAT-067 复验通过（不再直接创建） |
