## 1. 设计概述

### 1.1 系统边界（增量）

- v0.1.0 在 MVP 边界内新增**日程领域**：普通日程（normal）与任务日程（task，链接一个任务作为执行时段载体）；
- 不引入新外部依赖：不接入日历服务、不接入推送/通知通道、不接入时区库以外的第三方服务；
- 日程能力同时通过 \*\*REST（日程 Tab 手动入口）\*\*与 \*\*LLM 工具（助手 Tab 对话入口）\*\*开放，两条路径共用同一个 EventService（对齐 MVP TaskService 的"领域唯一入口"原则）；
- 任务领域有受控改动：任务删除级联删除任务日程、任务详情暴露排期列表。

### 1.2 设计目标与手段

| 目标        | 设计手段                                                        |
| --------- | ----------------------------------------------------------- |
| 双入口能力对等   | REST Controller 与 Tool Executor 均只调用 EventService，业务规则只实现一次 |
| 任务日程关联一致性 | DB CHECK + 外键约束；标题等展示字段实时 JOIN tasks，不冗余存储；任务删除事务内级联        |
| 冲突检测快且准   | 时间段重叠一条索引范围 SQL；冲突"不阻止保存"，用二次确认参数承载两阶段提交                    |
| AI 不产生脏关联 | task\_id 服务端归属/状态校验；模型必须先经任务查询工具查证，禁止凭名称猜 ID                |
| 月视图高性能    | 服务端按用户时区做日聚合，只返回日期 → 计数，不拉整月明细                              |
| 可平滑演进     | 周期日程、提醒字段在表结构上预留扩展空间，应用层不提前实现                               |

### 3.2 前端职责与约束（沿用 + 新增）

- 仍然**不保存业务数据**：月视图/当日视图数据每次进入拉取云端，不写 LocalStorage/IndexedDB；错误态只展示占位；
- 月聚合数据轻量（日期→计数），允许在日历 Tab 停留期间内存缓存当月，翻月/下拉刷新/从其他 Tab 切回时重拉；
- 冲突弹层交互由前端状态机承载：
  1. `POST /events`（不带 `confirm_conflict`）→ 201 直接成功，或 **409/code=4009** 返回 conflicts（数据未落库）；
  2. 用户点"仍要保存"→ 原样重发并带 `confirm_conflict=true`；
  3. 用户点"返回修改"→ 不重发，表单内容保留；
- 对话中的冲突由 ConflictBlock 承载，"仍要安排"通过下一条消息驱动模型重调工具（工具带 `confirm_conflict=true`），前端不自行重放 HTTP；
- 任务日程勾选直接调用 `POST /tasks/{id}/complete|uncomplete`（复用任务接口），成功后本地更新该卡片与全局任务 store。

## 4. 后端模块设计

### 4.1 Event 模块职责

| 子能力  | 方法（EventService）                                | 说明                                                               |
| ---- | ----------------------------------------------- | ---------------------------------------------------------------- |
| 创建   | `create(userId, input, source)`                 | 校验时间、类型一致性、关联任务归属与状态；写 conflicts 检测；未确认冲突时抛 `EventConflictError` |
| 编辑   | `update(userId, id, patch)`                     | 禁止改 event\_type/task\_id；时间变更重新冲突检测（排除自身）                        |
| 删除   | `remove(userId, id)`                            | 单条删除；任务日程不影响 tasks 表                                             |
| 查询   | `get / list / search`                           | 任务日程 LEFT JOIN tasks + task\_lists 实时组装 DTO                      |
| 月聚合  | `monthly(userId, year, month, tz)`              | 按设备时区聚合日计数                                                       |
| 冲突查询 | `findConflicts(userId, start, end, excludeId?)` | 单条范围 SQL，返回冲突日程与 level                                           |
| 任务维度 | `listByTask / countByTask / deleteByTask`       | 供任务详情、删除级联使用                                                     |

### 4.2 日程类型与关联的领域规则（服务端强制）

1. `event_type=normal`：`task_id` 必须为空，title 必填（trim 后非空，≤100）；
2. `event_type=task`：`task_id` 必填且通过三重校验——存在、归属当前用户、`status='todo'`（已完成任务拒绝排期，抛 4002，提示先恢复）；
3. 类型与关联**创建后不可变**：update 入参出现 `event_type/task_id` 一律拒绝（4003），不存在"改挂"部分成功；
4. 任务日程**不存标题副本**：events.title 允许 NULL，DTO 的 title 由 `COALESCE(t.title, e.title)` 实时产出；
5. 完成动作不经过 EventService：日程无完成状态，勾选走 TaskService.setStatus；
6. 删除联动：
   - 删任务日程：仅 DELETE events；
   - 删任务：TaskService.remove 单事务内 `count → DELETE events WHERE task_id → DELETE tasks`，返回 `deleted_event_count`；DB 外键同时设 `ON DELETE CASCADE` 兜底防漏；
7. 时间规则：`end_at ≥ start_at`（DB CHECK 兜底，全天允许相等=单日全天）；全天日程 start/end 为日期边界（左闭右开，跨 N 天存 N+1 日 00:00）；
8. 排期不回写 `tasks.due_at`。

### 4.3 冲突检测设计

**判定（SQL 层）**：对同一用户，时间段左闭右开相交：

```sql
SELECT e.*, t.title AS task_title, t.status AS task_status, t.priority,
       l.name AS list_name
FROM events e
LEFT JOIN tasks t ON e.task_id = t.id
LEFT JOIN task_lists l ON t.list_id = l.id
WHERE e.user_id = $1
  AND e.start_at < $2::timestamptz   -- 目标 end_at
  AND e.end_at   > $3::timestamptz   -- 目标 start_at
  AND e.id <> $4                      -- 编辑时排除自身
ORDER BY e.start_at
LIMIT 50;
```

- 命中索引 `idx_events_user_time (user_id, start_at, end_at)`；
- `conflict_level` 由应用层根据结果集判定：
  - 结果为空 → `none`；
  - 结果中含 all\_day 日程（或目标自身是全天）→ `all_day`（弱化提示）；
  - 其余 → `overlap`；
- 端点相接（`A.end = B.start`）因严格不等号天然不报；
- 冲突**从不阻断数据库**，阻断只发生在"未带确认标记"的应用层校验，见 4.4。

### 4.4 冲突两阶段确认（手动/对话同构）

| 阶段        | REST 行为                                             | LLM 工具行为                                                                                                        |
| --------- | --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 首次请求（未确认） | 有冲突 → HTTP 409 / code 4009，body 含 conflicts，**不写库** | `create_event/update_event` 返回 `{saved:false, need_conflict_confirmation:true, conflicts}`，**不写库**；提示词强制模型先告知用户 |
| 用户坚持      | 同参重发带 `confirm_conflict=true` → 200/201             | 模型同参重调工具带 `confirm_conflict=true` → 写库                                                                          |
| 改时间       | 前端保留表单重新提交                                          | 新时间重新检测                                                                                                         |
| 无冲突       | 直接 201，body 仍带 `conflicts:[] / level:none`          | 直接写库返回日程对象                                                                                                      |

> 该机制区别于危险操作的 pending\_actions：冲突不是危险操作，不做 300s TTL 与服务端挂起，只做无副作用的参数化二次提交，保证"只提示不阻止"且无重复创建。

### 4.5 危险操作门控（复用 MVP PendingAction）

- 新增危险工具登记：`delete_event`、`batch_update_events`；
- 复用现有 `pending_actions` 表与 confirm/cancel 接口，`tool_name` 记录新工具名，`affected` JSONB 存日程快照（含内嵌任务摘要）；
- 删除任务日程的确认描述固定包含"关联任务『××』不会被删除"；删除任务（既有 delete\_task）的预取描述追加"将同时删除其 N 条日程安排"（prepare 阶段调 EventService.countByTask）。

### 5.1 ER 关系（增量）


### 5.2 迁移文件 `003_events.sql`（概要）

```sql
-- 日程（普通日程 + 任务日程）
CREATE TABLE events (
  id          BIGSERIAL PRIMARY KEY,
  user_id     BIGINT NOT NULL REFERENCES users(id),
  event_type  VARCHAR(16) NOT NULL DEFAULT 'normal',   -- normal / task
  task_id     BIGINT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  title       VARCHAR(100) NULL,    -- normal 必填（应用层 trim 校验）；task 恒为 NULL，展示取 tasks.title
  note        VARCHAR(2000) NULL,
  location    VARCHAR(200) NULL,
  all_day     BOOLEAN NOT NULL DEFAULT FALSE,
  start_at    TIMESTAMPTZ NOT NULL,
  end_at      TIMESTAMPTZ NOT NULL,
  status      VARCHAR(16) NOT NULL DEFAULT 'scheduled', -- scheduled/cancelled，本期取消即删除（物理删）
  source      VARCHAR(16) NOT NULL DEFAULT 'manual',    -- manual / chat
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  -- 类型与关联一致性
  CONSTRAINT chk_event_task_link CHECK (
    (event_type = 'normal' AND task_id IS NULL) OR
    (event_type = 'task'   AND task_id IS NOT NULL)
  ),
  -- 任务日程不允许自拟标题；普通日程必须有标题
  CONSTRAINT chk_event_title CHECK (
    (event_type = 'task' AND title IS NULL) OR
    (event_type = 'normal' AND title IS NOT NULL AND char_length(btrim(title)) > 0)
  ),
  -- 结束不得早于开始（全天单日两端相等合法）
  CONSTRAINT chk_event_time CHECK (end_at >= start_at)
);

-- 冲突检测主索引（范围相交查询）
CREATE INDEX idx_events_user_time ON events(user_id, start_at, end_at);
-- 任务维度查询与删除级联
CREATE INDEX idx_events_user_task ON events(user_id, task_id);
-- 搜索（任务日程的任务标题在应用层 JOIN tasks 后 ILIKE，不在此建生成列）
CREATE INDEX idx_events_location_note ON events
  USING gin (to_tsvector('simple', coalesce(location,'') || ' ' || coalesce(note,'')));
```

**关键规则**

- 迁移随发布自动执行（沿用 `DB_AUTO_MIGRATE=true` 与 `db/migrate.ts`）；
- 所有查询强制 `user_id` 条件；task\_id JOIN 后再次校验 `t.user_id = e.user_id`（防御性，外键已间接保证）；
- 月聚合按时区换算日期：

```sql
SELECT (e.start_at AT TIME ZONE $1)::date AS day,
       e.event_type,
       count(*) AS cnt
FROM events e
WHERE e.user_id = $2
  AND e.start_at >= $3::timestamptz AND e.start_at < $4::timestamptz  -- 月首/次月首（UTC 边界放宽取整月+1天）
GROUP BY 1, 2;
```

输入为前端上传的 IANA 时区（如 `Asia/Shanghai`）；PG 内置 tzdata 支持；结果在应用层合并为 `{date: '2026-09-18', normal: 1, task: 2}`；

- 全天日程在聚合中计入其 `start_at` 所在日期；跨日全天日程只在首日计点（UX 月点只表"有安排"，明细由当日视图承载）。

## 6. API 设计

### 6.1 通用约定（沿用 MVP）

- Base `/api/v1`，Bearer JWT；统一包裹 `{code,message,data}`；时间 ISO 8601 UTC；
- 所有时间入参支持 `2026-09-18T15:00:00+08:00`；全天日程传 `00:00:00` 日期边界并置 `all_day=true`；
- 新增可选请求头/查询参数 `tz`（IANA 时区），仅月聚合接口必填，缺省取服务器时区。

### 6.2 日程接口清单

| 方法     | 路径                                                   | 说明                                                                          |
| ------ | ---------------------------------------------------- | --------------------------------------------------------------------------- |
| GET    | `/events/monthly?year=2026&month=9&tz=Asia/Shanghai` | 月视图聚合：`[{date, normal, task}]`                                              |
| GET    | `/events?date=2026-09-18&tz=`                        | 当日/范围查询：`date` 或 `date_from/date_to`（左闭右开）；支持 `event_type`、`task_id`、`sort` |
| GET    | `/events/search?keyword=`                            | P1：标题/地点/备注 + JOIN 任务标题                                                     |
| POST   | `/events`                                            | 创建；body 含 `confirm_conflict`（见 6.3）                                         |
| GET    | `/events/{id}`                                       | 详情（任务日程内嵌 task；附带当前 conflicts）                                              |

### 7.2 zod 校验要点（executor 层）

- 时间字段：`z.string().datetime()`（接受偏移），end ≥ start 在 Service 层校验（跨全天语义）；非法时间回灌模型自纠（沿用最多 2 轮）；
- `create_event`  refine：
  - `event_type==='task'` ↔ `task_id` 为正整数，二者必须同时满足；
  - `event_type==='normal'` ↔ title trim 非空；
- `list_events` refine：date 与 date\_from/date\_to 二选一形态，至少一种时间范围（防止拉全量）；
- 越权/幻觉 ID：Service 查不到返回 1004，executor 回灌"未找到该日程/任务，请先查询"，禁止模型编 ID；
- 已完成任务排期：Service 抛 4002，错误文案回灌模型（"任务已完成，请先恢复或换一个任务"）。

### 7.3 系统提示词追加段（要点）

```
【日程领域】
- 日程分两类：普通日程（独立事件）与任务日程（执行某个任务的时段，必须链接真实任务）。
- 创建任务日程前必须先用 search_tasks/list_tasks/get_task 查证任务：
  唯一命中→直接创建；多个候选→clarify_task_selection；无匹配→先询问用户是否新建任务，
  获肯定后先 create_task 再 create_event。禁止猜测 task_id。
- 任务日程没有自己的标题，不要传 title；完成任务日程上的事=完成关联任务，用 update_task_status。
- 只有开始时间时，结束时间按 +1 小时设置，并在回复中明示"默认安排 1 小时"。
- 工具返回 need_conflict_confirmation 时，必须先向用户陈述冲突日程（时段+标题），
  经用户明确同意后才允许带 confirm_conflict=true 重新调用；用户改时间则重新检测。
- 删除任务日程不删除任务；删除任务会级联删除其任务日程，确认文案以系统返回为准。
- 时间解析以注入的当前日期/星期/时区为基准；"周五""早上""节后"等歧义必须追问。
```

- 编排时注入环境行：`当前时间：2026-09-16 14:32（周三）Asia/Shanghai`；
- 对话轮次上限沿用 MAX\_TOOL\_ROUNDS=5；典型排期链路 search\_tasks(1)→create\_event(2)、create\_task(1)→create\_event(2) 均可容纳；冲突确认在用户下一轮消息重新计数。

### 7.4 历史卡片云端刷新扩展

- `conversation.service` 拉取历史消息时，从 payload 卡片中分别收集 task ids 与 event ids：
  - tasks 走既有 `getManyByIds`；
  - events 走新增 `getManyByIds`（一条 SQL：events JOIN tasks JOIN lists），用最新 DTO 覆盖快照；
- 关联任务被改名/完成/删除导致的变化随之生效：任务已删则其任务日程已被级联删除，卡片按 404 渲染为"该日程已删除"占位（沿用错误占位不展示陈旧数据原则）。

## 8. 关键时序

### 8.1 对话为任务排期（含多候选/无匹配分支）

```
H5 → POST /chat "把季度报告排到明天15:00-16:00"
Chat 编排 → DeepSeek → tool_call search_tasks(keyword=季度报告)
  ├─ 唯一 → tool_call create_event(event_type=task, task_id, start, end)
  │           EventService: 校验任务归属且 status=todo → 冲突查询
  │             ├─ 无冲突 → INSERT → cards{events:[dto]} → 模型总结 → done
  │             └─ 有冲突 → 不落库返回 conflicts → 模型输出冲突块(SSE cards/clarify 样式)
  │                            └─ 用户"仍要安排" → 下一轮 create_event(confirm_conflict=true)
  ├─ 多候选 → clarify_task_selection → 用户点选 → 前端回传 candidate_id 继续编排
  └─ 无匹配 → 模型文本询问 → 用户"新建吧" → create_task → create_event(task)
```

### 8.2 手动建日程命中冲突

```
H5 POST /events（confirm_conflict 缺省 false）
Service: 校验通过 → findConflicts 非空 → 409/4009 + conflicts（无 INSERT）
H5 渲染 ConflictSheet（返回修改 / 仍要保存）
用户点"仍要保存" → POST 同 body + confirm_conflict=true
Service: 跳过重检测的拦截位（仍执行检测以记录 level）→ INSERT → 201
```

### 8.3 删除任务的级联（REST 与对话同路径）

```
TaskService.remove(userId, taskId)  -- 单事务
  1) SELECT count(*) FROM events WHERE user_id=$1 AND task_id=$2  → n
  2) DELETE FROM events WHERE user_id=$1 AND task_id=$2
  3) DELETE FROM tasks WHERE user_id=$1 AND id=$2
  COMMIT → 返回 {deleted_event_count: n}
对话 prepare(delete_task) 阶段即取 n，confirm 文案："将同时删除其 N 条日程安排"
DB 层 ON DELETE CASCADE 仅作兜底，正常路径以应用事务为准（计数可返回、可审计）
```

### 8.4 任务日程勾选完成

```
DayView/EventCard 勾选 → POST /tasks/1024/complete（既有接口）
TaskService.setStatus → completed_at=now()
前端事件总线更新：任务 store + 当日视图行划线 + 任务日程卡片勾选态（下次拉取以云端为准）
events 表无任何写入
```

## 9. 安全设计（增量）

| 项         | 方案                                                                                                 |
| --------- | -------------------------------------------------------------------------------------------------- |
| 越权防护      | events 全部 SQL 带 user\_id；task\_id 归属三重校验（存在/归属/未完成）；JOIN tasks 后校验同用户；`/tasks/{id}/events` 先校验任务归属 |
