## 1. 背景与目标

### 1.1 背景

v0.1.0 上线了独立的日程领域（普通日程 / 任务日程、月视图与当日视图、时间冲突提示），并验证了"对话 + 日历"双入口体验。上线后反馈集中在两类**结构性能力缺失**与一项**导航形态问题**：

1. **日程只会"发生一次"**：周会、每日站会、每月还款日、每年体检等高频安排，用户只能逐条手工重复创建，日历数据冗余且无法统一修改；v0.1.0 评审决议第 4 条已明确"周期规则（含编辑整条/单条的语义）列入后续版本"；
2. **任务只有平铺一层**："季度报告"这类大任务无法拆解，用户被迫用标题前缀（"【报告】1. xxx"）或多条松散任务模拟拆分，缺少进度视角与完成联动；
3. **底部 Tab 扩展性到顶**：日程 / 任务 / 助手三个 Tab 已占满底部导航，未来新增一级入口（如统计、设置）无空间；同时"助手"作为最高频的自然语言入口，藏在与业务页平级的 Tab 中，入口层级偏深；
4. **右下角 FAB 当前仅用于"新建任务"**：功能单一、与"对话即可创建一切"的产品主张重叠，黄金触达位置没有承载最高价值入口。

v0.2.0 在不改变技术架构（H5 瘦客户端 + Node 云端 + PostgreSQL + DeepSeek）的前提下，交付四项变更：**周期循环日程、子任务、左侧抽屉菜单（替代底部 Tab）、FAB 改为聊天入口**。延续"双入口、数据同源、能力对等"原则：**凡手动可完成的周期日程与子任务操作，LLM 对话均可完成**。

### 1.2 产品目标（v0.2.0）

- **核心目标**：
  1. 让重复性时间安排"一次录入、自动循环、可整体可单次地调整"；
  2. 让复杂任务可拆解为多级子任务，并通过进度与完成联动降低跟进成本；
  3. 将导航重构为可扩展的抽屉结构，并把助手对话提升为全局一等入口；
- **成功假设**：
  1. 用户愿意用循环规则承载重复安排，循环日程创建后 4 周内的"单次例外修改/取消"流程顺畅、不产生误改整条的投诉；
  2. 使用子任务拆解的任务，其完成率不低于扁平任务，且用户理解父子任务的完成联动规则；
  3. Tab 改抽屉后，主导航切换效率与人均切换次数不低于 v0.1.0；FAB 成为进入助手的主要入口，对话创建占比随之提升。

### 1.3 非目标（v0.2.0 不做）

延续 v0.1.0 边界，并明确以下能力不在本版范围：

- **不做循环任务（任务的重复到期）**：任务仍只有一个 `due_at`；"每天背单词"这类重复待办本版建议用普通循环日程承载提醒时间，循环任务模型列入后续版本；
- **不做循环任务日程**：`event_type=task` 的任务日程不支持挂循环规则（理由见 4.9），循环仅支持普通日程；
- 循环规则不做完整 iCalendar RRULE 全集：不支持按"小时/分钟"频率、不支持 `BYMONTH` 多选、不支持序数与星期的任意组合、不支持农历/节假日/调休推断（"节后上班第一天"仍需追问具体日期）；
- 不做循环日程的单次实例**拖拽改期**（实例的修改走表单/对话）；不做周视图；
- 子任务最多 **5 级**，不做无限层级；不做跨清单的父子关系（子任务强制属于父任务所在清单）；不做拖拽排序与拖拽调层级；不做子任务独立的成员/指派（延续无协作边界）；
- 不做任务依赖（"子任务 A 完成后才能做 B"）、子任务权重与工时统计；
- 抽屉中**不新增设置页等新页面**：抽屉仅重组既有一级入口（日程 / 任务 / 助手）与账号区（邮箱、退出登录）；
- 延续 v0.1.0：不做任何主动触达/通知提醒、第三方日历同步、多人协作、原生 App、PC 专门适配、离线持久化、语音与多模态输入。

## 2. 目标用户与使用场景

### 2.1 目标用户

- 有大量固定节奏安排（周会、例会、定期缴费、周期运动/复诊）的个人用户；
- 需要推进多步骤复杂事项（写报告、装修、旅行准备、求职）的用户；
- 已养成"对助手说话完成管理"习惯，希望对话入口随时可达的用户。

### 2.2 核心使用场景

| 场景 | 描述 |
| --- | --- |
| 口语建循环日程 | 用户："每周一上午 10 点团队周会，重复到年底"，助手解析 weekly/周一/until，一次创建整条循环系列。 |
| 单次改期 | 本周周会临时改到周二：用户在当日视图点该实例 → "仅修改本次" → 改时间，其他周的周会不受影响。 |
| 单次取消 | "这周五的站会取消一次，以后照常"，仅该实例置为取消（显示删除线），系列与其余实例保留。 |
| 整条调整 | "周会以后都改到下午 2 点"——编辑整条系列，全部实例（含未来实例）统一变更。 |
| 循环冲突感知 | 创建"每天 18:00 健身"时，助手提示未来 90 天内与已有安排冲突的若干日期，用户仍可坚持保存。 |
| 拆解复杂任务 | 用户创建"季度报告"，在详情中添加子任务"收集数据/出图表/写初稿/评审"，任务卡片实时显示 2/4 进度。 |
| 对话拆解 | 用户："给季度报告加个子任务：约老板对齐口径，周五前完成"，助手命中父任务后创建带子任务关系的任务。 |
| 父任务联动完成 | 用户勾选"季度报告"时，系统提示"还有 2 个子任务未完成，将一并标记完成"，确认后整棵子树完成。 |
| 抽屉切换模块 | 用户在任意一级页面点左上角菜单图标（或左缘右滑）唤起抽屉，切换到任务/助手；底部不再占用导航栏。 |
| FAB 随时问助手 | 用户在日程页或任务页点右下角聊天按钮，直接进入助手；在对话列表页该按钮变为"新建对话"。 |
| 混合查询 | "我这周有什么周会？季度报告的子任务都做完了吗？"——助手分别展开循环实例查询与子任务树查询，分区作答。 |

## 3. 产品整体说明

### 3.1 产品形态（延续 v0.1.0）

- 仍为**移动端 Web（H5）**瘦客户端：循环规则计算与实例展开、子任务树与级联规则、LLM 调用与工具执行全部在服务端完成，端上仅展示与交互；
- 全部读写需联网，断网展示错误占位与重试入口，端上不产生本地业务数据；
- 账号体系沿用（邮箱 + 密码，JWT 鉴权，数据按用户隔离）。

### 3.2 信息架构（v0.2.0 调整：底部 Tab → 左侧抽屉）

v0.1.0 的底部三 Tab（日程 / 任务 / 助手）整体取消，一级入口迁移至**左侧抽屉菜单**；默认落地页仍为日程页（`/` 重定向 `/calendar` 不变）。

```
个人助手 App（v0.2.0）
├── 左侧抽屉菜单（全局一级导航，所有登录后页面可唤起）
│   ├── 日程（/calendar，默认落地）
│   │   ├── 月视图 / 当日视图 / 日程详情 / 新建·编辑表单
│   │   └── （循环实例详情区分：系列视角 / 单次实例视角）
│   ├── 任务（/tasks）
│   │   ├── 任务首页（根任务树视图，行内展开子任务）
│   │   ├── 任务详情（父任务面包屑 + 子任务分区）
│   │   ├── 清单管理 / 搜索（结果展示父子路径）
│   │   └── 新建/编辑任务（可指定父任务）
│   ├── 助手（/chat 对话列表、/chat/:id 对话页）
│   └── 账号区（邮箱展示、退出登录）
└── 全局右下角 FAB：聊天入口（详见 3.3）
```

- 抽屉在日程、任务、助手三个模块的**一级页与全部子页面**均可唤起；登录/注册/引导页不展示抽屉与汉堡按钮；
- 当前所属模块在抽屉菜单项上高亮；路由仅移除 `meta.tab` 的导航含义（改为按路由前缀 `/calendar`、`/tasks`、`/chat` 判定高亮），URL 结构全部保持不变，保证历史链接与浏览器后退可用。

### 3.3 全局浮动按钮（FAB）调整

- 右下角 FAB 由"新建任务"（plus 图标）**改为聊天入口**（对话气泡图标），位置、尺寸（56pt 圆形）、阴影与安全区规范沿用 v0.1.0；底部 Tab 移除后，FAB 的下边距改为相对安全区底部 + 16pt（不再依赖 tabbar 高度变量）；
- 行为按当前页面区分：
  | 当前页面 | FAB 行为 |
  | --- | --- |
  | 日程模块、任务模块全部页面 | 跳转助手对话列表 `/chat` |
  | 对话列表 `/chat` | 等价"新建对话"：创建并进入一个新对话 |
  | 对话页 `/chat/:id` | **隐藏 FAB**（避免与输入区冲突） |
  | 登录/注册/引导页 | 不展示 |
- FAB 不做未读红点/角标（v0.2.0 无消息推送，角标无数据源，列入后续版本观测）。

### 3.4 双入口关系（延续 v0.1.0 原则）

1. **数据同源**：循环系列、例外实例、子任务关系在手动与对话两个入口读写同一套数据，任一入口变更在另一入口实时可见；
2. **能力对等**：循环日程的创建/整条编辑/单次修改/单次取消/整条删除，以及子任务的增删、移动、完成联动，对话入口必须达到与手动入口**字段级一致**的数据效果；
3. **结果可追溯**：聊天产生的循环系列与子任务以结构化卡片展示，循环系列卡片可跳系列详情，实例信息可跳当次实例；
4. **既有领域关联不受影响**：任务日程（`event_type=task`）的全部 v0.1.0 规则保留；子任务同样可以被排期（任务日程链接子任务），规则与普通任务一致。

## 4. 功能需求一：周期循环日程

### 4.1 数据模型

#### 4.1.1 events 表新增字段（迁移 004）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| recurrence | jsonb | 否 | 循环规则，结构见 4.1.2；非空表示该日程为**循环系列主记录（master）**；`NULL` 为单次日程（含历史数据，平滑兼容） |
| derived_from_event_id | integer | 否 | "本次及以后"编辑时，新系列主记录指向被截断的原系列 id，仅用于溯源；普通系列与单次日程为 `NULL` |

- 系列主记录的 `start_at` / `end_at` 表示**首次实例**的起止时间；单次时长由 `end_at - start_at` 决定，所有实例沿用同一时长（全天系列沿用全天规则）；
- 新增约束：`event_type='task'` 时 `recurrence` 必须为 `NULL`（任务日程不可循环，见 4.9）。

#### 4.1.2 recurrence 规则结构（RRULE 受控子集）

```json
{
  "freq": "weekly",                 // daily / weekly / monthly / yearly，必填
  "interval": 1,                    // 每 N 个频率单位重复一次，1..99，默认 1
  "by_week_days": [1],              // 仅 weekly：0=周日 … 6=周六，最多 7 个值；缺省=首次实例所在星期
  "month_rule": {                   // 仅 monthly：二选一
    "type": "day_of_week",         //   day_of_month：每月第 N 日
    "ord": -1,                     //   day_of_week：第 ord 个 weekday（ord ∈ -1,1,2,3,4）
    "weekday": 5                   //   weekday ∈ 0..6
  },
  "end_type": "until",              // never / count / until，默认 never
  "count": 10,                      // end_type=count：总实例数，1..730
  "until": "2026-12-31"             // end_type=until：最后发生日期（用户时区的日期，含当天）
}
```

规则约束：

- `daily`：仅 `interval` 生效（每 N 天）；
- `weekly`：`by_week_days` 缺省时取首次开始时间的星期；周起始固定为**周一**；
- `monthly`：`day_of_month` 取 1..31，当月不存在该日（如 31 日）落到**当月最后一天**；`day_of_week + ord=-1` 表示"最后一个周 X"；
- `yearly`：v0.2.0 仅支持"每年同月同日"（月、日由首次实例决定），2 月 29 日在平年落到 2 月 28 日；
- 上限：`interval` 1..99；`count` 1..730；`until` 距首次实例不超过 **5 年**；`end_type=never` 的系列同样受展示/扫描窗口约束（见 4.5、4.8），不无限物化；
- 服务端做 zod + 业务双重校验，非法组合（weekly 传 month_rule 等）一律拒绝。

#### 4.1.3 例外实例表 event_overrides（迁移 004）

循环实例不逐行物化，按查询窗口**虚拟展开**；用户对单次实例的偏离以"例外覆盖"表达：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | serial | 主键 |
| user_id | integer | 用户隔离 |
| event_id | integer | 所属循环系列主记录 id，删除系列时级联删除 |
| occurrence_start | timestamptz | **实例身份键**：该实例按规则推算出的原始开始时间（UTC 存储） |
| action | enum | `cancelled`（仅取消本次）/ `modified`（修改本次） |
| patch | jsonb | action=modified 时的覆盖字段：`start_at`、`end_at`、`title`、`location`、`note`、`all_day` 中被修改的子集 |
| created_at / updated_at | timestamptz | 时间戳 |

- 唯一约束：`(event_id, occurrence_start)`，同一实例仅允许一条覆盖；
- 修改实例的时间后，其身份键仍是**原始 occurrence_start**（不随 patch 的新时间漂移），保证二次编辑仍命中同一实例；
- 取消的实例不允许再挂 modified：再次编辑已取消实例时，先引导"恢复本次"（删除 cancelled 覆盖）再修改，或直接以修改覆盖之（action 升级为 modified，等价于恢复并改期）。

#### 4.1.4 实例 DTO（展开后的读模型）

查询窗口内的每个实例返回类似单次日程的对象，附加：

| 字段 | 说明 |
| --- | --- |
| series_id | 系列主记录 id（单次日程为 null） |
| occurrence_start / occurrence_end | 本实例的起止时间（应用 patch 后） |
| occurrence_key | 原始开始时间 ISO 字符串，实例操作的定位参数 |
| override_state | `normal` / `modified` / `cancelled`（列表默认过滤 cancelled，仅在显式"显示已取消"或详情场景使用） |
| recurrence_summary | 规则人话摘要，如"每周一 10:00–11:00，至 2026-12-31 止" |

### 4.2 功能清单

| 编号 | 功能 | 优先级 | 描述 |
| --- | --- | --- | --- |
| R-01 | 创建循环日程 | P0 | 新建日程表单增加"重复"设置入口：选择频率（不重复/每天/每周/每月/每年/自定义）、间隔、星期/月内规则、结束条件；保存时展开首屏窗口并做冲突扫描（4.8）。 |
| R-02 | 循环规则摘要 | P0 | 表单、详情、卡片中以人话展示规则："每个工作日 09:00–09:30"、"每月最后一个周五 14:00，共 10 次"、"每年 6 月 1 日全天，永不结束"。 |
| R-03 | 月视图展示循环实例 | P0 | 循环实例与单次日程一样在月网格显示圆点与条数标记；切换月份时按该月窗口实时展开，不做端上缓存。 |
| R-04 | 当日视图展示实例 | P0 | 实例按开始时间进入时间轴；被取消实例不展示；被修改实例按 patch 后的时间/标题展示，并带"已调整"小标记。 |
| R-05 | 系列详情 | P0 | 从任意实例可进入"系列详情"：规则摘要、首次/下一次实例时间、未来实例列表（按时间倒序/正序分页，每次 20 条）、历史实例（含已取消/已修改标记）。 |
| R-06 | 编辑整条系列 | P0 | 修改系列任意字段（含规则本身）后，对全部实例生效；已有**单次例外（modified/cancelled）默认保留**，若规则变更导致例外对应的原始实例不再生成（如从每周一改为每周二），该例外成为孤儿数据、不再展示，系统不主动删除（列表"历史例外"中可查）。 |
| R-07 | 仅修改本次 | P0 | 在实例上修改时间/标题/地点/备注，写入 modified 覆盖，不影响系列与其他实例；修改时间时仅校验该实例的冲突。 |
| R-08 | 本次及以后 | P1 | 从某次实例起截断：原系列 `until` 提前到该实例前一天；以该实例为首次实例复制生成一条新系列（携带本次修改），两系列通过 `derived_from_event_id` 溯源；历史实例保持原状。 |
| R-09 | 仅取消本次 | P0 | 该实例写入 cancelled 覆盖；当日视图/月计数中剔除；系列详情中该次显示"已取消"；支持"恢复本次"（删除覆盖）。 |
| R-10 | 删除系列 | P0 | 删除整条系列（主记录 + 全部覆盖），二次确认文案区分"将删除该循环安排及其全部已排日期"；不可恢复（不做回收站）。 |
| R-11 | 循环日程冲突提示 | P0 | 创建/整条改期时对展开窗口内的实例批量做冲突检测并汇总（4.8）；单次改期仅检查该实例。 |
| R-12 | 循环日程搜索 | P1 | 关键词命中系列标题/备注/地点时，返回**系列主记录**（而非每个实例），点击进入系列详情。 |

### 4.3 表单交互要求

- "重复"默认值为**不重复**（即 v0.1.0 单次日程，老用户零学习成本）；
- 频率快捷选项：每天、每周（默认选中开始日的星期，可多选星期）、每月（默认"每月同日"，可切"第 N 个周 X"）、每年、自定义（展开全部参数）；
- "每个工作日"为每周频率下的多选快捷按钮（一至周五）；
- 结束条件三选一：永不（默认）/ 重复 N 次 / 截止到某日期；切换时实时更新摘要文案；
- 当开始时间变更时：weekly 缺省星期跟随变化（用户已手动勾选星期则不覆盖）；monthly 默认"每月同日"跟随日期变化；
- 全天循环：规则作用于日期，实例均为全天；
- 校验：`count`/`until` 与首次实例矛盾（截止日早于首次）、超过 5 年/730 次上限、间隔超界，均在表单内联报错，不可提交。

### 4.4 实例生成规则

- 实例一律**服务端按查询窗口虚拟展开**：入参为 `[window_start, window_end)` 与用户时区，输出窗口内实例（左闭右开），应用 overrides 后返回；任何情况下不在数据库物化实例行；
- 月视图窗口 = 当月网格包含的日期区间（含前后置灰日期）；当日视图窗口 = 单日；
- `count` 系列展开到第 N 个实例为止；`until` 系列含截止当天；`never` 系列只在**查询窗口内**展开，不返回窗口外实例；
- 跨时区：实例时间按设备时区展示，系列规则（星期、月内序数、until 日期）均以**用户当前时区**解释（v0.2.0 不支持手动切时区，沿用 v0.1.0 策略）；
- 已结束系列（count 用完 / until 已过）在月视图不再出现实例，系列详情仍可访问。

### 4.5 编辑与取消的入口语义

- 从月视图/当日视图点击实例进入的是**实例视角详情**：顶部展示所属日期与规则摘要，"编辑/删除"操作弹出作用域选择（ActionSheet）：

  | 操作 | 作用域选项 |
  | --- | --- |
  | 编辑 | ① 仅修改本次（默认高亮）② 本次及以后（P1）③ 编辑整条系列 |
  | 删除 | ① 仅取消本次（默认高亮）② 删除整条系列 |

- 从系列详情进入的编辑默认为**整条系列**作用域；
- 对话入口的作用域规则与手动完全一致（见 7.3）。

### 4.6 冲突检测在循环日程上的规则

- 冲突定义沿用 v0.1.0：同一用户日程时间段**左闭右开**相交即冲突，端点相接不冲突；全天日程为弱化的"时间重叠提醒"；冲突不阻止保存；
- **扫描窗口**：创建循环系列或整条改期时，对"首次实例起 **90 天**内（常量，服务端可配置）"的实例逐一展开并与该用户全部日程（含其他循环系列在同窗内展开的实例、单次日程、任务日程）相交检测；
- **结果汇总**：按实例日期升序列出冲突（"10 月 12 日、10 月 19 日与「季度复盘」冲突…"），最多展示前 5 条，超出折叠为"等共 N 次冲突"；用户可选"仍要保存"或返回修改；
- 单次实例改期：仅检查该实例新时段，且排除本系列自身其他实例；
- 编辑系列规则但未改时间（如只改结束条件）：不重新做 90 天扫描；
- 与循环实例端点相接的安排不判冲突；被取消（cancelled）的实例不参与冲突；
- 性能要求见 8.1。

### 4.7 循环与任务日程的边界（建议决议）

- v0.2.0 **任务日程不支持循环**（数据库约束 + 表单隐藏 + 工具参数拒绝三处一致）；
- 原因：任务日程的完成动作落在关联任务上（一次完成即任务完成），与"实例反复发生"的语义冲突；"每周五写周报"这类场景在本版的承载方式为：创建普通循环日程"写周报"作为时间占位，或每周对话为任务单独排期；
- 循环任务（任务按规则重复到期）与可循环的任务日程统一列入后续版本候选，需先定义"每次实例是否独立完成态"的领域模型。

### 4.8 历史数据兼容

- v0.1.0 全部存量日程 `recurrence = NULL`，读模型等价于单实例系列，接口与 UI 无需迁移数据；
- 老版本客户端（若存在缓存页面）遇到 recurrence 非空的日程，按首条实例展示标题与时间，不做阻断（H5 强制升级由部署保证，无多版本共存承诺）。

## 5. 功能需求二：子任务

### 5.1 数据模型（迁移 005）

tasks 表新增自引用外键：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| parent_id | integer | 否 | 父任务 id，引用同表 tasks(id)，`ON DELETE CASCADE`；根任务为 `NULL` |

约束与规则：

- **层级深度 ≤ 5 级**（根任务为第 1 级），由服务端在创建/移动时沿父链递归校验；
- **同清单约束**：子任务的 `list_id` 必须等于其**根任务**的 `list_id`；跨清单挂载一律拒绝；移动整棵树的清单时，全部后代跟随（见 5.5）；
- **无环校验**：修改 `parent_id` 不允许将任务挂到自身或自己的任意后代下；
- 子任务的标题、备注、优先级、`due_at`、状态字段与根任务完全一致，独立维护；
- TaskDTO 新增：`parent_id`、`depth`（相对本次查询根的深度）、`subtask_total`（直接子任务数）、`subtask_completed`（直接子任务中已完成数）；任务树接口支持按根任务一次性返回整棵子树（深度 ≤ 5，单次最多 200 个节点，超出提示收窄范围）。

### 5.2 功能清单

| 编号 | 功能 | 优先级 | 描述 |
| --- | --- | --- | --- |
| T-01 | 创建子任务 | P0 | 任务详情"子任务"分区提供"添加子任务"输入框/表单；新建任务表单可通过"父任务"选择器指定父任务（选择器仅展示同清单任务，不展示自己的后代）。 |
| T-02 | 任务树展示 | P0 | 任务首页默认展示**根任务**卡片，卡片左侧缩进 + 展开箭头显示直接子任务（点击行内展开，懒加载下一级）；父任务卡显示进度"子任务 2/5"与迷你进度条；最多展示 5 级缩进。 |
| T-03 | 子任务勾选完成 | P0 | 子任务可独立勾选/取消完成，实时更新各级祖先卡片的进度数字与进度条。 |

### 5.3 列表与排序规则

- 任务首页排序沿用 v0.1.0 的 `due_at / created_at` 排序键，排序以**根任务**为单位：根任务按排序键定位，其子树整体跟随，不把子任务拆散到排序结果中；
- 行内展开时子任务在其父子树内按同样排序键二级排序；
- 清单页、搜索页可平铺展示（非树形态），但必须带父子路径。

### 5.4 完成与进度规则（建议决议，见第 13 章）

1. **进度计算**：父任务卡片的 `subtask_completed/total` 统计**直接**子任务；详情页可展开看"含下级共 X/Y"；进度仅影响展示，不改变父任务状态；
2. **子任务独立完成**：任何子任务可随时勾选/取消完成，**不自动改变**任何祖先的完成状态——即使全部子任务完成，父任务仍保持未完成，卡片显示"子任务已全部完成"并提供一键"标记完成"；
3. **父任务完成级联**：父任务存在未完成后代时，勾选必须二次确认，确认后所有未完成后代置为完成；已完成的后代状态与 `completed_at` 不变；
4. **父任务取消完成不级联**：取消父任务的完成态仅把父任务自身改回 `todo`、清空其 `completed_at`，后代状态保持不变（卡片进度可能显示 5/5 但父任务未完成，属预期状态）；
5. **已完成父任务新增子任务**：向已完成父任务新增/移入一个未完成子任务时，父任务**自动恢复为未完成**（清空 `completed_at`），保证进度与待办重新可见；新增的是已完成子任务则不恢复；
6. 以上规则在手动入口、对话工具、任务日程勾选完成三条链路上由服务端统一实现，端上不做状态推断。

### 5.5 移动与清单规则

- "移动到另一清单"仅允许对**根任务**操作；对子任务执行该操作等价于先移出为根任务，需二次确认文案说明；根任务改清单时，全部后代 `list_id` 同步更新；
- 父任务选择器排除：自身、自己的全部后代、其他清单任务、已删除任务；已完成任务允许作为父目标（但新增未完成子任务会触发 5.4-5 的自动恢复）。

### 5.6 与既有特性的关系

- **任务日程**：子任务可独立被排期；删除子任务级联删除其任务日程（v0.1.0 既有规则）；删除父任务的级联计数需递归汇总子树内全部任务日程数；
- **循环日程**：子任务不支持循环、也不允许创建循环任务日程（4.7）；
- **对话创建**：见第 7 章；
- **数据隔离**：父子关系限定在同一用户内，外键与用户归属双重校验。

| A-06 | 循环/子任务卡片 | P0 | 对话中渲染循环系列卡片（规则摘要 + 下一次实例）、实例卡片（带"本次已调整/已取消"标记）、子任务组卡片（进度 x/y + 子任务清单）。 |
| A-07 | 规则摘要人话化 | P0 | 模型不得向用户输出 JSON 规则，统一使用服务端/卡片下发的 recurrence_summary。 |
| A-08 | 混合意图 | P1 | 同一句话涉及循环实例与子任务时分调工具、分区作答（沿用 v0.1.0 E-08）。 |

### 7.3 工具定义变更

| 工具 | 变更 |
| --- | --- |
| `create_event` | 新增可选入参 `recurrence`（4.1.2 结构）；服务端校验规则、任务日程禁带循环；响应增加系列对象、未来 90 天冲突汇总（按实例日期分组） |
| `update_event` | 新增 `scope`：`series`（默认）/ `this` / `following`；`this`/`following` 必传 `occurrence_key` 定位实例；`this` 写 modified 覆盖；`following` 执行截断+派生（P1）；`series` 更新主记录与规则 |
| `delete_event` | 新增 `scope`：`series`（默认，走 pending_actions 确认）/ `this`（写 cancelled 覆盖，无需高危确认，模型回执说明如何恢复）；`this` 必传 `occurrence_key` |
| `restore_occurrence`（新增，P0） | 删除某实例的覆盖记录，恢复为规则实例（恢复本次） |
| `list_events` | 窗口查询自动展开循环实例，返回 4.1.4 实例字段；新增 `series_id`、`include_cancelled`、`recurring_only` 过滤参数 |
| `get_event` | 传 `series_id` 返回系列详情（规则 + 实例分页）；传实例标识返回实例视角 |
| `search_events` | 循环命中返回系列主记录（R-12） |
| `create_task` | 新增可选 `parent_id`；服务端做归属、同清单、深度 ≤5 校验；父任务已完成且新子任务未完成时按 5.4-5 自动恢复父任务并在结果中回传告知 |
| `update_task` | 新增可选 `parent_id`（传 `null` 表示移出为根任务）；执行无环、深度、同清单校验；根任务改清单级联后代 |
| `update_task_status` | 服务端统一实现 5.4 完成联动：父任务完成需带 `cascade=true` 且经一次确认（确认条），否则返回"需确认 + 未完成后代数"业务错误；取消完成不级联 |

工具错误新增明确业务码：规则非法（频率/组合/上限）、实例不存在、覆盖与新规则冲突、超出深度、跨清单挂载、挂载成环、父任务不存在/越权——模型必须如实告知并引导，**不得编造 series_id / occurrence_key / task_id**。

### 7.4 自然语言循环表达解析规则

| 表达 | 解析 |
| --- | --- |
| "每天/每日早上 9 点" | daily, interval=1 |
| "每隔一天 / 每两天" | daily, interval=2 |
| "工作日每天 / 周一到周五" | weekly, by_week_days=[1,2,3,4,5] |
| "每周一、周四" | weekly, by_week_days=[1,4] |
| "每两周周五 10 点" | weekly, interval=2, by_week_days=[5] |
| "每月 15 号" | monthly, day_of_month=15 |
| "每月最后一个周五" | monthly, day_of_week, ord=-1, weekday=5 |
| "每月第一个周一" | monthly, ord=1, weekday=1 |
| "每年 6 月 1 日" / "每年生日" | yearly（月日取首次实例） |
| "重复 10 次 / 一共开 8 期" | end_type=count |
| "到年底 / 截止到 12 月 31 日" | end_type=until |
| "一直重复 / 长期" | end_type=never |

### 7.5 对话交互要求

- 作用域澄清：用户说"改一下明天那个周会"且未表达作用域时，默认追问"是只改这一次，还是以后的都改？"，**禁止默认按整条执行写操作**；删除场景同理（单次取消 vs 删除系列必须区分）；
- 实例卡片：展示日期、时段、标题、规则来源（"每周一 10:00 团队周会"）、实例状态标记；卡片点击进入实例视角详情；
- 子任务组卡片：父任务标题、进度 x/y、进度条、子任务列表（勾选态、优先级），点击跳任务详情；
- 高危门控：删除整条系列、级联完成子树、批量操作沿用 pending_actions（TTL 300s）；取消单次实例、增删子任务为普通写操作，不经确认条，但需结果回执；
- 历史卡片刷新：系列卡片回查规则主记录，实例卡片回查覆盖状态，子任务卡片回查树状态（沿用 v0.1.0 卡片刷新机制）；
- 系统提示词新增要点：循环只支持普通日程、任务日程禁循环；实例身份与三种作用域；90 天冲突窗口与汇总话术；子任务深度/同清单约束；完成联动规则（父完成需确认级联、取消不级联、新子任务自动恢复父任务）；禁止猜测任何 id 与 occurrence_key。

### 7.6 异常与边界

| 情况 | 处理 |
| --- | --- |
| 循环规则非法/超上限 | zod + 业务校验拦截并回灌模型，要求修正或向用户澄清，不写入 |
| 目标实例不存在（窗口外/已被规则变更移除） | 返回业务错误，模型引导用户改为操作整条系列或重新指定日期 |
| 对任务日程传 recurrence | 拒绝并说明：循环任务日程暂不支持，可创建普通循环日程 |
| 子任务超深度/跨清单/成环 | 业务错误码 + 明确原因，模型如实告知 |
| 级联完成确认被取消 | 父任务及全部子任务状态不变 |
| 循环冲突 ≥ 大量实例 | 汇总前 5 条 + 总数，不逐条刷屏 |
| LLM 超时/不可用 | 沿用 v0.1.0 友好文案，不影响抽屉、日历与任务模块手动使用 |

## 8. 非功能性需求

### 8.1 性能

- 循环实例展开（单月窗口，单用户 200 条活跃系列）P95 ≤ 100ms；90 天冲突扫描（含展开与相交查询）P95 ≤ 300ms；
- 月视图首屏（含循环展开）≤ 1.5s，与 v0.1.0 持平；
- 子任务树加载（200 节点内）P95 ≤ 300ms；行内展开下一级 ≤ 500ms；
- 抽屉开启动画 ≤ 250ms，唤起响应 ≤ 100ms；FAB 点击到对话列表可交互 ≤ 1s（常规网络）；
- 对话首字返回沿用 ≤ 3s（含循环展开/子树查询的服务端增量开销目标 ≤ 80ms）；
- 索引建议：`events(user_id, start_at, end_at)` 既有索引支撑窗口扫描；新增 `event_overrides(event_id, occurrence_start)` 唯一索引、`event_overrides(user_id)`；tasks 新增 `parent_id` 索引、`(user_id, list_id, parent_id)` 复合索引。

### 8.2 可用性与兼容性

- 沿用：iOS Safari、Android Chrome 近两个大版本、微信内置 WebView；375pt 基准、44pt 热区、安全区适配；
- 抽屉左缘滑动手势不得与微信 WebView 返回手势冲突（识别区限定左边缘 20pt 内、对话页禁用）；
- 5 级缩进在 320pt 小屏下仍保证标题与勾选框可用（过深层级用更紧凑缩进，最小标题可用宽度 ≥ 160pt）；
- PC 浏览器可打开不专门适配；不支持离线。

### 8.3 数据迁移与账号

- 新增迁移 004（events.recurrence、derived_from_event_id、event_overrides 表）、005（tasks.parent_id 及索引）；存量数据默认 `recurrence=NULL`、`parent_id=NULL`，无需回填；
- 迁移须可重复执行（IF NOT EXISTS）并在低峰上线；回滚预案：删除新表/新列不影响既有功能（发布前演练）；
- 数据按用户隔离；注销账号时循环系列、覆盖、子任务关系随主表级联删除。

### 8.4 隐私与安全

- 延续 v0.1.0：HTTPS、Key 不出服务端、发送给 DeepSeek 的上下文仅含必需结构化信息；
- 循环与子任务不引入新的个人数据类别；地点字段敏感提示沿用。

### 8.5 可观测性

- 埋点：循环日程创建量（按 freq/end_type 分布）、循环 vs 单次日占比、例外操作量（modified/cancelled/restore）、作用域分布（series/this/following）、90 天冲突命中率与"仍要保存"率、子任务创建率、平均层级深度、父任务级联完成确认接受率、子任务任务完成率对比、抽屉唤起方式（汉堡/手势）与各模块切换次数、FAB 曝光/点击/由 FAB 进入的新对话数、对话中循环与子任务工具成功率、追问率；
- 异常日志：规则校验失败、展开异常、孤儿例外、深度/成环/跨清单拦截、occurrence_key 定位失败、LLM 误传 id。

## 9. 关键业务流程

### 9.1 创建循环日程（手动，含冲突分支）

```
新建日程 → 填写标题/首次时间 → 打开"重复"设置
  → 选择频率与结束条件 → 实时摘要确认 → 保存
  → 服务端校验规则（上限/组合）
  → 展开首次起 90 天实例做冲突扫描
    ├─ 无冲突 → 写入系列主记录（recurrence 非空）
    └─ 有冲突 → 弹层按日期列冲突（前 5 条 + 共 N 次）
                 ├─ 返回修改 → 调整规则/时间
                 └─ 仍要保存 → 写入
  → 月视图/当日视图按窗口出现实例；助手对话查询同步可见
```

### 9.2 单次实例改期 / 取消

```
当日视图点击实例 → 实例详情 → 编辑
  → 作用域 ActionSheet
    ├─ 仅修改本次 → 改表单 → 校验该实例冲突
    │     → 写 event_overrides(action=modified, patch, occurrence_key)
    ├─ 本次及以后(P1) → 原系列 until 截断 + 派生新系列（derived_from_event_id）
    └─ 编辑整条系列 → 更新主记录（保留仍有效的既有例外）
删除：
    ├─ 仅取消本次 → 写 cancelled 覆盖（系列详情可"恢复本次"）
    └─ 删除整条系列 → 二次确认 → 删除主记录与全部覆盖
```

### 9.3 对话创建循环日程

```
用户："每周一 10 点周会，重复到年底"
  → 模型解析 weekly/by_week_days=[1]/until，要素齐全
    ├─ 时间或频率歧义 → 追问（不猜测）
    └─ 调用 create_event(recurrence)
  → 服务端校验 + 90 天扫描 → 返回系列 + 冲突日期汇总
    ├─ 无冲突 → 人话确认 + 系列卡片（规则摘要/下次实例）
    └─ 有冲突 → 先陈述冲突日期 → 用户坚持/调整
  → 日历同步出现实例
```

### 9.4 子任务完成联动

```
用户在父任务卡片勾选
  ├─ 无未完成后代 → 直接完成父任务
  └─ 存在未完成后代 → 确认条："还有 N 个子任务未完成，将一并完成"
        ├─ 取消 → 状态不变
        └─ 确认 → 服务端级联完成全部未完成后代（completed_at=now）
                  对话入口同链路（update_task_status + pending_actions）
反向：
  ├─ 取消父任务完成 → 仅父任务回 todo，子任务不动
  └─ 向已完成父任务新增未完成子任务 → 父任务自动回 todo 并回执提示
删除父任务 → 文案"含 N 个子任务、M 条任务日程" → 级联删除
```

### 9.5 抽屉导航与 FAB

```
任意一级页：汉堡按钮 / 左缘右滑 → 抽屉滑入（250ms）+ 遮罩
  → 点菜单 → 关闭抽屉 → 路由跳转（URL 不变更设计）→ 菜单项按路由前缀高亮
  → 遮罩/后退 → 关闭抽屉
日程或任务页点右下 FAB → /chat 对话列表
对话列表点 FAB → 新建并进入对话；对话页内 FAB 隐藏
```

## 10. 验收标准

### 10.1 周期循环日程

1. daily/weekly（含工作日、多选星期、间隔）/monthly（第 N 日与第 N 个周 X，含最后一个）/yearly 四类规则创建、展示、摘要正确；count/until/never 三种结束条件边界正确（含 31 日、2 月 29 日落月末/28 日）；
2. 实例由服务端按窗口虚拟展开，月视图、当日视图、系列详情、对话查询四处结果一致；切换月份无实例残留/缺失；
3. "仅修改本次"只影响目标实例，其他实例与系列规则不变；"仅取消本次"可恢复；"编辑整条系列"对未来全部实例生效且保留仍有效的单次例外；P1"本次及以后"截断与派生正确、溯源关系存在；
4. 冲突：循环创建按 90 天窗口汇总，按日期可追溯；端点相接不报、cancelled 实例不报、单次改期只检本实例、冲突不阻止保存；
5. 任务日程在表单、接口、LLM 工具三处均不可挂循环，违规 100% 被拦截；
6. 存量单次日程全部功能不回归；循环系列删除经二次确认且不可恢复。

### 10.2 子任务

1. 可经任务详情、新建表单、对话三种方式创建子任务；同清单、深度 ≤5、无环三项校验 100% 生效，非法操作返回可理解的原因；
2. 任务树缩进、展开/折叠、进度 x/y 与进度条在各端展示正确；排序以根任务为单位；
3. 完成联动符合 5.4：子任务独立完成不自动改父状态；父任务级联完成必经确认且只改未完成后代；取消父完成不级联；已完成父任务新增未完成子任务自动恢复；
4. 删除父任务级联整棵子树及其任务日程，确认文案含子任务与日程计数；
5. 子任务可独立排期并适用 v0.1.0 全部任务日程规则；搜索结果含父子路径；到期聚合不重不漏。

### 10.3 导航重构

1. 底部 Tab 在全部页面消失；三个一级入口均可经抽屉到达，当前模块高亮正确；默认落地仍为日程；
2. 汉堡按钮、左缘手势、遮罩、菜单项、后退五种开合路径行为一致；对话页左缘手势不与返回冲突；
3. 抽屉 a11y 属性齐全（role/aria-modal/aria-current/焦点管理），弱动效设置生效；
4. FAB 按 3.3 分流正确：日程/任务页进入对话列表、对话列表新建对话、对话页隐藏、登录态页面不展示；
5. 新建任务/日程入口在模块内可达，任务新建路径点击数较 v0.1.0 不增加超过 1 次；
6. 既有 URL 全部可访问、浏览器历史与返回行为正常。

### 10.4 LLM 助手

1. 第 7.3 节工具全部 P0 能力可通过对话完成，写入结果与手动入口字段级一致（recurrence/override/parent_id/联动规则）；
2. 循环表达解析：明确表达一次成功率 ≥ 85%；频率、作用域、时间任一歧义 100% 追问，不发生"想改单次误改整条"；
3. 删除整条系列、级联完成子树 100% 经确认条；取消单次实例有回执与恢复指引；
4. 不允许出现编造的 series_id / occurrence_key / task_id / parent_id，关联操作先查证；
5. 卡片刷新正确：规则变更、单次修改/取消、子任务增删与完成后，历史卡片再拉取展示最新状态；
6. v0.1.0 既有任务/日程能力与 TC-CHAT-015/018 长会话回归通过，无新增间歇失败。

### 10.5 非功能

性能指标达标（8.1）；迁移 004/005 在类生产数据量演练通过、可回滚；iOS Safari / Android Chrome / 微信 WebView 核心路径（建循环、单次例外、子任务拆解与联动、抽屉切换、FAB 进对话）可用。
