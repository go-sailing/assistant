## 1. 设计概述

### 1.1 系统边界（增量）

- v0.2.0 在既有边界内新增/改造三个领域能力：
  1. **循环日程**：普通日程（`event_type=normal`）支持 RRULE 受控子集；实例**虚拟展开、绝不物化**，单次偏离以 `event_overrides` 覆盖表承载；任务日程（`event_type=task`）不支持循环；
  2. **子任务**：tasks 自引用父子关系，深度 ≤ 5、同清单、无环；完成/删除级联规则在服务端统一实现；
  3. **导航重构**：底部 Tab → 左侧抽屉、FAB → 聊天入口，**纯前端改造，不新增服务端接口**；
- 不引入新外部依赖：不引入 rrule 等第三方循环库（规则子集简单，循环引擎自行实现，约 300 行可覆盖）；不引入新中间件、新外部服务密钥；
- 循环日程与子任务能力同时通过 **REST（手动入口）**与 **LLM 工具（对话入口）**开放，两条路径仍共用 EventService / TaskService（延续"领域唯一入口"原则）；
- 既有 v0.1.0 规则全部保留：普通/任务日程类型不可变、冲突只提示不阻止、任务日程标题实时取任务、删除任务级联任务日程。

### 1.2 设计目标与手段

| 目标 | 设计手段 |
| --- | --- |
| 循环实例快且不膨胀 | 实例按查询窗口在服务端虚拟展开（应用层引擎 + 仅取活跃系列），数据库零实例行；例外仅存 override |
| 单次/整条不混淆 | 实例身份键 = 原始 occurrence_start（UTC）；所有实例写操作必带 `scope`（this/following/series），服务端按作用域分流，默认永不隐式整条 |
| 循环冲突可信 | 创建/整条改期对首次起 90 天实例做展开相交检测，按日期分组汇总；沿用 4009 两阶段确认，不阻断保存 |
| 子树一致性 | DB 自引用外键 + ON DELETE CASCADE 兜底；深度/同清单/无环写时校验；完成与删除级联在单事务内执行并返回计数 |
| AI 不产生脏数据 | series_id / occurrence_key / parent_id 全部服务端归属与存在性校验；级联完成、删系列复用 pending_actions 门控 |
| 存量平滑 | 新列均 NULL 可空、零回填；`recurrence IS NULL` 与 `parent_id IS NULL` 分别等价于单次日程/根任务，旧查询行为不变 |
| 导航可扩展 | 抽屉为纯前端覆盖层组件；URL 与路由表不变，仅删除 `meta.tab` 语义与 AppTabBar 挂载 |

## 3. 前端设计（H5，增量）

### 3.1 前端职责与约束（沿用 + 新增）

- 仍然**不保存业务数据、不在端上计算循环规则**：实例展开、规则摘要（recurrence_summary）、"共 N 次"、下一次实例时间全部由服务端返回，端上只做渲染；端上不引入 rrule 类库；
- 抽屉开合状态为**纯内存 UI 态**（stores/drawer.ts），不持久化、不随路由重置之外的方式同步；打开抽屉不改变路由与历史栈，关闭（遮罩/菜单项/后退）仅切 UI 态；
- 树展开态仅会话内内存保留（切清单/排序/搜索后重置，见 UXUI 7.3-6）；子节点首次展开调 `GET /tasks/:id/subtree?depth=1` 懒加载，之后用本次会话缓存；
- 循环写操作的两阶段交互沿用 v0.1.0 冲突状态机，并新增作用域维度：
  1. 实例编辑/删除点击 → 先弹 ScopeSheet（纯前端，不发请求）；
  2. 选"仅本次/整条"后按所选 scope 发请求；循环冲突仍按 4009 → 弹层 → `confirm_conflict=true` 同参重发；
  3. 父任务完成遇 **4010**（需级联确认）→ 弹级联确认 → 同参重发带 `cascade=true`；
- 对话中的作用域澄清由 `scope` 块承载（见 6.4），用户点选后作为下一条消息的结构化回传驱动模型/执行器重试，前端不自行重放 HTTP；
- 历史卡片刷新：消息 payload 中系列卡片存 `series_id`，实例卡片存 `series_id + occurrence_key`；拉取历史时批量回查系列并重算实例态（见 7.5）。

### 3.2 导航壳实现要点

- `App.vue` 依据当前路由计算三件事：
  - 抽屉可用：`meta.requiresAuth` 为真（登录/注册/引导页禁用）；
  - FAB 形态：路径前缀 `/calendar`、`/tasks` → `open-chat`；`/chat` 且非对话详情 → `new-conversation`；`/chat/:id` → `hidden`；
  - 一级页判定（汉堡 vs 返回）：路由 name ∈ {calendar-month, task-home, conversation-list} 时 AppNavBar 左侧渲染菜单按钮；
- 抽屉手势：左边缘 20pt 内起手不拦截（让给系统/微信返回），20pt 外、横向位移 >24pt 且纵向位移 <24pt 唤起；对话页全域禁用；
- 浏览器后退：抽屉打开时 push 一个透明历史态（或 hash 标记 `#drawer`），popstate 优先关抽屉而非退出页面；
- 布局：删除 `.app-shell` 对 tabbar 的高度依赖；内容页底部 padding 由各页保证（列表末卡 ≥ 96pt）；`--tabbar-height` 变量标记废弃（保留一个版本周期避免第三方引用报错，值置 0）。

## 4. 后端模块设计：循环日程

### 4.1 RecurrenceEngine（纯函数展开）

位置：`modules/event/recurrence/engine.ts`，无 DB/IO。

```ts
interface RecurrenceRule {
  freq: 'daily' | 'weekly' | 'monthly' | 'yearly';
  interval: number;            // 1..99，默认 1
  by_week_days?: number[];     // 仅 weekly：0..6（0=周日），1..7 个值；缺省=首次星期
  month_rule?: {
    type: 'day_of_month' | 'day_of_week';
    day?: number;              // day_of_month：1..31（超月落到月末）
    ord?: -1 | 1 | 2 | 3 | 4;  // day_of_week：第 N 个
    weekday?: 0 | 1 | 2 | 3 | 4 | 5 | 6;
  };
  end_type: 'never' | 'count' | 'until';
  count?: number;              // 1..730
  until?: string;              // YYYY-MM-DD（用户时区日期，含当天）
}

/** 输出窗口内的原始实例（未应用 override），左闭右开 */
function expand(rule: RecurrenceRule, firstStart: Date, durationMs: number,
                windowStart: Date, windowEnd: Date, tz: string): OccurrenceSeed[]
```

规则要点（与 PRD 4.1.2 一一对应，服务端单点实现）：

1. **基准**：系列主记录 `start_at/end_at` 定义首次实例与单次时长 `duration = end - start`（全天系列为日期粒度）；
2. **时区**：规则在用户时区（IANA）解释。引擎内部以"用户时区下的本地日期时间"推进，再转换为 UTC 输出；使用 PG 会话时区或 JS Intl 换算，统一走 `utils/time` 的 tz 转换函数，禁止用设备本地时区；
3. **daily**：首次本地时间 + `n * interval` 天；
4. **weekly**：周起始固定周一；`by_week_days` 缺省取首次本地星期；每个 interval 周期内按所选星期各产生一次；interval>1 时周期锚点为首次所在 ISO 周；
5. **monthly**：
   - `day_of_month`：第 N 日，N 大于当月天数时落当月最后一天；
   - `day_of_week`：第 ord 个 weekday，ord=-1 取最后一个（先求当月 weekday 集合再取倒数第一）；
   - interval 月推进；
6. **yearly**：每年同一月日（由首次决定）；2 月 29 日在平年落 2 月 28 日；
7. **结束**：count 取前 N 个实例；until 取本地日期 ≤ until 的实例（含当天）；never 仅产出查询窗口内实例；
8. **上限**：interval ≤ 99、count ≤ 730、until 距首次 ≤ 5 年；单次展开产出上限 730 个种子，超出按上限截断并记 warn 日志（防规则组合导致的 CPU 放大）；
9. **输出**：`OccurrenceSeed { index, start_at(UTC), end_at(UTC), all_day }`，按 start 升序。

规则校验器 `validateRule(rule, firstStart, tz)` 在 REST zod 之后、Service 写库之前执行：非法组合（weekly 带 month_rule、by_week_days 越界、until 早于首次、超上限等）抛 4011。

### 4.2 实例物化与 OverrideStore

**实例身份**：`occurrence_key` = 按规则推算的**原始**开始时间 ISO 字符串（UTC），不随 modified patch 的新时间漂移。

**OverrideStore（`occurrence.service.ts`）**：

| 方法 | 行为 |
| --- | --- |
| `listBySeries(userId, seriesId)` | 取该系列全部覆盖，构造 `Map<occurrence_key, override>` |
| `upsertModified(userId, seriesId, key, patch)` | upsert（`(event_id, occurrence_start)` 唯一约束）：若已有 cancelled 行则升级为 modified（等价恢复+改期） |
| `upsertCancelled(userId, seriesId, key)` | upsert action=cancelled |
| `restore(userId, seriesId, key)` | 删除该 key 的覆盖行；返回恢复后的实例 DTO |
| `rekeyForFollowing(...)` | "本次及以后"时迁移 t0 之后的覆盖到派生系列（见 4.5） |

**物化合并**（`materialize`）：对窗口内每个 seed：

1. 查 override Map：
   - 无 → 正常实例，时间取 seed；
   - `cancelled` → 从默认列表剔除（`include_cancelled=true` 时输出 `override_state=cancelled`）；
   - `modified` → 应用 patch：`start_at/end_at/all_day/title/location/note` 取 patch 值（未覆盖字段取系列主记录）；`override_state=modified`；
2. **按应用 patch 后的 start_at 重新做窗口裁剪**（改期可能把实例移出/移入查询窗口）；
3. 输出 OccurrenceDTO（结构见 5.4）。

**系列数据读取**：列表/月聚合需要"窗口相关系列"，SQL 取主记录：

```sql
SELECT * FROM events
WHERE user_id = $1
  AND recurrence IS NOT NULL
  AND start_at < $2                      -- 首次不晚于窗口结束
  AND (
    (recurrence->>'end_type') = 'never'
    OR (recurrence->>'end_type') = 'count'
    OR ( (recurrence->>'until')::date >= $3 )  -- until 不早于窗口起点（按 tz 换算的日期比较）
  );
```

- count 系列无法在 SQL 判定实例耗尽位置，保守取出后由引擎按窗口展开（count ≤730，成本可控）；
- 命中部分索引 `idx_events_recurring_active`（见 5.2）。

### 4.3 EventService 改造点

| 方法 | 改造 |

| `create` | 接受 `recurrence`：先 `validateRule`；`event_type=task` 带 recurrence 直接 4016；写主记录（recurrence 列）；冲突检测分流：单次日走旧路径，循环走 `scanSeriesConflicts`（4.6），写响应携带系列对象与按日期分组的冲突 |
| `update` | 新增 `scope`：`series`（默认）走主记录更新（recurrence 变更重新校验并重新扫描 90 天）；`this/following` 转发 OccurrenceService；旧签名（无 scope）等价 series |
| `remove` | 新增 `scope`：`series`（默认）删主记录（override 级联）；`this` 写 cancelled 覆盖（**不 DELETE、不需 pending 确认**） |
| `list` | 合并两个来源：① 窗口内单次行（`recurrence IS NULL`，旧 SQL）② 系列展开物化结果；合并后统一按 start 排序、统一跑 attachConflicts（在合并集内两两比对）；支持 `series_id`、`recurring_only`、`include_cancelled` 过滤 |
| `monthly` | SQL 聚合单次行（normal/task）+ 应用层展开系列实例（normal 同时计入 recurring 计数；modified 按 patch 后日期计，cancelled 不计）；响应增加 `recurring` 字段（见 5.5） |
| `search` | 循环系列命中返回**系列主记录 DTO**（每个系列一条，不按实例重复） |
| `getSeries / listOccurrences` | 新增：系列详情（规则+摘要+下一次）与实例分页（未来正序/历史倒序，每页 20） |
| `getManySeriesByIds` | 新增：历史卡片批量回查（见 7.5） |
| `get`（单 id） | 主记录是系列时返回系列 DTO（带 recurrence 与摘要）；带 `occurrence_key` 查询参数时返回实例视角 DTO |
| `findConflicts` | 保留给单次实例改期（this scope 改时间后只检该实例，排除本系列其他实例，见 4.6） |
| `removeTaskWithEvents` | 不变（任务日程不允许循环，子任务排期仍为单次） |

关键不变量：

- 任何系列写操作前再次校验 `event_type='normal'`（DB CHECK + Service + zod 三处，见 5.2）；
- 系列主记录的 `title/note/location/all_day/start_at/end_at` 即"系列级字段"；`this` 作用域不允许改 recurrence（规则本身只能 series/following 改）；
- 编辑系列时**既有 override 默认保留**；规则变更导致某 override 的原始实例不再生成时，该 override 成为孤儿（不删、不展示在未来列表，仅系列详情"历史例外"可见——通过尝试展开定位，展示失败的 override 列表）。

### 4.4 作用域操作语义（scope 分流）

入参统一扩展：`scope: 'series' | 'this' | 'following'`，`occurrence_key?: string`（this/following 必填，先经引擎校验该 key 在规则下确实存在，不存在抛 4012）。

**编辑（PATCH /events/:id）**

| scope | 语义 | 冲突检测 |
| --- | --- | --- |
| `series` | 更新主记录字段与/或 recurrence；全部未来实例生效；保留仍有效的 override | 改了时间/规则 → 90 天扫描（4.6）；未改 → 不扫描 |
| `this` | upsert modified override（patch 仅允许 start_at/end_at/all_day/title/location/note） | 仅对 patch 后该实例做单次 findConflicts，排除自身系列 |
| `following`（P1） | 截断 + 派生（4.5） | 对新系列做 90 天扫描 |

**删除（DELETE /events/:id）**

| scope | 语义 | 门控 |
| --- | --- | --- |
| `series` | DELETE 主记录，override 随 FK 级联删除 | REST 二次确认（AppModal）；对话走 pending_actions |
| `this` | upsert cancelled override；可 restore | 普通写操作，无 pending；回执文案含恢复指引 |

### 4.5 "本次及以后"（following，P1）事务步骤

`OccurrenceService.updateFromFollowing(userId, seriesId, occurrenceKey, patch)` 单事务：

1. 加载主记录并校验归属；引擎验证 key 存在，取该实例本地日期 `d0`；
2. **截断原系列**：
   - end_type=never → 改为 `until = d0 - 1 天`；
   - end_type=until → until 提前到 `d0 - 1`（若新 until 早于首次日期，原系列删除，直接走"整组替换"）；
   - end_type=count → 重算为截断后实际剩余的 count（引擎展开计数）；
3. **派生新系列**：复制主记录字段，`start_at/end_at` 取本次实例的新时间（patch 时间）或原 seed 时间；recurrence 继承（保留 by_week_days 等星期规则，首次锚点为 d0），end_type/count/until 按原系列在 d0 之后的剩余量设置；写 `derived_from_event_id = 原系列 id`；
4. **迁移 override**：原系列中 `occurrence_start >= d0` 的覆盖行改挂新系列 id（key 不变）；`< d0` 的保留；本次 patch 直接体现在新系列主记录上（不写 override）；
5. 对新系列执行 90 天冲突扫描，按 4009 两阶段返回；
6. 返回 `{ old_series: SeriesDTO, new_series: SeriesDTO, conflicts }`。

### 4.6 循环冲突扫描

`scanSeriesConflicts(userId, rule, firstStart, durationMs, allDay, tz, excludeSeriesId?)`：

```
win = [firstStart, firstStart + EVENT_RECURRENCE_CONFLICT_WINDOW_DAYS(90)]
目标实例 = expand(rule, …, win, tz)                          // ≤730
候选日程 = 窗口内单次行（旧相交 SQL，excludeSeriesId）
         + 窗口相关其他系列 → 各自 expand + materialize(其 overrides)
对每个目标实例，与候选（含候选实例）做左闭右开相交：
  hit → {date: 目标实例本地日期, target_start, target_end,
         conflict: ConflictBrief}
按日期 group → ConflictDateGroup[]；汇总 dates_count、total_count
cancelled 实例、本系列自身实例不参与；端点相接不报；全天 level 规则沿用
```

- 性能：系列数与实例数双受控（活跃系列走部分索引；单次展开 ≤730）；候选集合先按窗口粗筛再内存比对，避免 N 次 SQL（目标 ≤ 8.1 预算）；
- 返回结构进入 4009 body：`data.conflicts`（前 5 个日期分组）、`data.conflict_dates_total`、`data.conflict_total`、`data.scope='series'`；
- 单次实例改期（scope=this）复用 v0.1.0 的 `findConflicts` 单条 SQL 路径，4009 body 增加 `scope='occurrence'`，前端渲染单次弹层而非按日期分组弹层。

### 4.7 规则摘要（summary）

`recurrence/summary.ts` 单点产出人话文案（中文），UX 六处共用、模型禁止自拼：

- 输入 rule + 首次时间 + tz；输出如：
  - `每天 09:00，长期重复`
  - `每周一、周四 10:00–11:00，至 2026-12-31 止，共 14 次`
  - `每 2 周周五 10:00，共 8 次`
  - `工作日 09:00–09:30，长期重复`（by_week_days 恰为周一~五）
  - `每月 15 日 14:00` / `每月最后一个周五 14:00`
  - `每年 6 月 1 日，全天`
- 系列 DTO 固定附带 `recurrence_summary`、`next_occurrence`（窗口外取"永不结束系列"的下一次：引擎从今天起小窗口展开求首个）；
- 31 日/闰年回落规则在摘要中注明"遇到小月落到当月最后一天"。

### 5.2 迁移 `004_event_recurrence.sql`

```sql
-- v0.2.0 循环日程：events 增加规则列 + 单次例外覆盖表

ALTER TABLE events ADD COLUMN IF NOT EXISTS recurrence JSONB;
ALTER TABLE events ADD COLUMN IF NOT EXISTS derived_from_event_id INTEGER
  REFERENCES events(id) ON DELETE SET NULL;

-- 任务日程禁止循环（DB 兜底，与 Service/zod 三处一致）
ALTER TABLE events DROP CONSTRAINT IF EXISTS chk_event_no_recur_task;
ALTER TABLE events ADD CONSTRAINT chk_event_no_recur_task
  CHECK (event_type = 'normal' OR recurrence IS NULL);

-- 实例单次偏离（虚拟展开的唯一持久化部分）
CREATE TABLE IF NOT EXISTS event_overrides (
  id               SERIAL PRIMARY KEY,
  user_id          INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  event_id         INTEGER NOT NULL REFERENCES events(id) ON DELETE CASCADE,
  -- 实例身份键：按规则推算出的原始开始时间（UTC），不随 modified 新时间漂移
  occurrence_start TIMESTAMPTZ NOT NULL,
  action           VARCHAR(16) NOT NULL,        -- cancelled / modified
  -- modified 时的覆盖字段子集：start_at/end_at/all_day/title/location/note
  patch            JSONB NOT NULL DEFAULT '{}'::jsonb,
  created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT chk_override_action CHECK (action IN ('cancelled','modified')),
  CONSTRAINT chk_override_patch CHECK (
    action = 'cancelled' OR (action = 'modified' AND patch ? 'start_at')
  ),
  CONSTRAINT uniq_override_occurrence UNIQUE (event_id, occurrence_start)
);

CREATE INDEX IF NOT EXISTS idx_override_user ON event_overrides(user_id);
CREATE INDEX IF NOT EXISTS idx_override_event ON event_overrides(event_id, occurrence_start);

-- 活跃系列部分索引（窗口查询只扫循环主记录）
CREATE INDEX IF NOT EXISTS idx_events_recurring_active
  ON events(user_id, start_at) WHERE recurrence IS NOT NULL;
```

要点：

- recurrence 为 NULL 的存量/单次日程走全部旧查询路径，无回填；
- override 的 `patch.start_at` 必填用于"改期后按新日期裁剪窗口"；仅改标题不改时间时 patch.start_at 写原值；
- 级联：删系列（events 行）→ override 全删；删用户 → 全删；
- 迁移幂等（`IF NOT EXISTS` / `DROP CONSTRAINT IF EXISTS`），随发布启动时自动执行（沿用 `DB_AUTO_MIGRATE`）。

### 5.3 迁移 `005_task_parent.sql`


### 6.2 挂载校验 `assertCanAttach(userId, parentId, listId)`

1. **存在/归属**：父任务存在且属于当前用户，否则 1004；`parentId=null`（挂根）直接通过；
2. **同清单**：上溯求父任务的根，新任务/被移动子树的根 list_id 必须与父根一致，否则 4014；
3. **无环（移动场景）**：被移动节点不得是目标父的祖先或自身——递归 CTE 求目标父祖先链，与移动节点 id 比对，相交抛 4015；
4. **深度**：挂载后链深 = 目标父链深度 + 被移动子树高度，>5 抛 4013（高度用递归 CTE 求 max(depth)）。

递归 CTE（祖先链 + 后代集一次求出）：

```sql
-- 目标父的祖先链（含自身），用于无环与同清单（链顶即根）
WITH RECURSIVE ancestors AS (
  SELECT id, parent_id, list_id, 1 AS d FROM tasks WHERE id = $parentId AND user_id = $userId
  UNION ALL
  SELECT t.id, t.parent_id, t.list_id, a.d + 1
  FROM tasks t JOIN ancestors a ON t.id = a.parent_id
)
-- 被移动节点的后代集（含自身）
WITH RECURSIVE descendants AS (
  SELECT id, parent_id, list_id FROM tasks WHERE id = $taskId AND user_id = $userId
  UNION ALL
  SELECT t.id, t.parent_id, t.list_id FROM tasks t JOIN descendants d ON t.parent_id = d.id
)
```

- 深度异常数据防御：递归 CTE 带 `CYCLE id SET is_cycle USING path`（PG 14+）或深度上限 32 硬截断，理论无环（写入保证），仅作防御；
- 移动子树时只校验"子树根挂载点"，子树内部关系不动；整棵子树因根挂载点变化而整体平移深度。

### 6.3 完成联动（两阶段，服务端统一）

`setStatus(userId, taskId, 'completed', opts?: {cascade?: boolean})`：

```
CTE 求子树中 status='todo' 的后代（不含自身）→ n
if status=completed 且 task 自身 todo:
  if n > 0 且 !cascade:
      不写库，抛 AppError.taskCascadeRequired(n)   // 409 / 4010
  else:
      单事务：
        UPDATE tasks SET status='completed', completed_at=now()
        WHERE id = $taskId OR (id IN (全部后代 id)) AND status='todo'
        （已完成后代的 completed_at 不变）
if status=todo（取消完成）:
      仅 UPDATE 自身 → todo, completed_at=NULL；后代一律不动（无确认、无级联）
```

- REST：`POST /tasks/:id/complete` body `{cascade?: boolean}`，4010 响应：

```json
{ "code": 4010, "message": "还有未完成的子任务",
  "data": { "incomplete_descendant_count": 2, "cascade_required": true } }
```

  前端弹级联确认后同参带 `cascade=true` 重发；`POST /tasks/:id/uncomplete` 无变化；
- 对话：`update_task_status(status=completed)` 遇 n>0 时工具**不执行**，executor 返回 `{need_cascade_confirmation:true, incomplete_descendant_count:n}` 并落 pending_actions（action=`complete_task_cascade`，affected=父任务+未完成后代快照），下 confirm SSE；用户确认后服务端带 cascade 执行（见 7.4）。取消完成是普通工具调用，无门控。

### 6.4 自动恢复规则

- 触发点：create（带子父）、update 移动 parent_id、批量移动导致新父为已完成；
- 条件：父任务 `status=completed` 且新增/移入的任务 `status=todo`；
- 动作：仅**直接父**恢复 todo（completed_at=NULL）；不沿祖先链递归恢复祖父，与"取消父完成不级联"的非对称规则保持同一语义边界；响应/工具结果携带 `revived_parent: {id,title}` 供 Toast 与话术；
- 新增的是已完成子任务：不恢复。

### 6.5 删除级联（子树版，替换 v0.1.0 单任务版）

`remove(userId, taskId)` 单事务：

```
1) 归属校验
2) descendants = 递归 CTE 求整棵子树（含自身）→ ids
3) n_tasks = ids.count
4) n_events = SELECT count(*) FROM events WHERE user_id=$1 AND task_id = ANY(ids)
5) DELETE FROM events WHERE user_id=$1 AND task_id = ANY(ids)   -- 子树内全部任务日程
6) DELETE FROM tasks WHERE id = ANY(ids)                        -- 自引用 FK CASCADE 兜底
返回 {deleted_task_count: n_tasks, deleted_event_count: n_events}
```

- REST DELETE 响应体携带两个计数；对话 `delete_task` 的 prepare 阶段即执行步骤 2~4 取计数写入 pending affected，确认文案"将同时删除 N 个子任务及 M 条日程安排"（计数为 0 的分句省略）；
- `removeTaskWithEvents`（v0.1.0 供 EventService 反向调用的路径）保持签名兼容：子任务排期的删除仍按单 task_id 清理事件，内部复用同一事务函数。

### 6.6 子树查询 DTO 组装

```sql
WITH RECURSIVE subtree AS (
  SELECT t.*, 1 AS depth FROM tasks t WHERE t.id = $root AND t.user_id = $user
  UNION ALL
  SELECT t.*, s.depth + 1 FROM tasks t JOIN subtree s ON t.parent_id = s.id
)
SELECT s.*, l.name AS list_name,
       (SELECT count(*) FROM subtree) AS subtree_size,
       c.done AS subtask_completed, c.total AS subtask_total
FROM subtree s
JOIN task_lists l ON l.id = s.list_id
LEFT JOIN (
  SELECT parent_id,
         count(*) AS total,
         count(*) FILTER (WHERE status='completed') AS done
  FROM tasks WHERE parent_id IS NOT NULL GROUP BY parent_id
) c ON c.parent_id = s.id
ORDER BY s.depth, (s.due_at IS NULL), s.due_at, s.id;
```

- 节点数 >200 抛 1001（提示收窄范围）；进度统计为**直接**子任务口径（与 PRD 5.4-1 一致）；
- 任务首页 `root_only` 列表：根卡 DTO 同样附带直接子任务进度（LEFT JOIN 同一聚合），折叠态右侧显示 "2/5"。

### 7.5 历史卡片云端刷新扩展

## 8. 关键时序

### 8.1 创建循环日程（含 90 天冲突分支）

```

  validateRule（4011）→ 任务日程禁循环（4016）

对话链路：工具返回 need_conflict_confirmation → 模型陈述冲突日期 →

```

### 11.2 迁移与发布

- `004_event_recurrence.sql`、`005_task_parent.sql` 经既有 migrate 机制启动时顺序执行，全部幂等；
- ALTER TABLE ADD COLUMN（可空、无默认函数）在 PG 上为元数据操作，不重写表；event_overrides 为纯新表；tasks 加列同理；
- 上线顺序：**先后端（新列新接口，旧客户端行为不变）→ 后前端**；

- 发布后核对：月聚合新旧字段一致性（normal = 单次 normal + recurring）、根任务数 = v0.1.0 任务总数；
