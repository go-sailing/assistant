## 1. 背景与目标

### 1.1 背景

v0.2.0 补齐了循环日程、子任务与抽屉导航三块结构性能力。v0.3.0 不引入新业务领域，聚焦 v0.2.0 上线后实测暴露的 **8 项使用摩擦与设计瑕疵**，全部来自真实走查：

1. **「每年」循环日期写死为首次日期**：新建日程选择"每年"重复时，重复日期只能等于开始日期（"由首次时间决定"），无法创建"每年 6 月 1 日体检"这类日期与创建日不同的年度安排；
2. **月历占地过大**：月历固定占 6 行，想专注看本周安排时无法折叠；
3. **日期信息重复**：日程主页头部已显示"2026 年 9 月"，下方日程列表标题又显示"9 月 17 日 周三 今天"，月份信息出现两次；
4. **到达日程详情路径冗余**：点击日程主页的普通日程 item 先进入"当日列表页"（DayView），需要再点一次才到详情；而当日列表页与日程主页功能高度重复；
5. **宽屏排版劣化**：浏览器窗口较宽时，月历格子按 `100vw` 等比放大，日历区域吞掉大半屏高，日程列表被压缩在很小的内部滚动区；
6. **清单新建/重命名输入区不可用**：清单管理页点"新建"后，名称输入框与"确认/取消"按钮挤在一行，输入框极小、无法正常输入，按钮排版不合理；
7. **会话模型与实际用法不符**：产品没有多会话诉求，却存在会话列表、新建会话、重命名、删除会话等一整套概念；用户真实需要的只是"清空上下文，重新开始"；
8. **子任务添加入口误触**：任务列表中每个子任务行右侧都有"+"按钮，可直接在列表里给子任务再添子任务，层级在列表中迅速失控；孙任务的创建应进入子任务详情页完成。

8 项需求按域归并为四组：**日程主页与日历（4 项）、循环规则补全（1 项）、清单与子任务交互修正（2 项）、助手单会话化（1 项）**。

### 1.2 产品目标（v0.3.0）

- **核心目标**：
  1. 日程主页成为"一屏可达"的单一主页：可折叠到周、信息不重复、点 item 一步到详情、整页滚动、宽屏不劣化；
  2. 补全年度循环的指定日期能力，保持 RRULE 受控子集的一致性与双入口对等；
  3. 移除多会话概念，助手回归"一个用户、一个会话、可清除记录"的轻量模型；
  4. 修正清单弹层与子任务添加入口两处明确的交互缺陷。
- **成功假设**：
  1. 日程主页到详情的点击路径由 2 次降为 1 次后，详情页日均到达率不下降、编辑/删除等详情操作的完成时长缩短；
  2. 折叠态承载"看本周"的高频诉求，展开态仍为默认，月视图信息密度不回退；
  3. 单会话化后，助手入口点击到可输入的耗时下降，"清除聊天记录"能承接原"删除会话"的全部真实意图；
  4. 8 项问题对应的用户反馈在上线后 4 周内归零。

### 1.3 非目标（v0.3.0 不做）

- 不做独立**周视图页面**：折叠周是月历的一个形态，不新增路由、不做左右翻周之外的周视图能力（多日横滑、周缩放等不做）；
- 不做循环规则的进一步扩展：不支持"每年第 N 个周 X"（如每年五月第一个周日）、多个月日、农历、节假日推断；daily/weekly/monthly 规则形态不变；
- 不恢复当日列表页（DayView）的任何独有能力为独立页面：**全天分区、竖向时间轴、当前时间线、按日前后翻页**随页面一并裁剪，本版不迁移；
- 不做多会话、会话命名、会话搜索、消息级选择性删除、聊天记录导出；
- 不做 PC 端专门适配：宽屏仅要求"不劣化、居中可读"，不做多栏布局；
- 不做子任务拖拽排序/调层级、子任务权限等 v0.2.0 已裁剪能力；
- 延续既有边界：不做主动触达/通知提醒、第三方日历同步、多人协作、原生 App、离线持久化。

## 2. 目标用户与使用场景

### 2.1 目标用户

延续 v0.2.0 全体个人用户，本版尤其面向：

- 以周为节奏管理日程、希望日历"想看周时只显示一行"的用户；
- 有固定月日的年度安排（生日、年检、续费、证件到期）的用户；
- 在宽屏设备/平板/桌面浏览器上打开 H5 的用户；
- 只用一个对话线程、偶尔希望"清空重新聊"的助手用户。

### 2.2 核心使用场景

| 场景 | 描述 |
| --- | --- |
| 折叠看本周 | 用户在日程主页点折叠按钮，月历收成选中日所在一周；左右箭头按周切换，下方列表始终是选中日的全部安排。 |
| 一步看详情 | 在主页日程列表点"15:00 季度复盘"，直接进入日程详情查看备注/地点、编辑或删除，不再经过当日列表页。 |
| 年度指定日期 | 9 月 17 日新建"每年 6 月 1 日全天体检，长期重复"：首次实例为 2027-06-01，此后每年一次；助手对话同样支持。 |
| 宽屏使用 | 在桌面浏览器把窗口拖到 1200px 宽：日历与列表居中显示为一栏（最大宽约 480px），整页滚动，格子不再异常放大。 |
| 新建清单 | 清单管理页点"+"，底部弹出新建弹层：标题、全宽输入框（自动聚焦）、上下排列的"确认/取消"，输入顺畅。 |
| 清除聊天记录 | 用户想"重新开始"：助手页右上角菜单 → 清除聊天记录 → 二次确认 → 消息全部清空，出现首次引导；任务与日程数据不受影响。 |
| 子任务添加入口 | 任务首页展开根任务，可给根任务添加子任务；想给某个子任务再添加下级时，点击该子任务进入其详情页添加，列表里没有行尾"+"可误触。 |

## 3. 产品整体说明

### 3.1 产品形态（延续）

- 仍为**移动端 Web（H5）**瘦客户端：年规则展开、单会话、聊天记录清除等业务逻辑全部在服务端完成，端上仅展示与交互；
- 账号体系、JWT 鉴权、数据按用户隔离、SSE 流式对话、Function Calling 工具集均不变；
- 全部读写需联网，断网展示错误占位，端上不产生本地业务数据。

### 3.2 v0.3.0 变更总览

| 分组 | 编号 | 变更 | 类型 |
| --- | --- | --- | --- |
| 日程主页与日历 | C-01 | 月历支持折叠为选中日所在周一行 | 交互优化 |
| 日程主页与日历 | C-02 | 去除日程列表标题与头部重复的月份信息 | 文案/排版 |
| 日程主页与日历 | C-03 | 日程 item 直达详情；当日列表页（`/calendar/day`）下线 | 信息架构 |
| 日程主页与日历 | C-04 | 日程主页改全页滚动；宽屏内容居中限宽，修复月格异常放大 | 布局修复 |
| 循环规则 | Y-01 | yearly 规则支持指定月日（`by_month_day`），不再绑定首次日期 | 能力补全 |
| 清单与子任务 | L-01 | 清单新建/重命名改为底部弹层，修复输入框与按钮排版 | 缺陷修复 |
| 清单与子任务 | S-01 | 删除子任务行尾"+"；孙任务仅可在子任务详情页创建 | 入口收敛 |
| 助手会话 | A-01 | 每用户唯一会话；删除会话列表页；"删除会话"替换为"清除聊天记录" | 模型调整 |

### 3.3 路由与信息架构变更

```
个人助手 App（v0.3.0）
├── 左侧抽屉菜单（不变：日程 / 任务 / 助手 + 账号区）
│   ├── 日程（/calendar，默认落地）
│   │   ├── 月历主页（折叠/展开双形态 + 当日全部日程，整页滚动）
│   │   ├── 日程详情 /calendar/:id（普通/任务/循环实例统一入口）
│   │   ├── 系列详情 /calendar/series/:id
│   │   └── 新建·编辑表单
│   ├── 任务（/tasks）
│   │   └── 任务首页 / 任务详情（孙任务在此页添加）/ 清单管理 / 搜索 / 表单
│   └── 助手（/chat，直接进入唯一会话页，无列表层）
└── 全局 FAB：日程/任务页 → /chat；助手页隐藏（取消"新建对话"形态）
```

路由处置：

| 路由 | v0.2.0 | v0.3.0 |
| --- | --- | --- |
| `/calendar` | 月历主页 | 保留，承载折叠/全页滚动 |
| `/calendar/day` | 当日列表页 | **删除**；访问旧地址 302/路由级重定向到 `/calendar`（保留 `date` query，由主页恢复选中日） |
| `/calendar/:id`、`/calendar/series/:id`、`/calendar/new`、`/calendar/:id/edit` | 详情/表单 | 保留不变 |
| `/chat` | 会话列表页 | **改为唯一会话页**（进入时服务端 get-or-create 单例会话） |
| `/chat/:id` | 会话页 | 会话页组件合并进 `/chat`；旧地址重定向到 `/chat` |
| 其余路由 | —— | 不变 |

### 3.4 双入口关系（延续）

- 年规则指定日期（Y-01）在手动表单与 LLM 对话两个入口字段级一致，写同一份 recurrence JSON；
- 日程 item 直达详情后，对话卡片跳详情的既有行为不变；
- 单会话化不改变工具能力：任务、日程、循环、子任务的全部对话操作与 v0.2.0 一致。

## 4. 功能需求一：日程主页与日历体验

### 4.1 功能清单

| 编号 | 功能 | 优先级 | 描述 |
| --- | --- | --- | --- |
| C-01 | 月历折叠/展开 | P0 | 月历与日程列表分界处提供折叠开关；折叠后仅显示周标题行 + 选中日所在周一行日期；折叠态左右导航与横滑按周切换；再次点击展开回月视图。 |
| C-02 | 日期信息去重 | P0 | 日程列表标题不再重复月历头部已有的月/年信息，仅保留"相对日 + 星期 + 日序"与"共 N 项"。 |
| C-03 | item 直达详情 | P0 | 主页列表全部日程 item 点击直接进入对应详情（普通/任务日程进日程详情；循环实例进实例视角详情）；当日列表页与相关跳转全部移除。 |
| C-04 | 全页滚动与宽屏限宽 | P0 | 日程主页取消列表区内部滚动，改为整页一个滚动容器；宽屏下页面内容按最大宽度居中，月历格子按容器宽度计算，不再按视口宽度放大。 |

### 4.2 C-01 月历折叠交互

**开关位置与形态**

- 折叠开关位于月历区域与日程列表分界处（月历下沿）：一条与列表等宽的操作条，中央放置向上/向下的 chevron 图标，配文案"折叠"/"展开"；热区高度 ≥ 44px；
- `aria-expanded` 表达月历展开态，`aria-label` 随态切换（"折叠月历"/"展开月历"）；
- 展开/折叠使用高度过渡动画，时长 ≤ 250ms，尊重系统"减弱动态效果"（直接切换）。

**展开态（默认）**

- 与 v0.2.0 一致：周标题行 + 6 行 ×7 格月网格；
- 默认每次进入页面为展开态（折叠态仅页面内存活，不做跨页面/跨启动持久化）；
- 头部 ‹ › 与左右横滑仍按月切换，选中日规则沿用 v0.2.0（切月回到当月今天或 1 号）。

**折叠态**

- 网格只渲染**选中日所在自然周**的一行（周一至周日），周标题行保留；选中日始终可见；
- 头部标题显示选中日所属"YYYY 年 M 月"；当该周跨月时，标题跟随选中日所在月份；
- 头部 ‹ ›、月历区左右横滑：选中日**前移/后移 7 天**，年、月、周行、选中态、下方列表全部跟随；
- 点击周行内任一日期：切换选中日并刷新列表，保持折叠态；点击补位的邻月日期时年月跟随，与展开态点补位格行为一致；
- "今天"按钮（非当前月/非当前周时出现）：选中日回到今天、年月回到今天所在月，保持折叠态；
- 折叠态周行可能横跨两个月：月计数标记点需要覆盖该行涉及的全部月份（至多 2 个月数据），由前端在选中日切换时按需补齐拉取，已拉取月份走缓存，不重复请求；
- 折叠态再点开关：展开为完整月网格，网格定位到包含当前选中日的月份（不重置选中日）。

**与列表的联动**

- 折叠与展开仅改变月历视觉形态，不改变选中日与列表数据语义；
- 折叠态下选中日变化等价于展开态点选某日：列表拉取该日全部日程、`eventSync` 脏标记机制不变；
- 折叠开关不遮挡列表首项，不与 iOS/微信底部手势冲突。

### 4.3 C-02 日期信息去重

- 头部保留"YYYY 年 M 月"，它是翻月/翻周导航所必需的上下文；
- 日程列表标题条（现有 `month__bar`）去除月份，文案规则：

  | 条件 | 标题文案（示例） |
  | --- | --- |
  | 选中日 = 今天 | `今天 周三` |
  | 选中日 = 明天/昨天 | `明天 周四` / `昨天 周一` |
  | 其他日期 | `周三 17 日`（不显示月/年，月/年由头部承载） |

- 标题右侧"共 N 项"计数与"+"新建按钮保留；
- 折叠态跨月选中邻月日期时，头部月份已同步切换，标题仍不显示月份，避免重复；
- 日程 item 行内的时段文案（如 `15:00–16:00`、`全天`）不变。

### 4.4 C-03 日程直达详情与当日列表页下线

**点击行为统一**

| item 类型 | 点击去向 |
| --- | --- |
| 普通日程（单次日程） | `/calendar/:id` 日程详情 |
| 任务日程（event_type=task） | `/calendar/:id` 日程详情（详情内可跳关联任务、勾选完成，沿用 v0.1.0） |
| 循环实例（带 occurrence_key） | `/calendar/:id?occurrence_key=...` 实例视角详情（沿用 v0.2.0） |

- 主页列表不再有任何进入 `/calendar/day` 的入口；原"查看全部 N 项/收起"按钮随全页滚动一并取消（列表直接展示该日全部日程，见 4.5）。

**DayView 能力处置**

| DayView 既有能力 | v0.3.0 处置 |
| --- | --- |
| 查看单日全部日程（时间轴排序） | 月历主页当日列表承接：全天日程置顶分组（组标题"全天"），定时日程按开始时间升序；不再渲染竖向时间轴与当前时间线 |
| 编辑 / 删除 / 循环作用域操作（仅本次/本次及以后/整条） | 全部由日程详情页承接（v0.2.0 详情页已具备作用域 Sheet） |
| 列表行左滑完成任务日程/删除 | 下线：主页 item 为纯点击热区；完成与删除在详情页操作 |
| ‹ › 按日前后翻页 | 由月历点选/折叠态按周切换替代 |
| `?from=chat` 来源标记 | 随页面删除（现存代码无实际跳转来源） |

**兼容**

- 路由表删除 `/calendar/day`；访问旧 URL（含 `?date=YYYY-MM-DD`）重定向到 `/calendar` 并透传 `date`，主页挂载时恢复该选中日（复用现有 `route.query.date` 定位逻辑）；
- 日程详情返回时携带 `?date=` 回主页的行为不变。

### 4.5 C-04 全页滚动与宽屏排版

**滚动模型**

- 日程主页改为**整页单一滚动容器**：头部、月历（展开或折叠）、列表标题条、当日全部日程列表依次纵向排布，整体随页面滚动；
- 列表标题条在页面滚动时吸顶（`position: sticky`），保证滚动长列表时仍能看到选中日与"+"入口；
- 取消原列表区的内部滚动容器与 3 条预览截断：当日日程一次性全部展示（单日条数上限沿用服务端 listMaxLimit=200）；
- 下拉刷新（如后续增加）作用于整页；本版不新增下拉刷新。

**宽屏限宽**

- 新增**全局内容中栏**：登录后全部页面的内容在宽视口下居中，内容最大宽度 **480px**，两侧为页面背景留白；头部、吸顶条、弹层遮罩以外的内容均在中栏内；
- 月历格子宽度由"视口宽度 `100vw`"改为"**中栏容器宽度**"计算：每格宽 = (容器内容宽 − 水平内边距) / 7，保持近似正方形（`aspect-ratio: 1`），375pt 基准下视觉与 v0.2.0 一致；
- 抽屉（`min(80%, 320px)` 规则不变）、FAB、Toast、全屏弹层（RepeatSheet 等）仍相对视口定位；在 >480px 的中栏设备上 FAB 贴视口右下，不随中栏居中（保持可达性）；
- 320px 小屏、安全区、横屏（不专门适配，但不得出现横向滚动）下不得出现格子挤压、标记点丢失；
- 本版仅实施内容中栏与日程主页滚动模型；其余页面的内部滚动保持现状，借全局中栏统一获得宽屏限宽收益。

### 4.6 异常与边界

## 5. 功能需求二：yearly 循环支持指定日期

### 5.1 规则模型变更

`recurrence` JSON（RRULE 受控子集）为 yearly 频率新增可选字段：

```json
{
  "freq": "yearly",
  "interval": 1,
  "by_month_day": { "month": 6, "day": 1 },   // v0.3.0 新增，仅 yearly 可出现
  "end_type": "never"                           // never / count / until，规则不变
}
```

| 字段 | 约束 |
| --- | --- |
| `by_month_day.month` | 整数 1..12 |
| `by_month_day.day` | 整数 1..31；当月不存在该日时落到当月最后一天（2 月 29 日平年落 2 月 28 日，与 v0.2.0 月末规则一致） |

语义约束：

- **缺省 `by_month_day`**：月、日沿用首次实例（anchor）的月日——与 v0.2.0 完全等价，存量系列与存量数据零改动；
- **时分与时长**：无论月日来自字段还是 anchor，实例的时刻/全天/时长一律取系列主记录 `start_at`/`end_at`/`all_day`；`by_month_day` 只决定"哪一天"，不携带时间；
- 其他频率（daily/weekly/monthly）携带 `by_month_day` 一律以循环规则非法（错误码 **4011**）拒绝；yearly 仍不允许 `by_week_days`、`month_rule`（v0.2.0 既有约束不变）；
- `interval`（1..99）、`count`（1..730）、`until`（距首次实例 ≤ 5 年）上限沿用；
- 校验仍为 zod + 业务双重校验，非法组合 100% 拦截。

### 5.2 首次实例的确定（关键语义）

- 候选年份序列为 `anchor.y + k × interval`（k = 0,1,2,…）；每个候选年的发生日 = 该年指定月日（月末回落）；
- **首次实例 = 发生日 ≥ anchor 本地日期的第一个候选**；
- 例：anchor 为 2026-09-17，规则"每年 6 月 1 日"→ k=0 的 2026-06-01 已过，首次实例为 **2027-06-01**；规则"每年 10 月 5 日"→ 首次为 **2026-10-05**；
- anchor 当天恰好等于发生日（含 2/29→2/28 等同日情形）时首次实例即当天；
- `count` 从首次实例起按间隔年计数；`until`/`never` 语义不变；扫描窗口（创建后 90 天冲突扫描）从**首次实例**起算——若首次实例晚于创建日超过 90 天，创建时 90 天扫描无命中，属预期（该系列在窗口内本就没有实例）；
- `occurrence_key`（原始开始时间）、例外覆盖（event_overrides）、三作用域编辑（仅本次/本次及以后/整条）语义与存储完全不变；修改系列时增删 `by_month_day` 后，与既有例外的孤儿规则沿用 v0.2.0 R-06（例外保留、不再展示，不自动删除）。

### 5.3 表单交互（RepeatSheet）

- yearly 区块由 v0.2.0 的只读文案"每年 M 月 D 日（由首次时间决定）"改为**月、日两个下拉选择器**：
  - "月"：1..12（显示"1 月…12 月"）；"日"：1..31；
  - 打开重复设置时默认带入首次开始日期的月、日；
  - 用户手动改过月/日后（touched 标记），修改表单顶部首次开始日期不再覆盖所选月日（与 weekly 星期勾选的 touched 策略一致）；未手动改过时跟随首次日期；
- 日选择 29/30/31 时，选择器下方常驻弱提示："当月没有这一天时，将安排在当月最后一天"；
- 实时预览摘要随选择更新："每年 6 月 1 日 09:00–10:00，长期重复"、"每年 2 月 29 日，全天，共 3 次（平年安排在 2 月 28 日）"；
- 编辑已有系列时，按规则回填月日（缺省字段回填 anchor 月日）；保存为整条系列更新；
- 校验：月/日必填（选择器总有值，不允许空）；与 `count`/`until` 的矛盾校验沿用现有规则。

### 5.4 服务端与摘要

- 循环引擎 yearly 分支改为：优先使用 `by_month_day`，缺省回退 anchor 月日；实例时刻由 anchor 的时分/全天拼装，时区解释、UTC 转换、虚拟展开窗口算法不变；
- 规则人话摘要（recurrence_summary）：
  - 常规：`每年 {M} 月 {D} 日`（后接时段/全天与结束条件，拼装规则沿用 v0.2.0）；
  - D=29：追加"（平年安排在 2 月 28 日）"；D=30/31：追加"（遇到小月落到当月最后一天）"；
- 系列详情、月/日视图、搜索返回系列主记录（R-12）等读模型对新字段透明透传。

### 5.5 LLM 对话能力

| 自然语言 | 解析 |
| --- | --- |
| "每年 6 月 1 日体检" / "每年生日，11 月 20 日" | yearly + by_month_day={month,day}，时刻缺省按既有规则处理（全天/默认 1 小时的策略沿用） |
| "每年 5 月第一个周日安排团建" | 本版**不支持**（"第 N 个周 X"），必须追问成具体月日或告知暂不支持 |
| "每年这时候"（无月日且无法从开始日期推断） | 追问具体月日，禁止猜测 |
| "每年跟今天一样" / 仅说"每年" | 缺省 = anchor 月日，沿用 v0.2.0，模型需在回执中明示日期 |
| "每隔一年的 4 月 1 日" | yearly, interval=2, by_month_day={4,1} |

- `create_event` 工具 recurrence 入参增加 `by_month_day`；`update_event` 改整条规则时同；
- 系统提示词补充：yearly 可指定与开始日不同的月日、首次实例取不早于开始日的第一个发生日、2/29 回落规则、不支持"第 N 个周 X"；
- 模型回执与卡片一律使用服务端 recurrence_summary，不得自造规则文案；不得编造月日；
- 冲突告知、作用域澄清、高危门控（删系列/批量）等既有对话规则不变。

### 5.6 存量与兼容

- 全部存量 yearly 系列 `recurrence` 无 `by_month_day`，引擎按 anchor 解释，展开结果逐实例不变；
- 无数据库结构变更（规则仍存 jsonb），不需要数据迁移；
- 历史卡片中的循环系列摘要按新摘要逻辑输出（对缺省字段结果与旧文案一致）。

## 6. 功能需求三：清单与子任务交互修正

### 6.1 L-01 清单新建/重命名弹层

**现状缺陷**：清单管理页点"+"后在列表顶部插入一行行内输入，输入框与两个文本按钮横排，窄屏下输入框被挤压，按钮紧贴、排版失衡。

1. 标题："新建清单" / "重命名清单"；

- 原列表顶部行内输入区、行内重命名态移除。

### 6.2 S-01 子任务添加入口收敛

**变更规则**

1. **删除子任务行（SubtaskRow）右侧的"+"按钮**：任务首页树、任务详情页树、对话卡片只读树三处统一移除，行内不再提供"给该行任务直接添子任务"的入口；

   - 任务首页：仅根任务的展开子树底部显示"添加子任务"（即只能给根任务添加直接子任务）；

**不改变的部分**

- 子任务的展开/折叠箭头、勾选与级联完成确认、进度条、缩进、懒加载、排序规则全部不变；
- 点击子任务行进详情的既有行为不变（本就存在）；

## 7. 功能需求四：助手单会话化

### 7.1 会话模型

- 业务规则调整为：**每个用户有且仅有一个会话**（conversation）；会话是消息的容器，长期存在，不随"清空"删除；
- 不再提供新建会话、会话列表、会话重命名能力；助手页顶部标题固定为"助手"，不显示会话名；
- "删除会话"语义替换为**清除聊天记录**：删除该会话下的全部消息与待确认动作，会话本身保留，用户可立即继续对话。

### 7.2 数据迁移（迁移 006）

迁移须幂等（IF NOT EXISTS / 可重复执行），内容：

1. **存量多会话收敛为单会话**：对每个用户保留 `updated_at` 最新的一条 conversations 行；其余会话的 **messages 按原 id 顺序改挂**到保留会话（保留全部历史可读）；非保留会话的 **pending_actions 直接删除**（临时待确认对象，无保留价值）；随后删除非保留会话行；
2. 收敛完成后创建**唯一索引 `conversations(user_id)`**（若存在重复则索引创建失败——收敛步骤必须先于索引）；
3. 回滚预案：迁移仅改数据归属与新增索引，回滚需删除唯一索引（不恢复被合并会话的形态，发布前演练确认）。

### 7.3 服务端接口变更

| 接口 | v0.2.0 | v0.3.0 |
| --- | --- | --- |
| `POST /conversations` | 新建会话（可传 title） | 改为**幂等 get-or-create**：存在则返回唯一会话，不存在则创建；请求 body 不再需要（兼容忽略 title） |
| `GET /conversations` | 会话列表 | 保留但前端不再使用（返回 0/1 条，便于过渡与排查）；后续版本可下线 |
| `GET /conversations/:id/messages` | 分页消息 | 不变（鉴权与归属校验不变） |
| `PATCH /conversations/:id` | 重命名 | **下线**（路由移除） |
| `DELETE /conversations/:id` | 删除会话 | **下线**（路由移除） |
| `POST /conversations/:id/clear` | —— | **新增：清除聊天记录** |

`clear` 语义与返回：

- 一个事务内删除该会话全部 `messages` 与 `pending_actions`，会话 `title` 重置为"新对话"、`updated_at=now()`；
- 返回 `{ id, deleted_messages: N }`；
- 清除后 `buildHistory` 为空，下一条消息按全新上下文处理；自动标题机制保留（清除后首条用户消息重新派生标题，仅存于数据层、前端不展示）；
- 清除时刻若有 SSE 进行中的请求，不强制断连；清除后旧待确认动作的 confirm/cancel 返回"该操作已失效"（沿用 pendingActionInvalid）。

### 7.4 前端路由与导航

- `/chat` 直接渲染会话页：进入时先调 `POST /conversations` 取单例会话（本地可缓存 id，清除记录不换 id），随后加载消息；**URL 始终保持 `/chat`**，不再跳到 `/chat/:id`；
- `/chat/:id` 旧地址重定向到 `/chat`；
- 助手页成为一级页：左上角为**汉堡按钮**（唤起抽屉），标题"助手"，右上角"更多"菜单只保留一项——**清除聊天记录**（红色危险项）；
- 抽屉"助手"菜单项、FAB 行为更新：

  | 位置 | 行为 |
  | --- | --- |
  | 抽屉 → 助手 | 进入 `/chat` |
  | 日程/任务模块 FAB | 进入 `/chat`（open-chat 形态不变） |
  | `/chat` 页面 | FAB **隐藏**（已在对话页） |
  | 其他页面 | FAB 隐藏 |

  FAB 的 `new-conversation`（新建对话）形态删除；
- ConversationListView 页面文件、会话列表相关 API 调用、会话重命名弹窗、删除会话弹窗一并删除；空态不再有"发起新对话"按钮（助手页自身即对话态）。

### 7.5 清除聊天记录交互

1. 入口：助手页右上角"更多"→ ActionSheet 单选项"清除聊天记录"；
2. 二次确认（AppModal，危险按钮"清除"）：
   - 标题："清除聊天记录？"
   - 正文："将永久清除与助手的全部聊天记录，且不可恢复。任务与日程数据不会被删除。"
3. 确认后：调用 clear 接口 → 清空本地消息与待确认条 → 展示首次对话引导（与 v0.2.0 空态一致："和助手说一句话试试" + 示例语句）→ toast"聊天记录已清除"；
4. 失败：toast 展示错误文案，消息不丢失；
5. 清除只影响消息与待确认动作，**不触碰任何任务、日程、清单、循环规则数据**；
6. 埋点：`chat_history_cleared`（含清除时消息条数分桶）。

### 7.6 LLM 与异常

- LLM 工具集、系统提示词、SSE 协议不感知会话数量变化；不存在"删除会话/新建会话"工具，无需改动；
- 边界：

| 情况 | 处理 |
| --- | --- |
| 多端同时使用 | 两端拿到同一个会话 id；一端清除后，另一端重新拉取历史即为空（沿用消息分页拉取，不做实时推送） |
| 清除后立刻发消息 | 正常创建无历史上下文的新对话轮次 |
| 收到已清除消息 id 的重试（client_msg_id） | 幂等查询不到，按新消息处理 |
| 接口收到不存在/越权的会话 id | 沿用"会话不存在"404；正常前端流程下不会出现（id 来自 get-or-create） |

## 8. 非功能性需求

### 8.1 性能

- 折叠/展开动画 ≤ 250ms，开关点击响应 ≤ 100ms；折叠态按周切换（含计数补齐 + 当日列表）P95 ≤ 500ms（常规网络）；
- 月历主页整页滚动在 300 项以内日程数据下保持 60fps（标记点与行渲染不新增复杂布局）；
- yearly 指定日期不新增查询：单月展开 P95 与 v0.2.0 持平（≤ 100ms）；
- `clear` 单会话删除基于 `messages(conversation_id, id)` 既有索引，P95 ≤ 300ms（单用户消息量级下）；
- get-or-create 会话接口 P95 ≤ 200ms。

### 8.2 可用性、兼容性与无障碍

- 沿用 iOS Safari、Android Chrome 近两个大版本、微信内置 WebView；375pt 基准、44pt 热区、安全区；
- 折叠开关、弹层、ActionSheet 均带正确 ARIA（`aria-expanded`、`role="dialog"`、`aria-modal`、焦点管理）；
- 宽屏 1024/1280/1920 宽度下：内容中栏居中、无横向滚动、月格不异常放大、抽屉与 FAB 可用；宽屏不属于专门适配目标，但不得出现元素重叠或不可操作；
- 弱动效设置：折叠与弹层动效退化为直接显隐。

### 8.3 数据迁移与接口兼容

- 仅 1 个新迁移 **006**（会话收敛 + 唯一索引），Y-01 无结构迁移；
- 旧 URL 兼容：`/calendar/day`、`/chat/:id` 均有重定向，不产生死链；
- 下线接口（PATCH/DELETE conversation）发布后即移除，无多版本共存承诺（H5 由部署保证一致）。

### 8.4 隐私与安全

- 清除聊天记录为不可逆操作，确认文案明确；删除仅限本人会话，归属校验与既有接口一致；
- 不新增个人数据类别；年规则、清单名称均为既有数据类型。

### 8.5 可观测性

- 新增/调整埋点：
  - `calendar_collapse_changed`（态：week/month，来源：开关/手势）；
  - `calendar_week_shift`（折叠态按周切换次数）；
  - `event_detail_arrived`（来源：home_item，用于度量一步直达）；
  - `recurring_yearly_custom_date_created`（yearly 中带 by_month_day 的创建占比）；
  - `list_create_sheet_opened/confirmed/canceled`、`list_rename_sheet_confirmed`；
  - `subtask_add_blocked_depth`（5 级置灰点击/4013）；
  - `chat_history_cleared`（消息量分桶）；
- 异常日志：by_month_day 校验失败、折叠态跨月计数拉取失败、会话收敛迁移中的多会话用户数、clear 事务异常、get-or-create 竞态（唯一索引冲突重试）。

## 9. 关键业务流程

### 9.1 创建"每年指定日期"循环日程（手动与对话）

```
手动：新建日程 → 标题/首次时间（2026-09-17 10:00）→ 重复 → 每年
  → 月/日选择器改为 6 月 1 日（默认带入 9 月 17 日，用户手改后不再被开始日期覆盖）
  → 预览「每年 6 月 1 日 10:00–11:00，长期重复」→ 保存
  → 服务端校验 by_month_day（4011 拦截非法组合）
  → 首次实例 = 2027-06-01 10:00（已跳过 2026-06-01）
  → 90 天扫描无窗内实例 → 写入系列；月历在 2027 年 6 月出现实例
对话："每年 6 月 1 日提醒我体检" → 模型解析 by_month_day
  → 月日歧义（"每年第 N 个周 X"）→ 追问，不猜测
```

### 9.2 日程主页折叠与直达详情

```
/ calendar 主页（默认展开月历）
  → 点折叠开关 → 月历收成选中日所在周（≤250ms）
  → ‹ / 横滑 → 选中日 −7 天，月计数按需补齐，列表刷新
  → 点列表 item（任意类型）→ 直达对应详情页（无中间页）
  → 详情页编辑/删除/作用域操作 → 返回主页（?date= 定位）
旧链接 /calendar/day?date=... → 重定向 /calendar?date=...
```

### 9.3 清除聊天记录

```
/chat（进入时 POST /conversations get-or-create 唯一会话）
  → 更多 → 清除聊天记录
  → 二次确认（明示不可恢复、任务日程不受影响）
    ├─ 取消 → 无变化
    └─ 确认 → POST /conversations/:id/clear
          事务删除 messages + pending_actions，返回 deleted_messages
          → 本地清空 → 首次引导 → toast「聊天记录已清除」
          → 下一条消息在空上下文上重新开始
```

### 9.4 新建清单

```
清单管理 → ＋ → 底部弹层（输入框自动聚焦）
  → 输入名称 → 确认（空名禁用 / 回车提交 / loading 防重）
    ├─ 成功 → 弹层关闭 + toast + 列表新增
    └─ 失败 → 弹层内联报错，输入保留
取消/遮罩 → 放弃关闭
```

### 9.5 给子任务添加下级

```
任务首页 → 展开根任务（可在子树底部给根任务加子任务）
  → 子任务行无行尾「+」；点子任务行 → 进入该子任务详情页
  → 详情页子任务区「添加子任务」→ 创建下一级（第 5 级任务详情页入口置灰，4013 兜底）
```

## 10. 验收标准

### 10.1 日程主页与日历

1. 折叠/展开开关行为与动画达标：折叠后仅周标题 + 一行周；折叠态 ‹ › 与横滑按周移动选中日，跨月时年月、计数、列表正确；展开后定位到选中日所在月且选中日不丢失；
2. 折叠态跨周月份的标记点正确（至多 2 个月计数补齐），无标记点残留/张冠李戴；
3. 列表标题不出现月份/年份（今天/明天/昨天 + 周 X，或周 X + 日序），与头部信息不重复；
4. 主页任意 item 点击一步到详情：普通/任务日程进日程详情，循环实例进实例视角详情；应用内不存在任何 `/calendar/day` 跳转；旧地址重定向到 `/calendar` 并恢复 `date`；
5. 主页为整页滚动，长列表可随页滚动，标题条吸顶；无"查看全部/收起"按钮，当日日程全量展示，全天置顶、定时按时间升序；
6. 1024/1280/1920 宽度下内容居中限宽（≤480px），月格按容器宽度计算、不异常放大，无横向滚动；320px 小屏无回退；
7. DayView 下线后，编辑/删除/完成/循环作用域操作均可在详情页完成，路径可走通。

### 10.2 yearly 指定日期

1. 表单可选任意 1..12 月 × 1..31 日并实时摘要；默认带入首次日期月日，手改后修改开始日期不覆盖；月末回落提示正确；
2. 首次实例语义正确：指定日已过则次年（按 interval），未过则本年；2/29 平年落 2/28；count/until/never 三结束条件与 90 天扫描起点符合 5.2；
3. 服务端对非 yearly 携带 by_month_day、yearly 携带 week/month_rule、月日越界 100% 以 4011 拦截；
4. 对话入口可解析明确月日表达，字段级结果与手动一致；"第 N 个周 X"等不支持表达 100% 追问/告知，不猜测；
5. 存量 yearly 系列（无 by_month_day）展开结果逐实例不变，无迁移；
6. 三作用域编辑、例外覆盖、冲突规则在新字段下全部不回归。

### 10.3 清单与子任务

1. 清单新建/重命名均为底部弹层：输入框全宽 ≥44px、自动聚焦、空名禁提交、loading 防重、回车确认、遮罩/取消放弃；成功/失败反馈符合 6.1；
2. SubtaskRow 行尾"+"在任务首页、任务详情、对话卡片三处全部消失；
3. 任务首页仅可给根任务行内加子任务；第 2 级及更深分组无任何行内添加入口；
4. 给子任务添加下级只能经其详情页完成，功能与深度/同清单/无环校验不回归；第 5 级详情入口置灰且服务端 4013 拦截。

### 10.4 助手单会话化

1. 每个用户仅一个会话：`POST /conversations` 幂等；数据库存在 `user_id` 唯一索引；迁移后无任何用户保留多条会话，多会话用户的消息按序合并到保留会话；
2. `/chat` 直接进入对话页（汉堡一级页、标题"助手"），应用内无会话列表、新建会话、重命名入口；`/chat/:id` 重定向到 `/chat`；
3. "清除聊天记录"二次确认后清空全部消息与待确认动作，空态与全新引导正确，任务/日程/清单数据无任何变化；清除后新对话在空上下文运行；
4. FAB 在日程/任务页进入 `/chat`，在 `/chat` 隐藏，无"新建对话"形态；
5. PATCH/DELETE conversation 路由移除；clear 归属校验、失败不丢数据、多端刷新行为符合 7.6；
6. v0.2.0 全部对话工具能力与长会话回归通过（TC-CHAT-015/018 等）。

### 10.5 非功能

性能指标达标（8.1）；迁移 006 幂等且在类生产数据量演练通过、可回滚；折叠/弹层 a11y 属性齐全；宽屏不劣化；埋点按 8.5 上报。
