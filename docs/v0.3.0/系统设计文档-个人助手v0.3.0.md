## 1. 设计概述

### 1.1 系统边界（增量）

v0.3.0 不新增业务领域，8 项需求按系统改造面归为四组：

1. **日程主页与日历（C-01～C-04）**：纯前端重构——月历折叠周形态、整页滚动、标题去重、item 直达详情、宽屏中栏；`DayView` 与路由 `/calendar/day` 下线。**后端接口零变更**（月计数、按日列表接口原样复用）；
2. **yearly 循环支持指定月日（Y-01）**：`recurrence` JSON 新增可选字段 `by_month_day`，循环引擎/校验/摘要/LLM 工具入参小幅扩展；**无表结构变更、存量零回填**；
3. **清单弹层与子任务入口（L-01、S-01）**：纯前端改造，后端清单与子任务接口、4013/4014/4015 校验全部不变；
4. **助手单会话化（A-01）**：新增**迁移 006**（存量多会话收敛 + `conversations(user_id)` 唯一索引）；`POST /conversations` 改为幂等 get-or-create；新增 `POST /conversations/:id/clear`；PATCH/DELETE 会话下线；前端删除会话列表页。

- 不引入任何新外部依赖、新中间件、新密钥；
- 唯一的破坏性接口变更（PATCH/DELETE `/conversations/:id`）随 H5 同版本部署，不做多版本共存；
- 既有规则全部保留：循环虚拟展开不物化、实例三作用域、普通/任务日程类型不可变、冲突只提示不阻止、子任务深度 ≤5/同清单/无环、级联操作服务端统一。

### 1.2 设计目标与手段

| 目标 | 设计手段 |
| --- | --- |
| 折叠只改视觉不改数据语义 | 折叠态复用月计数接口与月格组件，仅把 6 行裁为选中日所在周；选中日仍是唯一数据锚点，按周切换 = 选中日 ±7 天 |
| 宽屏不劣化 | 新增全局内容中栏（`--content-max-width:480px`）；月格宽度由视口公式改为容器百分比；浮层仍相对视口定位 |
| 年规则扩展零迁移 | `by_month_day` 为 recurrence jsonb 内可选字段；缺省即"取首次月日"，引擎按候选年序列自然跳过早于锚点的候选，首次实例语义不需要额外分支 |
| 单会话不丢历史 | 迁移保留每用户最新会话，其余会话消息**改挂**（非删除）、审计日志改挂、待确认动作删除；唯一索引兜底，应用侧 get-or-create + ON CONFLICT |
| 清除记录可解释 | 单事务删消息与待确认动作、重置标题、返回删除条数；任务/日程/清单数据无任何写入路径 |
| 下线不产生死链 | `/calendar/day`、`/chat/:id` 路由级重定向并透传 query；旧能力（编辑/删除/完成/作用域）回归确认由详情页承接 |
| 改动可回归 | 不新增错误码（by_month_day 非法复用 4011）；新增 1 个配置项、1 个迁移；全部改动点映射到第 12 章追溯表 |

## 3. 前端设计（H5，增量）

### 3.1 前端职责与约束（沿用 + 新增）

- 端上仍**不保存业务数据、不展开循环规则**：折叠周的计数与日程全部来自既有 `/events/monthly` 与 `/events?date=` 接口，端上只做"取哪一天/哪一月"的参数计算与缓存；
- **折叠态是纯内存 UI 态**：`collapsed` 默认 `false`，不写 localStorage、不跨新页面进入存活；同一次访问内详情页返回（组件存活 + `?date=`）保持当前态；
- 年规则的端上仅允许存在一处轻量计算：RepeatSheet 的**预览辅助**（候选年是否跨年的展示判断），与 v0.2.0 既有"端上拼预览、保存后以服务端 `recurrence_summary`/DTO 为准"策略一致；规则是否合法、首次实例的权威结果、月历实例全部来自服务端；
- 单会话 id 可端上缓存（localStorage 键 `assistant.conversation_id`），但**每次进入 /chat 仍调一次幂等 `POST /conversations` 校准**（本地 id 失效/被清库时自愈）；
- 中栏与滚动模型只影响布局 CSS，不改变任何接口入参与 store 结构。

### 3.2 日程主页重构（MonthView）

#### 3.2.1 组件状态模型

```ts
// MonthView 重构后的关键状态
const year = ref(...)            // 头部月份；折叠态始终等于 selectedDate 所在月
const month = ref(...)
const selectedDate = ref(dateKey(today))
const collapsed = ref(false)     // 新增：折叠态（内存）
const countsCache = ref<Map<string, MonthDayCount[]>>(new Map())  // 新增：key=`${y}-${m}`
const dayEvents = ref<CalendarEvent[]>([])
```

数据加载函数拆分：

| 函数 | 行为 |
| --- | --- |
| `ensureCounts(y, m)` | cache 命中直接返回；否则 `fetchMonthCounts(y,m)` 入缓存。**单月失败抛错**（调用方决定容错级别） |
| `loadMonthExpanded()` | 展开态：`ensureCounts(year,month)` + `loadDay()`，二者为当前月主数据，任一失败→整块错误占位（沿用现状，不清选中态） |
| `loadWeekCollapsed()` | 折叠态：计算选中日所在周的周一/周日，得到月份集合（1 或 2 个月）；对每个月 `Promise.allSettled(ensureCounts)`——**当前选中月失败=错误态；邻月失败仅静默缺标记点**；随后 `loadDay()` |
| `loadDay()` | `GET /events?date=selectedDate`（现状），失败错误占位，不保留旧数据 |

- 折叠态切周/选日只触发 `loadWeekCollapsed()`：邻月已缓存则整次调用只剩 `loadDay()` 一个请求；
- 展开→折叠：若缓存已有该周月份（通常已有当前月），仅按需补拉邻月，不整月重拉；
- 标记点渲染时从 `countsCache` 取对应年月的数据；MonthGrid 周模式下补位日按其真实年月在缓存中查点。

#### 3.2.2 导航语义

| 操作 | 展开态 | 折叠态 |
| --- | --- | --- |
| 头部 ‹ / › | `shiftMonth(±1)`（现状：选中日回今天/1 号） | `shiftWeek(±1)`：`selectedDate ±= 7d`；year/month 同步为选中日月；`loadWeekCollapsed()` |
| 月历区横滑 | ±1 月（沿用阈值与边缘避让） | ±1 周（同上手势识别，仅步长不同） |
| 点日期格 | `onSelect`（现状，补位日切月） | 同函数；补位日必然在本周内，year/month 同步后 `loadWeekCollapsed()` |
| 「今天」按钮 | 现状（非当月显示） | 选中日回今天、月份回本月，保持折叠 |
| 折叠开关 | `collapsed = true`（不重置选中日） | `collapsed = false`（展开到包含选中日的月份） |

- 展开态的 year/month 与 selectedDate 可能不同月（现状如此）；切折叠时以 selectedDate 为准对齐 year/month；
- 动画期间（250ms）忽略开关重复点击；
- 路由 query 同步：折叠态翻周/选日时 `router.replace({ query: { date: selectedDate } })`（replace 不压历史栈），使详情页返回与浏览器后退可恢复选中日；`onMounted` 从 `route.query.date` 恢复的现有逻辑保留。

#### 3.2.3 列表区：整页滚动 + 吸顶 + 全天分组 + 直达

- 模板结构由"固定导航+月历 / 内部滚动列表"改为单文档流：导航栏随页滚走；`日历区(含开关条)` 之后是 **sticky 标题条**（`position:sticky; top:0; z-index:10`，白底+底分隔），再往下是当日全部日程；

- 前端分组渲染（无需新接口字段，`all_day` 已在 DTO 中）：

```ts

const timedEvents = computed(() =>
  dayEvents.value.filter(e => !e.all_day).sort(byStart))
```

  有全天项时渲染"全天"组标题 + 卡片；其后按开始升序渲染定时项；

### 3.5 唯一会话 /chat 与清除记录

#### 3.5.1 会话自举（stores/conversation.ts，新增）

```ts
// 单例 store
const convId = ref<number | null>(loadCachedId())   // localStorage
async function ensureConversationId(): Promise<number> {
  const conv = await createConversation()           // POST /conversations，幂等 get-or-create
  convId.value = conv.id
  saveCachedId(conv.id)
  return conv.id
}
```

## 4. 后端模块设计：yearly 指定月日

### 4.1 规则类型与校验

`recurrence/types.ts`：

```ts
export interface ByMonthDay {
  /** 1..12 */
  month: number;
  /** 1..31；目标月无该日时落到当月最后一天 */
  day: number;
}

export interface RecurrenceRule {
  // ...既有字段
  /** 仅 yearly：指定每年的月日；缺省=取首次实例（anchor）的月日 */
  by_month_day?: ByMonthDay;
}
```

`schema.ts` 的 `recurrenceBase` 增：

```ts
by_month_day: z
  .object({
    month: z.coerce.number().int().min(1).max(12),
    day: z.coerce.number().int().min(1).max(31),
  })
  .optional(),
```

`engine.ts` 的 `validateRule` 增三条（全部抛 **4011**，不新增错误码）：

1. 非 yearly 携带 `by_month_day` → 「只有「每年」重复才能指定月日」；
2. month/day 结构外的业务兜底（zod 已挡非整数/越界，防御性再判一次）；
3. yearly 携带 `by_week_days`/`month_rule` 的既有拒绝不变；yearly 带 `by_month_day` 时仍不允许这两个字段（互斥关系不变）。

### 4.2 引擎展开（cycleCandidates / expand）

利用现有引擎"**早于锚点的候选不产生实例**"这一既有不变量（`expand` 中 `if (naive < anchorNaive) continue`），yearly 分支改为：

```ts
case 'yearly': {
  const y = anchor.y + k * rule.interval;
  const m = rule.by_month_day?.month ?? anchor.m;
  const d = rule.by_month_day?.day ?? anchor.d;
  const dim = daysInMonth(y, m);
  // 31 日落当月最后一天；2 月 29 日平年落 2 月 28 日
  return [at(y, m, Math.min(d, dim))];
}
```

语义推导（无需特判分支）：

- 候选年序列 = `anchor.y + k·interval`；候选日 = 指定月日落月末；实例时刻/时长仍取 anchor（`hh/mi/ss` 与 `all_day`/`durationMs` 不变）；
- 例：anchor=2026-09-17 10:00，`{month:6,day:1}`，interval=1 → k=0 候选 2026-06-01 < anchor 跳过；k=1 候选 2027-06-01 即**首次实例**；interval=2 → 首次 2028-06-01；
- anchor 当天即发生日（含 2/29→2/28 同日情形）：k=0 候选 ≥ anchor，首次即当天；
- `count` 计数：现有 `produced` 仅对 ≥ anchor 的候选递增，首次实例自然为第 1 次；
- `until/never`、窗口左闭右开、maxSeeds 上限、occurrence_key（原始开始 UTC ISO）全部不变；
- `cycleIndexForWindow` 的 default 分支按年差估算起始周期，对 by_month_day 仍是安全乐观估计（多跑至多 1 个周期，有 `naive < anchorNaive` 与 maxSeeds 双保险），无需改算法；
- **90 天冲突扫描**：`scanSeriesConflicts` 窗口起点仍是 firstStart、`expand(...)` 在窗口内无种子即 `seeds.length===0` 早返回空结果——首次实例晚于创建日 90 天以上时天然无扫描命中，符合 PRD 5.2 预期（补测试固化，不改逻辑）。

### 4.3 规则摘要（summary.ts）

- `freqPart` yearly 分支：`每 N 年 {M} 月 {D} 日`（M/D 取 `by_month_day ?? anchor`；interval=1 省略数字）；
- `fallbackNote` yearly 分支改为基于**实际生效月日**：
  - month=2 且 day=29 → `，平年安排在 2 月 28 日`；
  - day ∈ {29,30,31}（含非 2 月）→ `，遇到小月落到当月最后一天`；
  - 两条按实际月日只输出适用的一条；
- 结束条件、时段/全天拼装不变；存量无 `by_month_day` 的系列摘要文案与 v0.2.0 逐字一致。

### 4.4 首次实例输出（SeriesDTO.first_occurrence_at）

- 引擎导出辅助函数（复用 `firstOccurrenceAfter`，from=firstStart）：

```ts
export function firstOccurrenceAt(rule, firstStart, durationMs, tz): OccurrenceSeed | null {
  return firstOccurrenceAfter(rule, firstStart, durationMs, firstStart, tz);
}
```

  对所有频率统一可用（非 yearly 时结果=firstStart 当次）；
- `occurrence.service.ts` 的 `toSeriesDTO` 增 `first_occurrence_at`（UTC ISO；规则已耗尽为 null）；月/日列表实例、详情、卡片渲染不受影响；
- 写路径（create/update series）返回的 DTO 经同一组装函数，前端保存后即可拿到权威首次时间。

### 4.5 LLM 集成

### 5.1 getOrCreate（幂等建会话）

```ts
async getOrCreate(userId: number): Promise<ConversationDTO> {
```

### 5.2 clearHistory（清除聊天记录）

```ts
async clearHistory(userId: number, conversationId: number): Promise<{ id: number; deleted_messages: number }> {
  await this.getOwned(userId, conversationId);          // 归属/存在校验（404）
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    const msg = await client.query(
      `DELETE FROM messages WHERE conversation_id = $1`, [conversationId]);
    await client.query(
      `DELETE FROM pending_actions WHERE conversation_id = $1`, [conversationId]);
    await client.query(
      `UPDATE conversations SET title = '新对话', updated_at = now() WHERE id = $1`,
      [conversationId]);
    await client.query('COMMIT');
    logger.info('chat_history_cleared', { user_id: userId, conversation_id: conversationId,
      deleted_messages: msg.rowCount });
    return { id: conversationId, deleted_messages: msg.rowCount ?? 0 };
  } catch (e) { await client.query('ROLLBACK'); throw e; }
  finally { client.release(); }
}
```

- 待确认动作**物理删除**（临时对象，无保留价值；与"作废"语义一致且更省空间）；
- 清除后该会话下一条消息：buildHistory 为空、无 pending 可命中（旧 pendingId confirm/cancel 返回"该操作已失效"，沿用 pendingActionInvalid）；
- 消息删除依赖 messages 会话外键（无其他表引用 messages.id）；任务/日程/清单数据无任何 SQL 触及；
- 进行中的 SSE 不强制断连：清除发生在两条用户消息之间的常规时序；前端在 streaming 时禁用入口做并发规避。

## 6. 数据库设计：迁移 006

### 6.1 迁移 `006_single_conversation.sql`（幂等）

设计要点：

- 每用户保留 `updated_at` 最新（并列取 id 最大）的会话；
- **消息改挂而非删除**：按全局 id（SERIAL≈创建先后）并入保留会话，时间线天然有序；
- 合并前必须处理 `uniq_msg_client_id`（`(conversation_id, client_msg_id)` 部分唯一索引）：将**非保留会话全部消息的 client_msg_id 置 NULL**——该幂等键只用于近期发送重试，历史合并消息不会再重放，置空不影响业务；
- `tool_invocations.conversation_id` 无外键（可空）：改挂到保留会话，审计链不断；
- `pending_actions`：非保留会话行删除；
- 最后创建 `conversations(user_id)` 唯一索引；
- 幂等：以"索引是否已存在"为闸门，存在则整块跳过；迁移 runner 本身在单事务中执行并登记 schema_migrations。

```sql
-- 006：每用户收敛为唯一会话（个人助手 v0.3.0）
DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM pg_indexes
    WHERE indexname = 'uniq_conversations_user'
  ) THEN

    -- 1) 每用户保留最新会话（updated_at 最新，并列取 id 最大）
    CREATE TEMP TABLE _v030_keep_conv ON COMMIT DROP AS
      SELECT DISTINCT ON (user_id) user_id, id AS keep_id
      FROM conversations
      ORDER BY user_id, updated_at DESC, id DESC;

    -- 2) 解除待合并消息的幂等键，避免并入后 (conversation_id, client_msg_id) 冲突
    UPDATE messages SET client_msg_id = NULL
    WHERE conversation_id IN (
      SELECT c.id
      FROM conversations c
      JOIN _v030_keep_conv k ON k.user_id = c.user_id AND c.id <> k.keep_id
    );

    -- 3) 审计日志改挂保留会话（tool_invocations.conversation_id 无外键）
    UPDATE tool_invocations t SET conversation_id = k.keep_id
    FROM _v030_keep_conv k
    JOIN conversations c ON c.user_id = k.user_id AND c.id = t.conversation_id
    WHERE c.id <> k.keep_id;

    -- 4) 待确认动作随旧会话删除（临时对象）
    DELETE FROM pending_actions
    WHERE conversation_id IN (
      SELECT c.id
      FROM conversations c
      JOIN _v030_keep_conv k ON k.user_id = c.user_id AND c.id <> k.keep_id
    );

    -- 5) 消息改挂保留会话（id 顺序即全局创建顺序）
    UPDATE messages m SET conversation_id = k.keep_id
    FROM _v030_keep_conv k
    JOIN conversations c ON c.user_id = k.user_id AND c.id = m.conversation_id
    WHERE c.id <> k.keep_id;

    -- 6) 删除已腾空的非保留会话（messages/pending 外键此时均无引用）
    DELETE FROM conversations c
    USING _v030_keep_conv k
    WHERE c.user_id = k.user_id AND c.id <> k.keep_id;

    -- 7) 单会话唯一约束
    CREATE UNIQUE INDEX uniq_conversations_user ON conversations(user_id);

  END IF;
END $$;
```

### 6.2 ER 变化

- conversations：由"一用户多行"变"一用户一行"，新增唯一索引；列结构不变；
- messages / pending_actions / tool_invocations：列结构不变，仅数据归属收敛；
- events/tasks/lists 等业务表与本迁移完全无关。

### 6.3 发布前演练与核对

- 在类生产快照上演练：记录迁移前每用户会话数分布、消息总数；迁移后断言
  ① 每用户会话数 ≤1；② 消息总数不变（仅 conversation_id 改变）；③ tool_invocations 行数不变；④ pending_actions 仅剩保留会话上的行（理论上迁移窗口无活动流量）；
- 多会话用户数、合并消息量打 info 日志（可在迁移 SQL 中 RAISE NOTICE 或发布前用核对 SQL 输出）；
- 回滚：应用层回退即可，唯一索引保留不影响旧版本读（旧版本"新建会话"在唯一索引约束下会报错——故回滚需同时评估是否 DROP INDEX；DROP 索引脚本手工提供，不纳入自动迁移）。

## 8. 关键时序

### 8.1 折叠态按周切换（纯前端 + 既有接口）

```
用户点 ‹（折叠态）
 → MonthView: selectedDate -= 7d；year/month 同步；router.replace(?date=)
 → 计算周月份集合 {当前月[, 邻月]}
 → Promise.allSettled(ensureCounts(每个月))
      ├─ 缓存命中：无请求
      └─ 未命中：GET /events/monthly?year&month（每月一个）
 → GET /events?date=selectedDate
 → MonthGrid(week) 渲染周行 + 标记点；列表渲染当日全部日程
邻月失败：该月格子无点，不报错；当前月或列表失败：错误占位
```

### 8.2 主页直达详情与返回

```
点 item → /calendar/:id（或 +?occurrence_key=）
 → EventDetailView（编辑/删除/作用域 Sheet/任务完成，全部既有）
 → 返回：router.back()；MonthView 组件存活，collapsed/selectedDate/countsCache 保持
```

### 8.3 创建 yearly 指定月日（手动）

```
EventForm → RepeatSheet(yearly, by_month_day=6/1)
 → 本地预览：首次安排 2027-06-01（预览辅助，非权威）
 → POST /events {start_at:2026-09-17T10:00, recurrence:{yearly,bmd,never}}
 → zod 通过 → validateRule（4011 互斥/越界）
 → scanSeriesConflicts：窗口 [09-17, +90d] 内 expand 无种子 → 空冲突
 → 写系列主记录（start_at 仍为 2026-09-17T10:00）
 → 响应 SeriesDTO 含 recurrence_summary「每年 6 月 1 日 10:00–11:00，长期重复」
   与 first_occurrence_at=2027-06-01T02:00Z
```

### 8.4 对话创建 yearly（LLM）

```
用户「每年 6 月 1 日体检」→ 模型 create_event（recurrence.by_month_day）
 → 同一 zod/validateRule/写路径；工具结果卡用服务端摘要
「每年五月第一个周日…」→ 模型不支持该规则 → 追问/告知，不产生写操作
```

### 8.5 进入助手（单会话自举）

```
进入 /chat
 → ensureConversationId()
     ├─ 本地有缓存 id：仍 POST /conversations（幂等）→ 返回同一行（updated_at 不变）
     └─ 无缓存/新用户：POST → 新建并返回
 → GET /conversations/:id/messages → 有历史则渲染，无则空态引导
```

### 8.6 清除聊天记录

```
更多 → 确认 → POST /conversations/:id/clear
 → 服务端单事务：DELETE messages / DELETE pending_actions / 重置标题
 → {id, deleted_messages}
 → 前端清空 store 消息、复位会话态、保草稿、切空态、Toast
 → 下一条消息：buildHistory=[] → 全新上下文
```

### 8.7 旧链访问

```
/calendar/day?date=2026-09-17 → 路由 redirect /calendar?date=2026-09-17
                                → MonthView onMounted 恢复选中日
/chat/123                      → 路由 redirect /chat → 单会话自举
```

## 10. 安全设计（增量）

| 项 | 方案 |
| --- | --- |
| 越权防护 | clear/get-or-create 均以 JWT user_id 为唯一定位：clear 先 `getOwned`；get-or-create 的 INSERT/冲突路径不接受外部 user_id；旧 PATCH/DELETE 移除后无任何"删别人会话"路径 |
| 输入校验 | by_month_day 经 REST 与工具共用 zod（1..12 / 1..31）+ validateRule 互斥校验；clear 无 body 攻击面 |
| 迁移安全 | 收敛在单事务内完成（runner 包事务），失败整体回滚；唯一索引在收敛之后创建，杜绝"建索引失败留下半收敛数据"；幂等闸门为索引存在性 |
| 审计 | tool_invocations 改挂保留会话而非删除；清除记录落 info 日志（计数，无内容）；消息内容不进日志的既有约束不变 |
| 数据最小化 | 清除即物理 DELETE，不保留可恢复副本（确认文案已明示不可恢复）；备份层留存周期由既有 DB 备份策略承接，产品层不可恢复 |
| 并发 | get-or-create 依赖唯一索引 + ON CONFLICT，无应用层竞态；clear 与发送并发由前端禁钮 + 事务语义兜底（后到的消息写入空会话成功） |
| LLM | 模型不能指定会话 id 之外的任何会话操作（无会话类工具）；by_month_day 非法输入走 4011 回灌，不产生写入 |

## 11. 非功能与运维

### 11.1 性能预算

| 项 | 指标 |
| --- | --- |
| 折叠态按周切换（缓存命中，仅 1 个列表请求） | P95 ≤ 500ms（网络口径）；开关动画 ≤ 250ms 不掉帧 |
| 折叠态跨月补拉（多 1 个月计数请求） | 与列表请求并发，P95 ≤ 600ms；邻月失败不阻塞渲染 |
| yearly 展开 | 与 v0.2.0 yearly 同量级（候选分支 O(年数)，无额外查询），单月 P95 ≤ 100ms 不回退 |
| get-or-create（主键/唯一索引点查 + upsert） | P95 ≤ 200ms |
| clear（单用户消息量级） | P95 ≤ 300ms；走 `idx_msg_conv`/`idx_pending_conv` 索引 |
| 迁移 006 | 用户会话量级很小（单人 ≤100 行历史），全量秒级；锁注意点见 11.2 |
| 前端 | 月格改 1fr 后宽屏布局无大图/无额外 JS；MonthView 重构首屏 gzip 增量 ≤ 6KB；ListFormSheet/YearlyRulePicker 各 ≤ 2KB |

### 11.2 迁移与发布

- 迁移随服务启动由既有 migrate 机制执行（006 顺序在 005 之后），幂等；
- 锁与流量：conversations 表小，UPDATE 消息按 conversation_id 索引扫描；选择低峰发布；迁移事务期间该用户的会话写短暂等待，量级可忽略；
- 上线顺序：
  1. **后端**：迁移 006 执行 → get-or-create/clear/接口下线生效；
  2. 核对：每用户会话 ≤1、消息/审计总数不丢（6.3 断言）；
  3. **前端**：单会话页、日历重构、弹层、入口收敛发布；
- 回滚：后端应用回退后新接口 404，但唯一索引保留不影响读路径；若需恢复"多会话"能力再手工 DROP `uniq_conversations_user`（不自动）；
- 数据零回填说明：by_month_day 缺省等价锚点月日，无需 UPDATE events；
- `/healthz` 与限流不变（测试期若临时调高对话限流，发布前确认恢复默认）。
