## 1. 背景与目标

### 1.1 背景

v0.3.0 完成体验打磨后，产品在循环日程、子任务、单会话助手上的结构已经稳定。v0.4.0 的需求来自**真实使用中反复出现的 10 个问题**，分为四类：中国本土日历缺失（2 项）、已确认缺陷（3 项）、交互模型与对话策略调整（3 项）、聊天体验与账号设置补全（2 项）：

**本土日历能力缺失**

1. **"工作日"被写死为周一至周五**：循环日程的"工作日"快捷选项实际存的是星期 1~5，完全不感知中国法定节假日与调休补班。按它安排"每个工作日站会"，国庆假期仍会生成实例、调休上班的周日反而漏掉，语义错误；
2. **日历没有农历、日程也不能按农历安排**：月历只显示公历数字，看不到农历日期与传统节日；而生日（农历）、春节、端午、中秋、除夕等安排是中国用户的高频参照，用户既想"看到"农历，也想直接说"每年腊月三十回家""农历八月十五家庭聚餐"就能把日程建对；

**已确认缺陷**

3. **普通日程改为重复日程保存无效**：编辑一个无重复规则的日程、设置重复频率后保存，接口返回成功但重复规则没有写入，日程仍是单次日程（根因：服务端更新逻辑只处理了"已有规则 → 改规则"，遗漏了"无规则 → 加规则"分支）；
4. **进入聊天页停在最早消息**：每次打开助手页，消息区定位在最顶部（最早消息），必须手动上拉（下拉）才能看到最新消息，与聊天产品的基本预期相反；
5. **使用中突然提示登录失效**：登录凭证固定 2 小时过期、没有任何续期机制，用户在连续使用或微信 WebView 页面回收后返回时，会被突兀地踢回登录页、正在编辑的内容丢失；

**交互模型调整**

6. **任务列表仍承载子任务**：v0.3.0 虽收敛了"添加入口"，但任务首页仍可展开子任务树、仍能在列表里给根任务加子任务，列表层级复杂、认知负担重；子任务的创建与展示应彻底收敛到任务详情页；
7. **日程主页滚动与折叠策略需再调整**：v0.3.0 的"整页滚动"会把月历滚出屏幕，看日期与看列表不能同屏；折叠/展开完全靠用户手动，默认总是展开，日程多的日子列表可视区域过小；
8. **助手确认过多**：助手在信息基本足够时仍逐条追问（时间、清单、作用域……），完成一件小事常要三四轮对话。期望助手先用合理默认补齐、给出一个完整方案，用户一次确认即可。

**账号与设置**

9. **聊天消息只按纯文本渲染**：助手回复中的列表、加粗、步骤、链接都挤成一段，可读性差；
10. **没有个人信息与系统设置**：抽屉账号区只显示邮箱首字母和一个退出按钮，看不到账号信息、改不了称呼；农历开关、默认落地页等本版新增偏好无处安放。

10 项需求编号与分组：

| 分组 | 编号 | 需求 |
| --- | --- | --- |
| 本土日历 | H-01 | 法定工作日历：工作日循环感知节假日与补班 |
| 本土日历 | N-01 | 日历日期支持农历（含传统节日、节气） |
| 主页调整 | C-01 | 日历按当日日程数量决定默认折叠/展开；取消整页滚动，仅日程列表滚动 |
| 任务 | T-01 | 任务列表删除子任务展开与创建，统一收敛到任务详情页 |
| 助手 | A-01 | 助手"先定方案、再请确认"，减少反复追问 |
| 聊天 | M-01 | 助手消息支持 Markdown 渲染 |
| 缺陷修复 | B-01 | 修复普通日程改为重复日程无效 |
| 缺陷修复 | B-02 | 修复聊天页打开定位到最早消息 |
| 缺陷修复 | B-03 | 修复使用中突发登录失效（令牌续期机制） |
| 账号 | P-01 | 个人信息页 + 系统设置页 |

### 1.2 产品目标（v0.4.0）

- **核心目标**：
  1. 月历成为同时承载**公历、农历、法定节假日/补班**的中国本土日历，"工作日"重复语义正确；
  2. 日程主页在"日历总览"与"当日安排"之间自动取舍：日程多的日子默认给列表更大空间，日历与列表同屏可用；
  3. 三个确认缺陷全部修复：规则可补挂、聊天打开即最新、活跃用户不再被登录态打断；
  4. 任务列表回归"扁平的根任务清单"，层级管理全部归入详情页；
  5. 助手从"逐条追问"变为"一次给方案、一次确认"，常规写操作平均 ≤ 2 轮完成；
  6. 补齐账号信息与设置承载位，为后续偏好类功能预留位置。
- **成功假设**：
  1. 使用"工作日"重复的用户在节假日/调休日零错误实例反馈；农历与节假日角标在上线后 4 周内进入周活用户的日常使用；
  2. 智能折叠使"进入主页后无需手动操作即可看到当日全部安排"的比例 ≥ 80%；
  3. 登录态相关投诉（被踢、反复登录）归零，30 天留存用户无感知续期；
  4. 助手常规写操作（建日程/建任务/改期）平均对话轮次较 v0.3.0 下降 ≥ 40%，方案采纳率 ≥ 70%；
  5. 三个缺陷对应的反馈在上线后 4 周内归零。

### 1.3 非目标（v0.4.0 不做）

- **农历规则的边界**：日程支持农历（5.6 节），但仅支持"正常月份（正月..腊月）+ 日（初一..三十，小月回落）"的**单次日程农历日期**与**年度循环**；**不支持指定闰月、不支持按节气名（清明/冬至等）建循环、不支持多个农历月日**；"每年第 N 个周 X"仍不支持（沿用 v0.3.0 边界）；
- **不做多国家/地区工作日历**：仅支持中国大陆（CN）法定安排，不做地区选择、不做港澳台/海外假日；
- **不做节假日数据后台与自动抓取**：放假安排以官方公告手工录入、随迁移/版本发布；不做管理界面、不做在线订阅更新；
- **不做重复日程"改为不重复"的语义变更**：B-01 只修"无规则→加规则"；"有规则→去规则"沿用现状（拒绝并提示删除/重建），避免实例历史归属歧义；
- **不做助手多方案对比**：助手一次给**一个**推荐方案，不给 2~3 个候选让用户挑；
- **不做消息推送、通知提醒**（延续全版本边界）；
- **不做账号体系扩展**：手机号、第三方登录、邮箱换绑、自助找回密码仍不做；不做头像图片上传（头像仍为文字首字母）；
- **不做深色模式、字号调节、多语言**；
- **不做 PC 端专门适配**：延续中栏限宽策略；
- **不做消息级删除、聊天记录导出、多会话**（沿用 v0.3.0 边界）。

## 2. 目标用户与使用场景

### 2.1 目标用户

延续 v0.3.0 全体个人用户，本版尤其面向：

- 按法定工作日节奏安排事项（站会、排班、吃药、打卡）的国内用户；
- 习惯参照农历与传统节日安排家庭事务（生日、祭祖、团圆、过节）的用户；
- 每天日程较多、希望打开主页就能专注当日安排的用户；
- 在微信内置浏览器中长期使用、频繁被重新登录困扰的用户；
- 希望"说一句话、点一下确认"就把事办完的助手高频用户。

### 2.2 核心使用场景

| 场景 | 描述 |
| --- | --- |
| 工作日站会 | 用户说"每个工作日早上 9 点站会"：系统按法定工作日历展开——国庆/春节等假期当天不生成，调休补班的周日正常生成；月历上假期标"休"、补班标"班"。 |
| 看农历与节日 | 9 月中旬打开月历，日期格下显示农历日；中秋节当天格内显示"中秋"（而非农历日序），选中后列表标题旁可见农历与节日名。 |
| 按农历安排日程 | 用户说"每年农历八月十五晚上家庭聚餐"：助手方案卡写出"每年农历八月十五（2026 年对应公历 9 月 25 日 · 中秋节）18:00"，确认后年度循环按农历展开，以后每年公历日期自动浮动；手动表单也可把日期切成"农历"来建单次或年度重复日程。 |
| 给既有日程补挂重复 | 建了一个"周五复盘"单次日程，后来想让它每周重复：编辑 → 打开重复设置 → 保存，规则正确写入，后续实例出现在月历上。 |
| 打开助手就是最新 | 从任务页点 FAB 进助手，消息区直接停在最新一条回复上，输入框立即可用；从聊天中点任务卡片跳详情再返回，恢复到离开前的阅读位置。 |
| 长时间不掉线 | 用户连续几天在微信里使用，access 凭证在后台静默续期，全程不出现登录页；只有连续 30 天未使用才需要重新登录。 |
| 日程多的一天 | 今天有 6 个日程：进入主页月历默认折叠为一周一行，列表占据主要高度、内部滚动；某天只有 1 个日程时进入主页，月历默认展开整月。 |
| 任务列表变清爽 | 任务首页只显示根任务行（带"已完/总数"只读摘要），没有展开箭头与树；点任务进详情页，在详情页查看子任务树、添加各级子任务。 |
| 助手一次成案 | 用户说"明天下午帮我安排季度复盘"，助手不再追问，直接回复方案"好的，我计划：明天（周五）15:00–16:00 创建日程『季度复盘』，默认 1 小时，可以吗？"并附「就这么办 / 调整一下」；点确认即创建。 |
| 助手长回复可读 | 助手用分点、加粗、代码样式给出操作步骤，消息按 Markdown 排版，链接可直接点开。 |
| 管理账号与偏好 | 抽屉点头像/邮箱进入个人信息页（昵称、邮箱、注册时间）；从"系统设置"关闭农历显示、把默认落地页改成任务页、修改密码或注销账号。 |

## 3. 产品整体说明

### 3.1 产品形态（延续）

- 仍为**移动端 Web（H5）**瘦客户端：工作日历推算、农历换算、循环展开、令牌续期、方案生成等业务逻辑全部在服务端完成，端上仅展示与交互；
- 延续全云端架构：读失败展示错误占位，不使用本地旧数据；端上仅存登录凭证与必要的 UI 状态；
- 账号体系升级为 **access 凭证（2h）+ refresh 凭证（30 天轮转）**，对用户表现为"长时间不掉线"。

### 3.4 双入口关系（延续与加强）

- 法定工作日模式（H-01）在手动表单与 LLM 对话两个入口字段级一致，写同一份 recurrence JSON；
- **农历日程（N-01/5.6）同样双入口对等**：单次农历日期与"每年农历月日"循环在表单与对话中产生同一份公历存储/recurrence JSON，农历换算只在服务端发生；
- 助手的"工作日"口语表达解析为法定工作日模式；"周一到周五"解析为字面星期模式，二者不得混淆；
- 方案优先（A-01）只改变对话的交互编排，工具能力、服务端校验、危险门控、冲突门控与手动入口完全一致；
- 所有助手写操作执行后仍产出云端最新数据卡片，与列表/日历实时一致（沿用既有规则）。

## 4. 功能需求一：法定工作日历（H-01）

### 4.1 数据模型与数据来源

新增迁移 **007**，建工作日历表，只记录**偏离默认周历（周一~周五工作、周六日休息）的特殊日**：

```sql
CREATE TABLE work_calendar_days (
  country        CHAR(2)     NOT NULL DEFAULT 'CN',   -- 本版仅 CN
  day_date       DATE        NOT NULL,                -- 日期
  day_type       VARCHAR(16) NOT NULL,                -- holiday=法定放假 | makeup=调休补班
  holiday_name   VARCHAR(30),                         -- 节假日名称（holiday 时），如「国庆节」
  created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (country, day_date),
  CHECK (day_type IN ('holiday', 'makeup'))
);
```

- **holiday**：放假的日子（含落在工作日上的法定假日与调休连休中的工作日；本来就是周末的日子无需录入）；
- **makeup**：因调休而需要上班的周六、周日；
- 同一日期仅一行；全部语句幂等（`INSERT ... ON CONFLICT DO NOTHING`），后续年份通过追加迁移录入。

**判定函数（服务端单一实现）**：

```
isWorkdayCN(date):
  查 work_calendar_days(CN, date)
    命中 holiday → false
    命中 makeup  → true
    未命中       → 该日为周一至周五
```

**数据来源与更新机制**：

- 以**国务院办公厅每年发布的节假日安排通知**为准手工录入（通常上年 11~12 月发布次年安排）；
- v0.4.0 发布时随迁移 007 种子录入：**2025 全年、2026 全年，以及 2027 年已正式公布的部分**；具体日期以官方公告原文为准，本 PRD 不枚举（实施与测试以官方公告核对）；
- 每年新增一份追加迁移（如 010_work_calendar_2028.sql），不更新应用代码；
- 不做在线抓取、不做管理后台、不做用户自定义假日。

**覆盖范围边界**：

- 循环实例落在已录入年份：严格按法定工作日历；
- 落在尚未公布安排的未来年份：**回退为周一至周五**，规则摘要末尾与系列详情注明"未来年份调休安排公布前按周一至周五计算，公布后自动按法定工作日执行"；回退不报错、不阻断创建；
- 数据一经迁移更新，已有系列的未来实例下次展开时自动采用新数据（实例零物化，天然生效）。

### 4.2 循环规则模型变更

weekly 频率新增 `week_mode` 字段（RRULE 受控子集扩展，jsonb 存储，无表结构变更）：

```json
{ "freq": "weekly", "week_mode": "workdays_cn", "interval": 1, "end_type": "never" }
```

| 字段 | 取值 | 约束 |
| --- | --- | --- |
| `week_mode` | `weekdays`（缺省）/ `workdays_cn` | 仅 weekly 可出现；其他频率携带返回 4011 |
| `by_week_days` | 0~6 数组 | 仅在 `week_mode` 缺省（`weekdays`）时允许；`workdays_cn` 时必须缺省，二者同时出现返回 4011 |

语义：

- **缺省 `week_mode`**：完全等价于 v0.3.0——按 `by_week_days`（或 anchor 星期）展开。存量所有"工作日"快捷系列存的就是 `[1,2,3,4,5]`，**逐实例结果不变，零数据迁移、零语义漂移**；
- **`workdays_cn`**：从 anchor 本地日期起，按**自然日逐日步进**，对每个候选日调用 `isWorkdayCN`，工作日才产生实例，时刻/时长取系列主记录；`interval` 在该模式下语义为"每隔 N 个**工作周**"——为避免歧义，本版规定：`workdays_cn` 模式下 `interval` 仅允许为 1，传 >1 返回 4011 并提示"法定工作日暂不支持隔周"；
- 结束条件沿用：`count`（1..730，按实际产生的实例计数）、`until`（≤ 首次后 5 年）、`never`；
- 90 天循环冲突扫描在新候选生成器上运行，其余流程不变。

### 4.3 表单交互（RepeatSheet）

weekly 区块由"星期多选 chip + 工作日快捷"调整为三个互斥单选项：

1. **每周指定星期**：选中后展开现有星期多选（周一~周日 chip，含 anchor 默认勾选）；
2. **周一至周五**：字面星期，输出 `by_week_days=[1,2,3,4,5]`（与历史"工作日"快捷产生的规则一致）；
3. **工作日（法定）**：输出 `week_mode=workdays_cn`；副文案说明"避开法定节假日，调休补班日照常"。

- 编辑已有系列时按规则回填：有 `week_mode=workdays_cn` 选第 3 项；`by_week_days` 恰为 1~5 选第 2 项；其他选第 1 项；
- 实时摘要见 4.4；其余频率（每天/每月/每年）区块不变；
- 选"工作日（法定）"时若结束条件为 `until` 且跨入未公布年份，预览区显示 4.1 的回退提示。

### 4.4 规则摘要

服务端单点产出，表单/卡片/详情/对话共用：

| 规则 | 摘要示例 |
| --- | --- |
| `workdays_cn` | `每个工作日 09:00–09:30，长期重复`（节假日与补班语义写进系列详情的说明行，不塞进入每段摘要） |
| `[1..5]` 字面 | `每周一、周二、周三、周四、周五 09:00`（保持 v0.3.0 文案不变） |
| 跨入未公布年份 | 系列详情固定说明：`未来年份按官方安排公布后自动更新；公布前按周一至周五计算` |

### 4.5 月历节假日角标

月历日期格在公历数字 + 农历（见第 5 章）之外增加法定状态角标：

| 日期类型 | 角标 | 优先级（与农历同格竞争时） |
| --- | --- | --- |
| holiday（法定放假） | 绿色「休」 | 节假日名称（如"国庆"）> 角标 > 农历 |
| makeup（调休补班） | 红色/橙色「班」 | 「班」角标 > 农历日序 |
| 普通周末 | 无角标（周末本就非工作日，不标） | 农历日序 |

- 角标数据由月聚合接口按"年月"一并下发（见 5.3、11.2），前端不内置假日数据；
- 选中某天时，当日标题条在日期文案旁显示节假日名（如 `今天 周三 · 国庆节`）；
- 折叠态跨月周同样需要邻月角标，沿用 v0.3.0 折叠态跨月按需补齐机制。

### 4.6 LLM 对话能力

| 自然语言 | 解析 |
| --- | --- |
| "每个工作日早上站会""工作日 9 点""上班日提醒我" | `week_mode=workdays_cn` |
| "周一到周五""每周工作日历上的周一三五" | 字面 `by_week_days`（"周一到周五"=`[1..5]`） |
| "国庆后每个工作日……" | 用户需给出明确日期起点（如"10 月 9 日起"）；**用户只说"节后"等模糊时间仍需澄清**（沿用 A-01 硬边界），助手不自行推断官方假日边界 |
| "隔周工作日" | 告知暂不支持，追问是否改为每周 |

- 工具入参 `recurrence` 增加 `week_mode`；系统提示词补充两种工作日的区别、回退规则、不得混用字段；
- 模型回执与卡片一律使用服务端摘要，不得自造节假日日期；
- 方案优先（A-01）适用于本能力：如"帮我安排工作日站会"缺时间时，助手直接给"每个工作日 09:00，长期重复，可以吗？"，而不是追问时间。

### 4.7 异常与边界

| 情况 | 处理 |
| --- | --- |
| 年度数据尚未录入 | 不报错；按周一至周五回退 + 摘要/详情注明；数据补齐后自动生效 |
| `workdays_cn` + `by_week_days` 同传 / 非 weekly 携带 week_mode / interval>1 | 4011 拦截，`details.reason` 指明字段矛盾 |
| 任务日程 | 沿用 v0.2.0：任务日程禁循环（4016），本模式同样不可用 |
| 作用域编辑（仅本次/本次及以后/整条） | 与其他 weekly 系列完全一致；例外按 occurrence_key 覆盖，节假日当天被改成"要上班式安排"时以 override 为准（override 是用户显式行为） |
| 节假日当天恰好是用户显式指定的单次日程 | 不产生任何自动取消；H-01 只影响循环实例的生成，不影响用户已有单次日程 |

## 5. 功能需求二：农历显示与农历日程（N-01）

### 5.1 展示范围

农历分两层：**展示层**（5.1–5.5）与**日程层**（5.6）。展示层农历是只读文案，不写入日程数据；按农历建日程时由服务端换算为公历时刻存储或写进 recurrence 规则后由引擎展开，事件表结构零变更。展示层出现位置：

| 位置 | 展示内容 |
| --- | --- |
| 月历日期格 | 公历数字下一行小字：农历日序（初一～三十）；**初一显示农历月名**（正月、二月……冬月、腊月） |
| 月历日期格（节日/节气） | 命中传统节日或节气时，以节日/节气名替换农历日序（规则见 5.2） |
| 当日标题条 | 选中日文案例行追加：`· 八月十五 中秋节`（普通日仅在有空间时显示农历，不强塞） |
| 日程详情 / 编辑表单 | 日期字段下显示对应农历日（如 `农历 七月廿八`），辅助用户核对 |
| 对话卡片 | 日程卡片的日期行追加农历日（与详情一致） |

明确**不显示**农历的位置：输入类控件（时间选择器仍为公历）、通知（无通知能力）、循环规则摘要（规则仍是公历）。

### 5.2 显示规则与优先级

- 历法范围：**1900-01-31 ～ 2100-12-31**（标准农历表覆盖区间），含闰月；区间外公历日期不显示农历（不留白异常，直接无副字）；
- 同一日期多个标签时，日期格副字只显示一个，优先级：
  **法定节假日名（H-01）＞ 农历传统节日 ＞ 二十四节气 ＞ 农历月名（初一）＞ 农历日序**；
- 农历传统节日（按农历日匹配）：春节（正月初一）、元宵节（正月十五）、二月二（龙抬头）、端午节（五月初五）、七夕（七月初七）、中元节（七月十五）、中秋节（八月十五）、重阳节（九月初九）、腊八节（腊月初八）、小年（腊月廿三/廿四，本版取廿三）、除夕（腊月最后一天，按当年农历表判定，兼容闰月）；
- 二十四节气按节气表显示（从小寒到大寒，节气为太阳历，独立于农历日换算）；**节气显示优先级低于农历传统节日**；
- 日期格空间有限：节日名超过 4 个汉字时允许简称（"中元节"→"中元"、"龙抬头"→"龙抬头"3 字不缩），具体简称表在 UXUI 文档给出；
- 选中态、今天态的视觉强调仍以公历为主标识，农历副字不抢占主字颜色。

### 5.3 服务端实现与接口

- 农历换算与节气计算在**服务端**完成（云架构、双入口一致、前端不内置历法库）；
- 月聚合接口 `GET /events/monthly?year=&month=&tz=` 扩展返回，每日计数对象附带农历与法定信息：

  ```json
  {
    "date": "2026-09-25",
    "normal": 0, "task": 0, "recurring": 1,
    "lunar": { "month_label": "八月", "day_label": "十五", "festival": "中秋节", "term": null },
    "calendar_day": { "type": null, "name": null }
  }
  ```

  非节日/非节气日 `festival`、`term` 为 null；`calendar_day.type` 为 `holiday` / `makeup` / null；
- 新增按日查询（供详情/表单/卡片用）：`GET /events/lunar?date=YYYY-MM-DD` 或在现有日程详情/事件 DTO 上直接附带该日农历字段（二选一，由 SDD 定稿；优先随事件 DTO 附带以减少请求）；
- **新增反向换算（5.6 使用）**：`GET /events/lunar/resolve?lunar_year=&lunar_month=&lunar_day=` 农历→公历，返回该农历日期对应的公历日期、农历月日标签与命中的传统节日名；该接口同时供单次日程表单与 LLM 工具使用，换算逻辑与循环引擎共用同一份服务端实现；
- 性能：农历/节气为纯计算且结果不可变，服务端按年缓存（进程内 LRU，键 `CN-年份`），月聚合接口 P95 较 v0.3.0 退化 ≤ 10ms。

### 5.4 设置开关

- 系统设置（P-01）提供「显示农历」开关，**默认开启**；
- 关闭后：日期格农历副字、节日/节气名、标题条与详情中的农历文案全部隐藏；**法定节假日"休/班"角标与节假日名不受此开关控制**（它们是工作日循环语义的可视化，不是农历内容）；
- 开关即时生效（写入用户设置后重新渲染），不需要重启或重进页面。

### 5.5 异常与边界

| 情况 | 处理 |
| --- | --- |
| 超出农历表范围的日期 | 不显示农历副字，公历与角标正常；不报错 |
| 月聚合拉取失败 | 沿用 v0.3.0 整块错误态；不允许用端上推算补齐（云端架构一致） |
| 农历日与日程标记点竞争 | 标记点位置与角标位置在 UXUI 固定分区，不得互相遮挡（窄格 320px 下允许节日简称） |
| 用户在对话说"农历八月十五" | 走 5.6 日程层：单次/年度循环的判定与换算规则见 5.6.5；助手不得自行心算公历日期，一律经服务端换算后在方案中明示 |

### 5.6 按农历安排日程与年度循环

#### 5.6.1 能力总览

| 能力 | 说明 |
| --- | --- |
| 单次日程按农历日期 | 新建/编辑表单的日期可在「公历 / 农历」间切换；选农历后填农历月日，服务端换算为公历时刻落库；事件仍是普通单次日程，**不持久化农历来源** |
| 年度循环按农历月日 | yearly 规则新增 `by_lunar_month_day`，实例按农历月日逐年换算为公历；公历日期逐年浮动（中秋、除夕、农历生日等） |
| 不支持 | 指定闰月、按节气名循环（清明/冬至）、多个农历月日、农历的每天/每月/每周频率（农历只作用于"每年"） |

#### 5.6.2 单次日程的农历日期

- 日期区提供「公历 / 农历」分段切换（默认公历；编辑已有事件时恒为公历，因为单次事件不保存农历来源，不提供"切回农历"反算）；
- 切到农历后：年份取"开始时间拟落的公历年"（默认当前公历年；用户可在表单上改年份选择器），月份/日期为两个下拉——**正月..腊月、初一..三十**；
- 每次选择变化调用 5.3 的反向换算接口，表单实时显示：`对应公历 2026-09-25（周五）· 中秋节`；正月/腊月可能跨年（如腊月落在次年 1~2 月），以服务端返回的公历日期为准并完整展示；
- **小月回落**：选三十而该农历月仅 29 天时，换算结果为当月最后一天（廿九），表单预览明示"该月为小月，对应廿九"；典型如部分年份的除夕；
- 提交时写公历 `start_at`/`end_at`（日期来自换算，时刻/全天/时长仍由表单侧字段决定），创建/编辑/冲突校验路径与公历单次日程完全一致；表单农历切换态不入库。

#### 5.6.3 年度循环规则模型

yearly 频率新增可选字段，与 v0.3.0 的公历 `by_month_day` **互斥**；两者都缺省时仍回退 anchor 的公历月日（v0.3.0 语义，存量零影响）：

```json
{
  "freq": "yearly",
  "by_lunar_month_day": { "month": 12, "day": 30 },
  "interval": 1,
  "end_type": "never"
}
```

| 字段 | 约束 |
| --- | --- |
| `by_lunar_month_day.month` | 整数 1..12，指农历**正常月**（1=正月 … 12=腊月）；无闰月标记字段，传闰月概念一律 4011 |
| `by_lunar_month_day.day` | 整数 1..30；该农历月为小月（29 天）时落到当月最后一天（廿九） |
| 互斥 | 同一条规则同时出现 `by_month_day` 与 `by_lunar_month_day` → 4011；非 yearly 携带农历字段 → 4011 |
| interval | 1..99，按公历年步进（见下"首次实例"） |
| 结束条件 | count ≤ 730、until ≤ 首次实例后 5 年、never，沿用现有上限；换算结果必须全部落在农历表 1900–2100 内，越界 → 4011 并提示支持范围 |

**实例生成与首次实例（关键语义）**

- 候选公历年序列为 `anchor 公历年 + k × interval`（k=0,1,2,…）；每个候选年内把农历月日换算为公历日期——一个农历月日在一个公历年内唯一出现（如农历腊月落在次年 1~2 月，按该年实际历表解析）；
- **首次实例 = 换算公历日期 ≥ anchor 本地日期的第一个候选**；例：anchor=2026-09-18，规则"农历八月十五"→ 2026-09-25 即首次；规则"农历正月初一"→ 2026 年春节（2026-02-17）已过，首次为 2027 年春节（2027-02-06）；
- `count` 从首次实例起按间隔年计数；时刻/全天/时长一律取系列主记录；
- 闰月年份的处理：正常月份（非闰月）每年都存在，闰月出现不影响正常月的解析，无需特判；
- `occurrence_key`（原始开始时刻）、`event_overrides`、三作用域（仅本次/本次及以后/整条）、90 天冲突扫描、例外迁移全部复用既有机制，仅候选生成器换成农历换算；农历规则不引入任何新表或新列。

#### 5.6.4 表单交互（RepeatSheet yearly 区块）

yearly 区块由 v0.3.0 的"公历月/日双下拉"升级为**三个互斥单选项**：

1. **跟随首次日期（公历）**：缺省形态，等价 v0.2.0 语义；
2. **指定公历月日**：v0.3.0 的 1..12 月 × 1..31 日下拉（月末回落规则不变）；
3. **指定农历月日**：正月..腊月 × 初一..三十下拉；选三十时常驻提示"遇农历小月按当月最后一天（廿九）"。

- 农历模式下实时预览：`每年农历八月十五 18:00–19:00，长期重复（2026 年为公历 9 月 25 日 · 中秋节）`；跨年候选（如正月/腊月）预览同时给出未来 2~3 个实例的公历日期，帮助用户确认换算正确；
- 编辑已有系列时按存在的字段回填对应单选项；
- 校验信息：闰月/节气/多月日的表达不出现在表单（无入口）；与结束条件矛盾、超出 2100 范围按 4011 提示。

#### 5.6.5 LLM 对话能力与摘要

| 自然语言 | 解析 |
| --- | --- |
| "每年农历八月十五家庭聚餐""每年腊月三十回家""农历生日每年提醒" | yearly + `by_lunar_month_day`（腊月三十由引擎按小月回落为除夕当天） |
| "今年农历八月十五提醒我""2026 年重阳节安排体检" | 单次日程：经换算接口得到公历日期后按普通事件创建 |
| 仅说"农历八月十五提醒我"（无今年/每年） | 按方案优先（A-01）默认给**年度循环**方案，方案卡写明近一年对应公历日期与节日名，用户可在"调整一下"中改成仅今年一次，不单独追问 |
| "每年清明回家""每年冬至包饺子" | **节气名不做循环规则**：助手如实说明并给替代方案（如清明固定在公历 4 月 4/5 日，可建议指定公历月日；或先建今年单次），由用户确认 |
| "我今年闰六月生日，每年提醒" | 不支持闰月：说明并建议按正常六月或由用户指定公历/农历正常月日 |
| "每年农历二月二十九" | day=29 合法（农历二月可能是二十九天，正常回落）；模型不得臆造农历三十以外的非法值 |

- `create_event` / `update_event` 工具 recurrence 入参增加 `by_lunar_month_day`；系统提示词补充：农历日期必须经服务端换算、不得心算、小月回落、首次实例"不早于开始日"、闰月与节气边界；
- 规则人话摘要（服务端单点，表单/卡片/详情/对话共用）：
  - 常规：`每年农历八月十五 18:00，长期重复`；
  - 腊月三十：`每年农历腊月三十（除夕，遇小月按廿九）`；其余月三十：`每年农历 X 月三十（遇小月按当月最后一天）`；
  - 系列详情固定说明行：`按农历每年重复，公历日期逐年不同`；
- 对话方案卡与结果卡片中的日期一律带"公历 + 农历 + 节日名"对照，执行后卡片按云端数据刷新。

#### 5.6.6 异常与边界

| 情况 | 处理 |
| --- | --- |
| 农历换算超出 1900–2100 | 循环创建/续期（until）返回 4011 并提示支持范围；单次表单年份选择器不提供越界年份 |
| 农历月 29/30 选择 | 三十在小月自动回落廿九；表单与摘要明示；引擎按年实时判定，无需用户维护 |
| 与公历字段同传 / 非 yearly / 非法月日 | 4011 拦截，`details.reason` 指明 |
| 农历系列的单次改期（this/following） | 允许：override 存的是用户指定的公历时刻，与其他系列一致；后续年份仍按农历规则生成 |
| 农历系列冲突 | 按 90 天窗口换算后公历实例参与扫描，提示与公历系列完全一致（按日期分组） |
| 农历系列任务日程 | 任务日程禁循环（4016）不变，农历模式同样不可用 |

## 6. 功能需求三：主页折叠策略与列表独立滚动（C-01）

### 6.1 智能默认折叠

**规则**：每次进入 `/calendar`（含冷启动、从其他一级页切回）时，按**选中日**（默认今天；`?date=` 透传时为透传日）的日程总数决定初始形态：

| 选中日日程数 | 默认形态 | 理由 |
| --- | --- | --- |
| **≥ 3 项**（含全天日程，不含已取消实例） | **折叠**（周行形态） | 当日安排多，列表优先，日历收成一行仍可按周切换 |
| **< 3 项** | **展开**（整月形态） | 安排少，给月历总览更大空间 |

- 数据依据即当日列表接口返回（与标题条"共 N 项"同源），不为折叠判定新增请求；月计数与当日数据到达后再定型，避免计数闪烁（骨架期保持展开态占位，数据到达一次性定型，无弹动动画）；
- 用户随后手动折叠/展开后，**本次页面停留期间保持用户选择**（切换选中日不重置）；离开 `/calendar` 再进入重新按规则计算（不做跨启动记忆，与 v0.3.0"折叠态纯内存"一致）；
- v0.3.0 的手动折叠开关、周/月切换、跨月补齐、"今天"按钮等交互全部保留，本项只改**初始值**。

### 6.2 滚动模型调整（取代 v0.3.0 整页滚动）

页面改为**固定三段式布局**，只有日程列表区滚动：

```
┌─────────────────────────┐
│ 头部（菜单 年月 ‹ ›）     │  固定
│ 月历（展开 6 行/折叠 1 行）│  固定（高度随形态过渡）
│ 折叠开关条               │  固定
│ 当日标题条（日期/计数/＋） │  固定（不再 sticky，因为页面本身不滚）
├─────────────────────────┤
│ 当日日程列表             │  flex:1，区域内独立滚动
│ （全天分组 + 定时列表）   │
└─────────────────────────┘
```

- 取消 `.month__scroll` 整页滚动容器；头部/月历/开关/标题条不随滚动位移；
- 列表区 `flex: 1; min-height: 0; overflow-y: auto;`，保证在任何机型上至少占约 **38% 视口高度**（月历展开 6 行时）；当月历展开导致列表区不足 38% 时，月历区允许压缩行间距但不出现整页滚动（具体栅格压缩规则由 UXUI 定稿）；
- 列表内部沿用：全天分组置顶、定时按开始时间升序、全量展示（≤200 条）、空态"这天还没有安排"；
- 折叠/展开动画仍 ≤ 250ms，动画期间列表区域高度平滑变化、滚动位置不跳变；
- 宽屏中栏（max-width 480px）策略不变；中栏外页面背景不滚动、无橡皮筋整页回弹（微信 WebView 中需设置容器 `overscroll-behavior` 与高度约束）。

### 6.3 与其他能力的衔接

- H-01/N-01 的角标与农历副字在两种形态下都正常渲染（折叠态跨月补齐沿用 v0.3.0）；

- 设置中的"默认落地页"若为任务页，本规则在用户进入日程页时照常生效。

## 8. 功能需求五：助手"先方案后确认"（A-01）

### 8.1 设计原则

把助手的默认行为从"**缺信息就追问**"改为"**能用合理默认就先成方案，一次确认后执行**"：

1. 用户意图清晰、仅缺少非关键参数时，助手**不再逐问**，而是按 8.2 的默认策略一次性补齐，产出一个完整可执行的方案；
2. 方案以自然语言 + 结构化**方案卡（proposal）**呈现，底部仅两个操作：「就这么办」（主按钮）与「调整一下」（文本按钮，用户也可直接说话修正）；
3. 用户确认前**不执行任何写操作**；用户说"可以/行/就这样/确认"或点按钮后，助手再调用工具执行；
4. 危险操作、冲突、多候选等**硬边界（8.4）**仍必须打断，方案化不绕过任何服务端门控。

### 8.2 默认策略（助手补齐规则）

| 缺失要素 | 默认策略 |
| --- | --- |
| 开始时间（有日期） | 按事项类型取合理时段：会议/工作类 09:00（如下午则 15:00）、吃饭类 12:00/18:00、休息类 21:00；无法归类取当前小时向上取整到整点 |
| 只给开始时间 | 时长默认 1 小时（沿用既有规则），全天表达则全天 |
| 日期模糊但可推断 | "明天/下周一"等相对时间正常解析；无法换算的模糊时间（"节后""有空时"）不猜，走硬边界澄清 |
| 重复结束条件 | 默认"长期重复"（never）；方案中写明，用户可在"调整"中改次数/截止日 |
| 所属清单 | 用户的默认清单；方案中注明清单名 |
| 循环实例作用域修改 | 默认"仅本次"（沿用 v0.2.0 推荐项） |
| 优先级 | 不默认设置（保持无优先级） |
| 多步意图（建任务 + 排期） | 合并为一个方案，分步列出，一次确认 |

方案文本必须把所有"替用户默认了的参数"明示出来（例：`未指定时间，我按 15:00 安排；未指定结束，按长期重复`），用户一眼知道改什么。

### 8.3 交互与协议

- SSE/消息块新增 `proposal` 块：含方案标题、参数摘要列表（结构化字段，含来源标记"你提供的/我补的默认"）、关联操作类型（create_event/update_event/create_task…）；前端渲染为方案卡，「就这么办」回传一条结构化确认消息（等价用户文本"就这么办"），「调整一下」仅把输入框聚焦并预填引导，不发请求；
- 方案卡**不落入 pending_actions、不落库为可执行快照**：它是对话层的确认；用户确认后由模型按方案参数重新调用工具。为防止参数漂移，系统提示词要求确认轮必须逐字复用方案参数；工具执行后照常返回结果卡片，若实际执行与方案不符，用户可立即纠偏（该取舍见第 13 章决议）；
- 方案在以下情况失效：用户改了主意（自然语言修正 → 助手产出新方案卡，旧卡置灰）、涉及的对象在确认前消失（执行时工具返回不存在，助手如实告知并给新方案）；
- 一次对话可以连续出现多个方案卡（用户连续布置多件事），各自独立确认；纯查询类需求（"我今天有什么安排"）不需要方案卡，直接回答。

### 8.4 仍然必须打断的硬边界（方案化不得覆盖）

| 情形 | 行为 |
| --- | --- |
| 对象有 2 个及以上合理候选（同名任务/清单/日程） | 列候选卡片让用户选，禁止替用户挑一个 |
| 关联对象不存在（给任务排期、挂父任务） | 询问"没有找到 X，要顺便创建吗？"，同意后纳入方案 |
| 时间已过（"昨天 15 点"） | 明示时间已过并请确认（沿用现状） |
| 时间无法换算（"节后""找个有空的下午"） | 追问具体时间，不给默认 |
| 删除任务/清单/日程、批量操作、删除整条系列 | 服务端 pending 门控 + 影响范围二次确认（方案确认之后仍会再过一次系统确认，双层保护） |
| 时间冲突 | 先陈述冲突（循环按日期分组），用户明确坚持才执行（沿用现状） |
| 越权/对象不属于本人 | 1004，不猜测 |
| 超出能力（"每年第 N 个周 X"、闰月指定、按节气名循环） | 如实说明，按 5.6.5 给可支持的替代方案 |
| 参数自相矛盾或非法（4011 等） | 说明矛盾点并给修正方案 |

### 8.5 提示词与工具行为调整

- 系统提示词改写总则："先尝试用合理默认构造完整方案；除 8.4 硬边界外，不得对单个非关键参数发起追问；一次对话最多给一个方案卡"；
- 删除/弱化现提示词中"任一缺失即追问"类措辞（保留硬边界条款）；补入 8.2 默认表与"方案参数明示来源"要求；
- 工具定义不变；工具执行结果（need_confirmation / need_conflict_confirmation / clarify_*）的处理不变；
- 空结果与查询类回答保持简短直接，不允许为了"显得周全"而反问。

## 9. 功能需求六：聊天体验升级（M-01、B-02）

### 9.1 M-01 助手消息 Markdown 渲染

**渲染范围（白名单）**：

| 元素 | 用途 |
| --- | --- |
| 标题 h3/h4（###/####） | 分节（h1/h2 不渲染，避免字号失控） |
| 加粗、斜行、`行内代码` | 强调与参数名 |
| 有序/无序列表、嵌套一层 | 步骤、清单（方案卡参数与正文都受益） |
| 代码块（围栏）+ 换行保留 | 规则/命令示例，等宽字体，可整段横向滚动 |
| 引用块 | 备注、注意事项 |
| 链接 | 自动识别与 `[文字](url)`；**仅允许 http/https 协议** |
| 分隔线、换行 | 段落分隔 |

**安全与限制**：

- **原始 HTML 一律不渲染**（按文本转义显示）；不支持图片、表格、自定义链接协议（`javascript:`、`data:` 等一律剥离）；
- 渲染前经白名单净化（选型由 SDD 定稿，等价能力：markdown 解析 + DOMPurify 级白名单），链接统一加 `target="_blank" rel="noopener noreferrer"`；
- **渲染对象仅助手消息**；用户自己发送的消息按纯文本显示（保留原始换行），避免用户输入 HTML 带来的认知与安全问题；
- 历史消息与流式增量复用同一渲染组件：流式期间按增量解析，允许"半截代码块"以未闭合样式安全渲染（代码块未闭合时按代码块样式延续，不裸露符号）；
- 方案卡、任务/日程卡片、澄清块等结构化块不解析 Markdown（其字段为受控短文本）；卡片内标题等字段如含特殊字符按纯文本转义。

### 9.2 B-02 打开聊天页定位修复

**问题根因**：历史渲染后仅在一次 `nextTick` 后滚动，随后卡片云端刷新、图片/换行内容等高图素把容器继续撑高，定位失效；同时内存中保存的滚动位置在重新进入页面时被无条件恢复，导致冷启动也可能停在顶部。

**修复规则**：

1. **冷启动/每次进入 `/chat`**：历史数据渲染并**稳定后**锚定最新消息——`nextTick` 后双 `requestAnimationFrame` 再滚到底，并对消息容器做一次内容高度观测（ResizeObserver，首次高度不再变化后释放），确保异步卡片刷新后仍在底部；
2. **阅读位置仅用于"页内跳转返回"**：从聊天点任务/日程卡片跳详情再返回（同一次应用使用周期内、离开不超过若干分钟）才恢复保存的滚动位置；冷启动、F5/重新打开、从抽屉/FAB 进入一律锚定最新消息；保存位置仅存内存、不持久化；
3. **流式期间**：用户在底部附近（距底 < 120px，沿用现状阈值）时自动跟随新内容；用户主动上翻阅读历史时不强制拉回（沿用现状），新消息到达时底部出现"↓ 新消息"悬浮提示（本项新增，轻量）；
4. 键盘弹起（iOS/微信 WebView）时可视区域变化不把底部输入框与最新消息遮挡，沿用并回归 v0.1.0 软键盘适配；
5. 清除聊天记录后锚定空态引导位，无滚动条异常。

### 10.4 修改密码（P1）

## 11. 缺陷修复、登录态升级与非功能性需求

### 11.1 B-01 普通日程改为重复日程

**根因**：`EventService.update` 仅在 `existing.recurrence && patch.recurrence` 分支把 `recurrence` 拼进 UPDATE 语句；普通日程（`existing.recurrence` 为 NULL）提交规则时不命中任何写入分支，其他字段正常保存，造成"保存成功但重复无效"。

**修复要求**：

1. 新增分支 `!existing.recurrence && patch.recurrence`：`buildRule` 校验通过后把 `recurrence` 写入 SET；**按新建系列同口径做 90 天未来实例冲突扫描**（命中且未确认 → 4009/`need_conflict_confirmation`，确认后带 `confirm_conflict` 重提，与建循环体验一致）；
2. zod 更新入参允许在无规则事件上提交 `recurrence`（校验当前是否人为拦截，一并放开）；事件类型仍受约束：任务日程补挂循环继续返回 4016；
3. 规则写入后该事件即成为系列主记录：月历展开、系列详情、作用域编辑、对话卡片全部按系列工作；原单次时间作为系列 anchor，首次实例语义与"新建循环"完全一致（包括 yearly 指定月日的"不早于开始日"规则）；
4. 反向操作（系列 → 无规则）维持现状拒绝并返回"请使用删除操作移除重复规则"，本版不改；
5. 前端编辑表单修复"非重复事件打开重复开关后规则未随表单提交/被回填逻辑覆盖"的任何同类问题，并回归 v0.2.0/v0.3.0 全部循环编辑用例。

### 11.2 B-03 登录态稳定性升级（access + refresh）

**根因**：access 凭证固定 2h、无续期；过期后首个请求 401，客户端立即清凭证跳登录。用户在连续使用或 WebView 回收返回时被打断。

**凭证模型（迁移 008）**：

```sql
CREATE TABLE refresh_tokens (
  id          BIGSERIAL PRIMARY KEY,
  user_id     INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  token_hash  CHAR(64) NOT NULL UNIQUE,       -- SHA-256(random 48 字节)，只存哈希
  expires_at  TIMESTAMPTZ NOT NULL,           -- 签发后 30 天
  revoked_at  TIMESTAMPTZ,
  replaced_by BIGINT REFERENCES refresh_tokens(id),  -- 轮转链
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_refresh_user ON refresh_tokens(user_id);
```

- **access 凭证**：沿用 JWT，有效期保持 **2h**；
- **refresh 凭证**：不透明随机串，**30 天滑动有效**；每次使用**轮转**（签发新串、旧串写 `revoked_at`+`replaced_by`），旧串重放视为异常（吊销该凭证链，可只记日志不强制踢人，具体由 SDD 定稿）；
- 登录/注册响应增加 `refresh_token`（保留原 `token` 字段放 access，旧版客户端 2h 内仍可用，之后需重新登录一次）。

**接口行为**：

| 接口 | 行为 |
| --- | --- |
| `POST /auth/login`、`/auth/register` | 返回 access + refresh + user |
| `POST /auth/refresh` | body `{refresh_token}`；有效且未过期未吊销 → 轮转返回新的一对凭证；无效/过期/被吊销 → 1002（前端清态跳登录）；接口单独限流（如 10 次/分钟/IP） |
| `POST /auth/logout` | 吊销当前 refresh（access 在 2h 内仍被黑名单即时拦截，沿用现有 jti 黑名单） |
| 注销账号 / 修改密码 | 级联/批量吊销该用户 refresh（改密时当前设备除外，见 10.4） |

**前端策略**：

1. 每次启动/发请求前检查 access 的 JWT `exp`，**剩余有效期 < 10 分钟即静默刷新**；多个并发请求共用同一个刷新 Promise，不重复刷新；
2. 请求进行中收到 401：先尝试一次 refresh 重放原请求，仍 401 才清态跳登录；SSE 对话流遇到 401 走同样的"刷新→重连"，尽量保留用户已输入文本（输入框内容不清空）；
3. 微信 WebView 页面回收后返回：先用 refresh 静默恢复，成功则用户无感知，失败再跳登录；
4. 凭证仍存 localStorage（同源部署现状延续；httpOnly Cookie 方案列为后续演进，本版不做）；
5. 任何情况下"续期失败"必须是**明确的 30 天未使用/已登出/已改密**，不得因服务重启、时间小偏差等误伤——服务端时钟校验保持宽限（jwt `clockTolerance` 30s），并排查确认不存在其他伪 401 来源（错误的 Authorization 头拼接、SSE 重连丢头等），测试期全链路抓验。

### 11.3 性能

- 月聚合附带农历/角标：按年进程内缓存，接口 P95 较 v0.3.0 退化 ≤ 10ms（绝对值仍 ≤ 120ms）；
- 工作日判定为小表主键查询，循环引擎允许按展开年份一次性载入该年记录后内存判定；`workdays_cn` 系列 90 天展开 P95 ≤ 120ms；
- 农历反向换算接口（resolve）为不可变纯计算（按年缓存），P95 ≤ 50ms；`by_lunar_month_day` 系列 90 天展开 P95 ≤ 120ms，跨年候选预览（2~3 个实例）P95 ≤ 80ms；
- `/auth/refresh` P95 ≤ 150ms（含哈希校验与一次 UPDATE/INSERT）；
- 聊天历史首屏（100 条消息量级）渲染完成 + 锚定最新 ≤ 300ms（中端机型）；Markdown 增量解析不阻塞输入（单条消息解析 ≤ 16ms）；
- 智能折叠只复用已有当日数据，不新增请求；折叠/展开动画 ≤ 250ms。

### 11.4 兼容性与无障碍

### 11.5 隐私与安全

## 12. 关键业务流程与验收标准

### 12.1 关键业务流程

**流程一：法定工作日系列创建（对话）**

```
用户："每个工作日早上 9 点提醒我站会，长期重复"
  → 助手方案卡：计划创建「站会」每个工作日（法定工作日历，避开放假、含补班）09:00–09:30，长期重复
    ├─ 调整 → 用户改时间/结束条件 → 新方案卡
    └─ 就这么办 → create_event(recurrence={freq:weekly, week_mode:workdays_cn})
         → 服务端逐日按 isWorkdayCN 展开 + 90 天扫描 → 落库 → 结果卡片（服务端摘要）
  → 国庆假日所在周：仅收假后与补班日有实例；月历对应日期标「休」「班」
```

**流程二：普通日程补挂重复**

```
/calendar/:id（单次日程）→ 编辑 → 重复：每周一 → 保存
  → update 命中「无规则 → 加规则」新分支 → buildRule + 90 天冲突扫描
    ├─ 冲突 → 4009 冲突块 → 用户坚持 → confirm_conflict 重提 → 规则写入
    └─ 无冲突 → 直接写入 → 返回系列 DTO → 月历出现后续实例
```

**流程三：智能折叠与独立滚动**

```
进入 /calendar（选中日=今天，6 项）
  → 骨架期展开占位 → 当日数据到达 → 一次性定型为折叠（无弹动）
  → 头部/月历/标题固定不动，列表区独立滚动看完 6 项
  → 手动展开 → 本次停留保持展开；切走到任务页再回来 → 重新按当日条数定型
```

**流程四：静默续期**

```
access 剩余 <10 分钟 → 下次请求前 POST /auth/refresh（并发请求合并）
  → 拿到新 access + 轮转 refresh → 原请求照常发出，用户无感知
  → refresh 也失败（30 天未用/已改密）→ 清态跳登录（保留当前路由，登录后回到原页）
```

**流程五：助手成案与硬边界**

```
"明天下午安排季度复盘" → 方案卡（15:00–16:00，默认清单，明示默认来源）→ 一次确认 → 创建
"把周报删了"           → 命中两个同名任务 → 候选卡（硬边界，不替选）
"把这周的会都改时间"   → 危险/批量 → 方案后仍走 pending 影响范围确认
```

**流程六：个人信息与设置**

```
抽屉 → 账号区 → /me（邮箱、注册时间、改昵称）→ 设置齿轮 → /settings
  → 关闭农历 → 开关即保存 → 返回主页农历副字消失（休/班角标仍在）
  → 默认启动页改「任务」→ 下次登录落 /tasks
```

**流程七：农历年度循环（除夕回家）**

```
用户："每年农历腊月三十提醒我回家吃年夜饭"
  → 助手不心算：经服务端换算近一年公历日期
  → 方案卡：每年农历腊月三十（除夕，遇小月按廿九），2027 年对应公历 2 月 5 日，全天
    ├─ 调整 → 改时刻/改成仅今年 → 新方案卡
    └─ 就这么办 → create_event(recurrence={freq:yearly, by_lunar_month_day:{month:12,day:30}})
         → 引擎按农历逐年换算（小月年份自动落廿九）+ 90 天冲突扫描 → 落库
         → 结果卡片日期带「公历 + 农历 + 除夕」对照；月历对应公历日期出现实例
手动：新建日程 → 日期区切「农历」建单次；或重复设置 → 每年 → 指定农历月日
```

### 12.2 验收标准

**H-01 法定工作日历**

1. 迁移后 `work_calendar_days` 含已公布年度数据且可重复执行；2025/2026 调休安排抽样核对与国务院公告 100% 一致；
2. `workdays_cn` 系列在法定假日当天无实例、调休补班周末有实例、普通周一~五有实例、普通周末无实例；跨入未公布年份按周一~五回退且摘要注明；
3. 存量 `[1..5]` 系列展开逐实例不变；表单三选一互斥、回填正确；非法组合（week_mode+by_week_days、interval>1、非 weekly）100% 返回 4011；
4. 月历"休/班"角标与节假日名正确，折叠跨月补齐正确；
5. 对话"工作日/上班日"与"周一到周五"解析 100% 落到不同模式，回执用服务端摘要；三作用域编辑、冲突扫描、例外覆盖不回归。

**N-01 农历显示与农历日程**

6. 1900–2100 区间内抽样日期（含闰月、除夕、月末）农历换算正确；传统节日与节气名按优先级显示；区间外无副字无报错；
7. 农历出现在月格、标题、详情、对话卡片四处，开关关闭后全站隐藏但休/班角标保留；
8. 月聚合接口性能达标（11.3），农历随接口下发、前端无历法数据；
9. **单次农历日期**：表单公历/农历切换正常，正月..腊月 × 初一..三十换算结果（含正月/腊月跨年、三十遇小月落廿九）与权威历表一致；提交后事件以公历存储、冲突/编辑路径与公历事件一致；
10. **农历年度循环**：抽样验证"农历八月十五""腊月三十（含小月年份落廿九）""正月初一（本年已过→次年）"的逐年实例公历日期与首次实例语义正确；闰月年份正常月不受影响；
11. 农历规则非法组合 100% 返回 4011（与 by_month_day 同传、非 yearly、月日越界、超 2100）；对话"每年农历 X/今年农历 X/裸农历日期/节气名/闰月"按 5.6.5 分流正确且不心算日期；三作用域编辑、90 天冲突扫描、例外覆盖、任务日程 4016 在农历系列上不回归。

**C-01 主页布局**

12. 进入主页选中日 ≥3 项默认折叠、<3 项默认展开；定型无弹动；手动切换后本次停留保持、重进重算；
13. 页面仅列表区滚动：头部/月历/标题固定；列表区最小占视口 ≥38%；无整页橡皮筋滚动；微信 WebView 软键盘不遮挡输入与最新内容。

**T-01 子任务收敛**

14. 任务首页无展开箭头、无子树、无行内"添加子任务"，根任务行显示只读进度摘要且点击统一进详情；
15. 子任务树与各级添加仅在详情页可用；搜索仍可命中子任务并直达其详情；对话创建层级能力与 4013/4014/4015 校验不回归。

**A-01 方案优先**

**M-01 Markdown / B-02 定位**

**B-01 补挂规则**

**B-03 登录态**

22. access 过期前自动静默刷新，并发不重复刷新；401 自动续期重放成功；SSE 401 可刷新重连且输入文本不丢；refresh 失效才跳登录并回跳原页；

**P-01 个人信息与设置**

26. 未知设置键 1001；所有新接口鉴权与归属校验正确。

**非功能**
