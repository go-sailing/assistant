## 1. 设计目标与原则

### 1.1 设计目标

1. **中国日历一眼可读**：在一个日期格内同时承载公历、农历、节假日名/节气、"休/班"角标，拥挤但不混乱，主次严格分层；
2. **日历与列表同屏可用**：取消整页滚动，月历与当日列表永远同时在屏；初始折叠/展开由数据替用户决定，用户手动选择后本次停留不再被打断；
3. **助手一次成案**：把"逐条追问"改成"一张方案卡 + 两个按钮"，默认值来源透明（你提供的 / 我补的），长回复用 Markdown 排版可读；
4. **登录无感知**：续期过程零界面、零打断；只有真实失效才回登录页，并回到原页面；
5. **任务列表回归扁平**：首页只讲"有哪些根任务"，层级管理全部收进详情页；
6. **账号设置可发现、可退出**：抽屉账号区可点进个人信息，设置项少而完整，不放假入口。

### 1.2 设计原则（v0.4.0 新增/强化）

| 原则 | 说明 |
| --- | --- |
| **一格一主字** | 日期格公历数字永远是视觉主体；农历/节日/角标全部是从属信息，字号、颜色、位置不得与主字竞争 |
| **状态替代提问** | 能用数据直接决定的（折叠/展开、默认时间、默认清单），不要问用户；替用户做的决定必须在方案或界面上可被发现、可改回 |
| **固定优先于跟随** | 高频参照信息（月历、标题条）固定，只有内容区滚动；避免参照系随手指丢失 |
| **确认不超过一次** | 每个写意图最多一次主动确认（方案卡）；危险操作的系统强制确认不计在内，但两层确认的文案必须各自说清自己在保护什么 |
| **静默不代表隐藏** | 静默续期不弹窗；但"30 天未使用需重新登录"等规则在设置页可查；失败时文案准确，不出现笼统的"登录失效" |
| **同语义同入口** | 公历/农历建日程、工作日两种模式、助手/手动两入口，同一份数据用同一套表单结构与预览样式 |
| **短文本防错** | 农历、法定日历的换算结果必须在提交前以"公历对照"明示，不让用户为历法换算承担心智负担 |

## 4. 核心用户流程（UX Flow）

### 4.1 安排"每个工作日站会"（法定工作日模式）

```
新建日程 → 标题"站会" 09:00
  → 打开重复设置
     ○ 每周指定星期
     ● 周一至周五
     ○ 工作日（法定）  副文案：避开法定节假日，调休补班日照常
  → 选「工作日（法定）」
  → 实时摘要：每个工作日 09:00–09:30，长期重复
  →（until 跨入未公布年份时）预览区黄字提示：
     2028 年安排公布前按周一至周五计算，公布后自动按法定工作日执行
  → 保存
```

- 表单上不出现"节假日列表"等维护概念，用户只需选择模式；
- 保存后月历上 10 月 1~7 日的实例自然缺失、对应日期显示绿"休"，调休周日显示橙"班"且有实例。

### 4.2 创建"每年农历腊月三十回家"（农历年度循环）

```
新建日程 → 日期区
  [公历|农历] 分段控件 → 切「农历」（仅新建单次时用于单次日期）
  重复：每年 → 每年重复于
     ○ 跟随首次日期（公历）
     ○ 指定公历月日
     ● 指定农历月日   [腊月 ▾] [三十 ▾]
  → 常驻提示：遇农历小月按当月最后一天（廿九）
  → 预览区：
      每年农历腊月三十（除夕，遇小月按廿九）
      · 2027 年 公历 2 月 5 日（周五）· 除夕
      · 2028 年 公历 1 月 25 日（周二）· 除夕
      · 2029 年 公历 2 月 12 日（周一）· 除夕
  → 保存
```

- 对话路径：助手直接给方案卡，卡内同样列"公历 + 农历 + 节日名"对照（见 4.6）。

### 4.3 进入主页：智能定型与独立滚动

```
冷启动 /calendar（骨架期：日历展开占位，不闪）
  → 当日数据到达
     ├─ 今天 6 项（≥3）→ 日历一次性收到折叠态（无高度弹动），列表区占主要高度
     └─ 今天 1 项（<3）→ 保持展开态
  → 用户在列表区内上下滑动：头部/月历/标题条不动
  → 用户手动展开 → 本次停留不再被自动改回；切去任务页再回来 → 重新按条数定型
```

### 4.4 任务列表到子任务

```
/tasks：每行一条根任务（标题、优先级、右侧"2/5"只读摘要、chevron）
  → 点行 → /tasks/:id
     → 子任务分区：树（可展开各级）、进度条、面包屑
     → 当前任务子树底部「＋ 添加子任务」
     → 想给孙任务加下级：点孙任务行 → 孙任务详情 → 再添加
```

### 4.5 聊天：打开即最新、Markdown、新消息提示

```
点 FAB → /chat
  → 历史渲染（双 rAF + 高度观测）→ 稳定后锚定最新一条，输入框立即可用
  → 助手回复含标题/加粗/列表/代码：气泡内按 Markdown 排版
  → 用户上翻看历史时新消息到达：不强制拉回，底部出现「↓ 新消息」胶囊
  → 点胶囊 / 滚回底部 → 胶囊消失
```

### 4.6 助手方案化（缺时间的建日程请求）

```
用户："明天下午帮我安排季度复盘"
  →（无追问）助手气泡：好的，我计划：
  ┌─ 方案卡 ──────────────────────────┐
  │ 📅 创建日程                        │
  │ 标题      季度复盘                 │
  │ 时间      明天（9/19 周五）15:00–16:00  │ 标记：我补的默认
  │ 重复      不重复                   │ 标记：我补的默认
  │ 清单/归属  （任务无）              │
  │ ──────────────────────────────── │
  │ 未指定具体时间，我按 15:00 安排    │
  │ [ 就这么办 ]   调整一下            │
  └──────────────────────────────────┘
  →「就这么办」→ 卡态变为执行中（按钮禁用 + loading）→ 结果卡片接续
  →「调整一下」→ 输入框聚焦，占位"把要改的地方告诉我，如：改成 16 点、要每周重复"
```

### 4.7 登录态静默续期

```
用户连续使用第 2 小时（access 剩余 <10min）
  → 下一次请求前后台 POST /auth/refresh：界面无任何变化
  → WebView 被系统回收，2 小时后用户切回
     → refresh 有效：静默恢复页面与输入草稿，无登录页
     → refresh 失效（30 天未用/已改密）：登录页，顶部说明"登录已过期，请重新登录"，
       登录成功后回到原目标页（redirect 回跳）
```

### 4.8 个人信息与设置

```
抽屉账号区 → /me：头像、昵称（可改）、邮箱、注册时间、修改密码、危险区
齿轮 → /settings：
  显示农历              [开]
  二十四节气            [开]（农历关时禁用置灰）
  默认启动页  [ 日程 ▾ ]
  ────────
  清除聊天记录
  修改密码
  关于            个人助手 v0.4.0  ›
  ────────
  退出登录（红）
  注销账号（红）
```

布局规则：

| 规则 | 规格 |
| --- | --- |
| 页面容器 | `height:100dvh; display:flex; flex-direction:column; overflow:hidden;`（禁止整页滚动/橡皮筋） |
| ① 头部 | 固定高 44pt，不再随滚动位移（与 v0.3.0 不同） |
| ② 月历区 | flex none；展开 6 行、折叠 1 行；高度过渡 250ms；展开时若竖向空间不足，行间距压缩（下限见 6.2），但**不挤占列表区低于 38% 视口高**——触达下限时月格启用 `aspect-ratio` 收缩而非页面滚动 |
| ③ 开关条 | 沿用 v0.3.0 控件；位置始终在月历下沿 |
| ④ 标题条 | 固定高 44pt；白底 + 底部 1pt 分隔（不再需要 sticky） |
| ⑤ 列表区 | `flex:1 1 auto; min-height:0; overflow-y:auto; overscroll-behavior:contain;`；最小高 = 38vh；内边距沿用 |
| 安全区 | 底部 `padding-bottom: safe-area-inset`；FAB 相对视口定位不变 |
| 微信 WebView | 软键盘顶起时仅压缩整页高度（dvh 自适应），列表区滚动位置与输入不受影响 |

智能定型时序：

1. 挂载：骨架期日历以**展开态**渲染占位（月格骨架 6 行），列表 3 行骨架；
2. 当日列表与计数返回后：一次性设置形态（≥3→折叠、<3→展开）；**不允许先展开再收起的弹动**——数据未到达期间不响应用户对形态的视觉预期（开关条在骨架期隐藏，数据到达后淡入）；
3. 本次停留期间手动切换优先；切走（路由离开 /calendar）销毁状态，重进重算；
4. 计数与列表口径同源：以当日 list 返回条数为准（含全天、不含已取消实例），与标题条"共 N 项"一致。

### 5.2 日期格增强：农历副字与"休/班"角标

**单格解剖（375pt 标准格 ≈ 47pt 宽）**

```
┌──────────────┐

└──────────────┘
```

- **主字**：公历数字，16pt，`--text-primary`；今天/选中/邻月态沿用 v0.3.0；
- **副字行**（仅一行，按优先级只出一个内容）：

| 优先级 | 内容 | 颜色 |
| --- | --- | --- |
| 1 | 法定节假日名（国庆、春节…，≤2 字简称优先：国庆节→"国庆"） | `--color-holiday`（绿） |
| 2 | 农历传统节日名（中秋、端午…；中元节→"中元"） | `--color-festival`（红/玫） |
| 3 | 二十四节气名（白露、秋分…） | `--color-term`（赭/橙） |
| 4 | 农历月名：初一显示"正月/二月…/腊月" | `--text-secondary` |
| 5 | 农历日序：初二…三十（廿三、卅） | `--text-secondary` |

- **角标**（独立行，与副字行可并存）：

| 类型 | 样式 |
| --- | --- |
| holiday | 12×12pt 圆角 2pt 绿底白字「休」（10pt 字），贴格左上角 |
| makeup | 同样式橙红底「班」 |
| 普通周末 | 无角标 |

- 非节假日/非节气日：副字行显示农历月名或日序；设置关闭农历后副字行整体隐藏（**角标保留**），格内容垂直居中微调；

- 折叠周行使用完全相同的格结构（含邻月补位格的副字与角标）；
- 320px 窄屏：节日名最多 2 字、农历日序最多 3 字（"廿三"2 字），不换行不截断主字。

标题条农历/节日追加：`今天 周四 · 国庆节`（有法定假日名时追加，分隔点 secondary）；普通日不追加农历（避免标题冗长）。

## 7. 关键交互细则

### 7.1 智能定型与形态稳定

1. 形态只由"进入瞬间的选中日条数"决定一次；本次停留期间只有用户手动能改；
2. 骨架期开关条隐藏，避免用户在数据到达前点到一个会被立刻改掉的形态；
3. 选中日切换（点格/翻周）**不**重新定型——否则用户展开看月历时，点到一个 ≥3 项的日子日历会突然收起；
4. 列表条数在停留期间从 2 变成 4（他端新增）也不重定型；
5. 形态不持久化（内存态随路由离开销毁），与 v0.3.0 折叠态存储策略一致。

### 7.2 独立滚动防穿透

1. 列表区滚到顶/底不带动整页（`overscroll-behavior:contain` + 容器固定高）；
2. 月历区不接收纵向滚动手势；横滑翻月/翻周只在月历区生效，列表区横滑不触发；
3. iOS 微信 WebView 键盘弹起时以 `100dvh` 收缩，输入框（弹层/表单）不被遮挡；
4. 从详情返回恢复列表滚动位置（仅列表容器的 scrollTop），月历形态与选中日恢复内存态。

### 7.3 农历/法定信息防错

1. 任何农历输入在保存前必有公历对照（表单预览行、方案卡、结果卡三处一致）；
2. 换算服务失败时禁止保存农历规则/日期，宁停不猜；
3. 角标与副字只来自接口，端上不内置任何历法/假日数据；
4. 农历开关关闭只隐农历，不隐休/班——视觉上要能看出两者独立（开关分组名"显示与历法"下只有农历与节气两项）。

### 7.4 方案卡确认流

1. 同一消息流中可有多张未决方案卡（用户连下两单），各自独立确认，按钮互不影响；
2. 执行中卡禁止重复点按（防双创建）；执行失败卡回到 proposal 态并显示错误行，可再次确认或调整；
3. 「就这么办」发送的确认消息在消息流中显示为用户气泡"就这么办"（与纯文本体验一致）；
4. 纯查询不出现方案卡；方案卡不替代危险操作的系统 ConfirmBar（双层时先方案、后系统确认，中间有明确衔接文案，如"该操作会删除 3 个任务，请再次确认"）。

### 7.5 Markdown 流式与安全

1. 增量到达即重解析当前气泡（单条 ≤16ms）；未闭合代码块/引用按闭合态延续；
2. 链接仅 http/https，新页打开；长按不弹"复制图片"等不存在元素的菜单；
3. 历史消息回填一次性渲染，不出现"先纯文本后跳版"（v-if 渲染时机：内容到达即 MarkdownText，无降级闪烁）。

### 7.6 聊天定位精确规则

1. 冷启动/抽屉进入/FAB 进入/登录回跳：一律锚定最新；锚定时机：数据渲染 → nextTick → 双 rAF → ResizeObserver 首次稳定（高度 300ms 内不再变化即释放）；
2. 仅"消息流内卡片/链接跳详情再返回"恢复 scrollTop（内存、5 分钟内有效）；
3. 流式自动跟随阈值：距底 <120px；跟随用 `behavior:auto`（瞬时），点新消息胶囊用 smooth；
4. 清除记录后锚定空态引导区。

### 7.7 续期交互边界

1. 刷新中并发请求共用等待（界面无 loading 遮罩——用户不应感知到刷新存在）；
2. 仅当 refresh 也失败才出现登录页与提示条；
3. 主动退出、改密他端失效、注销三类跳转不带"登录已过期"提示（语义不同：退出是用户主动行为）。

### 7.8 层级入口（延续 v0.3.0 防误触）

- 任务首页不再有任何层级控件；详情页 Composer 热区与勾选/行点击间距沿用 8pt 分隔规则；第 5 级置灰说明位置不变。

## 8. 可访问性（A11y，增量）

| 对象 | 要求 |
| --- | --- |
| 日期格 | 整体 `role="button"`、`aria-label` 完整朗读：`2026 年 9 月 25 日，周五，农历八月十五，中秋节，法定放假日，3 个日程`；视觉副字仅作增强 |
| 休/班角标 | 不单独进可聚焦序列（信息已在格 aria-label 中）；`aria-hidden="true"` |
| 折叠开关 | 沿用 `aria-expanded`；label："折叠月历，只看本周"/"展开月历"；智能定型变化时不发 live 公告（避免刷屏），手动操作公告"月历已折叠/展开"（polite） |
| Radio 组（工作日/年规则） | `role=radiogroup` + 组标签；从属 chips/下拉禁用态 `aria-disabled` |
| 农历下拉 | label"农历月份/农历日期"；换算结果行 `aria-live="polite"`（读屏朗读公历对照） |
| 方案卡 | 卡 `role="group"` + 名称；「就这么办」为主按钮；执行中 `aria-busy="true"`；默认参数在朗读中加"默认"前缀 |
| 新消息胶囊 | 按钮 label"有新消息，跳到最新" |
| Markdown | 标题、列表输出语义标签；链接可读 URL 标题；代码块 `role="code"` |
| Switch | `role="switch"` + `aria-checked`；禁用（节气随农历）时说明原因 |
| /me、/settings | 标准导航标题；只读行无按钮角色；危险操作与正常项分组隔离 |
| 对比度 | 新增语义色按 6.1 标准；农历副字在选中/今天反白底上走查 |
| 动效 | 方案卡/折叠/胶囊均尊重 reduced-motion |
