## 1. 设计概述

### 1.1 系统边界（增量）

v0.4.0 在不改变"模块化单体 + 全云端 + SSE 函数调用"总体形态的前提下，新增/改动五条技术线：

1. **历法与法定日历域（新建服务端模块）**
   - `lunar` 服务：公历↔农历换算、农历传统节日、二十四节气（1900–2100）；
   - `work_calendar` 域：`work_calendar_days` 表 + `isWorkdayCN` 判定 + 年度缓存；
   - 循环引擎扩展两类候选生成器：weekly `week_mode=workdays_cn`、yearly `by_lunar_month_day`。
2. **鉴权域升级**：access JWT（2h，沿用）+ refresh 不透明令牌（30 天轮转，只存哈希）；新增 `/auth/refresh`、`/auth/change-password`；前端静默刷新与 401 重放。
3. **账号设置域（新模块）**：users 增 `nickname`；`user_settings` 单行 jsonb；`/me`、`/settings` 接口。
4. **助手对话协议扩展**：新增"前端呈现型工具" `present_proposal` 与 SSE/消息块 `proposal`；系统提示词方案化改造；消息气泡白名单 Markdown 渲染。
5. **前端结构改造**：MonthView 三段固定布局 + 智能定型；任务首页去树；ChatView 锚定修复；新增 `/me`、`/settings` 页面。

不在本期：httpOnly Cookie、节假日后台、多地区历法、农历闰月/节气规则（PRD 1.3）。

### 1.2 设计目标与手段

| 目标 | 手段 |
| --- | --- |
| 存量规则零漂移 | 新模式全部为**新增字段**（`week_mode`、`by_lunar_month_day`），缺省即旧语义；normalizeRule 白名单扩展但不动旧分支 |
| 历法可信、端上零数据 | 引入 `lunar-javascript`（数据型纯 JS 库）并收敛在单一 wrapper 内；换算结果随既有接口下发；对库做权威历表对照测试 |
| 假日数据可审计 | 迁移 007 种子 SQL 逐条带节假日名注释、注明文号（国办发明电〔2025〕7 号等）；追加年度只加迁移文件 |
| 登录续期对用户透明 | refresh 轮转单事务完成；前端单飞（single-flight）刷新；只有 refresh 失败才跳登录 |
| 方案化不绕过任何门控 | proposal 是**呈现层工具**，无副作用、不落 pending；真正执行仍走既有工具与 need_confirmation/conflict/clarify 门控 |
| 模型输出可安全渲染 | markdown-it + DOMPurify 白名单，禁原始 HTML/图片/非 http(s) 链接 |
| 缺陷修复最小侵入 | B-01 仅在 EventService.update 增加"无规则→有规则"分支；B-02 仅改锚定时序与位置恢复语义 |

### 3.3 RepeatSheet：双三选一与农历预览

- weekly 区块：`weekMode: 'custom'|'weekdays'|'workdays_cn'`（'custom'=显式 by_week_days；`weekdays` 提交 `[1..5]` 且不带 week_mode，保证存量语义）。`buildRule()` 分支：
  - custom → `by_week_days:[…]`；
  - weekdays → `by_week_days:[1,2,3,4,5]`；

### 3.9 鉴权：静默刷新与 401 重放

token.ts：

```ts
const ACCESS_KEY='pa_token'; const REFRESH_KEY='pa_refresh'
export const getAccess/getRefresh/setTokens/clearAuth …
export function accessExpiringSoon(skewSec=600){ 解析 JWT exp → Date.now()/1000 + skewSec > exp }
```

api/client.ts：

```ts
let inflightRefresh: Promise<boolean> | null = null   // 单飞
async function ensureFresh(){
  if (!accessExpiringSoon()) return true
  return (inflightRefresh ??= refreshPair().finally(()=>{inflightRefresh=null}))
}
request 包装：await ensureFresh() → fetch
  └ 401 → 仅重试一次：await refreshPair() 成功则重放原请求；失败 → unauthorizedHandler
unauthorizedHandler（main.ts）：router.replace({path:'/login', query:{redirect: 当前fullPath}})
```

- 并发：多个请求同时命中过期阈值共用一个 inflightRefresh；
- chat store 的 SSE fetch：响应 401 时同样 `ensureRefresh→重连`，输入草稿在组件本地不清；
- router 守卫改 async：无 access 但有 refresh → `await authStore.bootstrap()`（refreshPair + getMe）成功后放行；
- 登录成功落地页：authStore.homeRoute（settings），默认 `/calendar`。

## 4. 后端模块设计：历法、法定工作日与循环引擎

### 4.1 lunar.service.ts（历法 wrapper）

隔离第三方库的唯一模块，其余后端代码只依赖这里的接口：

```ts
export interface LunarDayInfo {
  month_label: string;   // '正月'..'腊月'
  day_label: string;     // '初一'..'三十'（初一返回月名，调用方按优先级决定展示）
  festival: string|null; // 农历传统节日名（白名单 11 个）
  term: string|null;     // 二十四节气名
}
// 公历 → 农历（月聚合/详情/卡片用）
export function solarToLunar(date: string /* YYYY-MM-DD */): LunarDayInfo
// 农历 → 公历（表单 resolve、引擎 yearly 用）
export function lunarToSolar(lunarYear:number, lunarMonth:number, lunarDay:number): {
  gregorian_date: string; weekday:number;           // 0=周日
  clamped: boolean;                                  // 三十遇小月回落廿九=true
  month_label:string; day_label:string; festival:string|null; term:string|null;
}
```

实现要点（基于 `lunar-javascript`）：

- `Solar.fromYmd(y,m,d).getLunar()` 取 `getMonthInChinese()/getDayInChinese()`；
- 节日白名单在 wrapper 内维护映射（不直接透出库的全部节日，避免"植树节"等非约定名称进入 UI）：春节/元宵/二月二/端午/七夕/中元/中秋/重阳/腊八/小年（腊月廿三）/除夕；除夕 = `Lunar.fromYmd(y,12, getMonthDays(y,12))` 的日，逐日比对；
- 节气：按年惰性预计算 24 节气 Map（库的 `LunarYear`/`JieQiTable` 能力），键为公历日期；
- `lunarToSolar`：`days = LunarMonth.fromYm(y,n).getDayCount()`；`effectiveDay=min(day,days)`（clamped 标记）；再 `Lunar.fromYmd(y,n,effectiveDay).getSolar()`；
- 范围守卫：仅支持 1900-01-31..2100-12-31，越界抛 `AppError.paramInvalid`（4011 由 validateRule 映射；resolve 接口直接 1001）；
- 纯函数无 I/O，年度 Map 进程内缓存（≤201 年，内存可忽略）。

### 4.2 workday.service.ts


**（a）yearly 农历分支**（cycleCandidates 内）：

### 5.1 refresh 令牌轮转（auth.service.ts）

```ts
// 签发
function generateRefresh(): string { return crypto.randomBytes(48).toString('hex') }
function sha256(s:string){ createHash('sha256').update(s).digest('hex') }

async function issuePair(userId:number) {
  const raw = generateRefresh()
  await query(`INSERT INTO refresh_tokens(user_id,token_hash,expires_at)
               VALUES ($1,$2, now() + ($3 || ' days')::interval)`,
    [userId, sha256(raw), config.refreshTtlDays])
  return { access: issueToken(...), refresh: raw }
}

// 轮转（单事务）
async rotateRefresh(raw:string) {
  const hash = sha256(raw)
  withTransaction:
    SELECT … FROM refresh_tokens WHERE token_hash=$1 FOR UPDATE
    不存在 → throw unauthorized(1002)
    expires_at < now() / revoked_at not null →
        重放分支：若 revoked 且 replaced_by 非空 → 吊销该用户全部活跃 refresh（防盗用）→ 1002
    INSERT new row; UPDATE old SET revoked_at=now(), replaced_by=new.id
  return issuePair(user_id)
}
```

- login/register：返回体增加 `refresh_token`，保留 `token`（access）；
- logout：除既有 access jti 黑名额外，若 body 带 refresh_token 则一并吊销；
- deleteAccount：`DELETE FROM users` 级联清 refresh_tokens（外键 ON DELETE CASCADE）；
- `/auth/refresh` 独立限流（10 次/分钟/IP，配置项）；
- JWT 校验放宽时钟容忍：jsonwebtften `clockTolerance: 30`（消除服务间小偏差导致的伪 401）。

### 5.2 /me 与 settings（settings 模块）

- `getMe(userId)`：users 行 + 计算 `avatar_initial`（nickname 首字，空则邮箱首字母大写）+ created_at（YYYY-MM-DD）；
- `updateNickname`：null 或 1..20 字符（trim；空白串视为 null）；
- `getSettings`：读 user_settings.payload（无行返回默认），与默认对象深合并：

### 5.3 changePassword（P1）

单事务：bcrypt 校验旧密码（失败 2001 统一文案）→ 新密码强度复用 `validatePassword` → 更新 password_hash → `UPDATE refresh_tokens SET revoked_at=now() WHERE user_id=$1`（**先吊销全部**刷新凭证，避免任何旧串残留）→ 在同一事务内为当前设备 `issuePair` 并随响应返回 `{ token, refresh_token }`。前端用响应中的新对覆盖本地凭证，本端不掉线；其他设备的旧 refresh 再来即 1002（且因旧串已 revoked，命中重放保护日志）。

### 7.2 SSE proposal 块协议

## 8. 关键时序

### 8.1 workdays_cn 系列创建与展开

```
客户端 → POST /events {start_at, recurrence:{freq:'weekly',week_mode:'workdays_cn',end_type:'never'}}
  schema.parse → buildRule/validateRule（互斥/interval=1）
  → scanSeriesConflicts：预取窗口年份 special-day Map → workdaySeedStream 生成 → 相交检测
  → 无 confirm 且无冲突：INSERT events(recurrence)
  → 读（monthly/list）：listSeriesInstances 同一 stream 展开归并；10-1~10-7 无实例、9-28(补班)有实例
```

### 8.2 农历年度循环

```
RepeatSheet（yearMode=lunar）→ GET /events/lunar/resolve?lunar_year=2026&month=12&day=30&n=3
  → lunarToSolar 逐年换算（小月 clamped）→ [{2027-02-05 除夕},{2028-01-25 除夕},{2029-02-12 除夕}]
保存 → buildRule（1900–2100 校验）→ INSERT recurrence={freq:'yearly',by_lunar_month_day:{12,30}}
展开：cycleCandidates yearly 农历分支 → key=公历实例时刻 → override/作用域机制不变
```

### 8.3 普通日程补挂重复（B-01）

```
PATCH /events/:id {recurrence:{…}, confirm_conflict?}
  existing.recurrence 为 null 且 patch.recurrence 存在
  → buildRule → scanSeriesConflicts（90 天）
      命中且未 confirm → 4009 + 冲突分组（前端 ConflictSheet）→ 带 confirm_conflict 重提
  → UPDATE SET recurrence=$j → 返回系列 DTO（含 first_occurrence_at / recurrence_note）
```

### 8.4 静默续期与 401 重放

```
请求前：exp-skew≤0 → 单飞 POST /auth/refresh（事务：验旧→插新→废旧）→ 200 新对
并行请求共享同一 Promise；拿到后原请求照发
请求中 401：refreshPair 一次 → 成功重放原请求（用户无感）；失败 → 清凭证 → /login?redirect=…
SSE：fetch 返回 401 → 不弹错 → refreshPair → 重连（resume：last_event_id 沿用现有断线续传）
```

### 8.5 助手方案卡

```
用户文本 → LLM（工具全集含 present_proposal）
  → toolCall(present_proposal) → 编排器：不落业务库、不调真实工具
     SSE proposal 块 → 前端渲染 ProposalCard（pending）→ 本轮结束
用户「就这么办」→ 普通用户消息入历史 → LLM 按方案参数调 create_event…
  → 既有门控（4009/4010/clarify）照常 → SSE 结果 cards → 旧卡置 done
用户改口 → 新 proposal 块；旧卡 superseded
```

### 8.6 主页智能定型

```
进入 /calendar → 骨架（展开占位，开关隐藏）
 并行：day list + monthly（含 lunar/calendar_day）
 两个数据就绪 → collapsed = events.length>=3（一次）→ settled（开关淡入）
手动 toggle → 更新 collapsed（本次停留有效；切日/翻周不重算；离开销毁）
```

### 8.7 改密后他端失效

```
A 设备 POST /auth/change-password（旧密码 OK）
  → 事务：更新 hash → 吊销该用户全部旧 refresh → 签发新对并随响应返回
A：用响应中的新 access/refresh 覆盖本地 → 不掉线
B 设备：下次 ensureFresh 使用旧 refresh → 已 revoked → 1002
   → 跳登录（不显示"登录已过期"，文案为"账号安全设置已变更，请重新登录"）
   → 旧串若被反复使用则命中重放保护（8.4），保持全链吊销
```

## 10. 安全设计（增量）

1. **refresh 存储**：只存 SHA-256 哈希；传输依赖 HTTPS（同源 nginx 反代）；length=48 字节随机，不可枚举；
2. **轮转重放**：已吊销令牌再次使用 = 失窃信号 → 吊销该用户全部活跃 refresh；
3. **刷新端点**：独立限流（防爆破、防遍历）；成功响应不区分"令牌不存在/过期/吊销"（统一 1002 文案"登录已失效，请重新登录"）；
4. **改密**：旧密码错误不泄露账号状态；他端立即失效（见 8.7）；
5. **Markdown XSS**（本版新增渲染面，重点评审）：
   - `html:false` 从解析层禁原始 HTML；DOMPurify 标签/属性白名单；URI 仅 http/https；
   - 覆盖测试：`<script>`、`<img onerror>`、`<a href=javascript:>`、`data:`、事件属性、svg/object、样式注入、嵌套编码混淆；
   - 链接强制 `rel=noopener noreferrer target=_blank`；
6. **proposal 注入**：模型产出的 params 是展示数据，前端按文本插入（MarkdownText 不用于 proposal 参数行）；真正执行以模型下一轮工具调用为准且全量过既有校验，proposal 不携带任何可执行结构；
7. **农历/假日接口**：均为鉴权只读接口，输入为范围受限整数（年/月/日），无 SQL 拼接（参数化）；
8. **设置越权**：所有 /me、/settings 语句带 user_id 主键条件；JWT 与现有鉴权中间件不变。
