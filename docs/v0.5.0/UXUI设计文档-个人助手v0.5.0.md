## 1. 设计目标与原则

### 1.1 设计目标

1. **智能在暗处**：上下文超限时助手自己"回顾整理"，用户不需要理解 token、压缩、窗口这些概念，界面上只有一条轻提示与一条分界；
2. **记忆有实体**：长期记忆不是隐藏开关，而是用户能进入、能通读、能删除的一个真实页面；归档动作的"得到（记忆）"与"失去（记录）"在确认前讲清楚；
3. **冲突只报真冲突**：全天安排与定时安排互不打扰，冲突提示只在"两个具体时段真的重叠"时出现；
4. **入口做减法**：清除记录、修改密码、退出登录各回到最合理的 1~2 个入口，抽屉底部不再堆动作；
5. **聊天流只留结果**：助手找日程的过程不刷屏，用户看到的永远是"一句话回应 + 被改动的那一张卡"。

### 1.2 设计原则（v0.5.0 新增/强化）

| 原则 | 说明 |
| --- | --- |
| **过程隐形，结果显性** | 为完成操作而做的查询、定位、压缩都不进消息流；只有最终结果与必须由用户决策的澄清/确认可以占据消息位 |
| **自动不等于无告知** | 压缩全自动，但在历史中留下可发现的分界文案；不弹窗、不打断、不要求确认 |
| **先存后弃，可见可删** | 归档必须让用户先知道"会提炼记忆、会清空记录"；所有记忆随时可读、可单条删、可全部删 |
| **危险分离** | 归档（普通样式、信息动作）与清除（红色危险样式、丢弃动作）在同一菜单中视觉分级；删除记忆、退出、注销保持红色危险语义 |
| **删入口不删能力** | UI-01/02/03 只移除入口，能力与页面仍在；任何被删入口都有明确的替代路径，不让功能"消失" |
| **折叠优于消失** | 信息太多时先折叠（大卡组、长历史），不要直接不展示；用户主动展开即可得到全部 |
| **数据分区朗读** | 记忆、摘要对模型是"资料"，对用户是"说明文案"：界面文案用日常语言，不出现技术术语 |

## 4. 核心用户流程（UX Flow）

### 4.1 长对话自动压缩（无感）

```
用户连续对话至超水位轮
  → 发送消息后，助手气泡区顶部先出现临时状态条：
   「正在回顾之前的对话…」（spinner + caption 色，不遮罩、不禁输入历史）
  → 状态条消失，助手正常流式回复
  → 用户上翻历史，在被摘要段与近期消息之间看到一条居中小字分隔：
    ────── 更早的对话已自动摘要，仍可向上翻看完整记录 ──────
  → 早期决定仍可引用（"还是按之前说的 9 点半"助手能接住）
失败分支：状态条不出现或一闪而过，回复正常返回（用户无感知降级）
```

### 4.2 归档聊天记录

```
/chat 右上角「⋯」→ ActionSheet：
   归档聊天记录（普通黑字）
   清除聊天记录（红字）
  → 点归档 → AppModal 确认弹层（5.2）
     ├─ 取消 → 关闭，无任何变化
     └─ 归档并清空 → 按钮 loading「归档中…」
        ├─ 成功：toast「已归档，保存了 N 条长期记忆」+ 右侧「查看」
        │        聊天回空态引导；会话标题重置；分界条消失
        ├─ 无可提炼：弹层内/二次询问「本次没有提炼到需要长期保留的内容，仍然清空吗？」
        │             「仍然清空」/「取消」
        └─ 失败：toast「归档失败，聊天记录未受影响，请稍后重试」，记录原样保留
```

### 4.3 管理长期记忆

```
/settings「对话」分组 → 长期记忆（右侧：12 条）› → /me/memories
  → 列表通读：内容 + 类别标签 + 归档时间
  → 单条删除：行尾删除图标 → 轻确认「删除这条记忆？」→ 行收起移除 + toast
  → 全部删除：底部红框「全部删除」→ AppModal 危险二次确认 → 空态
空态：插画位（可选）+「还没有长期记忆」+ 说明 +「去助手」主按钮 → /chat
```

### 4.4 全天日程与冲突

```
建全天「出差」（同日已有 09:00 晨会）→ 保存直接成功，无冲突条
建定时「10:00 评审」撞 10:00 已有会 → 照常出 ConflictBlock「与 XX 时间重叠」
全天日程在月历、当日列表全天分组、详情中的展示完全不变
```

### 4.5 聊天里改日程不刷屏

```
用户："把明天的周会改到下午 4 点"（明天日程较多）
  → 助手过程中调用查询：消息流无卡片
  → 结果：一句话「已把明天的周会改到 16:00–17:00」+ 仅 1 张周会结果卡
用户："我明天有什么安排"（12 项）
  → 文字回答 + 卡组折叠条「明天共 12 项安排 · 点击展开」
历史旧消息（升级前产生的大卡组）→ 同样默认折叠展示
```

### 4.6 账号入口精简后的登出/改密

```
抽屉：无退出 → 点账号区 → /me → 危险区「退出登录」（直接退出，沿用现有行为）
改密：/me → 修改密码（/settings 不再有入口）
```

## 5. 页面设计规格（线框 + 说明）

### 5.1 助手页更多菜单（改造）

```
┌───────────────────────────┐
│  归档聊天记录              │  普通行（text-primary，左侧 archive 图标）
│  清除聊天记录              │  危险行（danger 色，左侧 trash 图标）
└───────────────────────────┘
```

- 复用现有 AppActionSheet（v0.4.0 仅一项"清除聊天记录"）；新增项置于上方、普通样式；
- 助手流式回复进行中：菜单可打开但两项均禁用（置灰 + 副文案"助手回复中，请稍候"挂在归档项下，或菜单整体禁止打开——本版采用**菜单可打开、两项置灰**，与 ChatView 现有 `moreItems` 禁用策略一致）；
- 无消息（空态）时：归档项置灰（无内容可归档），清除项维持现有禁用/可用策略。

### 5.2 归档确认弹层（新增）

```
┌───────────────────────────┐
│  归档聊天记录？            │  AppModal 标题（17pt 粗）
│ ───────────────────────── │
│  系统会从当前对话中提炼长期 │  正文 14/22，secondary
│  记忆并保存，之后与助手的   │
│  新对话可以使用这些记忆。   │
│                            │
│  提炼完成后，当前聊天记录   │  后果段用 danger-weak 色（#B4554D 档）
│  将被清空且不可恢复。       │  或整段普通色 +「清空且不可恢复」加粗
│  任务与日程数据不会被删除。 │
│ ───────────────────────── │
│ [ 归档并清空 ]             │  primary block 48pt，loading 态「归档中…」
│  取消                      │  text 按钮
└───────────────────────────┘
```

- 不复用"清除聊天记录"弹层：标题、正文、主按钮文案全部独立，避免用户混淆两个动作；
- 主按钮**不使用红色**：归档是信息整理动作，红色只留给"不保留任何内容"的清除；但后果句必须明确；
- 弹层开启时遮罩、圆角、grabber（若用底部 sheet 版）沿用 AppModal 规范；本版采用与清除一致的居中 AppModal。

**归档进行态**：主按钮显示 spinner +「归档中…」，取消按钮与遮罩点击禁用（防中途离开造成认知歧义；服务端任何失败都不清空，故禁用仅为防重复提交）；最长等待按接口超时（SDD 定为 8s 量级 P95），超时走失败 toast。

**成功 toast**：

```
┌────────────────────────────────┐
│ 已归档，保存了 3 条长期记忆  查看 │  深底浅字 toast，右侧「查看」primary 内联按钮
└────────────────────────────────┘
```

- N=0 时不使用该 toast，走 4.2 的"仍然清空吗"分支；
- 点「查看」跳 `/me/memories`；不点 4s 自动消失。

### 5.3 聊天流：压缩状态条与历史分界（新增）

**临时状态条（SSE 进行中，挂消息流底部、输入框上方）**

```
┌───────────────────────────┐
│  ⟳ 正在回顾之前的对话…     │  胶囊条：bg-card + 边框 + caption 字
└───────────────────────────┘
```

- 与新消息胶囊同档视觉（bg-card、阴影/边框、高 32pt、圆角 16），左侧 12pt spinner；
- 仅在压缩实际发生的轮次出现，随首个文本增量到达而淡出（200ms）；不落消息历史、刷新后不可见；
- 不遮罩、不阻断输入（但发送入口沿用流式禁用）。

**历史分界条（渲染层，不入库）**

```
────────  更早的对话已自动摘要，仍可向上翻看完整记录  ────────
```

- 居中、12pt、`text-disabled/secondary`，左右 1pt 分隔线各占剩余宽度，垂直 margin 12pt；
- 位置：在"最近原文窗最早一条消息"之上；前端依据会话摘要水位（归档/清除后重置）渲染，**不产生消息行、不占消息分页**；
- 整个会话只有 0 或 1 条分界（多次压缩仍是同一条，位置随水位移动）；
- 不可点击（本版不做摘要详情页，见 PRD 1.3）。

### 5.4 长期记忆页 /me/memories（新增）

```
┌───────────────────────────────────┐
│ ‹   长期记忆                       │  标准二级导航栏
│ ───────────────────────────────── │
│ 归档聊天记录时自动提炼，用于让助手  │  说明区：13pt secondary，padding 16
│ 更了解你的长期情况。               │
│ ───────────────────────────────── │
│ ┌───────────────────────────────┐ │
│ │ 用户每周三 19:00 健身，安排    │ │  记忆卡：bg-card、圆角 12、padding 12/14
│ │ 日程时应避开该时段             │ │  正文 14/22 primary，最多 3 行，超出…
│ │ [固定作息]      9 月 18 日归档  🗑│ │  底行：类别小标签（浅底）+ 时间 caption + 删除
│ └───────────────────────────────┘ │
│ ┌───────────────────────────────┐ │
│ │ 习惯早起，会议尽量安排在上午    │ │
│ │ [时间偏好]      9 月 18 日归档  🗑│ │
│ └───────────────────────────────┘ │
│ ┌───────────────────────────────┐ │
│ │ 默认清单为「工作」              │ │
│ │ [常用对象]      9 月 12 日归档  🗑│ │
│ └───────────────────────────────┘ │

│ [   全部删除   ]                  │  底部危险区：danger 线框/文字 block 按钮
└───────────────────────────────────┘
```

- 列表按归档/更新时间倒序；卡间距 8pt，页面左右 16pt；
- 类别标签 6 类以内（个人情况 / 时间偏好 / 固定作息 / 常用对象 / 长期事项 / 其他），浅底小胶囊（radius 4、字 11pt、各用中性/浅色，不新增色相体系，复用 primary-light 与暖灰系）；
- 时间格式：当年 `M 月 D 日归档`，跨年 `YYYY 年 M 月 D 日`；tabular-nums；
- 单条删除：行尾垃圾桶图标按钮 ≥44pt 热区（图标 20pt，热区外扩）；点击出 AppModal 轻确认：

  > **删除这条记忆？** 删除后助手将不再参考它。「删除」（红）/「取消」

  删除成功卡片 200ms 收起（高度 + 透明度过渡），列表上移；toast「已删除」（不做撤销，删除即生效）；
- 全部删除：按钮固定在列表末尾（非 sticky，随内容滚动）；确认弹层：

  > **删除全部长期记忆？** 将删除全部 N 条记忆，之后助手将完全不了解你的历史偏好，且不可恢复。「全部删除」（红 block）/「取消」
- 空态：

```
┌───────────────────────────┐
│        ( 🧠 线稿图标 )      │   图标 56pt，secondary 40%
│   还没有长期记忆            │   15pt 粗
│ 在助手页归档一次聊天记录，  │   13pt secondary，最多两行
│ 助手会帮你提炼。            │
│ [   去助手   ]             │   primary block → /chat
└───────────────────────────┘
```

- 错误态：复用 StateError（错误占位 + 重试，不展示陈旧列表，符合云端无缓存约束）；删除失败 toast 报错、卡片保留。

## 7. 关键交互细则

### 7.1 压缩的可感知边界

1. 压缩提示只在"真的发生压缩"的轮次出现，正常对话永不出现；
2. 状态条是临时流状态：刷新、断线重连后不再出现（不补显）；分界条是持久渲染但不入库；
3. 压缩进行中沿用流式期规则（禁发送），但**不阻塞**用户阅读历史、打开卡片详情；
4. 压缩失败降级对用户完全隐形：无错误条、无 toast（错误只进日志/埋点）。

### 7.2 归档防错

1. 归档弹层与清除弹层文案必须有一眼差异：归档主按钮是普通 primary 且首句讲"提炼记忆"；清除首句讲"永久清除"；
2. 归档中禁关闭弹层、禁重复点按；失败后弹层关闭并 toast，消息零变化是硬验收点；
3. N=0 的"仍然清空"必须二次选择，禁止默认清空；
4. 归档成功后聊天页空态、标题、输入草稿沿用清除后的现有规则（草稿保留）。

### 7.3 记忆管理防错

1. 删除是即时生效（下一轮模型请求即不注入），因此单条删除也要确认，但只做一次轻确认（不再追加二次弹窗）；
2. 全部删除使用危险二次确认并显式条数；
3. 从归档 toast 进入记忆页时，新记忆在列表最顶部可见；
4. 设置页条数与记忆页始终同源：记忆页返回设置页时重新拉取；删除全部后返回立即变"0 条"。

### 7.4 卡片收敛边界

1. 折叠只作用于 cards 块；clarify/confirm/conflict/scope/proposal 永远完整展示；
2. 折叠状态仅内存态（本次查看），不持久化用户展开偏好（保持简单）；
3. 历史卡组折叠不触发任何网络请求、不改写消息 payload；
4. 写操作轮"过程查询无卡"由服务端保证（客户端不自行隐藏，避免与实时流不同步）；前端只负责"收到什么渲染什么"+ 大卡组折叠。

### 7.5 入口删除后的回归保证

1. 退出登录路径数量 3→2（/me、/settings），两处行为完全一致（直接退出、清偏好、跳登录）；
2. 修改密码路径 2→1（/me），`/me/password` URL 保持可直达（旧书签不死链）；
3. 清除记录路径 3→2（/chat 菜单、/settings）；
4. 抽屉删除退出后，账号区视觉重心不悬空：foot 区与导航区间距重新平衡（UXUI 走查点）。
