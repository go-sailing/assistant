## 1. 测试概述

### 1.1 范围与方法

按用例文档的 8 个模块（CMP / MEM / CF / ENTRY / CARD / SEC / NFR / AUDIT，共 248 项）执行，采用四层方法：

| 层级 | 手段 | 覆盖模块 |
| --- | --- | --- |
| 接口 + 数据库级 | `curl` 打通真实 HTTP（zod 校验、错误码、限流、SSE），并回查 PostgreSQL 行/约束 | CMP、MEM、CF、ENTRY、CARD、SEC、NFR、AUDIT |
| 可编程 LLM 桩级 | 桩 `:4010` 通过 `POST /__control` 注入确定性的提取/合并/压缩/主模型行为（含 fail/hang/oversize/garbage），`GET /__state` 观测每次请求的角色分区与内容归属 | CMP（水位/地板/降级/装配）、MEM（四态/边界/去重）、CARD（写轮缓冲裁决）、CF（工具路径） |
| 前端源码 + DOM 级 | Vite dev 真实浏览器代理走查（登录 → 折叠/平铺/抽屉/记忆页）+ 源码级结构核对（阈值、ARIA、文案、状态机） | CARD 5.2/5.3、CMP 1.7、MEM 2.7、ENTRY 4.1/4.3 |
| 真实 LLM 级 | 独立实例接真实 `deepseek-flash`（窗口 20000），跑写/查询/归档/压缩/稳定性链路 | CMP 1.8、MEM 2.3/2.6、CARD 5.4、CF 3.4、NFR 081/083/093 |

**独立证据原则**：桩层断言取服务端真实落库结果与桩侧请求快照（两条独立证据链）；压缩"是否压掉未决交互"以 `compacted_until_id` 与地板消息 id 的大小关系判定，而非仅看摘要文本；埋点核验以服务端日志实际行（含字段）为准，不以源码中存在字符串代替。

1. 启动服务端必须设 `RATE_LIMIT_AUTH_PER_MIN=2000`、`RATE_LIMIT_CHAT_PER_MIN=2000`，否则脚本中途注册被限流 → token 为空 → 后续全部鉴权失败（易误判为产品缺陷）。
2. 测试库重置用 `reset_db`（TRUNCATE + RESTART IDENTITY），**不要 DROP DATABASE**（在线连接会阻塞）。
3. **注册接口会把邮箱归一化为小写**：用 `SELECT id FROM users WHERE email='...'` 回查时必须用小写邮箱（曾误判为"会话 id 为空"）。
4. **记忆注入分区按 userId 缓存 60s**（仅删除/归档失效）：用 SQL 直插记忆的脚本需把 `users` 序列推到随机高位，否则会读到上一轮同 id 的缓存。
5. **固定开销约 12988 token**（system 4278 + tools 6710 + 用户预算 2000）：窗口配置若小于该值，任何一轮都会"超水位"，`keep` 递减分支会被持续触发。做"正常轮 keep=10"类断言必须使用窗口 ≥20000 的实例（t_cmp.sh 的 `:3205 / v050_cmp_real`）。
6. 脚手架坑：函数内单行 `curl|jq` 管道偶发返回空（改为先取 raw 再 jq）；`${4:-{}}` 会展开成非法 JSON；`grep -c` 无匹配时退出码非 0（需 `|| true`）。
7. 另有一个"单用户单会话"约束（迁移 006）：同一用户的多次 `POST /conversations` 返回同一会话，真实链路脚本需按"累计水位"而非"每轮独立会话"设计断言。
