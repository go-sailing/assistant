## 1. 背景与目标

### 1.1 背景

v0.5.0 完成助手「记性」建设后，单任务、单日维度的管理体验已经成熟，但**多任务的"集合化管理"仍然空白**；同时，经过 v0.3.0~v0.5.0 三个版本的连续迭代，日程主页、全局入口、日程表单等高频界面沉淀了 8 项明确的体验瑕疵。v0.6.0 需求共 9 项，分为两组：

**项目管理能力缺失（新增 1 项）**

1. **一组相关任务没有"容器"**：现实工作中大量事情成组出现——"准备季度述职"包含写 PPT、约评审、改稿、彩排等一系列任务；当前它们只能以扁平任务 + 手工子任务的方式存在，没有项目级的进度总览、没有明确的创建入口，任务多了以后难以分辨哪些任务属于同一件事。需要：
   - 用户可以**创建项目**；
   - 项目中可以**创建一系列任务**；
   - 给任务增加**任务类型**：**普通任务**与**项目任务**（项目本身即一个项目任务，成员关系复用现有 parent_id 层级机制，而非另起一套数据模型）；
   - **同步取消普通任务的子任务功能**：普通任务不再具备子任务，也不再能挂到普通任务下；任务的层级关系只存在于「项目 → 项目成员」一种形态。

**体验优化（8 项）**

2. **系统设置页危险项冗余**：退出登录、注销账号在个人信息页危险区已有入口，设置页再放一处造成重复，应从设置页删除；
3. **个人信息/系统设置页左上返回按钮语义不符**：这两个页面均由左侧抽屉进入，是抽屉下属的一级页面，左上角应与日程/任务首页一致，放**抽屉菜单按钮**而非返回箭头；
4. **右滑打开抽屉与浏览器/系统返回手势冲突**：当前在页面任意位置向右滑动都会唤起抽屉，容易误触、也与微信 WebView 的侧滑返回打架，应取消该手势，抽屉统一由菜单按钮打开；
5. **右下角助手浮动按钮（FAB）冗余且占位**：助手入口在左侧抽屉中已存在，FAB 常驻遮挡内容，应删除；
6. **日程主页头部与列表标题行信息冗余、操作分散**：头部的左右换月按钮可由滑动替代、头部"今天"按钮位置不佳；日程列表标题行（日期标题 + 共 N 项 + ＋）与头部重复。应删除换月按钮与头部今日按钮，把 ＋ 移到日历头部最右侧、删除日程列表标题行；当选中日期不是今天时，在主页右下角显示一个**浮动"今日"按钮**，点击回到今天；
7. **日历折叠/展开依赖显式开关条**：折叠/展开点击行占据空间且操作不直觉。应删除该点击行；首次进入默认展开；**向下滑动自动展开、向上滑动自动折叠**，由手势驱动形态；
8. **新建/编辑日程页把普通日程与任务日程合并在一起**：页面顶部需要用分段开关切换类型，概念混淆。应拆分为两个独立页面：从日程主页点 ＋ → 新建普通日程；从任务里点"安排日程" → 任务日程；
9. **日程详情底部编辑入口与头部重复**：循环实例详情底部同时有"编辑本次安排""编辑整条系列"两个按钮，而头部已有"编辑"入口（经作用域选择可覆盖全部三种作用域），底部两个按钮应删除。

9 项需求编号与分组：

| 分组 | 编号 | 需求 |
| --- | --- | --- |
| 项目管理（新增） | PRJ-01 | 项目管理：创建项目（项目任务），项目内创建一系列任务；任务增加普通/项目两种类型；**普通任务取消子任务**，层级仅存在于项目与其成员之间 |
| 入口收敛 | UI-01 | 删除系统设置页"退出登录""注销账号"项 |
| 入口收敛 | UI-02 | 个人信息页、系统设置页左上角返回按钮改为抽屉菜单按钮 |
| 手势收敛 | UI-03 | 取消右滑屏幕打开抽屉的手势 |
| 入口收敛 | UI-04 | 删除右下角浮动助手入口按钮 |
| 日程主页 | CAL-01 | 头部与标题行改造：删换月/头部今日按钮、＋移头部最右、删列表标题行、浮动今日按钮 |
| 日程主页 | CAL-02 | 日历折叠展开手势化：删开关点击行、默认展开、上下滑动驱动 |
| 日程表单 | FRM-01 | 普通日程与任务日程拆分为两个独立页面 |
| 日程详情 | DTL-01 | 删除详情底部"编辑本次安排""编辑整条系列"按钮 |

### 1.2 产品目标（v0.6.0）

- **核心目标**：
  1. 用户能以"项目"为容器组织成组任务：一键创建项目、在项目中连续添加任务、随时看到项目整体进度；任务层级关系收敛为「项目 → 成员」一种，普通任务回归纯粹的单任务形态，不再有多层子任务带来的复杂度；
  2. 日程主页信息密度与操作效率提升：头部只保留菜单、月份、＋；换月靠滑动、回今天靠右下角浮动按钮；日历形态随手势自然伸缩，无任何多余开关；
  3. 日程表单概念清晰：普通日程与任务日程各自独立、入口与场景一一对应，不再有"类型切换"；
  4. 完成账号/助手入口的最终收敛：退出与注销只在个人信息页，助手只从抽屉进入，抽屉只从菜单按钮打开。
- **成功假设**：
  1. 项目功能上线 4 周内，任务周活中创建过项目的比例 ≥ 30%；多任务用户（周创建 ≥ 10 个任务）中使用项目组织任务的比例 ≥ 50%；
  2. "任务太多分不清/找不到一组任务"类反馈较 v0.5.0 下降 ≥ 70%；
  3. "右滑误开抽屉"类反馈归零；日程主页手势（翻月、折叠展开、浮动今日）相关操作成功率 ≥ 98%；
  4. 日程新建流程的取消/误开率（进入表单后立刻退出）较合并表单时期下降；日程详情编辑动作全部可经头部"编辑"完成，零功能缺失投诉。

### 1.3 非目标（v0.6.0 不做）

- **不做多人协作**：项目仍是个人数据；不做项目成员、任务指派、共享/评论；
- **不做重型项目管理能力**：不做甘特图、看板、时间线、里程碑（独立于任务的里程碑对象）、项目模板、项目报表、项目导出、工时与预算；
- **不做自定义任务类型**：任务类型只有普通任务、项目任务两种，不允许用户扩展；项目不支持自定义颜色/图标（视觉由 UXUI 统一规范）；
- **不做独立于清单的项目归属**：项目与其成员任务沿用现有清单归属与"同清单"约束，不新建项目空间概念；
- **不做历史任务批量转项目的专门工具**：任务类型创建后不可变更；用户可新建项目后把既有普通任务移动到项目下（移动不改任务类型）；
- **不保留普通任务的子任务能力**：普通任务不可再有子任务、普通任务之间不再存在层级；v0.2.0 起的多层子任务、子树 CTE、直接子任务进度等规则仅以「项目成员」形态保留于项目，其余既有规则（循环日程、冲突检测、长期记忆、上下文压缩等）不变；
- **不做通知提醒、消息推送**（延续全版本边界）；
- **不删除既有接口路径**：退出登录、注销账号、会话、任务层级等接口路径全部保留，仅调整端上入口与参数语义（普通任务不再接受层级挂载）；
- **不做深色模式、字号调节、多语言、PC 端专门适配**。

## 2. 目标用户与使用场景

### 2.1 目标用户

延续 v0.5.0 全体个人用户，本版尤其面向：

- 同时推进**多件多任务事项**（述职、活动组织、考试准备、旅行筹备）的用户；
- 任务密度高、希望快速分辨"哪些任务属于同一件事、完成到什么程度"的用户；
- 对界面冗余操作、手势冲突、表单概念混淆敏感的体验向用户。

### 2.2 核心使用场景

| 场景 | 描述 |
| --- | --- |
| 创建并推进项目 | 用户要准备季度述职：新建项目「季度述职」，在项目内连续添加「写 PPT」「约评审会议室」「彩排」等任务；项目详情顶部显示进度（如 1/4）。完成一项勾选一项，进度实时推进。 |
| 把既有任务归入项目 | 用户之前零散建了几个述职相关任务；新建项目后，在任务移动/层级操作中把这些普通任务挂到项目下，即成为项目成员，不需要重建。 |
| 对话创建项目 | 用户对助手说："帮我建一个「周末搬家」项目，里面加上收拾东西、约搬家公司、提前打包三个任务"：助手创建项目任务后依次创建三个成员任务；聊天中以项目卡片展示，可直接点进项目。 |
| 项目日程安排 | 用户在项目成员任务「约搬家公司」上点"安排日程"，直接进入任务日程表单（关联任务已锁定），设好打电话的时间。 |
| 日程主页手势操作 | 用户进入日程主页：月历默认完整展开；向上滑动浏览当日安排时，月历自动收成一周；想回看月历时在列表顶部向下拉，月历重新展开。左右滑动月历切换月份/周；点非今天的日期浏览后，右下角出现浮动"今日"按钮，一点即回到今天。头部最右侧 ＋ 随时可在选中日新建普通日程。 |
| 入口精简 | 用户从抽屉进入个人信息/系统设置：左上角是菜单按钮，点开即抽屉；想退出登录或注销账号时，只在个人信息页危险区操作；设置页不再出现危险项；屏幕右滑不再唤起抽屉；页面右下角不再有助手浮动按钮，助手统一从抽屉进入。 |
| 循环日程编辑收敛 | 用户在循环实例详情：底部只有"取消本次安排"；点头部"编辑"，在作用域选择中选仅本次/本次及以后/整条系列，进入对应编辑表单。已取消的实例仍可"恢复本次安排"。 |

## 3. 产品整体说明

### 3.1 产品形态（延续）

- 仍为**移动端 Web（H5）**瘦客户端：项目规则校验、进度统计、LLM 编排均在服务端完成，端上仅展示与交互；
- 延续全云端架构：项目与任务存云端数据库，端上不缓存；读失败展示错误占位，不展示陈旧数据；
- 延续单会话、服务端统一 LLM 代理、Function Calling + SSE 流式、模型可在服务端替换的总体架构。

### 3.2 v0.6.0 变更总览

### 3.4 项目、清单、成员任务三者的关系（关键，避免误解）

v0.6.0 不新增独立"项目系统"，而是在现有任务体系上增加一个类型维度，并**把 parent_id 层级关系限定为项目专属**：

| 概念 | 关系 |
| --- | --- |
| **项目任务**（task_type=project） | 一种特殊任务：承载项目名称、备注、优先级、截止时间、清单归属；**必须是根任务（parent_id 为空）**，因此项目之间不可嵌套 |
| **项目成员任务** | 直接挂在该项目任务下（parent_id=项目 ID）的普通任务；**仅一层**：项目为第 1 层、成员为第 2 层；成员任务不能再有自己的子任务 |
| **普通任务**（task_type=normal，含全部存量任务） | 独立单任务，**不再具备子任务**：普通任务之间不能互相挂载；挂到项目下即成为项目成员，移出（parent_id 置空）即退出项目回到独立任务 |
| **清单** | 项目与其成员仍归属清单，沿用"同清单"约束；不新增项目维度的空间 |
| **任务日程** | 成员任务、项目任务本身均可安排任务日程，规则（禁循环 4016 等）不变 |

- 项目与普通任务的**本质差异**：项目任务可以拥有成员（parent_id 挂载）、有项目式外观与成员进度总览；普通任务一律为无层级的单任务；
- 级联完成（4010）、级联删除（含关联日程）、同清单校验等既有机制**复用**于「项目 → 成员」；面向普通多层子任务的成环校验、深度校验、子树 CTE 在新模型下不再有触发面（由"父任务必须是项目任务"这一单一规则收窄）。

## 4. 功能需求一：项目管理（PRJ-01）

### 4.1 项目的创建

- **创建入口（三处）**：
  1. 任务表单：新建任务页顶部提供任务类型选择（普通任务 / 项目），默认普通任务；选"项目"后表单语义变为新建项目（标题字段文案为"项目名称"）；
  2. 任务首页"项目"筛选视图下提供"＋ 新建项目"，直达类型=项目的表单；
  3. 助手对话："帮我建一个 XX 项目……"（见 4.6）；
- **项目字段**：项目名称（必填，沿用任务标题长度上限 200；普通日程标题上限为 100，二者不混用）、备注、优先级、截止时间（可选）、所属清单；类型选择仅创建时出现，编辑时不可更改；
- 创建空项目合法（先建容器、后加成员）；项目创建成功后可直接进入项目详情添加成员。

### 4.2 项目成员任务

- 在项目详情中"添加任务"：以项目任务为父任务直接创建成员任务；**成员仅一层**，成员任务下不再能添加子任务；
- 支持把**已有普通任务**移入项目（沿用同清单校验），移入即成为项目成员；也支持把成员任务移出项目（parent_id 置空，回到独立普通任务）；普通任务不能挂到普通任务下，成员不能挂到另一个成员下；
- 成员任务的完成、编辑、删除、安排日程等行为与独立普通任务一致，差异仅是归属项目；
- 单项目成员数量上限沿用规模上限（`TASK_TREE_MAX_NODES=200`，语义过渡为项目成员上限），超出时服务端拒绝并提示。

### 4.3 项目进度与状态

- **项目进度按成员任务口径统计**：成员总数 / 已完成数（成员仅一层，直接统计即可），进度条展示百分比；
- 普通任务为单任务、无进度概念（不再有子任务计数）；
- 项目**不自动完成**：即使全部成员任务完成，项目仍需用户显式点"完成项目"，避免状态意外跳变；
- "完成项目"时若存在未完成成员任务，沿用 **4010 级联完成确认**（显示未完成成员数），确认后全部成员一并完成；
- 新增未完成成员任务时，若项目此前已完成，沿用"自动唤醒父任务"（revived_parent）规则恢复项目为未完成。

### 4.4 项目详情（项目形态的任务详情）

- 进入方式：任务首页点击项目行、对话项目卡片、链接直达；路由形态由 SDD 定稿（建议复用 `/tasks/:id` 按 task_type 呈现项目形态，或提供 `/projects/:id` 别名）；
- 页面内容：
  - 项目头部：项目名称、状态、优先级、截止时间、所属清单、创建来源；
  - 进度区：进度条 +「已完成 X / 共 Y」（成员口径）；
  - 成员区：成员任务列表（一层，直接成员），支持直接勾选完成、点击进入成员详情；
  - 操作：添加任务、安排日程（→ 任务日程表单）、编辑项目、完成项目（级联确认）、删除项目（级联确认）；
- **删除项目**：级联删除全部成员任务及其关联日程，删除前必须明示影响数量（复用 previewRemove 口径），二次确认；项目任务本身的任务日程一并删除；
- 加载失败显示错误占位 + 重试；删除失败 toast 报错且数据保留。

### 4.5 任务首页的项目呈现与筛选

- 新增**类型筛选**：全部 / 普通任务 / 项目（默认全部）；与现有状态筛选（全部/未完成/已完成）、清单筛选正交可叠加；
- 项目在列表中以**项目卡片行**呈现：项目图标、项目名称、成员完成进度条、成员计数（如 2/5）；点击进入项目详情；行内可勾选完成（走级联确认）；
- 普通任务行为单任务行（无子任务进度/子树入口）；筛选态空态文案区分（如"还没有项目，点＋新建一个"）。

### 4.6 助手（LLM）项目能力

- `create_task` 工具新增可选参数 **task_type**：`normal`（默认）/ `project`；模型据用户语义创建项目或普通任务；
- 创建"带任务的项目"时，模型须**先创建项目、再以返回的真实项目 ID 作为 parent_id 依次创建成员任务**（禁止猜测 ID；父任务必须为项目，否则 4018）；
- `list_tasks` 支持按 task_type 筛选（如只看项目）；项目成员查询复用既有按父查询能力（parent_id=项目）；
- 系统提示词补充项目语义：什么情况下建议用项目（≥2 个相关任务、用户明确说"项目"）；普通任务已不支持子任务，任何"给普通任务加子任务"的表达都应建议改用项目；
- 对话中的项目写操作结果以**项目卡片/项目成员组**呈现（项目名 + 成员与进度）；卡片渲染时沿用云端最新数据刷新（按项目重拉成员）机制；
- 一轮中创建项目 + 多成员属于多次工具调用：最终只展示项目结果组，过程性查询不产生卡片（沿用 v0.5.0 CHAT-01 规则）。

### 4.7 数据模型与接口（产品级要求，细节由 SDD 定稿）

- 新增迁移 **011_project_management.sql**（幂等、可重复执行）：
  - `tasks` 新增任务类型列（建议名 `task_type`），取值 `normal` / `project`，默认 `normal`；类型列零回填（存量任务全部即普通任务）；
  - 类型列约束（CHECK）+ 用户维度类型筛选索引（如 project 部分索引）；
  - **一次性层级清理**：存量子任务（parent_id 非空者）在新模型下无合法父任务，统一将其 parent_id 置空、拆散为独立任务（任务本身及其日程、备注等数据全部保留，仅解除层级关系；多层子树一次性全部拆散）；
  - 不新增独立项目表、不改动 events 表结构；
- 任务 DTO 增量字段：`task_type`；项目任务额外返回**成员计数**（成员总数/已完成数，字段命名由 SDD 定稿）；既有子任务计数字段在普通任务上恒为 0，可保留兼容；
- 接口变更（均为鉴权接口，仅访问本人数据，沿用统一响应与错误体系）：

| 方法 | 路径 | 变更 |
| --- | --- | --- |
| POST | `/tasks` | 接受 `task_type`（normal/project，默认 normal）；project 时 parent_id 必须为空，否则 4017；normal 任务的 parent_id 只能指向项目任务，否则 4018 |
| GET | `/tasks` | 新增 `task_type` 筛选；root_only 与类型可组合 |
| GET | `/tasks/:id` | 返回 task_type；project 返回成员计数 |
| GET | `/tasks/:id/subtree` | 语义收窄：仅项目任务返回其成员；普通任务返回空/仅自身 |
| PATCH | `/tasks/:id` | task_type 不可变更（携带即参数校验错误）；项目移动到父任务下 → 4017；普通任务 parent_id 仅允许置空或指向项目，否则 4018 |

- 领域唯一入口原则不变：REST 与 LLM 工具共用同一 TaskService。

### 4.8 校验与新增错误码

- 沿用 4014（跨清单）、4010（级联确认）于项目全链路；4013（超深度）、4015（成环）编号保留，但层级收窄为两层后不再有触发面；
- 新增错误码 **4017（PROJECT_INVALID_STATE，建议文案"项目任务不能挂到其他任务下，项目须为顶层任务"）**：覆盖"创建项目时携带父任务""把项目移动到某父任务下"；项目嵌套被同一规则天然禁止；
- 新增错误码 **4018（SUBTASK_NOT_SUPPORTED，建议文案"普通任务不支持子任务，仅项目可包含任务"）**：覆盖"创建普通任务时 parent_id 指向普通任务""把普通任务移动到普通任务/成员任务下""给成员任务再挂子任务"；
- 项目成员超规模、task_type 非法值等沿用既有参数校验，不新增错误码。

| 当前形态 | 手势 | 结果 |
| --- | --- | --- |

- 日历形态为**纯内存 UI 态**：同一访问期间从日程详情返回时，沿用离开时的形态、选中日与列表滚动位置（沿用现有 5 分钟内恢复机制，扩展保存形态）；

| 日程详情编辑（任务日程） | 任务日程编辑 |
| LLM 对话 | 不经页面，工具能力与行为不变 |

### 11.3 编辑入口分流与旧链兼容

- `/calendar/:id/edit` 为统一编辑入口：进入时按日程实际类型（普通/任务）**分流**到对应表单；循环实例（仅本次/本次及以后）与整条系列编辑沿用普通日程表单的作用域逻辑（任务日程不存在系列形态）；
- 原任务选择页（合并表单中用来查找关联任务）**停用**：相关路由旧链重定向到任务首页（`/tasks`），不保留死页面；
- 已锁定的关联任务、草稿恢复、冲突二次确认、农历换算等既有表单内能力按表单性质各自保留（农历换算仅普通日程新建可用，沿用现状）。

### 11.4 边界

- 任务日程表单在关联任务被删除后进入：展示错误态（关联任务不存在），不得保存出无主日程；
- 编辑中类型不可变更（既有规则），两个表单之间不提供互跳；
- 表单拆分不改变任何服务端创建/更新接口与字段，仅端上页面重组。

## 12. 功能需求九：日程详情底部编辑入口收敛（DTL-01）

- 循环实例详情（非取消态）底部操作区：**删除「编辑本次安排」与「编辑整条系列」两个按钮**；

- 删除后不新增任何编辑入口；头部编辑在取消态下的显示规则沿用现状（取消态不显示编辑）。

## 13. 非功能性需求

### 13.1 性能

- 任务类型筛选与项目列表：类型列走索引，首页查询 P95 不劣于 v0.5.0；项目卡片所需的成员计数须避免 N+1（随列表查询批量聚合或等价方案）；
- 单项目成员列表（≤200 成员）详情首屏 P95 ≤ 300ms；成员增删后进度刷新 P95 ≤ 200ms；
- 日历手势：折叠/展开动画跟手流畅，列表滚动不掉帧；手势监听保持 passive，不得阻塞滚动；
- 移除全局右滑监听与 FAB 后，应用外壳触摸监听减少，触摸响应路径只减不增；
- 所有换月/折叠/回今日操作不依赖额外冗余请求（计数/列表缓存沿用现有策略）。

### 13.2 兼容性与数据

- 迁移 011 为**加列 + 一次性层级清理**（默认 normal + CHECK + 索引），幂等可重复执行；任务、事件、会话、记忆数据本身零丢失；类型列零回填；**唯一有意调整**是存量 parent_id 层级统一拆散（原普通任务子任务的成员成为独立任务）；
- 任务 DTO 新增 task_type 与成员计数为增量字段：旧客户端可忽略；但旧客户端若按旧语义为普通任务提交 parent_id，新服务端返回 4018（行为变更，随版本升级接受）；
- UI-01/03/04 为端侧入口与监听删除：退出、注销、会话等服务端接口路径全部保留；
- FRM-01 页面拆分与任务选择页停用：旧路由提供重定向/分流，书签与历史链接不报死链；
- CAL 系列变更不涉及历史数据；升级后首次进入一律展开，无需数据修复；
- 迁移须在 v0.5.0 类生产存量库快照上演练通过（含多层普通子任务拆散、拆散后任务日程仍正确归属的场景）；
- 历史聊天中的普通子任务组卡片：升级后按云端最新状态渲染（成员已拆散为独立任务），历史消息本身不删除、不改写。

### 13.3 隐私与安全

- 项目与成员为用户个人数据：任务/子树/移动接口的归属校验、越权统一 404 语义延续；注销账号级联删除项目与成员（既有任务级联）；
- LLM 创建项目与成员必须使用真实返回 ID（提示词 + 服务端双重约束），禁止猜测；项目相关工具纳入现有鉴权与限流；
- 服务端日志不记录任务/项目正文（沿用只记 ID 与事件的规范）；
- 长期记忆/压缩摘要等既有数据面规则不受本版影响。

### 13.4 可观测性（新增埋点/日志）

- `project_create`（含来源 manual/chat）、`project_member_add`、`project_member_move_in/out`、`project_complete`（含级联成员数）、`project_delete`（成员/日程计数）；
- `task_type_filter_use`（类型筛选分布）、`project_detail_view`；
- `calendar_today_fab_show / click`、`calendar_auto_collapse / auto_expand`（含触发时列表位置）、`calendar_period_swipe`（翻月/翻周）；
- `event_form_open`（区分 normal/task）、`event_edit_route_dispatch`（编辑分流类型）；
- 错误日志：4017/4018 触发、项目规模上限拒绝、任务日程关联任务不存在、手势与滚动冲突异常。
- 下线埋点：原 FAB 打开助手、右滑打开抽屉（对应代码与埋点一并移除）。

## 14. 关键业务流程与验收标准

### 14.1 关键业务流程

**流程一：创建项目并添加成员**

```
任务首页 → 新建（类型选「项目」）/「项目」筛选下＋新建项目
  → 填项目名称/清单/截止时间 → 保存（task_type=project，parent_id=null）
  → 进入项目详情（进度 0/N）→ 添加成员任务（parent_id=项目ID，仅一层）
  → 勾选完成成员 → 进度按成员口径实时推进
若创建项目时携带 parent_id / 把项目移到其他任务下 → 4017 拒绝
若普通任务挂到普通任务/成员下、给成员再拆子任务 → 4018 拒绝
```

**流程二：对话创建项目**

```
用户："建一个「周末搬家」项目，加：收拾东西、约搬家公司、提前打包"
  → create_task(task_type=project) → 取得真实项目 ID
  → 依次 create_task(parent_id=项目ID) ×3
  → 聊天仅展示项目结果组（项目名 + 进度 0/3，可点进详情）
  → 过程性查询不产生卡片（v0.5.0 规则）
```

**流程三：项目完成与删除（级联复用）**

```
项目存在未完成成员 →「完成项目」→ 4010 显示未完成数 → 确认后一并完成
删除项目 → 明示成员任务 N 个、关联日程 M 条 → 二次确认 → 级联删除
之后新增未完成成员到已完成项目 → 项目自动恢复未完成（revived_parent）
```

**流程三b：升级时普通任务子任务拆散**

```
v0.5.0 存量库中 parent_id 非空的普通任务（含多层子树）
  → 迁移 011：parent_id 统一置空 → 成为独立任务（日程/备注/完成状态不变）
  → 普通任务详情不再显示子任务与子树操作；如需归组，用户可新建项目后把任务移入
```

**流程四：日程主页手势与浮动今日**

```
进入主页：月历默认展开
列表顶部上滑 → 月历折叠为选中周；继续上滑浏览列表
回列表顶部下拉 → 月历展开
日历区左右滑动 → 展开翻月 / 折叠翻周
点选非今天日期 → 右下角出现浮动「今日」→ 点击：选中日/月历/列表全部回到今天，按钮隐藏
头部＋ → 选中日新建普通日程
```

**流程五：日程表单拆分**

```
日程主页 ＋ → 普通日程表单（手输标题、可设循环/农历）
任务详情「安排日程」→ 任务日程表单（任务锁定、标题不可改、无重复行）
/calendar/:id/edit → 按日程类型分流到对应表单
旧链 /calendar/tasks → 重定向 /tasks
```

**流程六：循环实例编辑收敛**

```
循环实例详情：底部仅有「取消本次安排」
头部「编辑」→ 作用域 Sheet（默认仅本次）
  → 仅本次/本次及以后/整条系列 → 进入对应表单
已取消实例 →「恢复本次安排」保留
```

**流程七：入口收敛**

```
/settings：无危险区（止于关于）；左上角为菜单按钮
/me：左上角为菜单按钮；危险区是退出/注销唯一入口
全局：右滑不开抽屉；无助手 FAB；助手由抽屉进入
下级页（改密/记忆）保持返回
```

### 14.2 验收标准

**PRJ-01 项目管理**

1. 可经任务表单、项目筛选视图、LLM 三种方式创建项目；项目为 task_type=project 的根任务；空项目可创建；
2. **成员仅一层**：项目下添加的普通任务直接为成员，成员任务不能再挂子任务；已有普通任务可移入/移出项目，移入即成员、移出（parent_id 置空）即回到独立任务；成员规模超 200 被拒绝；
3. 项目进度按成员口径正确统计并实时刷新；普通任务为单任务、无子任务计数与进度；项目不自动完成；
4. 完成项目走 4010 级联确认且成员一并完成；删除项目前明示成员与关联日程数量、二次确认后级联删除；对已完成项目新增未完成成员可自动唤醒项目；
5. 项目详情包含头部、进度、成员列表与全部操作，加载失败有错误占位；任务首页类型筛选（全部/普通/项目）与清单/状态筛选可正交叠加，项目以项目卡片呈现且空态正确；
