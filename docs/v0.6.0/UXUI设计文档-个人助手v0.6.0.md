## 1. 设计目标与原则

### 1.1 设计目标

1. **项目是看得见的容器**：用户一键创建项目、在项目内连续添加任务、随时看到「已完成 X / 共 Y」的整体进度；项目有区别于普通任务的统一视觉身份；
2. **层级只剩一种**：任务层级仅存在于「项目 → 项目成员」之间且成员仅一层；普通任务回归纯单任务形态，界面上不再出现多层子任务、子树与层级深度概念；
3. **日程主页手势化**：头部只留菜单、月份、＋；换月/换周靠左右滑动、回今天靠右下角浮动按钮；日历形态由列表区上下滑动驱动，无任何显式开关；
4. **表单概念一一对应**：普通日程与任务日程拆为两个独立页面，入口即场景，不再有同页类型切换；
5. **入口完成最终收敛**：退出/注销只在个人信息页、助手只从抽屉进入、抽屉只从菜单按钮打开。

### 1.2 设计原则（v0.6.0 新增/强化）

| 原则 | 说明 |
| --- | --- |
| **容器显性，成员一层** | 项目以卡片、专属图标、进度条明确「这是一个容器」；成员永远只直接挂在项目下，界面不提供任何二级拆分入口 |
| **手势有主** | 同一区域只承认一个主方向：日历区主横向（翻期）、列表顶部主纵向（折叠展开）；方向锁判定后手势余量交还正常滚动，不抢滚动 |
| **删除必有承接** | 被删的按钮/行/手势都有明确替代：‹ ›→滑动、头部今天→浮动今日、底部两编辑按钮→头部编辑作用域 Sheet、右滑抽屉→菜单按钮、FAB→抽屉助手 |
| **危险动作显数量** | 完成项目、删除项目等级联动作，确认前必须明示未完成成员数、成员与关联日程数量，二次确认后才执行 |
| **状态不自动跳变** | 项目不随成员全部完成而自动完成；但在已完成项目中新增未完成成员时允许自动唤醒（并 toast 告知） |
| **入口唯一，能力不下线** | UI-01/03/04 只收敛端上入口与监听；退出/注销、会话、任务层级等接口路径全部保留 |
| **不新增视觉体系** | 不引入 UI 库、不新增色相；项目颜色由 UXUI 统一规范，用户不可自定义项目颜色/图标 |

## 4. 核心用户流程（UX Flow）

### 4.1 创建项目并连续添加成员

```
任务首页 → 头部 ＋（新建任务，类型默认「普通任务」）
  → 顶部类型选择切到「项目」→ 标题字段文案变为「项目名称」
  或：「项目」类型筛选视图 →「＋ 新建项目」直达类型=项目表单
  → 填项目名称（必填，≤200）/ 清单 / 截止时间（可选）/ 优先级 / 备注
  → 保存（task_type=project，parent_id 恒为 null）
  → 进入项目详情：进度 0/N（空项目为 0/0）
  → 成员区「＋ 添加任务」：行内输入连续添加（parent_id=项目 ID，仅一层）
  → 勾选成员完成 → 进度条与「已完成 X / 共 Y」实时推进
异常分支：
  创建/移动时项目携带父任务、项目被挂到其他任务下 → 4017 拒绝（toast/行内错误）
  普通任务挂到普通任务/成员任务下、给成员再拆子任务 → 4018 拒绝
  成员达 200（TASK_TREE_MAX_NODES 语义过渡为项目成员上限）→ 服务端拒绝并提示
```

### 4.2 对话创建项目

```
用户："帮我建一个「周末搬家」项目，里面加：收拾东西、约搬家公司、提前打包"
  → create_task(task_type=project) → 取得真实项目 ID（禁止猜测 ID）
  → 以该 ID 为 parent_id 依次 create_task ×3
  → 聊天仅展示最终「项目卡片」：项目名 + 进度 0/3 + 成员预览，可点进项目详情
  → 过程性查询不产生卡片（沿用 v0.5.0 CHAT-01）
  → 卡片按云端最新数据渲染（按项目重拉成员与计数）
```

### 4.3 项目完成与删除（级联复用）

```
完成：项目存在 N 个未完成成员 →「完成项目」
  → 4010 级联确认：明示「还有 N 个成员未完成，标记后将一并完成」
  → 确认 → 项目与全部成员完成；toast「已标记完成」
  → 之后向该项目新增未完成成员 → 自动唤醒项目为未完成（revived_parent），toast 告知
删除：「删除项目」
  → previewRemove 口径明示：N 个成员任务、M 条关联日程（含项目自身的任务日程）
  → 二次确认 → 级联删除；成功回任务首页
失败：删除失败 toast 报错，项目与成员数据保留
```

### 4.4 既有任务移入/移出项目

```
普通任务详情 →「移入项目」→ 列出同清单内全部项目 → 选择
  → parent_id=项目 ID，成为直接成员（同清单 4014 校验）
成员任务详情 →「移出项目」→ parent_id 置空，回到独立普通任务
  → 项目进度同步刷新；任务本身、备注、关联日程全部保留，仅解除归属
普通任务之间不可互相挂载 → 4018
```

### 4.5 日程主页手势与浮动今日

```
进入 /calendar：月历默认完整展开（骨架按展开形态占位）
列表顶部上滑（≥32px、纵向占优）→ 月历折叠为选中日所在周；余量交还列表滚动
折叠态列表顶部下拉（≥32px）→ 月历重新展开为整月
日历区左右滑动 → 展开态翻月 / 折叠态翻周；点邻月补位日自动切月
点选非今天日期 → 右下角出现浮动「今日」
  → 点击：选中日切回今天、月历定位今天所在月/周、列表刷新为今天，按钮隐藏
  → 不改变当前日历形态（展开仍是展开、折叠仍是折叠）
头部 ＋ → 在当前选中日新建普通日程
进入详情再返回：形态、选中日、滚动位置 5 分钟内恢复；浮动今日按条件照常出现
```

### 4.6 日程新建/编辑分流

```
/calendar 头部 ＋ → 普通日程表单（手输标题、全天、公历/农历、重复、地点、备注）
任务详情/项目成员任务「安排日程」→ 任务日程表单（任务锁定带入、标题不可改、无重复行、无农历）
/calendar/:id/edit → 读取日程实际类型
  ├─ 普通日程（含循环实例 this/following、整条 series）→ 普通日程表单
  └─ 任务日程 → 任务日程表单
旧链 /calendar/tasks → 重定向 /tasks（无死页）
```

### 4.7 循环实例编辑收敛

```
循环实例详情（非取消态）：底部仅「取消本次安排」
头部「编辑」→ 作用域 Sheet：仅本次（默认）/ 本次及以后 / 整条系列
  → 选择后进入普通日程表单对应作用域形态
已取消实例：头部不显示编辑；底部「恢复本次安排」保留
```

### 4.8 入口收敛

```
/settings：保留并止于 显示与历法 / 通用 / 对话 / 关于；无危险区；左上菜单按钮
/me：左上菜单按钮；危险区为退出/注销唯一入口
全局：右滑不开抽屉；无助手 FAB；助手统一由抽屉进入
下级页 /me/password、/me/memories：保持返回箭头
```

## 7. 关键交互细则

### 7.1 日历左右滑动翻期

| 项 | 规格 |
| --- | --- |
| 监听区域 | 日历区（`month__cal`），touchstart/touchend passive |
| 起手避让 | 触点 `clientX < 20` 或 `> innerWidth − 20`（屏幕左右缘 20pt）不跟踪，让给浏览器/微信前进、返回手势 |
| 位移阈值 | touchend 时 `|dx| > 40pt` |
| 方向判定 | `|dx| > |dy|` 才判定为横向翻期，否则放弃（避免与纵向滚动/折叠手势冲突） |
| 翻期规则 | 展开态：左滑（dx<0）→ 下一月、右滑 → 上一月；选中日规则沿用（目标月含今天→选中今天，否则该月 1 号）。折叠态：±7 天翻周，年月跟随选中日 |
| 补位日 | 点击非当月补位日 → 自动切月并选中该日（保留） |
| 防连触 | 翻期动画 250ms 内 `animating=true`，忽略新手势；快速连扫以最后一次 touchend 为准，今日胶囊显隐随选中日实时更新 |

### 7.2 上滑折叠 / 下拉展开（CAL-02 手势细则）

| 项 | 规格 |
| --- | --- |
| 监听区域 | 列表区（`month__body`），touchstart/touchmove/touchend（均 passive，不阻塞滚动） |
| 起手条件 | 列表 `scrollTop === 0`；touchmove 前 8pt 为方向观察期 |
| 方向锁 | 纵向占优：`|dy| > 1.5 × |dx|`；不满足则视为横向/普通滚动，不触发形态变化 |
| 触发阈值 | 竖向位移 **≥ 32pt**（在 PRD 建议 24~40pt 区间内定稿） |
| 展开 → 折叠 | 列表顶部手指上移、`dy ≤ −32pt`：日历折叠为选中日所在周；允许列表先行滚动少量位移，折叠后以选中周承接，不跳变；**一次手势只触发一次**，触发后手势余量交还列表正常滚动 |
| 折叠 → 展开 | 顶部手指下拉、`dy ≥ 32pt`：展开为整月并定位选中日所在月 |
| 跟手规范 | 折叠态下拉：列表顶部与月历之间出现跟手空隙，空隙 = 手指位移（1:1、阻尼、上限 40pt），月历不实时拉高；展开态上滑：不实时压缩月历（优先保证列表滚动跟手），顶部越界采用橡皮筋阻尼 0.4 |
| 吸附/回弹 | 松手达阈值：播放 250ms 形态动画并同步收起空隙；未达阈值：空隙 200ms 回弹，形态不变 |
| 动画 | 日历高度 + 周行位移 **250ms ease-out**；动画期间忽略一切新形态手势 |
| 列表离开顶部 | 仅正常滚动，不触发形态变化；需展开时先回顶部再下拉 |
| 选中日 | 折叠/展开均**不重置选中日期**；折叠周跨月补齐邻月计数 |
| 形态保持 | 纯内存 UI 态；5 分钟内从详情返回恢复「形态 + 选中日 + 列表滚动位置」；页面重建（刷新/重登录/外部进入）回到默认展开 |

### 7.3 抽屉打开方式（UI-03）

1. 删除应用外壳层全部右滑触摸监听后，屏幕任意位置右滑均不唤起抽屉（含 /chat 以外页面、含左缘区域）；
2. 打开方式统一为各页左上角菜单按钮：/calendar、/tasks、/chat、/me、/settings；
3. 遮罩点击/Esc/后退优先关闭、透明历史态压入与回收、菜单项替换历史项等机制不变；
4. 日历左右翻期、聊天区横向操作等页内横向手势零回归。

### 7.4 项目相关防错

1. 项目必须为根任务：端上项目表单不提供任何父级选择；创建/移动误带父级 → 4017 toast；
2. 成员仅一层：成员行与成员详情不出现任何「添加子任务」；违例 → 4018 toast；
3. 完成项目必须经级联确认并看到未完成成员数；删除项目必须看到成员任务与关联日程数量；主按钮分别为「全部完成」「删除」（红色）；
4. 空项目合法、可随时补成员；成员达 200 时添加入口给出上限提示；
5. 项目不自动完成；自动唤醒必须 toast，不静默改状态。

### 7.5 表单拆分与编辑分流防错（FRM-01/DTL-01）

1. 两个表单无类型开关、互不跳转；进入即确定形态；
2. `/calendar/:id/edit` 先读取实际类型再分流，编辑中类型不可变更；循环实例的 this/following 与 series 形态统一在普通日程表单内承接；
3. 任务日程表单任务锁定不可改、无重复行、无农历；关联任务缺失时禁止保存；
4. `/calendar/tasks` 旧链与书签一律重定向 `/tasks`，无死页；
5. 循环实例的所有编辑动作必须且只能经头部「编辑」→ ScopeSheet（默认仅本次），底部不再出现编辑入口。

### 7.6 浮动「今日」边界（CAL-01）

1. 仅以「选中日 ≠ 今天」为显隐唯一条件，与月份、形态、列表滚动无关；
2. 点击不改形态、不入库、不入历史；连切月份显隐实时无残留；
3. 详情返回选中日保持时按钮照常出现；今日数据失败时按钮保留作重试入口。
