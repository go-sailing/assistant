## 1. 设计概述

### 1.1 系统边界（增量）

v0.6.0 不改变"模块化单体 + 全云端 + SSE 函数调用 + 服务端统一 LLM 代理"的总体形态，新增/改动三条技术线：

1. **项目管理域（task 模块内增量，PRJ-01）**：`tasks` 表新增类型维度 `task_type`（`normal` 普通任务 / `project` 项目任务，默认 `normal`）。项目即项目任务，项目成员即直接挂在该项目任务下（`parent_id` = 项目 ID）的普通任务；**层级关系收敛为「项目 → 成员」唯一一种形态、成员仅一层**。新增项目创建、成员挂载/移入/移出、成员口径进度统计、4017/4018 校验、LLM 项目编排与项目结果组卡片。
2. **日程主页手势化（CAL-01 / CAL-02）**：头部收敛为「菜单 · 月份 · ＋」；删除列表标题行；选中日非今天时显示右下角浮动「今日」按钮；删除折叠/展开开关点击行，改为列表顶部"上滑折叠、下拉展开"（阈值 + 方向锁 + 250ms 高度过渡 + 形态内存态）。
3. **入口与表单收敛（UI-01~04 / FRM-01 / DTL-01）**：普通日程与任务日程拆分为两个独立页面，`/calendar/:id/edit` 按日程实际类型分流，任务选择页停用并重定向；日程详情底部两个编辑按钮删除（头部「编辑」→ ScopeSheet 全作用域可达）；设置页删除危险区；移除全局右滑开抽屉手势与右下角助手 FAB。

不在本期：多人协作、甘特图/看板/时间线/里程碑/模板/报表/导出、自定义任务类型、项目空间与项目自定义颜色图标、历史任务批量转项目工具、通知推送、深色模式/多语言/PC 适配。既有接口路径（退出登录、注销账号、任务层级、会话等）全部保留，仅端上入口与参数语义调整。

### 1.2 设计目标与手段

| 目标 | 手段 |
| --- | --- |
| 项目即任务、不另起数据模型 | tasks 增 `task_type` 列 + CHECK + 索引；项目复用 parent_id 挂载、同清单约束、级联完成/删除；不新增项目表、events 表不变 |
| 层级收敛为「项目 → 成员」一层 | 两条硬规则：`assertProjectRoot`（项目必须 parent_id 为空，违反 4017）、`assertParentIsProject`（普通任务 parent_id 只能指向 project，违反 4018）；成环/深度旧校验编号保留、无触发面 |
| 项目进度实时、无 N+1 | 列表查询内单次聚合子查询（按 parent_id GROUP BY）LEFT JOIN 回主表；DTO 统一字段 `member_total/member_completed` |
| 项目状态不意外跳变 | 项目不自动完成；完成走 4010 级联确认（未完成成员数）；删除走 previewRemove 口径级联（成员 + 关联日程）；新增未完成成员唤醒已完成项目（revived_parent） |
| LLM 与 REST 能力对等 | 领域唯一入口：LLM 工具执行器与 REST 路由共用同一 TaskService；LLM 建成员必须使用 create_task(project) 返回的真实 ID |
| 手势不抢滚动、不误触 | 手势监听 passive 不阻止原生滚动；方向锁（纵向 > 1.5 倍横向）+ 32px 阈值 + 列表顶部判定 + 动画 250ms 互斥 |
| 入口删除零功能下线 | 退出/注销接口保留、唯一入口收敛到 /me；FAB/右滑监听删除；任务选择页旧链 302 到 /tasks；编辑入口分流无死链 |
| 存量零丢失 | 迁移 011 为加列 + CHECK + 索引 + 一次性拆散 parent_id；任务/日程/备注/完成状态零变更，仅解除层级；幂等可重复执行 |

### 1.3 核心概念与领域不变量

| 概念 | 定义 |
| --- | --- |
| 普通任务（task_type=normal） | 独立单任务；`parent_id` 只能为 NULL 或指向某个 project；挂到项目下即项目成员，置空即退出项目 |
| 项目任务（task_type=project） | 特殊任务，承载项目名称/备注/优先级/截止时间/清单归属；`parent_id` 必须为 NULL，项目之间不可嵌套 |
| 项目成员 | parent_id = 项目 ID 的普通任务；项目第 1 层、成员第 2 层，成员不能再有子任务 |
| 项目进度 | 按直接成员口径聚合：member_total / member_completed；普通任务恒为 0、无进度概念 |

领域不变量（由服务端 TaskService 在 create/update 全路径保证）：

1. `task_type='project' ⇒ parent_id IS NULL`（违反 → 4017）；
2. `parent_id IS NOT NULL ⇒ 父任务 task_type='project' 且父子同清单`（父非项目 → 4018；跨清单 → 4014）；
3. 单项目直接成员数 ≤ `TASK_TREE_MAX_NODES`（默认 200，语义过渡为项目成员上限）；
4. `task_type` 创建后不可变更（PATCH 携带 → 1001）；
5. 项目不自动完成；项目完成必须显式操作，未完成成员走 4010 级联；
6. 删除任何任务级联删除其子树（项目下即成员）及子树内全部任务日程（previewRemove 口径明示计数）。

## 3. 前端设计：项目管理（PRJ-01）

### 3.1 任务表单类型选择（TaskFormView.vue）

- 仅**新建态**（route name = `task-create`）在表单顶部渲染类型分段控件：

```ts
const taskTypeOptions = [
  { label: '普通任务', value: 'normal' },
  { label: '项目', value: 'project' },
]
const taskType = ref<TaskType>('normal')          // 默认普通任务
```

  - query `task_type=project`（任务首页「项目」筛选下＋新建项目）→ 初始选中 `project`；
  - query `parent_id=P`（项目详情「添加任务」进入）→ 强制 `normal` 且所属项目行预填、锁定来源；
- 选「项目」时：标题字段 label/placeholder 变为「项目名称 * / 请输入项目名称」；**隐藏「所属项目」行**（项目不能挂父）；其余字段（备注、优先级、截止时间、所属清单）不变；
- **编辑态**：不渲染类型控件（task_type 创建后不可变更）。项目编辑时隐藏所属项目行；普通任务（含成员任务）编辑时显示「所属项目」行用于移入/移出；
- 保存：新建 payload 增加 `task_type`；编辑 payload 不含 task_type。

「所属项目」行（取代旧「父任务」行）：

```ts
function projectText(): string {
  if (taskType.value === 'project') return ''
  return parentId.value ? parentTitle.value : '无（独立任务）'
}
```

  - 点击打开 `ProjectPickerSheet`；仅 `normal` 类型可见；
  - 选择项目后跟随项目清单（同清单约束）；选择「无」→ parent_id 置空。

### 3.3 项目详情（复用 /tasks/:id 按 task_type 呈现）

不新增独立路由。TaskDetailView.vue 收敛为瘦容器：

```
TaskDetailView（路由参数 id；加载 GET /tasks/:id）
  ├─ task.task_type === 'project' → <ProjectDetailPanel :task>
  └─ task.task_type === 'normal'  → <NormalTaskPanel :task>
```

加载/错误/骨架由容器统一承担（沿用现有 StateError + 重试），两个面板只接收已加载的 Task。

**ProjectDetailPanel.vue** 内容：

1. **项目头部**：项目名称、状态（未完成/已完成）、优先级（PriorityFlag）、截止时间 formatFull（逾期红色 + 逾期天数）、所属清单、创建来源（manual/chat → 手动创建/对话创建）；
2. **进度区**：ProgressBar + 文案「已完成 X / 共 Y」（member_completed/member_total）；全部完成时文案「成员已全部完成，可点下方完成项目」（项目本身不自动完成）；
3. **成员区**：`<MemberList :members>`（一层），行内直接勾选完成、点击进入 `/tasks/:memberId`；
4. **添加任务**：`<MemberComposer :project-id :project-title :list-id>`，快速输入即创建成员（parent_id=项目 ID）；「更多字段」→ `/tasks/new?parent_id=P&list_id=L`；
5. **操作区**：安排日程（→ `/calendar/task/new?task_id=P`）、编辑项目（→ `/tasks/:id/edit`）、完成项目（走 4010 级联确认）、删除项目（previewRemove 口径）。

成员增删/勾选后的刷新：面板维护 `members: Task[]`，本地原位替换；同时重拉 `GET /tasks/:id` 刷新 member_total/completed（P95 ≤ 200ms 目标）。MemberComposer 创建成功后：本地追加成员；若响应带 `revived_parent`（项目原为已完成）→ toast「项目已自动恢复为未完成」。

**删除项目交互**（复用 previewRemove 口径）：

```ts
async function askDeleteProject(): Promise<void> {
  const preview = await taskApi.fetchPreviewRemove(task.id)
  // 弹 AppModal 二次确认，文案含权威计数
  modalText = `将删除项目及 ${preview.deleted_task_count - 1} 个成员任务`
    + `、${preview.deleted_event_count} 条关联日程安排，且不可恢复。`
}
// 确认 → deleteTask(id) → router.replace('/tasks')
```

**完成项目交互**：点击「完成项目」→ `completeTask(id)`；若返回 4010（details.incomplete_member_count=n）→ AppModal「还有 N 个成员未完成，标记后将一并标记完成」→ 确认后带 cascade=true 重发；无未完成成员时直接完成。

### 3.4 普通任务详情收敛（NormalTaskPanel.vue）

- 保留：勾选完成主行、优先级/清单/截止时间 meta、备注、日程安排分区（含「安排日程」→ `/calendar/task/new?task_id=X`）、创建/完成时间、标记完成/删除操作；
- **删除**：子任务分区（标题/进度/树）、整棵 subtree 拉取、parents 面包屑；容器不再调用 fetchSubtree/fetchAncestors；
- 成员任务（parent_id 非空的 normal）在 meta 区新增一行「所属项目」：显示项目名称，点击跳 `/tasks/:parentId`；非成员普通任务不显示；

### 4.4 折叠/展开手势化（具体实现）

删除折叠/展开开关点击行（.month__toggle）及 toggleCollapse 的点击入口。手势监听挂在**列表区**（.month__body），全部 passive，不阻止原生滚动。

常量（MonthView 模块内）：

```ts
const GESTURE_LOCK_PX = 8            // 起手 8px 内不判方向
const SHAPE_THRESHOLD_PX = 32        // 竖向触发阈值（PRD 24~40 区间定稿 32）
const DIRECTION_RATIO = 1.5          // |dy| > 1.5|dx| 才判纵向（方向锁）
const SHAPE_ANIMATION_MS = 250       // 高度过渡时长，动画期互斥
const LIST_TOP_TOLERANCE = 2         // 列表顶部判定（scrollTop ≤ 2px）
```

手势状态机（页面本地）：

```ts
interface ShapeGesture {
  startX: number; startY: number
  lock: 'none' | 'vertical' | 'horizontal'
  fired: boolean                    // 一次手势只触发一次
}
let shapeGesture: ShapeGesture | null = null
```

```ts
function onShapeTouchStart(e: TouchEvent): void {
  if (animating.value) { shapeGesture = null; return }
  const list = listEl.value
  if (!list || list.scrollTop > LIST_TOP_TOLERANCE) { shapeGesture = null; return } // 非顶部不接管
  const t = e.touches[0]
  shapeGesture = { startX: t.clientX, startY: t.clientY, lock: 'none', fired: false }
}

function onShapeTouchMove(e: TouchEvent): void {
  const g = shapeGesture
  if (!g || g.fired || animating.value) return
  const t = e.touches[0]
  const dx = t.clientX - g.startX
  const dy = t.clientY - g.startY

  if (g.lock === 'none') {
    if (Math.abs(dx) < GESTURE_LOCK_PX && Math.abs(dy) < GESTURE_LOCK_PX) return
    g.lock = Math.abs(dy) > DIRECTION_RATIO * Math.abs(dx) ? 'vertical' : 'horizontal'
  }
  if (g.lock !== 'vertical') return
  const list = listEl.value
  if (!list || list.scrollTop > LIST_TOP_TOLERANCE) return   // 列表已离开顶部 → 只滚动，不触发

  if (!collapsed.value && dy <= -SHAPE_THRESHOLD_PX) {       // 展开态：手指上移 → 折叠
    g.fired = true
    void collapseCalendar()
  } else if (collapsed.value && dy >= SHAPE_THRESHOLD_PX) {  // 折叠态：手指下拉 → 展开
    g.fired = true
    void expandCalendar()
  }
}

function onShapeTouchEnd(): void { shapeGesture = null }
```

折叠 / 展开动作（沿用现有高度过渡与 renderWeek 切换）：

```ts
async function collapseCalendar(): Promise<void> {
  animating.value = true
  collapsed.value = true                  // gridHeight → weekHeight，触发 height 过渡
  void loadCollapsed()                    // 跨月周补齐邻月计数
  window.setTimeout(() => {
    renderWeek.value = true               // 动画结束后只渲染选中周
    animating.value = false
  }, SHAPE_ANIMATION_MS)
}

async function expandCalendar(): Promise<void> {
  animating.value = true
  collapsed.value = false
  renderWeek.value = false
  const d = fromDateKey(selectedDate.value)
  year.value = d.getFullYear()            // 定位选中日所在月
  month.value = d.getMonth() + 1
  await nextTick()
  void loadExpanded()
  window.setTimeout(() => { animating.value = false }, SHAPE_ANIMATION_MS)
}
```

模板接线：

```html
<div ref="listEl" class="month__body"
     @touchstart.passive="onShapeTouchStart"
     @touchmove.passive="onShapeTouchMove"
     @touchend="onShapeTouchEnd"
     @touchcancel="onShapeTouchEnd">
```

防抖动要点（对应 PRD 10.3）：

- **阈值**：竖向位移满 32px 才触发，轻移不触发；**方向锁**：纵向位移须 > 1.5 倍横向，横滑翻月零冲突；
- **一次手势一次**：`fired` 标记后本次手势不再判定；`animating` 250ms 内忽略一切新手势；
- **不抢滚动**：监听 passive、不调用 preventDefault。展开态上滑时浏览器原生滚动同步进行（"手势余量交还列表"），scrollTop 离开顶部后后续 move 自动只滚动列表；折叠态下拉在顶部橡皮筋区间累计位移、不触发滚动跳转；
- 折叠后展示选中日所在周，跨月周补齐邻月计数（ensureNeighborCounts 沿用）；折叠/展开均**不重置选中日期**。

```sql
-- 「项目任务 task_type='project' → 项目成员 task_type='normal'」。
-- 幂等可重复执行：IF NOT EXISTS + 系统目录判定 + 拆散谓词守卫。
-- 执行顺序：① 加列 → ② CHECK 约束 → ③ 一次性拆散存量层级 → ④ 索引。
-- ============================================================

-- ① 任务类型列：normal 普通任务 / project 项目任务；存量零回填
ALTER TABLE tasks
  ADD COLUMN IF NOT EXISTS task_type VARCHAR(16) NOT NULL DEFAULT 'normal';

COMMENT ON COLUMN tasks.task_type IS
  '任务类型：normal=普通任务（独立单任务，parent_id 只能为空或指向 project），project=项目任务（parent_id 必须为空，可拥有一层成员任务）';

-- ② CHECK 约束（PostgreSQL 无 ADD CONSTRAINT IF NOT EXISTS，以系统目录判定）
DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM pg_constraint
    WHERE conname = 'ck_tasks_task_type'
      AND conrelid = 'tasks'::regclass
  ) THEN
    ALTER TABLE tasks
      ADD CONSTRAINT ck_tasks_task_type
      CHECK (task_type IN ('normal', 'project'));
  END IF;
END $$;

-- ③ 一次性层级拆散：存量 parent_id 非空任务的父任务此时全部为普通任务
--    （task_type 默认 normal，尚无项目），将其 parent_id 置空成为独立任务。
--    任务标题/备注/优先级/截止时间/完成状态/关联日程全部不变，仅解除层级。
--    多层子树由同一条 UPDATE 一次拆散（拆散后各层均为根任务）。
--    谓词守卫保证可重复执行：迁移完成后成员任务的父任务 task_type='project'，
--    NOT EXISTS 条件不成立，成员关系不受影响；新模型下「父非项目」的行不可能
--    由服务端写入，因此脚本在任何时点重跑均为安全 no-op。
UPDATE tasks AS child
SET parent_id = NULL
WHERE child.parent_id IS NOT NULL
  AND NOT EXISTS (
    SELECT 1 FROM tasks AS parent
    WHERE parent.id = child.parent_id
      AND parent.task_type = 'project'
  );

-- ④ 索引：用户维度类型筛选 + project 部分索引
CREATE INDEX IF NOT EXISTS idx_tasks_user_task_type
  ON tasks (user_id, task_type);

CREATE INDEX IF NOT EXISTS idx_tasks_user_project
  ON tasks (user_id, status, due_at)
  WHERE task_type = 'project';
```

### 6.3 一次性拆散的正确性论证

| 关注点 | 结论 |
| --- | --- |
| 覆盖多层子树 | UPDATE 不以深度为条件；任意深度的 parent_id 非空行均被命中，一条语句全部拆散 |
| 数据零丢失 | 仅 SET parent_id=NULL；标题、备注、优先级、due_at、status、completed_at 不变；events.task_id 指向不变，任务日程仍正确归属 |
| 项目成员不误伤 | 谓词 `NOT EXISTS (父 task_type='project')` 守卫：首次执行时无 project 故全拆散；重跑时成员父为 project 被排除 |
| 约束顺序 | 先 ADD COLUMN（带 DEFAULT，瞬时完成，不重写表）再 UPDATE，满足"先加列再拆散"；CHECK 在拆散前后均成立（拆散不涉及 task_type） |
| 外键行为 | parent_id 自引用外键（005 迁移）保留；置 NULL 合法；ON DELETE CASCADE 仅作删除兜底 |

### 6.4 events 与其他表

- events 表结构、事件冲突、循环规则等全部不变；项目任务与成员任务均可作为 events.task_id 关联对象，任务日程禁循环（4016）等规则照旧；
- 005 迁移建立的 idx_tasks_parent / idx_tasks_user_root / idx_tasks_user_list_parent 索引保留，继续服务成员查询与根任务列表。

### 7.2 查询 SQL：成员聚合（避免 N+1）

将现 SUBTASK_PROGRESS_JOIN 更名并保持"一次聚合 + LEFT JOIN"形态。新模型下只有 project 行拥有 parent_id 非空的子行，聚合结果即成员计数：

```ts
/**
 * 项目成员进度聚合：单次 GROUP BY 扫描后 LEFT JOIN 回主查询，
 * 列表/详情共用，避免 N+1。新模型保证 parent_id 仅指向 project。
 */
const MEMBER_PROGRESS_JOIN = `
  LEFT JOIN (
    SELECT parent_id,
           count(*)::int AS total,
           count(*) FILTER (WHERE status = 'completed')::int AS done
    FROM tasks
    WHERE parent_id IS NOT NULL
    GROUP BY parent_id
  ) c ON c.parent_id = t.id
`;

const TASK_SELECT = `
  SELECT t.*, l.name AS list_name,
         COALESCE(c.total, 0)::int AS member_total,
         COALESCE(c.done, 0)::int AS member_completed,
         COALESCE(c.total, 0)::int AS subtask_total,
         COALESCE(c.done, 0)::int AS subtask_completed
  FROM tasks t
  JOIN task_lists l ON l.id = t.list_id
  ${MEMBER_PROGRESS_JOIN}
`;
```

### 7.3 校验函数（签名与伪码）

```ts
/** 任务类型归一化：undefined → 'normal'；非枚举 → 1001 */
function normalizeTaskType(raw: unknown): TaskType {
  if (raw === undefined || raw === null) return 'normal'
  if (raw !== 'normal' && raw !== 'project') {
    throw AppError.paramInvalid('任务类型不合法，仅支持 normal 或 project')
  }
  return raw
}

/**
 * 4017 校验：项目任务必须为根任务。
 * 覆盖创建 project 携带 parent_id、PATCH 把 project 移到父下。
 */
async function assertProjectRoot(taskType: TaskType, parentId: number | null): Promise<void> {
  if (taskType === 'project' && parentId !== null) {
    throw AppError.projectInvalidState()
  }
}

/**
 * 4018 校验：普通任务的 parent_id 只能指向项目任务。
 * 父任务不存在/越权由 getOwned 统一 404；父 task_type≠project → 4018。
 * 成员仅一层由此天然保证：成员是 normal，挂到成员下即父非 project → 4018。
 */
async function assertParentIsProject(
  userId: number, parentId: number
): Promise<TaskRow> {
  const parent = await this.getOwned(userId, parentId)
  if (parent.task_type !== 'project') throw AppError.subtaskNotSupported()
  return parent
}

/** 4014：成员任务必须与项目同清单 */
function assertSameList(childListId: number, parentListId: number): void {
  if (Number(childListId) !== Number(parentListId)) {
    throw AppError.subtaskListMismatch()
  }
}

/**
 * 项目成员规模上限：直接成员数 < TASK_TREE_MAX_NODES（默认 200）。
 * excludeTaskId 用于移动场景（任务已在项目内时不计自身）。
 */
async function assertMemberCapacity(
  userId: number, projectId: number, excludeTaskId?: number
): Promise<void> {
  const res = await query<{ n: string }>(
    `SELECT count(*)::int AS n FROM tasks
     WHERE user_id = $2 AND parent_id = $1
       AND ($3::int IS NULL OR id <> $3::int)`,
    [projectId, userId, excludeTaskId ?? null]
  )
  if (Number(res.rows[0]?.n ?? 0) >= config.task.treeMaxNodes) {
    throw AppError.paramInvalid(`项目成员最多 ${config.task.treeMaxNodes} 个`)
  }
}
```

```ts
async create(userId, input, source: 'manual'|'chat' = 'manual'): Promise<TaskWriteResult> {
  const taskType = normalizeTaskType(input.task_type)
  const title = normalizeTitle(input.title)
  const note = normalizeNote(input.note)
  const dueAt = normalizeDueAt(input.due_at)

  if (parentId !== null) {
    const parent = await this.assertParentIsProject(userId, parentId)  // 404 / 4018
    this.assertSameList(listId, parent.list_id)                       // 4014
    await this.assertMemberCapacity(userId, parentId)                  // 规模
  }

  const res = await query(
    `INSERT INTO tasks(user_id, list_id, title, note, priority, due_at, source, parent_id, task_type)
     VALUES ($1,$2,$3,$4,$5,$6,$7,$8,$9) RETURNING id`,
    [userId, listId, title, note, input.priority ?? 'none', dueAt, source, parentId, taskType]
  )
  const newId = res.rows[0].id
  // 新建任务恒 todo；挂到已完成项目 → 唤醒项目
  const revived = parentId !== null
    ? await this.maybeReviveParent(userId, parentId, 'todo')
    : null
  return { ...(await this.get(userId, newId)), revived_parent: revived }
}
```

```ts
async update(userId, taskId, patch): Promise<TaskWriteResult> {
  const existing = await this.getOwned(userId, taskId)
  // task_type 不可变更：携带即参数校验错误
  if (patch.task_type !== undefined) {
    throw AppError.paramInvalid('任务类型创建后不可变更')
  }
  // ...sets/params 初始化沿用

  if (patch.parent_id !== undefined) {
    const newParentId =
      patch.parent_id === null || Number(patch.parent_id) === 0 ? null : Number(patch.parent_id)
    if (newParentId !== (existing.parent_id ?? null)) {
      if (existing.task_type === 'project' && newParentId !== null) {
        throw AppError.projectInvalidState()                           // 4017
      }
      if (newParentId !== null) {
        const parent = await this.assertParentIsProject(userId, newParentId) // 4018
        this.assertSameList(existing.list_id, parent.list_id)                // 4014
        await this.assertMemberCapacity(userId, newParentId, taskId)
      }
      sets.push(`parent_id = $${index++}`); params.push(newParentId)
      if (newParentId !== null) {
        revived = await this.maybeReviveParent(
          userId, newParentId, existing.status as TaskStatus)         // 已完成成员移入不唤醒
      }
    }
  }

  // 标题/备注/优先级/截止时间处理不变
  if (patch.list_id !== undefined && patch.list_id !== null) {
    const listId = await this.resolveListId(userId, patch.list_id)
    if (existing.parent_id !== null) throw AppError.subtaskListMismatch() // 成员不能独立改清单
    if (listId !== existing.list_id) {
      if (existing.task_type === 'project') {
        // 项目改清单：项目自身 + 直接成员一并迁移（仅一层）
        await query(
          `UPDATE tasks SET list_id = $3, updated_at = now()
           WHERE user_id = $2 AND (id = $1 OR parent_id = $1)`,
          [taskId, userId, listId]
        )
      }
    }
  }
  // UPDATE 主语句与返回逻辑沿用
}
```

```ts
async maybeReviveParent(
  userId: number, parentId: number, childStatus: TaskStatus
): Promise<{ id: number; title: string } | null> {
  if (childStatus !== 'todo') return null          // 已完成成员/项目不触发
  const res = await query<{id:number;title:string;status:string}>(
    `SELECT id, title, status FROM tasks WHERE id = $1 AND user_id = $2`,
    [parentId, userId]
  )
  const parent = res.rows[0]
  if (!parent || parent.status !== 'completed') return null
  await query(
    `UPDATE tasks SET status='todo', completed_at=NULL, updated_at=now()
     WHERE id=$1 AND user_id=$2`,
    [parentId, userId]
  )
  logger.info('project_auto_revived', { user_id: userId, project_id: parentId })
  return { id: parent.id, title: parent.title }
}
```

### 7.8 subtree 接口语义收窄

```ts
async getSubtree(userId, rootId, depth?: number | null): Promise<TaskDTO[]> {
  const root = await this.getOwned(userId, rootId)
  if (root.task_type !== 'project') {
    return [toTaskDTO(root)]           // 普通任务：仅自身、零成员（保持数组形态）
  }
  const maxLevels = depth && depth > 0 ? depth : null
  const res = await query<TaskRow>(
    `${TASK_SELECT}
     WHERE t.user_id = $1
       AND (t.id = $2
            OR (t.parent_id = $2 AND ($3::int IS NULL OR $3::int >= 1)))
     ORDER BY (t.id = $2) DESC, (t.due_at IS NULL), t.due_at, t.id`,
    [userId, rootId, maxLevels]
  )
  // 成员口径规模保护（写入侧已保证，实际不可触发）
  if (res.rowCount - 1 > config.task.treeMaxNodes) {
    throw AppError.paramInvalid(
      `项目成员超过 ${config.task.treeMaxNodes} 个，请收窄范围`)
  }
  return res.rows.map(toTaskDTO)        // [0]=项目，其余为直接成员
}
```

### 9.2 项目编排约束（硬约束）

```
用户："建一个「周末搬家」项目，加：收拾东西、约搬家公司、提前打包"
  ① create_task(task_type='project', title='周末搬家')
       → 响应取得真实项目 ID（如 42），禁止凭空编号
  ② create_task(parent_id=42, title='收拾东西')
  ③ create_task(parent_id=42, title='约搬家公司')
  ④ create_task(parent_id=42, title='提前打包')
任一步父任务非 project → 4018；project 携带 parent_id → 4017
成员超 200 → 1001
```

- 成员创建顺序无关、可连续调用；模型可在创建前用 list_tasks(task_type='project') 核对既有项目，避免重复建项；
- 把既有普通任务归入项目：update_task(task_id, parent_id=项目真实 ID)，同清单校验 4014 保留；
- 用户只给项目名、未列成员 → 建空项目，告知「建好后可以随时往里加任务」。

### 9.3 系统提示词增量（llm/prompt.ts）

在 buildSystemPrompt 中以 `# 项目与任务类型（v0.6.0，重要）` 小节替换旧 `# 子任务` 小节，要点（常量字符串）：

- 任务分两类：普通任务（normal，独立单任务）与项目任务（project，一组相关任务的容器）。
- **何时建议项目**：用户明确说「项目」；或一件事包含 ≥2 个相关任务（如「准备述职，要写 PPT、约评审、彩排」）→ 创建 project 并把其余任务作为成员。单一事项用普通任务，不要把无关任务塞进同一项目。
- **普通任务已无子任务**：普通任务之间不能互相挂载。用户说「给 XX 任务加子任务/拆几个子任务」时，说明普通任务不再支持子任务，**建议改为新建项目**（可将原任务作为项目成员或保留为独立任务），经用户同意后执行；不得直接按旧多层语义尝试（会返回 4018）。
- 创建带成员的项目：先建 project 拿到真实 ID，再以 parent_id 逐个建成员；ID 只能来自工具返回，禁止猜测；成员仅一层。
- 完成项目：若存在未完成成员，系统返回级联确认（need_cascade_confirmation），确认前不写数据；删除项目会级联成员与其日程，确认文案以系统计数为准。
- 向已完成项目新增未完成成员，项目自动恢复未完成（revived_parent），须在回复中告知。
- 项目日程安排规则不变（任务日程禁循环 4016）。

### 9.4 项目结果组卡片与云端刷新

chat.orchestrator.ts 在工具循环内对 create_task/update_task 的写结果改为**轮末聚合**（confirm/clarify/conflict/scope/proposal 仍即时展示并提前结束）：

```
工具循环：写结果入 pendingWriteTasks（按 id 去重、原位更新）
轮末（模型 finish）：
  projectIds = pendingWriteTasks 中 task_type='project' 的 id
  memberTasks = pendingWriteTasks 中 parent_id ∈ projectIds 的任务
  对每个 projectId：
    云端刷新：taskService.getSubtree(userId, projectId)
      → [项目(最新 member_total/completed), ...成员(最新状态)]
    emit cards { subtask_groups: [{ root_task_id: projectId, nodes }] }
  其余写任务（projectIds 与 memberTasks 之外）：
    emit cards { tasks: 其余 }
```

- 一轮「项目 + N 成员」最终**只展示一个项目结果组**（项目名 + 成员列表 + 进度 0/N），不产生 N+1 张散卡；卡片可点击进入 `/tasks/:projectId`；
- 云端刷新保证卡片不展示过程性快照（如成员已完成、进度已推进）；历史消息回填路径（refreshBlocksWithLatest）同样按 root_task_id 重拉 subtree 后渲染；项目已删除 → SubtaskGroup.missing 占位；
- 升级拆散后，历史聊天中的旧普通子任务组：按云端最新状态渲染（原成员已为独立任务，重拉 subtree 仅返回已拆散的普通任务自身，组卡片退化为单任务/删除占位），历史消息本身不改写。

### 9.5 写操作轮过程查询不产生卡片

沿用 v0.5.0 CHAT-01：READ_TOOL_NAMES（list_events/search_events/get_event/list_tasks/search_tasks/get_task/get_subtree/list_lists/resolve_lunar_date）在写操作轮（writeToolCalled=true）中的结果卡全部缓冲、轮末丢弃；工具 JSON 照常进模型。项目编排中的查询（查项目、查成员）属过程查询，不落地卡片；纯查询轮（如「我有哪些项目」）读卡照常展示。

tools/executor.ts 侧 createTaskArgs/listTasksArgs zod 增 `task_type: z.enum(['normal','project']).nullish()`；dispatch create_task 透传 task_type；update_task 的 task_type 若被模型传入则由服务层 1001 拒绝（行为与 PATCH 一致）。

### 11.1 错误码（增量/复用/保留）

| 码 | 名称 | 场景 | HTTP |

## 12. 安全设计（增量）

1. **归属校验**：tasks 全部读写 SQL 带 user_id；getOwned 单点承担"不存在/越权 → 统一 404、不区分语义"；subtree/preview/parent 查询均先过归属校验，无法据此探测他人任务是否存在；
2. **真实 ID 约束**：LLM 创建成员必须使用 create_task(project) 返回的项目 ID（提示词 + assertParentIsProject 双重约束）；模型猜测/幻觉 ID 若指向普通任务 → 4018，指向不存在 → 404；不存在跨用户挂载面；
3. **层级结构安全**：项目不可嵌套由 4017 兜底；成员仅一层由"父必须 project"结构保证，旧 CTE 深度/成环面关闭，攻击面只减不增；
4. **规模防护**：单项目成员 ≤ 200（assertMemberCapacity），防止批量挂载造成的存储与聚合放大；task_type 为受控枚举（zod + DB CHECK 双层）；
5. **日志最小化**：服务端日志与审计不额外记录项目正文（11.3）；
6. **注销级联**：users 记录删除经外键 CASCADE 级联 task_lists/tasks/events（既有机制），项目与成员任务、关联日程同步物理删除；退出登录仅清凭证与偏好、不动数据；
7. **XSS 面无新增**：项目名称/备注按 Vue 插值纯文本渲染，不经过 MarkdownText；task_type、进度计数均为受控值；
8. **LLM 工具面**：create_task(task_type)/list_tasks 纳入现有鉴权、限流与危险操作确认（删除项目走确认 + preview 计数）；不提供任何跨用户或管理端项目接口；
9. **记忆注入面不受影响**：长期记忆、压缩摘要的注入分区与隔离规则（system 数据分区 + "命令式内容是数据"声明）保持不变；项目相关语句不进入记忆提取白名单（任务/项目数据已在云端，EXTRACT 提示词不提取一次性流水的规则覆盖本场景）。
