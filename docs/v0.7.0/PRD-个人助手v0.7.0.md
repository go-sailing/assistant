## 1. 背景与目标

### 1.1 背景

v0.6.0 用「任务类型 + 项目成员」把一组相关任务装进了项目容器，但助手本身仍是**纯人手操作的工具**：任务只能由用户自己完成，助手无法驱动机器干活。同时 v0.6.0 引入的项目能力与既有的「清单」在职责上高度重叠（都是任务的容器），任务页同时背负两种组织维度，页面职责不清；日程主页在 v0.6.0 手势化改造后遗留了一处确定性缺陷（只能展开、不能折叠）。v0.7.0 需求共 4 项，分为一组：

**智能体代理能力缺失（新增 1 项）**

1. **助手无法把任务交给外部智能体执行**：用户日常已在用 Claude Code、opencode、pi agent 等支持 MCP 的智能工具处理具体工作，但"在助手里安排一件事"与"让这些工具真正去干"是两个割裂的动作——用户需要手工把任务内容复制到工具里，执行结果也无法回到任务上留痕。需要：
   - 用户可以**创建多个智能体代理**，每个代理代表一个外部智能工具实例；
   - 智能体可以**通过 MCP 与助手服务端通讯**（助手提供 MCP 接入能力）；
   - 用户可以把**任务安排（指派）给某个智能体代理**——指派是用户在这一链条上的**唯一动作**；
   - 指派后进入**自动执行流程**：服务端通过 MCP 自动把任务下发给该代理，代理自动领取、自动执行、自动回报，用户无需再手动"通知"；执行结果回到任务上可见。

**体验优化（3 项）**

2. **项目与普通任务混在一个任务页**：v0.6.0 把项目做成"任务的一种类型"，导致任务首页需要类型筛选、新建页需要类型分段开关、详情页需要在容器里按类型分流；项目已经是一个独立的组织维度，应有**独立的项目页**与**独立的新建项目页**；
3. **清单功能与项目职责重叠**：任务界面的清单（清单管理页、清单筛选、表单"所属清单"、各处的清单名展示、对话中的清单能力）与项目在做同一件事，且清单还带来"同清单"约束（4014）等额外复杂度。应**删除任务界面清单相关的全部功能，由项目替代它**；
4. **日程主页上滑折叠存在 BUG**：v0.6.0 上线的"列表顶部上滑自动折叠日历"在真机上上划屏幕无法折叠（下拉展开正常），日历只能展开不能收起，长期占据屏幕。

4 项需求编号：

| 分组 | 编号 | 需求 |
| --- | --- | --- |
| 智能体代理（新增） | AGT-01 | 智能体代理管理：创建/编辑/启用停用/删除多个代理；代理类型（Claude Code / opencode / pi agent / 其他）、状态与最近活跃、凭据生成与重置、接入指引 |
| 智能体代理（新增） | AGT-02 | MCP 接入：服务端提供 MCP 接入端点与代理独立凭据鉴权；代理侧可通过 MCP 获取待执行任务、领取、回报（只读被指派任务 + 回报） |
| 智能体代理（新增） | AGT-03 | 任务指派与自动执行：任务指派给某个代理后**自动入队并自动下发**，无需用户手动通知；代理自动领取、自动执行 |
| 智能体代理（新增） | AGT-04 | 执行状态与记录：未指派/待领取/执行中/已完成/失败状态；任务详情可见执行记录时间线；成功回报自动完成任务；失败可「重新执行」 |
| 智能体代理（新增） | AGT-05 | 助手（LLM）指派能力：对话中可将任务指派给代理（指派即自动执行）（可裁剪项） |
| 项目页 | PRJ-02 | 新增项目页与新建项目页；项目与普通任务在页面/路由层彻底分离（项目详情归入项目路径） |
| 任务页 | PRJ-03 | 任务页纯化为普通任务：移除任务类型分段控件、类型筛选与项目相关入口 |
| 清单下线 | LIST-01 | 删除任务界面清单相关的全部功能（管理页/筛选/表单字段/展示/对话能力），由项目替代；数据保留、任务归属一次性归位 |
| 日程主页 | CAL-03 | 修复日程主页上滑无法折叠日历的 BUG（下拉展开行为保持） |

### 1.2 产品目标（v0.7.0）

- **核心目标**：
  1. 助手从"记录与提醒"升级为"可以派活"：用户能在助手里创建多个智能体代理，**把任务指派给代理即完成派活**（下发、领取、执行、回报全自动），并在任务上看到执行过程与结果；
  2. 外部智能工具（Claude Code、opencode、pi agent 等）能以 MCP 客户端身份接入助手，指派后自动感知新任务、自动领取、自动回报，无需为每个工具单独定制对接，也无需用户二次触发；
  3. 组织维度唯一化：**项目**是任务分组与推进的唯一容器；任务页只管普通任务、项目页只管项目，页面职责与入口一一对应；
  4. 清单概念对用户消失：任务不再有"属于哪个清单"的负担，也不再有清单管理、清单筛选与同清单约束的心智负担；
  5. 日程主页手势可用：上滑折叠与下拉展开双向都可靠生效。
- **成功假设**：
  1. 智能体代理上线 4 周内：活跃用户中创建过 ≥1 个代理的比例 ≥ 20%；使用过代理的用户中，被指派任务占其新建任务比例 ≥ 15%；"指派→代理领取"时延中位数 ≤ 30s；
  2. 代理执行闭环可用：领取任务的成功率 ≥ 99%（无并发冲突误报），"回报成功→任务自动完成"零错单；失败任务 100% 携带可读原因；
  3. 页面分离后："在任务页找项目/在项目页找普通任务"类困惑反馈归零；任务页与项目页的列表查询性能不劣于 v0.6.0；
  4. 清单下线后："清单与项目分不清"类反馈下降 ≥ 90%，用户不再产生清单相关的功能性诉求；
  5. 日历手势：上滑折叠成功率 ≥ 98%（列表可滚动场景下连续 10 次全部成功），手势相关投诉归零。

### 1.3 非目标（v0.7.0 不做）

- **不做智能体编排与协作**：不做多代理协作、任务依赖/DAG、串并行编排、代理间通讯、按能力/负载自动路由与自动分派（用户只做"指派"这一个显式动作，选哪个代理由用户决定；下发与执行自动，但不对多任务做编排调度）；
- **不做代理托管与安装**：不负责在用户机器或服务端安装、升级、守护外部智能工具，不提供 stdio 形态的本地进程拉起；用户自行安装并在工具侧配置 MCP 接入；
- **不做代理写操作**：智能体不能创建/修改/删除任务、日程、项目，也不能操作清单；只能**读取被指派给它的任务**并回报执行结果（进度/完成/失败）；
- **不做执行产物的文件/代码传输**：不上传/展示代码 diff、附件、构建产物、截图，仅支持文本结果摘要与进度留言；
- **不做实时日志流与终端回放**：仅提供执行记录时间线摘要（指派/入队/领取/进度/完成/失败/重新执行）；
- **不做用户手动触发的执行开关**：不提供"通知执行/暂停/撤回通知"等二次触发按钮（指派即自动执行）；也**不做 App 内推送通知与消息提醒**（延续全版本边界）——指派结果仅表现为任务状态与端上"等待代理领取/执行中"标识，不产生手机推送；
- **不做失败自动重试与重试策略编排**：失败后需用户显式「重新执行」（不自动循环重试、不做退避/次数上限策略）；
- **不做代理配额、计费、代理市场/模板市场、多用户共享代理**；
- **不做项目能力扩展**：不做看板/甘特/里程碑/项目模板/项目报表；项目仍为个人容器；
- **不做清单能力的替代品**：不引入标签、分组、文件夹等新组织维度，项目即唯一组织维度；不提供清单数据导出与清单数据可视化；
- **不物理删除清单数据**：清单表与任务的清单列保留在库（能力下线、数据归位），以便回滚与审计；
- **不做日程主页其余手势与布局改造**：仅修 CAL-03 的上滑折叠缺陷；头部布局、下拉展开、左右翻月/翻周、浮动今日、形态保持均不变；
- **不做深色模式、字号调节、多语言、PC 端专门适配**。

## 2. 目标用户与使用场景

### 2.1 目标用户

延续全体个人用户，本版尤其面向：

- **重度使用外部智能工具的用户**：日常用 Claude Code / opencode / pi agent 写代码、查资料、整理文档，希望"任务在助手里、执行在工具里"打通；
- **需要把活派出去的用户**：把可自动化/可委托的任务（如"整理本周会议纪要""把这份数据清洗成 CSV"）交给代理，自己只做验收；
- **对页面职责敏感的体验向用户**：希望任务页就是任务、项目页就是项目，不再有类型筛选与清单概念。

### 2.2 核心使用场景

| 场景 | 描述 |
| --- | --- |
| 创建代理并接入工具 | 用户在抽屉进入「智能体」→＋ 新建代理，选择类型「Claude Code」，填名称"工作机-CC"，保存后看到接入地址与凭据（仅此一次完整可见），按指引把配置粘贴到本地 Claude Code 的 MCP 配置中；回到助手，代理状态从"未连接"变为"已连接（1 分钟前）"。 |
| 指派即执行 | 用户在任务「整理本周会议纪要」详情点「指派给智能体」→ 选"工作机-CC"；**指派完成即自动入队下发**，任务显示"等待代理领取"，用户无需再做任何操作；代理侧自动感知新任务、自动领取、自动执行，回报完成并附一段结果摘要；任务自动标记完成，详情里的执行记录显示完整时间线（指派 → 入队 → 领取 → 完成）。 |
| 代理连续接活 | 同一代理被连续指派多个任务，全部自动入队；代理按待执行队列顺序自动领取执行，无需用户逐个触发；已领取的任务再被其他代理领取时被明确拒绝（"任务已被领取"）。 |
| 执行失败与重试 | 代理执行失败，自动回报原因"缺少访问权限"；任务保持未完成，详情显示失败状态与原因；用户补权限后点「重新执行」，任务重新入队，代理自动再次领取执行。 |
| 代理离线时指派 | 用户在代理离线时把任务指派给该代理：任务立即进入待执行队列并显示"等待代理领取（代理当前离线）"；用户无需再做操作，代理连接后自动领取执行。 |
| 代理凭据泄漏处置 | 用户怀疑本机凭据泄漏，在代理详情点「重置凭据」：旧凭据立即失效，拿到新凭据后更新本地工具配置；期间已在执行中的任务不受影响。 |
| 任务页与项目页分离 | 用户点抽屉「任务」只看到普通任务（未归属项目的待办）；点「项目」看到项目卡片列表（名称、进度 2/5、截止时间）；＋ 直接进入新建普通任务页；在项目页 ＋ 进入独立的新建项目页。 |
| 清单概念消失 | 用户升级后：任务页顶部不再有清单筛选与"管理清单"入口；任务表单不再有"所属清单"行；任务卡片不再显示清单名；对话里说"把任务放到 XX 清单"时，助手说明清单能力已下线并建议用项目组织。 |
| 日程主页上滑折叠 | 用户在日程主页浏览完当天安排（列表内容超过一屏），从列表顶部向上滑动，月历随手势收起为选中日所在周，列表获得更大空间；需要看整月时在列表顶部下拉，月历重新展开。 |

## 3. 产品整体说明

### 3.1 产品形态（延续）

- 仍为**移动端 Web（H5）**瘦客户端：任务/项目规则校验、代理与任务状态机、MCP 协议处理、LLM 编排均在服务端完成，端上仅展示与交互；
- 延续全云端架构：代理、指派关系、执行记录、任务与项目均存云端数据库，端上不缓存；
- 延续单会话、服务端统一 LLM 代理、Function Calling + SSE 流式、模型可在服务端替换的总体架构；
- **新增的对外形态**：服务端在原有 REST（App 端）之外，**新增 MCP 接入面**（面向外部智能体），两者共用同一套领域服务（"领域唯一入口"原则延续）。

### 3.4 任务、项目、智能体代理三者关系（关键，避免误解）

v0.7.0 不改变 v0.6.0 的任务模型，只在其上新增"执行维度"，并删掉"清单维度"：

| 概念 | 关系 |
| --- | --- |
| **项目**（task_type=project） | 顶层任务，任务的**唯一组织容器**；必须是根任务（parent_id 为空），项目之间不可嵌套；**项目本身不可指派给代理** |
| **项目成员任务** | 直接挂在项目下的普通任务（仅一层），可安排日程、可指派代理；在任务页不出现（只在项目详情与搜索结果中出现） |
| **普通任务**（task_type=normal） | 独立单任务；可有 0 或 1 个**所属项目**（作为成员）、可有 0 或 1 个**指派代理** |
| **智能体代理** | 用户级的外部智能工具接入身份，不属于任何项目；可同时被指派多个任务 |
| **任务代理执行状态** | 与任务完成状态（todo/completed）**正交的第二个维度**：未指派 / 待领取（指派即自动入队，等待代理领取）/ 执行中（已领取）/ 已完成（成功回报）/ 失败；见 4.7 |
| **清单（已下线）** | v0.7.0 起不再对用户可见、不可管理、不可筛选、不可作为任务表单字段；数据表与任务归属列保留在库，存量归属一次性归位到各用户的默认清单；"同清单"约束（4014）编号保留但失去触发面 |

- 项目与代理**无关**：指派发生在普通任务（含项目成员任务）这一层，项目本身只做容器与进度汇总；
- 一个任务同一时刻最多一个代理；指派即自动执行（无需用户二次触发）；换代理 = 取消旧指派 + 新建指派（旧指派立即出队，历史执行记录保留）；
- 智能体**不能**改变任务的结构（不能创建任务、不能改所属项目、不能改状态），只能回报自己任务的执行进度与结果（见 1.3 非目标）。

## 4. 功能需求一：智能体代理（AGT-01 ~ AGT-05）

### 4.1 概念与术语

| 术语 | 含义 |
| --- | --- |
| 智能体代理（代理） | 用户在助手里创建的一个接入身份，代表一个外部智能工具实例（如本机的 Claude Code） |
| 代理凭据 | 供外部工具接入 MCP 使用的专用密钥，与用户登录令牌（JWT/refresh）**完全独立**；每代理一枚，可重置、可吊销 |
| 指派 | 用户把某个任务安排给某个代理（建立"任务 ↔ 代理"关系）；**指派即自动执行**：指派成功的同时任务自动进入该代理待执行队列并自动下发，无需用户再做任何触发动作 |
| 自动下发 | 服务端在指派成功后自动通过 MCP 通道把任务告知代理（长轮询响应或服务端推送，SDD 定稿），用户无感知、无操作 |
| 领取 | 代理自动由 MCP 原子地取走一个待领取任务，任务进入执行中；同一任务不可被两个代理同时领取 |
| 回报 | 代理执行过程中的自动反馈：进度留言、完成（附结果摘要）、失败（附失败原因） |
| 重新执行 | 失败后由用户显式触发的重排：任务重新入队回到"待领取"，代理自动再次领取执行（不自动重试） |
| 执行记录 | 任务维度的代理交互时间线：指派（含自动入队）/ 取消指派 / 领取 / 进度 / 完成 / 失败 / 重新执行，含时间与来源代理 |

### 4.2 代理的创建与管理（AGT-01）

- **代理字段**：
  - 名称（必填，≤50 字符，同一用户内唯一，建议名如"工作机-CC"）；
  - 类型（必填，预设：Claude Code / opencode / pi agent / 其他；选"其他"时填写自定义名称，≤30 字符）；类型仅用于展示与接入指引，不改变协议行为；
  - 描述/用途（可选，≤200 字符）；
  - 状态：`已启用` / `已停用`（用户手动停用后凭据立即失效，代理无法再通过 MCP 调用）；
  - 连接状态（派生，非用户可编辑）：**未连接**（从未成功调用）/ **已连接**（最近活跃时间在活跃窗口内，建议 5 分钟，SDD 定稿）/ **离线**（曾连接但超出活跃窗口）；
  - 最近活跃时间、创建时间、当前进行中任务数。
- **操作**：创建、编辑（名称/类型/描述）、启用、停用、重置凭据、删除。
- **删除规则**：删除前必须告知影响——该代理当前关联的任务数（待领取/执行中分别计数），二次确认后删除；删除后：
  - 凭据立即失效；
  - **待领取**任务回到"未指派"（不丢任务，只是不再排队，用户可另指派其他代理）；
  - **执行中**任务保持"执行中"状态但标记为"代理已删除"，等待用户处理（重新指派或取消指派）；
  - 历史执行记录保留（内容不删除，端上标注"代理已删除"）。
- **空态**：无代理时列表页引导"还没有智能体代理，点右上＋创建，把任务交给你的工具去执行"。

### 4.3 代理凭据与 MCP 接入（AGT-02）

- **凭据生成**：创建代理时自动生成一枚凭据；**明文仅在创建成功与重置成功时完整展示一次**，此后端上只显示前缀与"已生成"状态，不可再次查看（丢失只能重置）；
- **凭据重置**：新凭据生成后旧凭据**立即失效**；重置需二次确认（提示"已在本地工具中使用的旧凭据将立即失效，需更新配置"）；
- **接入信息**：代理详情展示可直接复制的接入信息，至少包含：MCP 服务地址、凭据、以及针对常见工具（Claude Code / opencode / pi agent）的**配置片段示例**（让用户复制即用）；
- **接入方式**：服务端提供 MCP 接入端点，外部工具以 MCP 客户端身份通过 HTTP 传输接入（协议版本、传输形态、端点路径与 JSON-RPC 细节由 SDD 定稿）；**不提供 stdio 形态的服务端托管**（本地工具按自身能力接远程 MCP 服务）；
- **鉴权**：MCP 请求必须携带代理凭据；凭据无效/已重置/代理已停用 → 拒绝并返回统一鉴权错误（4019，见 4.11）；鉴权失败不泄露任何业务数据；
- **连接可见性**：任一成功的 MCP 调用都会刷新该代理的"最近活跃"；端上代理列表与详情据此展示连接状态；
- **接口下线影响**：本项为纯新增，不影响 App 端既有 REST 与用户令牌体系。

### 4.4 代理侧可选用的能力（MCP 工具集，AGT-02）

代理通过 MCP 可用的能力（工具命名与参数细节由 SDD 定稿，以下是**产品能力清单与约束**）：

| 能力 | 说明 | 约束 |
| --- | --- | --- |
| 查询我的任务 | 返回被指派给本代理的任务列表（可按执行状态筛选），含任务 ID、标题、备注、优先级、截止时间、所属项目名、指派（入队）时间 | 仅限指派给本代理的任务 |
| 等待新任务 | 长轮询等待新任务自动入队（建议单次挂起上限 25s，SDD 定稿），超时返回空并允许客户端再次调用；建议代理侧常驻该调用以形成"自动执行"闭环 | 仅本代理队列 |
| 领取任务 | 原子领取一个待领取任务，成功返回任务详情；**任务已被其他代理领取/已被取消指派** → 明确拒绝（4020）；**重复领取同一任务** → 明确拒绝（4020） | 幂等友好：重复领取不产生二次状态变更 |
| 查询单个任务详情 | 返回任务全文（标题/备注/优先级/截止/所属项目）+ 本代理在该任务上的历史进度 | 仅限指派给本代理的任务 |
| 回报进度（可选） | 追加一条进度留言（≤500 字符），任务保持执行中，端上时间线可见 | — |
| 回报完成 | 提交结果摘要（≤2000 字符），任务转为已完成（见 4.7） | 仅"执行中"任务可回报完成 |
| 回报失败 | 提交失败原因（≤500 字符），任务保持未完成并显示失败状态 | 仅"执行中"任务可回报失败 |
| 查询我执行过的任务 | 返回本代理的历史任务与终态（可选能力） | 仅限本代理 |

- **权限边界（硬要求）**：代理只能读取与回报"被指派给它的任务"；访问未指派任务、他人数据一律拒绝（与 App 端一致的"不存在"语义，避免探测）；代理**没有任何写任务/日程/项目的工具**（见 1.3）；
- **限流**：MCP 端点按代理凭据维度独立限流（建议 60 次/分钟，SDD 定稿）；长轮询并发连接有上限（SDD 定稿），不得阻塞其他请求。

### 4.5 任务指派（AGT-03）

- **可指派对象**：普通任务与项目成员任务（二者都是普通任务形态）；**项目本身不可指派**（对项目指派 → 拒绝，4021）；
- **指派入口（端上）**：任务详情（普通任务面板）新增「智能体执行」区，未指派时显示"指派给智能体"按钮 → 选择代理（底部弹层，列出已启用代理；无代理时引导去创建）；
- **指派结果（指派即执行）**：指派成功**同时**完成任务入队与自动下发——任务直接进入该代理待执行队列（状态"待领取"），**用户不再有任何二次触发动作**；任务的完成状态、所属项目、日程安排均不受影响；
- **一个任务一个代理**：已有代理时只能"更换"（选择"更换代理"= 取消旧指派 + 新建指派，旧指派立即出队，历史记录保留）；
- **取消指派**：允许；待领取任务取消指派 → 立即出队（状态回到"未指派"）；执行中的任务取消指派 → 需二次确认（提示"代理可能仍在执行，取消后回报将被拒绝"）；
- **已完成任务**：不可指派（提示"任务已完成，如需执行请先取消完成"）；
- **队列上限**：指派时若该代理待执行队列已达上限（建议 100 条，SDD 定稿）→ 指派被拒绝（4022）并提示"该代理待执行任务过多，请稍后再试或先处理队列"；
- **边界**：任务被删除时，其指派关系与排队项一并清理，执行记录随任务级联删除。

### 4.6 自动执行流程：自动下发与自动领取（AGT-03）

- **自动下发（无用户操作）**：指派成功即触发对该代理的下发，任务进入待执行队列（状态"待领取"）；下发由服务端自动完成（长轮询响应或服务端推送，由 SDD 定稿）；
- **即时性（硬要求）**：已连接的代理应在**指派后 ≤10s 内可通过 MCP 获得该任务**；建议代理侧以常驻长轮询（或订阅推送）形成"有任务即执行"的自动闭环；
- **代理离线时的语义**：代理离线/未连接不影响指派——任务照常入队，端上显示"等待代理领取（代理当前离线）"；代理连接后**自动领取**，无需用户重试或再次操作；
- **自动领取规则（并发正确性，硬要求）**：
  - 领取是**原子操作**：同一任务在任一时刻只能被一个代理领取成功；并发领取只有一个成功，其余返回 4020；
  - 领取成功 → 任务状态转为"执行中"，记录领取时间与代理（此动作由代理自动发起）；
- **重复入队保护**：同一任务在待领取/执行中状态下不可再次入队（取消指派后重新指派才会重新入队），避免队列重复项；
- **不提供用户侧执行开关**：不提供"通知执行/暂停/撤回通知"等按钮；用户可用的控制动作只有**指派（含更换）**、**取消指派**、**失败后重新执行**（见 1.3 非目标）。

### 4.7 执行回报、状态与记录（AGT-04）

**任务代理执行状态机**（与任务完成状态正交）：

| 状态 | 进入条件 | 可执行动作 |
| --- | --- | --- |
| 未指派 | 初始态 / 取消指派后 / 代理被删除后 | 指派（指派即自动入队） |
| 待领取 | **指派成功（自动入队）** | 取消指派、更换代理；代理侧：领取 |
| 执行中 | 代理领取成功（自动） | 代理侧：回报进度/完成/失败；用户侧：取消指派（二次确认） |
| 已完成 | 代理回报完成成功 | 查看记录；（如需重做）取消指派后重新指派（自动再次入队） |
| 失败 | 代理回报失败 | 「重新执行」→ 回到"待领取"（重新入队）；取消指派 |

- **完成与任务状态的联动**：代理回报**完成** → 任务自动置为 `completed`（记录完成时间），并在执行记录中标注"由代理完成"；用户手动取消完成不影响执行状态与记录（仍显示"已完成（代理）"）；若用户随后取消指派并重新指派，执行状态重置为"待领取"（自动入队），历史记录保留；
- **失败**：任务保持未完成；执行记录与任务详情显示失败原因与时间；支持「重新执行」（由用户显式触发，任务重新入队回到"待领取"，代理自动再次领取）；**失败不自动重试**（见 1.3）；
- **执行记录（时间线）**：任务详情可见，按时间倒序，至少包含：动作（指派（含自动入队）/取消指派/领取/进度/完成/失败/重新执行）、来源代理（名称，删除后标注"代理已删除"）、时间（相对时间 + 可展开绝对时间）、文本（进度/结果摘要/失败原因）；
  - 保留策略：每任务保留最近 N 条（建议 50 条，SDD 定稿），更早记录可按策略清理；
  - 记录为业务数据（用户可见），非服务端日志；
- **重复回报**：相同任务上重复"回报完成"或对非"执行中"任务回报 → 拒绝（4021），保证状态不被反复改写；
- **端上呈现**：任务详情「智能体执行」区显示当前代理、当前状态（等待代理领取/执行中/已完成/失败，附代理在线状态）、最近一次结果/原因摘要、最新 3 条记录 + "查看全部"；失败态显示「重新执行」。

### 4.8 端上呈现（AGT-01/AGT-03/AGT-04）

- **抽屉一级入口「智能体」**：位于「项目」与「助手」之间；
- **代理列表页 `/agents`**：代理卡片行 = 状态点（已连接/离线/停用）+ 名称 + 类型 + 最近活跃（如"3 分钟前"）+ 进行中任务数；顶部 ＋ → 新建代理；空态引导；加载失败显示错误占位 + 重试；
- **新建/编辑代理页**：名称、类型（预设 + 其他自定义）、描述；保存后：新建成功 → 进入代理详情并展示凭据（一次）；编辑成功 → 返回详情；
- **代理详情页 `/agents/:id`**：
  - 头部：名称、类型、连接状态与最近活跃；
  - 凭据区：完整展示仅一次（创建/重置后），其余时间显示前缀 + 「重置凭据」；含 MCP 接入地址与「复制接入配置」；
  - 连接指引：按类型给出对应工具的配置片段（可折叠）；
  - 绑定任务区：按执行状态筛选（全部/待领取/执行中/已完成/失败），行内可跳任务详情；
  - 操作区：编辑、启用/停用、重置凭据、删除（告知影响计数并二次确认）；
- **任务详情「智能体执行」区**：按 4.5~4.7 描述呈现指派（含自动入队状态）、取消指派、重新执行、状态与记录；**不再有"通知执行/撤回通知"按钮**；
- **可访问性**：状态不只靠颜色（配文字标签），按钮热区 ≥44pt，复制操作有成功反馈。

### 4.9 助手（LLM）能力（AGT-05，可裁剪）

- **新增工具**（命名由 SDD 定稿）：
  - `list_agents`：列出用户已启用代理（名称/ID/状态/进行中任务数）；
  - `assign_task_to_agent`：把任务指派给指定代理（任务未完成、代理存在且启用）；**指派即自动入队执行，无需第二个"通知"工具**；
- **提示词补强**：说明"代理/智能体/交给工具执行"类表达的处理方式——选中代理并调用一次指派即可，之后任务会自动被处理；代理不存在或未启用时如实告知并列出可用代理；不得编造代理 ID；
- **对话卡片**：指派结果以任务卡片呈现（含任务标题、代理名、执行状态"等待代理领取"），可点进任务详情；
- **危险操作**：指派可逆（可取消指派），不纳入危险确认；**对话中不提供删除代理**（删除仅在端上代理详情，避免误删）；
- **可裁剪说明**：若评审认为 v0.7.0 范围偏大，AGT-05 可降级为"仅 list_agents + 端上引导"（保留能力，不放开写操作）。

### 4.11 校验、上限与新增错误码

- **上限（建议值，环境变量可配，SDD 定稿）**：单用户代理数 ≤ 20（`AGENT_MAX_PER_USER`）；单代理待执行队列 ≤ 100（`AGENT_QUEUE_MAX`）；代理名称 ≤ 50、类型名 ≤ 30、描述 ≤ 200；进度留言 ≤ 500；结果摘要 ≤ 2000；
- **新增错误码（编号建议，从 4019 起；SDD 定稿）**：

| 编号 | 名称 | 语义 / 触发 | HTTP |
| --- | --- | --- | --- |
| 4019 | AGENT_UNAUTHORIZED | MCP 凭据无效/已重置/代理已停用或已删除；代理侧鉴权失败 | 401 |
| 4020 | AGENT_TASK_CONFLICT | 领取冲突：任务已被其他代理领取、重复领取同一任务、并发领取未抢到 | 409 |
| 4021 | AGENT_TASK_INVALID_STATE | 状态不允许该操作：重复指派（已有代理未取消）、对项目指派、已完成任务指派、对非执行中任务回报、对非失败态任务「重新执行」 | 409 |
| 4022 | AGENT_LIMIT_EXCEEDED | 代理数超出上限，或指派时该代理待执行队列已满 | 409 |

- **既有错误码**：4010（级联完成）、4017（项目须顶层）、4018（普通任务不支持子任务）规则不变；**4014（同清单）编号保留，但清单下线后失去触发面**（与 v0.6.0 对 4013/4015 的处理一致）；
- 代理名称重复 → 复用 1005 CONFLICT；名称/描述超长、凭据格式错误、非法类型 → 复用 1001 PARAM_INVALID。

### 4.12 安全与隐私

- **凭据安全**：只存哈希；明文仅创建/重置时返回一次；凭据不得出现在服务端日志、埋点、错误信息与响应体中（除那一次返回）；
- **最小权限**：代理只能访问"指派给它的任务"；跨代理、跨用户访问统一按"不存在"处理；代理无任何任务/日程/项目写权限；
- **审计**：每次 MCP 调用记录审计（agent_id、方法、任务 ID、结果、耗时、traceId，复用既有工具审计表或新建，SDD 定稿）；审计不含任务正文；
- **日志规范**：服务端日志不记录任务标题/备注正文、执行结果正文（沿用"只记 ID 与事件"规范）；端上执行记录属用户可见业务数据；
- **限流与防爆破**：MCP 端点独立限流（按代理凭据维度）；连续鉴权失败计入日志与限流；
- **注销账号**：级联删除代理、凭据、指派关系与执行记录（既有用户级联删除路径）；
- **客户端信任边界**：服务端不信任代理回报内容的语义正确性（只做长度与状态校验），不据回报内容执行任何动作；回报文本在端上按纯文本渲染（不做 HTML 注入）。

### 4.13 边界与异常

- 代理凭据重置后，**执行中**任务仍可回报（状态保留），但回报必须使用新凭据；旧凭据的进行中请求被拒绝（4019）；
- 代理删除后，执行中任务的回报一律拒绝（4019），端上提示"代理已删除，请重新指派"；
- 待领取任务长期无人领取（代理长期离线）：不自动过期、不自动改派（保留排队），端上显示入队时间与代理在线状态以便用户判断，用户可取消指派或改派其他代理；
- 同一任务"指派 → 取消指派 → 重新指派"可反复进行，记录逐条留痕；同一任务在待领取/执行中状态下不会产生重复队列项；
- 任务在"待领取/执行中"期间被用户删除：级联删除指派关系与执行记录；代理侧后续领取/回报该任务 → 按"不存在"拒绝；
- 任务在"执行中"被用户改标题/备注/截止时间：允许，代理侧下次查询/回报即拿到最新内容（不锁定字段）；
- 网络抖动导致代理重复调用"领取/回报"：由原子领取与回报幂等（同状态重复回报拒绝但不产生脏状态）保证一致性；
- 代理侧长轮询断开：返回空结果，客户端可立即重连；不产生错误状态。

### 6.4 存量数据归位（迁移 013）

- 迁移 `013_task_list_retire.sql`（幂等、可重复执行）：
  1. 将每个用户的**全部任务**（含项目与项目成员，不论当前属于哪个清单）`list_id` 归位到该用户的默认清单；
  2. 删除该用户的**自定义清单行**（默认清单保留；此时已无任务引用自定义清单，外键不阻塞）；
  3. 若存在异常数据（如无默认清单的用户），需在迁移中兜底补齐默认清单后再归位；
- **零丢失**：任务、项目、成员关系、完成状态、日程关联、备注等全部保留；**唯一有意调整**是任务的清单归属被统一（原多清单归属信息不再对用户可见，但任务本身不受影响）；
- **回滚考虑**：保留表与列使回滚成本可控（回滚后用户可重新建清单，但原归属无法自动还原——属可接受代价，评审确认）。

### 6.5 边界与不做

- 升级后首次进入任务页：无清单筛选、无清单名；用户不会看到"默认清单"字样；
- 历史对话消息中的清单名文本：属于历史消息内容，不删除、不改写（仅不再产生新的清单内容）；
- 清单接口下线对 App 端无影响（端上清单入口已删除，无调用方）；
- 清单相关的 4014 错误不再产生；端上不再有对应提示文案；
- 本版不提供"清单迁移到项目"的自动转换（用户如需归组，自行建项目并把任务移入）。

## 7. 功能需求四：日程主页上滑折叠 BUG 修复（CAL-03）

### 7.1 现象与复现

- **现象**：日程主页在列表顶部**向上滑动无法折叠日历**；折叠态下拉展开正常。表现为"日历只能展开、不能收起"，长期占屏。
- **复现（真机/移动端浏览器）**：
  1. 进入日程主页（日历默认展开），选中某天并使其**日程列表内容超过一屏**（可滚动）；
  2. 手指置于列表区域顶部向上滑动（纵向位移明显大于横向，位移 ≥ 32px）；
  3. 结果：列表只发生滚动，日历形态不变；反复尝试均不折叠。
- **对照**：当日程列表内容不足一屏（列表不可滚动）时，上滑有时能折叠；折叠态在列表顶部下拉可正常展开。

### 7.2 根因分析（基于现有实现）

现有实现要点（`src/web/src/views/calendar/MonthView.vue`）：

- 形态手势监听绑定在**日程列表滚动容器**上（`.month__body`，`ref="listEl"`），且 `touchstart` / `touchmove` 均为 `passive`（`onShapeTouchStart` / `onShapeTouchMove`）；
- 起手判定：`onShapeTouchStart` 仅在 `list.scrollTop <= 2`（`LIST_TOP_TOLERANCE`）时记录起手点，否则放弃本次手势；
- 移动判定：`onShapeTouchMove` **每一帧都重新读取实时的 `list.scrollTop`**，只要 `> 2` 就 `return`（视为"已离开列表顶部"，交还滚动）；
- 折叠条件：`!collapsed && dy <= -32`（`SHAPE_THRESHOLD_PX`）；展开条件：`collapsed && dy >= 32`。

**根因**：向上滑动时，由于监听是 passive 的，列表内容会**先被浏览器按原生滚动上移**；在手指位移达到 32px 阈值之前，`scrollTop` 就已超过 2px 容错值，`touchmove` 判定随即认为"不在列表顶部"而放弃，折叠分支**不可达**。向下拉展开方向因列表顶部无法向上越界滚动、`scrollTop` 恒为 0 而不受影响，因此表现出"只展开不折叠"的不对称现象；当列表内容不足一屏（不可滚动）时 `scrollTop` 恒为 0，折叠偶发可用，因此该缺陷与"列表内容多少"强相关，容易被误判为"偶发不灵"。

**次要因素**：形态手势的起手区域仅限列表容器；用户在日历网格区域起手上滑完全不参与形态判定；列表底部空白区起手同样受同一 `scrollTop` 判定影响，实际可用起手区比预期小。

### 7.3 修复要求（行为级）

1. **判定基准改为"起手快照"**：本次手势是否从列表顶部开始，以 `touchstart` 时刻的滚动位置为准；手势进行中不再用实时 `scrollTop` 取消判定。起手时列表不在顶部 → 本次手势只滚动列表（不切换形态）；
2. **上滑折叠必达**：当"起手在列表顶部"且"纵向位移达阈值且方向为纵向"时，**必须**触发折叠；与列表内容是否可滚动、是否已产生原生滚动位移无关；
3. **下拉展开保持不变**：现有展开行为、阈值与判定逻辑不回退，双向对称（同一套阈值与方向锁）；
4. **一次手势只触发一次**：触发后本次手势不再重复触发形态切换，剩余位移交还列表滚动，不产生跳动、不回弹、不抢滚动；
5. **防抖参数沿用**：起手观察期 8px、方向锁 1.5 倍（纵向显著大于横向）、阈值 32px、动画 250ms 内忽略新手势、列表已离开顶部（起手判定）不接管；
6. **可选的跟手反馈**：折叠触发前可提供不超过阈值的位移跟手反馈（程度与形式由 UXUI 定稿，不强制，不作为验收项）；
7. **起手区域**：至少保证"列表区（含列表底部空白区）"起手有效；是否将起手区扩展到日历区下沿（不得影响日历区左右翻月/翻周手势的优先判定）由 UXUI 与 SDD 定稿（建议扩展，但方向锁必须能区分横竖）；
8. **状态不残留**：一次未触发的上滑手势结束后，手指回到顶部再上滑可立即正常触发；页面切换/详情返回后形态与选中日按既有 5 分钟机制恢复（`collapsed` 已纳入 `lastView`）。

### 7.4 回归要求

- 左右滑动：展开态翻月、折叠态翻周、选中日与年月同步、补位日切月，均不回归；
- 折叠态跨月周的邻月计数补齐、月格标记点，不回归；
- 折叠/展开动画连续（高度过渡），动画期间忽略新手势，不出现回弹；
- 列表正常滚动、惯性滚动、`overscroll-behavior: contain` 行为不变；滚动到列表中部后上滑只滚动列表；
- 详情返回的形态/选中日/滚动位置恢复机制不回归；
- 浮动「今日」按钮、头部三元素（菜单/月份/＋）不回归。

### 7.5 验收方式（硬要求）

- 在"列表内容超出一屏"的场景下，从列表顶部连续上滑 10 次，10 次均折叠成功（成功率 100%，≥98% 为达标下限）；
- 在列表已滚动到中部时上滑 10 次，形态均不变（只滚动）；
- 折叠态在列表顶部下拉 10 次，10 次均展开成功；
- 真机（微信 WebView + iOS/Android 浏览器）专项验证通过，手势无跳动、无卡顿投诉。

## 8. 非功能性需求

### 8.1 性能

- **MCP 端点**：单次工具调用（领取/回报/查询，不含长轮询等待）P95 ≤ 300ms；待执行队列查询（≤100 条）P95 ≤ 200ms；
- **指派即时性**：指派成功后已连接代理在 ≤10s 内可获取任务（长轮询单次挂起上限建议 25s，SDD 定稿）；长轮询连接有并发上限且不阻塞其他请求处理（实现方式由 SDD 定稿）；
- **端上**：代理列表/详情首屏 P95 ≤ 300ms；任务详情的「智能体执行」区不引入额外串行请求（随详情返回或并行加载）；项目页列表查询 P95 不劣于 v0.6.0 任务列表；
- **清单下线收益**：任务列表查询减少一次 `task_lists` JOIN 与一次按清单过滤，查询路径只减不增；
- **日历手势**：修复后形态切换与列表滚动不互相抢手势，动画跟手流畅、不掉帧；监听保持 passive（不阻塞滚动）；
- 长轮询与 MCP 限流不得影响 App 端 REST 与聊天 SSE 的响应时间。

### 8.2 兼容性与数据

- **迁移**：`012_agent_proxy.sql`（新表/新列/索引，零回填）与 `013_task_list_retire.sql`（清单归位与自定义清单清理）均**幂等、可重复执行**；单迁移单事务（沿用现有机制）；
- **数据零丢失**：任务、项目、成员关系、日程、会话、记忆、长期记忆均不受影响；清单数据（表与列）保留在库；
- **DTO 变更**：任务不再返回 `list_id`/`list_name`；新增 `agent_*` 字段；旧客户端忽略新字段即可，但不再展示清单名（端上随版本升级）；
- **接口变更**：清单 4 个接口下线（旧客户端命中 → 1004）；任务接口不再接受 `list_id` / `list_name` 参数（携带即参数校验失败或忽略，SDD 定稿，建议明确拒绝并提示）；新增 11 个代理/指派接口（见 4.10）；
- **路由兼容**：`/lists`、`/tasks/new?task_type=project`、项目形态的 `/tasks/:id`、`/tasks/:id/edit` 均有重定向，书签与历史不报死链；
- **凭据与状态兼容**：重置凭据不影响执行中任务的状态（但旧凭据请求被拒）；删除代理后其待领取任务回到"未指派"（不丢任务），执行中任务保持"执行中（代理已删除）"；
- **演练要求**：迁移须在 v0.6.0 类生产存量库快照上演练通过，覆盖：多清单用户（任务分散在多个清单）、项目与成员任务、任务日程归属、含手动创建的自定义清单、无默认清单的异常用户；演练需验证"归位后任务/项目/日程数量与关联关系不变"；
- **历史聊天**：含清单名的历史消息不改写；项目卡片按新路径打开。

### 8.3 隐私与安全

- 智能体代理凭据只存哈希、仅创建/重置时明文返回一次；凭据不得进入日志、埋点、错误信息；
- 代理最小权限（只读被指派任务 + 回报）与"不存在的等价语义"越权处理；代理无写任务/日程/项目/清单能力；

- 注销账号级联删除代理与执行记录；代理删除后凭据立即失效；
- 清单下线不引入新的数据暴露面；清单接口下线后不存在"清单数据被读取"的路径；
- 端上渲染：代理回报文本按纯文本渲染，防注入。

## 9. 关键业务流程与验收标准

### 9.1 关键业务流程

**流程一：创建代理并接入外部工具**

```
抽屉「智能体」→ ＋新建代理（名称/类型/描述）→ 保存
  → 代理详情展示凭据（仅一次）＋ MCP 接入地址 ＋ 复制配置片段
  → 用户在本地工具（Claude Code / opencode / pi agent）粘贴配置
  → 工具发起 MCP 调用成功 → 代理状态变为「已连接」，最近活跃刷新
异常：凭据错误/代理停用 → MCP 调用被拒（4019）；凭据丢失 → 端上重置凭据（旧凭据立即失效）
```

**流程二：指派任务（指派即自动执行）**

```
任务详情（普通任务/项目成员任务）→「智能体执行」→ 指派给代理（未完成、项目本身不可指派）
  → 指派成功 = 自动入队 + 自动下发 → 状态：待领取（用户操作到此结束，无二次触发）
     - 代理在线：≤10s 内自动获得任务
     - 代理离线：显示"等待代理领取（代理当前离线）"，代理连接后自动领取
  →（可选）更换代理：旧指派出队，历史记录保留
  →「取消指派」→ 出队，状态回到未指派
异常：重复指派/对项目指派/已完成任务指派 → 4021；该代理队列已满 → 4022
```

**流程三：代理自动领取、执行与回报**

```
代理侧常驻（自动执行闭环，无需用户参与）：
  长轮询等待新任务 / 查询待执行任务 → 自动领取（原子）→ 状态：执行中（记录领取时间）
  →（可选）自动回报进度（时间线可见）
  → 自动回报完成（结果摘要）→ 任务自动完成 + 状态：已完成 + 执行记录留痕
  → 或自动回报失败（原因）→ 任务保持未完成 + 状态：失败 + 原因可见
用户侧仅在需要时介入：
  - 失败后点「重新执行」→ 重新入队 → 代理自动再次领取
  - 放弃则「取消指派」→ 出队
异常：
  - 其他代理/重复领取同一任务 → 4020（无二次状态变更）
  - 对非执行中任务回报 → 4021
  - 代理被删除后回报 → 4019，端上提示重新指派
```

**流程四：代理凭据轮换与代理删除**

```
重置凭据：二次确认 → 新凭据生成（旧凭据立即失效）→ 用户更新本地配置
  - 执行中任务状态保留，用新凭据回报
删除代理：展示受影响任务计数（待领取/执行中）→ 二次确认 → 删除
  - 待领取任务回到「未指派」（用户可另指派其他代理）
  - 执行中任务标记「代理已删除」，等待用户重新指派或取消
  - 执行记录保留并标注「代理已删除」
```

**流程五：项目页与任务页分离**

```
抽屉「任务」→ 仅普通任务列表（无类型筛选、无清单筛选）
抽屉「项目」→ 项目列表（进度/成员计数/截止）→ 点项目 → /projects/:id
项目页 ＋ → /projects/new（名称/备注/优先级/截止时间）→ 保存 → 项目详情 → 添加成员
任务页 ＋ → /tasks/new（无类型分段；可选所属项目）→ 保存
旧链：/lists → /tasks；/tasks/new?task_type=project → /projects/new；项目形态 /tasks/:id → /projects/:id
```

**流程六：清单功能下线与数据归位**

```
升级 → 迁移 013：全部任务 list_id 归位到各用户默认清单 → 删除自定义清单行
端上：清单管理页/清单筛选/"所属清单"行/各处清单名 → 全部消失
对话：清单工具下线；用户提到清单 → 助手说明已下线并建议用项目
服务端：清单接口下线；任务读写不再解析清单参数；DTO 不再返回清单字段
```

**流程七：日程主页上滑折叠修复验证**

```
进入日程主页（默认展开）→ 选中某天使其列表内容超过一屏
  → 列表顶部上滑（≥32px、纵向为主）→ 日历折叠为选中周  ← 修复后必达（原缺陷：不折叠）
  → 折叠态列表顶部下拉 → 日历展开为整月
  → 列表已滚动到中部上滑 → 只滚动列表，形态不变
  → 动画期间再次手势 → 忽略，不重复触发
```

### 9.2 验收标准

**AGT-01 代理管理**

1. 可创建多个代理（名称唯一、类型预设含 Claude Code/opencode/pi agent/其他、描述可选）；可编辑、启用/停用、重置凭据、删除；列表展示状态（已连接/离线/未连接/已停用）、最近活跃与进行中任务数；
2. 凭据明文仅创建/重置时展示一次；重置后旧凭据立即失效；停用后代理无法通过 MCP 调用（4019）；
3. 删除代理前告知受影响任务数并二次确认；删除后待领取任务回到"未指派"、执行中任务标记"代理已删除"、执行记录保留；超出代理数上限被拒绝（4022）。

**AGT-02 MCP 接入**

4. 外部智能工具可用代理凭据通过 MCP 接入，完成"查询待执行任务/等待新任务/领取/汇报进度/回报完成/回报失败/查任务详情"；接入信息与配置片段可直接复制；
5. 凭据无效/已重置/代理停用/已删除的 MCP 调用返回 4019 且不泄露业务数据；代理只能访问被指派给它的任务，越权统一按"不存在"拒绝；
6. 代理无任何任务/日程/项目写能力；MCP 端点按代理维度限流，超限被拒绝；每次调用有审计记录（不含正文）。

**AGT-03 指派与自动执行**

7. 普通任务与项目成员任务可指派代理；项目本身指派被拒（4021）；一个任务同一时刻只有一个代理；可取消指派、可更换代理；
8. **指派即自动执行**：指派成功后任务立即进入"待领取"并自动下发，端上无"通知执行/撤回通知"等任何二次触发按钮；已连接代理 ≤10s 内可获得任务；代理离线时照常入队并显示"等待代理领取（代理当前离线）"，代理连接后自动领取，无需用户重试；
9. 重复指派/对项目指派/已完成任务指派被拒（4021）；该代理队列已满时指派被拒（4022）并有明确提示；待领取任务取消指派立即出队且不回退其它数据；领取为原子操作，并发/重复领取只有一个成功，其余 4020。

**AGT-04 执行状态与记录**

10. 执行状态机按 4.7 正确流转：未指派/待领取/执行中/已完成/失败（无独立"已指派"中间态）；与任务完成状态正交；
11. 代理回报完成 → 任务自动完成，执行记录留痕（含来源代理与时间）；回报失败 → 任务保持未完成并显示原因，用户点「重新执行」后任务重新入队（不自动重试）；对非执行中任务回报、对非失败态任务重新执行被拒（4021）；
12. 任务详情可见执行记录时间线（动作/代理/时间/文本，倒序，最新 3 条 + 查看全部）；代理删除后记录保留并标注；任务删除时记录级联删除。

**AGT-05 助手能力（若保留）**

13. 对话中"把任务交给 XX 代理执行"一次指派即完成派活（无第二个"通知"动作），结果以任务卡片呈现（含代理名与"等待代理领取"状态）；代理不存在/未启用时如实告知并列出可用代理，不编造 ID；对话中不提供删除代理。

**PRJ-02 / PRJ-03 项目页与任务页分离**

14. 抽屉含「项目」一级入口；`/projects` 仅显示项目（卡片含进度/成员计数/截止时间），支持状态筛选与排序，空态与筛选态空态正确；`/projects/new` 为独立新建项目页，字段符合 5.2，保存后进入项目详情；
15. 项目详情走 `/projects/:id`，头部无清单行，成员列表/添加成员/安排日程/编辑/级联完成/级联删除功能零缺失；`/projects/:id/edit` 可编辑项目；
16. `/tasks` 仅显示普通任务（不含项目与项目成员），无类型筛选、无清单筛选；`/tasks/new` 无类型分段控件且恒创建普通任务；`/tasks/:id` 与 `/tasks/:id/edit` 仅处理普通任务；
17. 旧链重定向正确无死链：`/lists`→`/tasks`、`/tasks/new?task_type=project`→`/projects/new`、项目形态的任务详情/编辑→项目路径；对话项目卡片与搜索结果按类型正确跳转；
18. 默认启动页新增「项目」选项并正确生效（若决议通过）；顶部栏与抽屉高亮、返回语义正确。

**LIST-01 清单下线**

19. 端上不存在任何清单功能：无清单管理页与路由（旧链重定向）、无清单筛选与"管理清单"入口、表单无"所属清单"行、任务/项目/日程/对话卡片/搜索结果均无清单名；
20. 对话中清单工具与提示词已删除；用户提到清单时助手如实说明并建议用项目；不再产生清单类长期记忆；
21. 清单 REST 接口下线（旧调用 → 1004）；任务接口不再解析清单参数；任务 DTO 不再返回清单字段；注册默认清单兜底逻辑保留；
22. 迁移 013 幂等可重复执行：全部任务归位到各用户默认清单、自定义清单行删除、异常用户（无默认清单）有兜底；任务/项目/成员关系/日程/备注零丢失；演练结果与预期一致。

**CAL-03 手势修复**

23. 列表内容超出一屏时，从列表顶部上滑 10/10 次折叠成功；列表已滚动时上滑只滚动列表；折叠态顶部下拉 10/10 次展开成功；

25. 回归零缺陷：左右翻月/翻周、跨月周计数、形态与滚动位置恢复、浮动今日、头部三元素、列表滚动与惯性滚动均不回归。

**非功能**

26. 性能指标（8.1）达标：MCP 调用与队列查询时延、指派即时性（指派→代理可获取 ≤10s）、页面首屏、长轮询不阻塞；
