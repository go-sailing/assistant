## 1. 设计目标与原则

### 1.1 设计目标

1. **派活只需一次点击**：用户在任务详情点「指派给智能体」→ 选代理，交互即结束；此后"等待代理领取 → 执行中 → 已完成（由代理完成）"全部自动推进，界面用一条状态链把"机器正在替我干活"讲清楚；
2. **代理是可管理、可接入的实体**：代理列表/详情让用户看清"哪个工具在线、在用几个任务、凭据在哪里、怎么接入"；凭据一次性可见 + 可重置，接入配置可一键复制到 Claude Code / opencode / pi agent；
3. **项目与任务各归其位**：项目页只放项目、任务页只放普通任务，新建入口也各自独立，页面标题与内容一一对应，不再有类型筛选与类型分段开关；
4. **清单概念从界面彻底消失**：任务页、任务表单、任务/项目/日程/对话卡片、搜索与设置中不再出现"清单"字样与入口；组织任务只用项目；
5. **日历手势真正可用**：上滑折叠与下拉展开双向都可靠触发，视觉与手势反馈保持 v0.6.0 基线不变（本版只修行为，不新增视觉控件）。

### 1.2 设计原则（v0.7.0 新增/强化）

| 原则 | 说明 |
| --- | --- |
| **一次触发，自动到底** | 凡"用户已表达意图、后续可由系统完成"的环节一律自动（指派→入队→下发→领取）；界面不设第二个触发按钮，也不设"暂停/撤回"类开关 |
| **状态可见，操作可逆** | 自动链路必须可见（等待领取/执行中/已完成/失败 + 入队时间 + 代理在线状态）；用户随时可「取消指派」纠正，失败可「重新执行」 |
| **凭据只露一次** | 代理凭据明文仅在创建/重置成功的那一次展示，页面必须显著提示"立即复制保存"，之后只显示前缀与重置入口 |
| **一个页面一个对象** | 项目页=项目、任务页=普通任务、智能体页=代理；页面内不再用"类型筛选/类型切换"承担分流 |
| **删除即抹平** | 清单下线要连"文字残留"一起清：筛选、表单行、卡片副行、空态文案、对话文案、危险确认文案、埋点与死代码全清 |
| **能力可用，心智为零** | 清单的"归组"能力由项目承接；用户不再需要理解"清单 vs 项目"的区别，界面上也不做迁移引导弹窗 |
| **修缺陷不改观感** | CAL-03 只改判定逻辑；不新增跟手反馈、不改动画时长与形态视觉（理由见 7.4） |

## 2. 设计基准

### 2.1 沿用基准（v0.1.0~v0.6.0）

- 375pt 基准宽、480px 中栏（`--content-max-width`）、tokens.css 色板与字号阶梯、间距/圆角/阴影；

## 4. 核心用户流程（UX Flow）

### 4.1 创建代理并接入外部工具

```
抽屉「智能体」→ 列表空态 → ＋（或空态主按钮「＋ 新建代理」）
  → 新建代理页：名称（必填 ≤50）/ 类型（Claude Code / opencode / pi agent / 其他）/ 描述（可选）
  → 保存成功 → replace 进入代理详情，顶部展示「接入凭据」一次性卡片：
       - 凭据明文（等宽字体）+「复制凭据」
       - MCP 接入地址 +「复制接入配置」
       - 警示：「凭据仅显示这一次，请立即复制保存；离开本页后将不再显示」
  → 用户在本地工具粘贴配置 → 工具发起 MCP 调用成功
  → 返回代理详情：状态点变绿「已连接 · 刚刚」，一次性凭据卡已收起为前缀 + 「重置凭据」
异常分支：
  凭据丢失 → 「重置凭据」二次确认（旧凭据立即失效）→ 新凭据再次一次性展示
  代理停用后工具调用失败 → 代理详情状态显示「已停用」，工具侧报鉴权失败（4019）
```

### 4.2 指派即执行（含离线与失败）

```
任务详情（普通任务 / 项目成员任务）→「智能体执行」区 →「指派给智能体」
  → 指派弹层（AppActionSheet）：列出已启用代理（状态点 + 名称 + 类型 + 进行中数）
  → 选择代理 → 指派成功（无二次确认，可逆）→ 状态立即变为「等待代理领取」
       - 代理在线：卡片显示「已入队 · 代理在线」，通常数秒内转「执行中」
       - 代理离线：卡片显示「已入队 · 代理离线，连接后自动领取」（不阻塞，无需用户操作）
  → 代理自动领取 → 状态「执行中 · 领取于 x 分钟前」
  → 代理自动回报 → 成功：任务自动完成 + 状态「已完成（代理）」+ 记录新增「完成」节点
                  失败：状态「失败」+ 失败原因 + 主按钮变「重新执行」
用户可随时：
  -「更换代理」：旧指派出队（留痕），新代理自动接管排队
  -「取消指派」：待领取直接出队；执行中需二次确认（提示"代理可能仍在执行"）
  - 失败后「重新执行」：任务重新入队，代理自动再次领取（不自动重试）
异常分支：
  对项目指派 / 已完成任务指派 / 重复指派 → 4021 行内提示
  代理待执行队列已满 → 4022 提示「该代理待执行任务过多，请稍后再试或先处理队列」
```

### 4.3 代理凭据重置与删除代理

```
重置凭据 → AppModal 二次确认：「旧凭据将立即失效，已接入的工具需要更新配置」
  → 确认 → 详情页展示新凭据一次性卡片（同 4.1）
  → 执行中的任务不受影响，但后续回报需使用新凭据
删除代理 → AppModal 影响告知：「将解除 N 个待领取任务、M 个执行中任务的指派，且不可恢复」
  → 确认 → 删除
  → 待领取任务回到「未指派」（可再指派其他代理）
  → 执行中任务保留「执行中（代理已删除）」标记，等待用户重新指派或取消指派
  → 历史执行记录保留，节点上标注「代理已删除」
```

### 4.4 项目页与任务页分离

```
抽屉「任务」→ 列表仅普通任务（无类型分段、无清单胶囊），＋ → 新建任务页（无类型分段）
抽屉「项目」→ 项目列表（项目卡片行 + 状态筛选 + 排序），＋ → 新建项目页
  → 新建项目：项目名称 / 备注 / 优先级 / 截止时间 → 保存 → replace 进项目详情（进度 0/0）
  → 项目详情「添加任务」连续加成员（成员=普通任务，可指派代理）
任务详情「所属项目」：未归属任务显示「无 ›」可选择项目；归属后显示项目名，可跳转项目详情
旧链保底：
  /lists → /tasks（书签不报错）
  /tasks/new?task_type=project → /projects/new
  /tasks/:id（项目）→ /projects/:id（含 from=chat 等 query 透传）
```

### 4.5 清单功能消失（升级后界面变化）

```
升级后用户可见的变化（一次性发生，无引导弹窗、无迁移提示）：
  任务页：清单胶囊与「管理清单…」消失 → 删除类型分段与清单筛选后，筛选区只剩状态分段与排序
  任务表单：「所属清单」行消失；「所属项目」成为唯一的归属选择（改「无 / 项目名 ›」）
  详情与卡片：普通任务行、项目卡片行、项目详情、任务详情、任务日程详情、搜索结果的清单名全部消失
  对话：不再产生清单相关卡片与确认条；用户说"放到 XX 清单"→ 助手文字说明"清单能力已下线，可用项目组织"
```

## 7. 关键交互细则

### 7.1 指派与自动执行的状态呈现细则

| 项 | 规格 |
| --- | --- |
| 指派动作 | 弹层选择即可，**无二次确认**（可逆）；指派成功立即关闭弹层并在原位置显示状态卡（不等接口二次返回） |
| 乐观与回滚 | 指派采用乐观更新（卡片立即显示"等待代理领取"）；失败（4010 类/4021/4022/网络）则回滚并 toast 具体原因，回到未指派形态 |
| 状态推进 | 由任务详情的数据刷新驱动（进入页面拉取 / 从记录弹层返回时重拉）；**不引入轮询与长连接**，避免端上耗电；用户停留在详情时可下拉刷新 |
| 状态文案与依据 | 待领取：`agent_state=pending`；执行中：`running`；已完成：`succeeded`；失败：`failed`；`none` 不展示该区块状态卡 |
| 在线状态 | 依据代理「最近活跃」窗口（PRD 4.2 建议 5 分钟，SDD 定稿）：窗口内 = 代理在线；否则显示「代理离线，连接后自动领取」 |
| 待领取副行 | 「已入队 {相对时间} · 代理在线/代理离线，连接后自动领取」；相对时间每分钟刷新（仅当页面可见） |
| 执行中副行 | 「领取于 {相对时间}」；不展示进度条（代理进度为文本留言，不虚构百分比） |
| 已完成副行 | 「用时 {x 分钟}」；任务完成勾选同步为已完成（任务完成状态与执行状态双可见） |
| 失败副行 | 「原因：{文本}」最多 2 行 + 省略；点卡片正文区可展开完整原因（就地展开，不跳页） |
| 操作按钮 | 未指派：指派；待领取：更换代理 / 取消指派；执行中：取消指派；已完成：更换代理 / 取消指派；失败：重新执行（主）/ 取消指派 |
| 状态自动变化 | 停留期间状态变化只更新卡片与记录，不弹 toast、不整页刷新、不移动滚动位置 |
| 多任务并发 | 同一代理多个任务各自独立展示状态，互不阻塞；任务页行上的状态点仅作示意，不提供操作 |

### 7.2 凭据一次性展示与复制

1. **展示时机**：仅"创建成功 → 详情页"与"重置成功 → 详情页"两次会话内渲染；以内存态标记（如 `justCreated/justRotated`），刷新或重新进入即不渲染；
2. **展示内容**：完整凭据、MCP 接入地址、「复制接入配置」（含凭据的整段 JSON，便于直接粘贴）；
3. **警示必须显著**：顶部警示条 + 文案「凭据仅显示这一次 / 请立即复制保存，离开本页后不再显示」；不做拦截式二次确认（避免打断复制）；
4. **复制实现**：`navigator.clipboard.writeText` 优先；不可用时回退到隐藏 textarea + `document.execCommand('copy')`；仍失败则自动选中文本并 toast「请长按复制」；
5. **复制反馈**：按钮文案瞬时变「已复制」+ 图标变 `check`（800ms 复原），同时 toast；
6. **常态展示**：仅前缀 + `…`；「重置凭据」为唯一取回路径；无「查看」入口；
7. **安全细节**：凭据不以 `title`/`aria-label` 明文重复暴露；离开页面立即从组件状态清除（`onBeforeUnmount` 清空）。

### 7.3 执行记录时间线

| 项 | 规格 |
| --- | --- |
| 排序 | 时间倒序（最新在上） |
| 默认条数 | 3 条；超出显示「查看全部」 |
| 完整视图 | AppActionSheet（全高 80%），可滚动；分页加载，底部 `LoadingDots`；到底提示「没有更多了」 |
| 节点 | 6pt 圆点，颜色按动作（见 6.1）；左侧 1pt 竖线连接，首尾节点线不悬空 |
| 内容 | 动作标签（12pt）+ 相对时间（12pt `--text-secondary`）+ 正文（14pt） |
| 正文来源 | 指派/取消指派：无正文或操作来源（手动/对话）；领取：无；进度：留言文本；完成：结果摘要；失败：失败原因；重新执行：无 |

### 7.4 上滑折叠修复（CAL-03，设计侧定稿）

- **视觉不变**：不新增跟手反馈、不新增控件、不改动画时长（250ms `--dur-page`）与折叠态一周的视觉呈现；本次只修判定逻辑，避免"修 BUG 顺带改观感"带来的回归面；
- **跟手反馈定稿为「不采用」**：理由——列表区已有原生滚动，若折叠也参与跟手，会出现"到底跟手还是滚动"的抢手势观感；v0.6.0 的越界橡皮筋（阻尼 0.4）已由浏览器原生提供，足够；
- **起手区域定稿为「列表区（含列表底部空白）」**，**不扩展到日历网格区**：日历区已承载点选日期与左右翻期，纵向手势并入会与"按住某日期拖动"冲突；
- **行为要求（验收口径，源自 PRD 7.3）**：
  | 项 | 规格 |
  | --- | --- |
  | 判定基准 | 以**手势起手时**列表是否在顶部为准（快照），手势进行中不再用实时滚动位置取消判定 |
  | 上滑折叠 | 起手在顶部 + 纵向占优 + `dy ≤ −32pt` → 必折叠（与列表是否可滚动无关） |
  | 下拉展开 | 保持不变：折叠态顶部下拉 `dy ≥ 32pt` → 展开（同样以起手快照为准） |
  | 方向锁 | `|dy| > 1.5 × |dx|`；8pt 起手观察期 |
  | 一次一次 | 一次手势只触发一次，触发后手势余量交还列表滚动，不跳变、不回弹 |
  | 动画互斥 | 250ms 动画期间忽略新手势 |
  | 列表非顶部起手 | 只滚动列表，不切换形态 |
  | 状态不残留 | 未触发的手势结束后，回顶部再滑可立即触发 |
- **回归项**：左右翻月/翻周、补位日切月、折叠态跨月周计数、详情返回形态与滚动位置恢复、浮动今日显隐、头部三元素。
