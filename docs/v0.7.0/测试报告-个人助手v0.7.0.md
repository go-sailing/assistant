## 7. 重点验证结论

### 7.1 迁移 012 / 013（19/19）

- **012**：`agents` 表、`tasks` 6 个代理列、`agent_task_logs` 表、6 条 CHECK、8 个索引在全新库一次到位；非法 `agent_state`（`assigned`/缺 `queued_at`/终态缺 `finished_at`）被 CHECK 全部拒绝（3/3）；**幂等重放零副作用**；
- **013**（v0.6.0 快照升级）：多清单用户的任务（含项目与成员）全部归位默认清单、自定义清单行被删除、异常用户（无默认清单）先补默认清单再归位；**任务 5→5、日程 2→2、父子关系与日程归属逐行一致（零丢失）**；重放 no-op；升级后代理状态机链路（pending→running→succeeded + 任务完成）可用；
- 代理名唯一约束按 `lower(btrim(name))` 生效（`work` 与 ` Work ` 冲突被拒）。

### 7.2 代理与指派（REST + MCP，86/86）

- **凭据**：明文 `ak_live_` + base64url，`token_prefix` = 明文前 12 位，库中仅存 sha256 且与明文摘要一致；重置后**旧凭据立即 401**，删除代理后凭据立即失效；所有响应不含 `token_hash`；
- **指派即执行**：指派成功即 `pending` + `queued_at` + 写 `assigned` 日志；**不存在任何"通知执行/撤回通知"接口与按钮**（接口清单、工具表、界面文案三处交叉验证）；更换代理产生 `assigned,unassigned,assigned` 三条留痕；
- **状态机与约束**：项目/已完成任务/重复指派 → 4021；不存在代理 → 1004；停用代理 → 4021；队列满 → 4022；非失败态 retry → 4021；失败回报后任务保持 `todo` 且**1.2s 内无自动重试**；
- **并发正确性**：并发领取同一任务恰 1 成功、1 个 4020，且 `claimed` 日志仅 1 条；FIFO 领取命中最久等待者；
- **日志**：动作序列与倒序正确，按 `AGENT_LOG_KEEP` 裁剪生效（设置 3 → 实际保留 3 条）；
- **删除代理**：pending → 未指派（清空代理列）、running → `agent_id=NULL` 保留执行中、写"代理已删除"快照日志，返回计数与实际迁移逐项一致。

### 7.3 MCP 协议（脚本客户端）

- `initialize` 版本协商（在列回显 / 不在列回服务端最新）与 `instructions` 自动执行闭环；`notifications/initialized` → 202 空体；`tools/list` 8 个工具且代理**无任何写任务/日程/项目工具**；
- 协议错误码：非法 JSON → -32700、缺 method → -32600、未实现方法 → -32601；业务失败一律 `isError` + `structuredContent.error.code`（4020/4021/1001/1004）；
- 鉴权：无凭据/非法/停用/已重置/已删除 → HTTP 401 + `data.biz_code=4019`（不区分原因，防枚举）；用户 JWT 访问 `/mcp` → 401（通道隔离）；`GET`/`DELETE` → 405；无 `Mcp-Session-Id`（无状态）；
- `wait_agent_task`：空队列 `timeout_ms=0` 立即返回 null（非错误）；队列非空立即返回队首；指派后由同进程唤醒实现即时下发。

### 7.4 清单下线（静态 + 接口）

- 4 个 `/lists` 接口全部 404；任务/事件响应无清单字段；`list_id` 入参在 GET/POST/PATCH/batch 四处**显式拒绝 1001**；新建任务仍落默认清单；注册仍创建默认清单；**成员创建不再触发 4014**；
- 前端：清单页面/弹层/API/类型已删除；业务代码零 `list_name|list_id|api/lists` 引用；**用户可见文案零「清单」字样**（含引导页）；`/lists` 重定向 `/tasks`；确认条无 `delete_list` 分支。

### 7.5 页面分离与手势

- 路由 `/projects*`、`/agents*` 八个路由登记齐全；抽屉 5 项顺序正确；`AppNavBar` 一级页含 project-home/agent-home；默认启动页含「项目」；版本号 v0.7.0；任务详情容器做项目形态**双向重定向**（query 透传）、任务表单项目态重定向到项目编辑页；
- 服务端口径：项目查询只返回项目；任务页口径（`task_type=normal` + `root_only`）不含项目与成员；4017/4018/4010 回归通过；
- **CAL-03**：`startAtTop` 起手快照已落地，`touchmove` 中**已无实时 `scrollTop` 判定**，阈值(32)/方向锁(1.5)/起手观察期(8)/动画(250ms) 与折叠展开函数、形态恢复逻辑均未改动（静态核验）。

### 7.6 真实 LLM（3/3）

- **指派（L1，首轮即通过）**：工具序列 `search_tasks → list_agents → assign_task_to_agent`，**一次调用完成派活**，任务落库 `pending`，全程无 notify/withdraw 类工具；
- **清单诉求（L2）**：模型未调用任何清单工具（工具表已不存在），并以文字说明"清单功能已下线" + 方案卡「新建项目并移入任务」承接——与 PRD 6.2 的预期行为一致。

## 8. 结论与建议

### 8.1 结论

1. 自动化与静态可执行范围内，**四层 146 项断言 100% 通过**，未发现 v0.7.0 产品缺陷；
2. 四条需求主链路（代理接入与指派、MCP 协议与工具闭环、清单下线、页面分离与项目页）在服务端与结构层面均已可用，迁移 012/013 满足"幂等 + 归零丢失"要求；
3. CAL-03 的实现已消除 v0.6.0 的判定缺陷根因（起手快照），**真机 10/10 复测仍建议发布前补做**；
4. 阻断发布的遗留项：**无**（在"自动化可验证范围"内）。

### 8.2 发布前建议按序补做

1. **真机手势专项**：在可滚动列表场景下上滑折叠 10/10、已滚动不触发、下拉展开 10/10，三容器（iOS/Android/微信）各一轮；

3. **微信 WebView**：凭据复制降级、键盘遮挡代理/项目表单、页面回收不重复指派；
4. **默认配置规模用例**：代理上限 20、队列上限 100、日志保留 50 各跑 1 次真值；
5. **埋点核验**：按 PRD 8.4 逐项核对 `agent_*` 事件字段；确认 T9（端上埋点不上报）经评审确认或按变更单补上报；
