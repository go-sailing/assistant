## 1. 背景与目标

### 1.1 背景

v0.7.0 把项目从"任务的一种类型"推进到"独立页面与独立入口"，但**数据模型仍停留在 v0.6.0 的形态**：项目依旧是 `tasks` 表里 `task_type='project'` 的一行，项目因此继承了任务的全部字段（优先级、截止时间）、全部接口（`/tasks` 系列）与全部状态机（`todo/completed` 手工切换、4010 级联完成确认）。上一版把"项目"的**界面**抽离了，却没有把"项目"的**模型**抽离，于是新一版的需求集中落在这一层欠账上；同时 v0.7.0 新上线的两处手势/回跳交互在真机使用中暴露了确定性缺陷，代理凭据区与已完成任务详情也留下了不一致的可用性缺口。v0.8.0 需求共 9 项：

**模型层欠账（1 项）**

1. **项目不是独立实体**：项目与任务同名同表同接口，导致（a）"普通任务 / 项目任务"的类型概念必须一直携带在模型、接口与 DTO 中；（b）项目被迫拥有**它并不需要**的字段——优先级与截止时间；（c）项目被迫复用任务的接口与错误码，语义（如 4017/4018/4010）越积越绕。项目已经从界面上独立，**模型上也应彻底抽离**：项目独立建表、任务取消类型字段、项目不再有优先级与截止时间。

**体验调整（6 项）**

2. **任务页看不到项目下的任务**：v0.7.0 把 `/tasks` 纯化为"仅根普通任务"，项目下的任务只能在项目详情里看到；但用户的心智是"任务就是我要做的事，只是有些属于某个项目"。任务页需要**展示全部任务（含项目下的任务）**，并在列表左上方**增加项目筛选器**以便按项目查看；
3. **项目页控件过多**：项目页同时提供"排序方式"与"全部/进行中/已完成"状态 Tab，而项目字段收敛后（无截止时间、无手工完成）这两组控件的价值已不成立，页面需要**简化**；
4. **项目详情底部按钮冗余**：项目详情最下方同时存在「安排日程」「编辑项目」「完成项目」——项目详情不是任务详情，这三项要么不该在项目上（安排日程）、要么与顶部入口重复（编辑）、要么与"项目由成员进度驱动"的新口径冲突（完成项目），应**整体删除**；
5. **已完成任务的详情页仍给出无效入口**：任务已完成时，详情页仍渲染「智能体执行」区与「安排日程」按钮，用户点击后才被服务端拒绝（4021 / 4002），属于"先给入口、后报错"的坏体验，应**直接隐藏**；
6. **代理凭据区重复提供重置入口**：代理详情的凭据区行内与页面底部操作区各有一个重置入口，凭据区应只管"看与复制"，重置入口**唯一化**。

**缺陷修复（3 项）**

7. **新建任务保存后回错页面**：从项目详情点「更多字段」进入新建任务页，保存成功后固定跳回任务页（`/tasks`），用户丢失了"我正在给这个项目加任务"的上下文，应**返回来源项目详情**；
8. **列表左滑会误触发下拉刷新**：任务列表与项目列表中左滑 item 时，会同时触发下拉刷新（水平手势被当成垂直下拉），**两个手势需要互斥**；
9. **日程主页手势不可靠**：日程较多时上滑折叠**有延迟**，下划屏幕**不自动展开、需要下滑两次**才展开。

9 项需求编号：

| 分组 | 编号 | 需求 |
| --- | --- | --- |
| 数据模型 | MDL-01 | 项目从任务中彻底抽离：项目独立建表；任务取消 `task_type`（不再区分普通任务与项目任务）；项目**无优先级、无截止时间** |
| 任务页 | TASK-01 | 任务页展示**全部任务**（含项目下的任务）；任务列表**左上方新增项目筛选器**（全部 / 未归属项目 / 指定项目） |
| 任务页 | TASK-02 | 新建任务保存后**回到来源页面**：从项目详情进入的新建任务保存后返回该**项目详情**（并高亮新增任务） |
| 项目页 | PRJ-04 | 项目页简化：删除**排序方式**控件、删除**全部/进行中/已完成 Tab** |
| 项目页 | PRJ-05 | 项目详情底部删除「安排日程」「编辑项目」「完成项目」三个按钮 |
| 列表手势 | GES-01 | 修复任务列表与项目列表中**左滑 item 误触发下拉刷新**的缺陷（水平/垂直手势互斥） |
| 任务详情 | AGT-06 | 已完成任务的任务详情页**不再显示**「智能体执行」区与「安排日程」入口 |
| 智能体 | AGT-07 | 删除代理详情**接入凭据区内的行内「重置」按钮**（重置入口唯一化） |
| 日程主页 | CAL-04 | 修复日程主页上滑折叠**延迟**与下划**不自动展开/需两次下滑**的缺陷 |

### 1.2 产品目标（v0.8.0）

- **核心目标**：
  1. **模型一次做对**：项目成为独立实体（独立表、独立接口、独立状态口径），任务不再有"类型"这一维度；"普通任务 / 项目任务"的区分在模型、接口、DTO、提示词中**全部消失**，此后新增项目能力不再受任务字段与任务状态机牵连；
  2. **项目只保留它需要的**：项目 = 名称 + 备注 + 进度（成员完成度派生）+ 创建/完成时间；**无优先级、无截止时间**，也没有手工"完成/恢复"动作；
  3. **任务页成为唯一任务视图**：用户在任务页能看到**全部**要做的任务（含项目下的任务），并能用项目筛选器一键聚焦某个项目；项目页只管"项目本身"；
  4. **入口与状态一致**：已完成任务不再展示任何"执行/排期"入口；代理凭据区只负责"查看与复制"；
  5. **手势可靠**：列表的"左滑操作"与"下拉刷新"互不干扰；日程主页的折叠与展开都"一次到位"（折叠不延迟、展开不需第二次手势）。
- **成功假设**：
  1. 项目模型抽离后，"任务/项目类型混淆"类反馈归零；任务/项目列表查询性能不劣于 v0.7.0（接口请求数与数据量只减不增）；
  2. 任务页含项目任务后，"项目下的任务找不到"类反馈归零；项目筛选器使用率形成基线（筛选过项目的用户占比 ≥ 30%）；
  3. 已完成任务的"点了才报错"反馈归零（4021/4002 的端上触发次数降至 0）；
  4. 列表手势：左滑 10 次 0 次触发下拉刷新；下拉 10 次全部正常刷新；
  5. 日程主页手势：折叠"延迟"投诉归零；折叠态下划**一次**即可展开的成功率 ≥ 98%。

### 1.3 非目标（v0.8.0 不做）

- **不做项目能力扩展**：不做项目优先级、项目截止时间、项目负责人/协作成员、项目模板、看板/甘特/里程碑/项目报表、项目归档与回收站；项目仍是个人容器；
- **不做项目的多层级结构**：项目之间不可嵌套、项目下不可再建项目；任务仍然"最多属于 1 个项目"（一层成员关系，延续 v0.6.0 收敛后的口径）；
- **不做项目的手工完成**：项目状态由成员任务完成度**自动派生**（见 4.5；**决议 4 已批准**）；端上不提供"完成项目/恢复项目"按钮，项目页也不设状态 Tab（PRJ-04/PRJ-05 按此执行，原"保留手工完成"备选作废）；
- **不做任务分页与虚拟滚动**：任务页与项目页仍为"首页 50 条"口径，不引入分页/上拉加载（本次不因"展示全部任务"而扩列表结构）；
- **不做任务页的高级筛选**：不新增优先级/截止时间/代理状态等筛选器，项目筛选器是本次唯一新增筛选维度；
- **不做项目页的排序与状态筛选**：本次是**删除**（PRJ-04），不以其它形式补偿；
- **不做已完成任务的"执行记录只读展示"**：已完成任务的智能体执行区整体隐藏（不保留只读时间线，历史记录可在任务未完成时查看；如需追溯由后续版本决定）；
- **不做代理凭据能力的删除**：AGT-07 仅删除凭据区的行内按钮，`POST /agents/:id/token/rotate` 接口与底部「重置凭据」入口保留（凭据遗失必须可找回）；
- **不做日程主页的其它手势/布局改造**：仅修 CAL-04（折叠延迟、展开需两次），左右翻月/翻周、浮动今日、头部三元素、形态恢复机制均不变；也不把"上滑折叠"扩展为"列表中途上滑也可折叠"（折叠仍要求起手在列表顶部，见 9.3）；
- **不做清单、记忆、会话、LLM 编排能力的变更**：清单已下线且本期不动；长期记忆与压缩逻辑不受影响；
- **不做代理/MCP 能力变更**：指派、执行状态机、MCP 工具集均不变，仅收敛"已完成任务"的入口；
- **不做深色模式、字号调节、多语言、PC 端专门适配**。

## 2. 目标用户与使用场景

### 2.1 目标用户

延续全体个人用户，本版尤其面向：

- **把项目当"工作包"用的用户**：项目下有若干任务、任务分散在不同时间与优先级；希望"任务页能一次看全，又能按项目收起来"；
- **对模型/入口一致性敏感的用户**：不接受"项目还有优先级和截止时间""项目还要手动完成""已完成的任务还给执行按钮"这类自相矛盾的界面；
- **高频列表操作用户**：习惯左滑删任务/改状态，也习惯下拉刷新，要求两者互不干扰；
- **日程重负荷用户**：一天日程多、列表经常超一屏，要求日历折叠/展开"手到即变"。

### 2.2 核心使用场景

| 场景 | 描述 |
| --- | --- |
| 任务页看全量并按项目聚焦 | 用户打开任务页，看到全部任务（含"年度体检"等项目下的任务），列表项带项目标识；点左上「项目」筛选器选"装修项目"，列表立即只剩该项目下的 5 个任务；再选"全部"恢复全量。 |
| 给项目加任务后回到项目 | 用户在项目详情点「更多字段」，进入新建任务页（标题/备注/优先级/截止时间，所属项目已预填）；保存成功后**回到该项目详情**，新成员任务出现在成员列表并高亮，进度从 2/5 变为 3/5。 |
| 项目页一眼看完 | 用户打开项目页，直接看到全部项目（无排序按钮、无状态 Tab），每个项目卡片只有名称、进度、成员计数；项目是否"完成"由成员完成度自动决定，用户无需手动完成。 |
| 项目详情专注做事 | 用户进入项目详情：头部（名称/进度/时间）→ 成员列表 → 快速添加成员 → 删除项目；底部不再有「安排日程」「编辑项目」「完成项目」；要改项目名点右上「编辑」即可。 |
| 列表左滑不误触刷新 | 用户在任务列表左滑一条任务露出「完成/删除」，页面**不发生下拉刷新**；随后垂直下拉列表，正常触发刷新。 |
| 已完成任务不再给无效入口 | 用户在日程详情看到任务已完成，进入任务详情：详情只展示信息与「取消完成 / 删除」，**没有**「智能体执行」区、**没有**「安排日程」按钮。 |
| 代理凭据区只读 | 用户在代理详情看凭据前缀与接入地址、点「复制接入配置」，凭据区没有「重置」按钮；需要换凭据时到页面底部点「重置凭据」（二次确认，旧凭据立即失效）。 |
| 日程列表多也能收放自如 | 用户选中日程最多的一天（列表超一屏），列表顶部上滑 → 日历**立即**折叠为选中周；再下划一次 → 日历展开为整月（一次手势到位，无需第二次）。 |

## 3. 产品整体说明

### 3.1 产品形态（延续）

- 仍为**移动端 Web（H5）**瘦客户端：任务/项目规则校验、代理与任务状态机、MCP 协议处理、LLM 编排均在服务端完成，端上仅展示与交互；
- 延续全云端架构与单会话、服务端统一 LLM 代理、Function Calling + SSE 流式、模型可在服务端替换的总体架构；
- 延续"领域唯一入口"原则：REST（App 端）与 MCP（外部代理）共用同一套领域服务；本版新增的项目领域服务同样对外只暴露一套。
- **本版不新增对外协议、不新增鉴权通道**：仅调整领域模型与端上交互。

### 3.2 v0.8.0 变更总览

| 分组 | 编号 | 变更 | 类型 |

| 任务页 | TASK-02 | `/tasks/new` 携带来源时保存后**回到来源项目详情**并高亮新增任务；无来源时维持回任务页并高亮 | 缺陷修复 |
| 项目页 | PRJ-04 | `/projects` 删除排序方式控件与状态 Tab；列表固定按创建时间倒序展示全部项目；卡片去掉优先级/截止时间/完成勾选 | 页面精简 |

| 列表手势 | GES-01 | 任务列表/项目列表：左滑与下拉刷新**方向互斥 + 手势占用标记**，水平滑动不再触发刷新 | 缺陷修复 |
| 任务详情 | AGT-06 | 任务 `status=completed` 时，详情页不渲染「智能体执行」区与「安排日程」入口 | 体验一致性 |

| --- | --- | --- |
| `/tasks` | 仅根普通任务（不含项目成员）；类型/清单筛选已删 | **全部任务**（含项目下任务）；新增**项目筛选器**（左上） |

| `/tasks/:id` | 仅普通任务详情（命中项目 → `/projects/:id`） | 同左；**已完成任务隐藏智能体执行区与日程安排分区** |
| `/projects` | 项目列表 + 状态筛选 + 排序 | **全部项目**（创建时间倒序）；删除排序与状态 Tab |
| `/projects/new`、`/projects/:id/edit` | 名称/备注/优先级/截止时间 | **名称/备注**（去优先级、去截止时间） |
| `/projects/:id` | 头部含优先级/截止；底部 4 个按钮 | 头部去优先级/截止；底部**仅删除项目**；成员任务点击 → `/tasks/:id` |
| `/agents/:id` | 凭据区含行内「重置」 | 凭据区**不含**行内「重置」；重置在底部操作区 |
| 旧链 `/tasks/:id`（原项目） | 重定向 `/projects/:id` | 重定向 `/projects/:id`（**项目 id 直通**，决议 3 已批准） |

### 3.4 任务、项目、智能体代理三者关系（关键，避免误解）

| 概念 | v0.8.0 关系 |
| --- | --- |
| **项目** | **独立实体**（`projects` 表），与任务不再同表同接口；项目不是任务，**没有优先级、没有截止时间、不可安排日程、不可指派代理、没有手工完成**；项目状态由成员任务完成度派生（4.5） |
| **任务** | 模型上只有一种任务，**没有类型维度**；任务可有 0 或 1 个**所属项目**（`project_id` 可空）；可有 0 或 1 个**指派代理** |
| **项目下的任务** | 就是普通任务（`project_id` 非空），一层结构，不可再挂任务；在项目详情与任务页均可见 |
| **智能体代理** | 用户级外部工具接入身份，与项目无关；只能指派**任务**（项目不可指派） |
| **任务代理执行状态** | 与任务完成状态正交的第二维度（未指派/待领取/执行中/已完成/失败），v0.8.0 不变；已完成任务不再展示该维度入口（AGT-06） |
| **清单（已下线）** | 延续 v0.7.0：对用户不可见、不可筛选、不可作为表单字段；任务内部仍落各用户默认清单（`tasks.list_id` 保留） |

- **"类型"一词在本版从模型中消失**：`task_type` 列、接口参数、DTO 字段、提示词与前端类型定义一并移除（见 4.6）；
- 项目与代理**无关**：指派只发生在任务这一层；
- 任务与项目的删除级联关系保持：删除项目 = 删除其成员任务及其任务日程（详见 4.4）。

## 4. 功能需求一：项目模型抽离（MDL-01）

### 4.1 现状（问题）与目标

**现状（基于现有实现）**：

- 项目 = `tasks` 表中 `task_type='project'` 的行（`src/server/src/db/migrations/011_project_management.sql:9-14`），项目因此拥有 `priority`（默认 `none`）与 `due_at`（可空）两个字段（`001_init.sql:33-34`），项目与任务共用 `/tasks` 全部接口（`src/server/src/modules/task/task.routes.ts`），并用错误码区分语义（4017 项目须为根、4018 普通任务只能挂项目、4010 完成项目需级联）；
- 端上因此需要一直携带类型判断：列表查询固定带 `task_type`、详情容器按类型做双向重定向、搜索结果按类型分流、项目表单需要"无类型分段"的特殊说明；
- 项目还能被"安排日程"（项目详情底部「安排日程」→ `/calendar/task/new?task_id=<项目 id>`，服务端 `requireSchedulableTask` 只拦截已完成任务，`src/server/src/modules/event/event.service.ts:328-340`），即项目在库中可关联 `events.task_id`。

**目标**：

1. 项目独立建表，项目与任务在模型层彻底分离；
2. 任务取消类型字段，模型上只有一种任务；
3. 项目只保留必要字段：名称、备注、状态、来源、时间；**无优先级、无截止时间**；
4. 现有项目能力（成员、进度、删除级联、助手建项目）**零缺失**地迁移到新模型。

### 4.2 目标数据模型（产品级）

**新增 `projects` 表**（字段与约束的产品级要求，DDL 由 SDD 定稿）：

| 字段 | 说明 | 约束 |
| --- | --- | --- |
| `id` | 主键 | 见 12.2 决议 3（**已批准**：复用原项目任务 id，实现旧链直通） |
| `user_id` | 归属用户 | 必填，删除用户级联删除项目 |
| `name` | 项目名称 | 必填，≤200 字符（沿用项目名称长度口径） |
| `note` | 备注 | 可空，≤2000 字符 |
| `status` | 项目状态 | `todo` / `completed`，默认 `todo`；**由成员完成度派生**（4.5），不接受用户直接写入 |
| `completed_at` | 完成时间 | 派生为 completed 时写入；回到 todo 时清空 |
| `source` | 来源 | `manual` / `chat`，默认 `manual`（与任务同口径，用于区分端上创建与助手创建） |
| `created_at` / `updated_at` | 时间戳 | 必填，默认 `now()` |
| ~~`priority`~~ | **不存在** | 项目无优先级 |
| ~~`due_at`~~ | **不存在** | 项目无截止时间 |

**`tasks` 表变更**：

| 变更 | 说明 |
| --- | --- |
| 删除 `task_type` | 模型上不再区分普通任务与项目任务；`ck_tasks_task_type` 约束、`idx_tasks_user_task_type` 索引一并删除 |
| 删除 `parent_id` | 该列在 v0.7.0 已被收窄为"项目 → 成员"一层关系（`011_project_management.sql:30-44` 已把旧多层子树拆散），其唯一语义由 `project_id` 承接 |
| 新增 `project_id` | 可空，指向 `projects(id)`，删除项目时级联删除成员任务（`ON DELETE CASCADE`）；建立 `(user_id, project_id)` 与 `(user_id, status, project_id)` 索引 |
| 保留 | `list_id`（内部默认清单）、`priority`、`due_at`、`status`、`completed_at`、`source`、`agent_*` 全部保留——**任务的优先级与截止时间不变**（只是项目不再有） |

### 4.3 项目字段与端上呈现

- **新建/编辑项目表单字段**：项目名称（必填，≤200）、备注（≤2000）；**删除优先级分段控件与截止时间字段**；
- **项目卡片（项目页）**：项目名称 + 成员进度条 + 成员计数（`X/Y`）+ 状态徽标（派生，见 4.5）；**删除优先级、截止时间展示与行内完成勾选**；
- **项目详情头部**：项目名称 + 状态徽标 + 备注 + 来源 + 创建时间（+ 完成时间，若已完成）；**删除优先级行与截止时间行**；
- 项目**仍支持改名与改备注**（入口：详情右上「编辑」→ `/projects/:id/edit`，见 PRJ-05）；
- 项目**不再支持**：优先级、截止时间、手工完成/恢复、安排日程、指派代理。

### 4.4 任务与项目的关系（核心规则）

1. **归属**：一个任务最多属于 1 个项目（`project_id` 可空）；一个项目可包含多个任务（成员），**仅一层**，项目下的任务不可再被当作容器；
2. **创建**：新建任务时可选择"所属项目"（可空）；也可在项目详情内快速添加成员（沿用 v0.7.0 内联创建）；
3. **移入/移出**：任务可被移入某个项目（设置 `project_id`）或移出（`project_id=null`），沿用 v0.7.0 的"所属项目"入口与候选项目弹层；
4. **删除级联**：删除项目 → 级联删除其成员任务与这些任务的任务日程（沿用 v0.7.0 语义与 `preview-remove` 二次确认：明确告知将删除的成员任务数与关联日程数）；删除任务 → 其任务日程级联删除（不变）；
5. **项目不可导入**：项目不能作为任务的"父级任务"概念出现在任何层级结构中（原 4018 场景在模型上不可能发生）；
6. **不可嵌套**：项目之间无父子关系。

### 4.5 项目完成口径（派生，不在端上手工操作）

- **派生规则（决议 4 已批准）**：项目下**全部任务均已完成**时，项目自动置为 `completed`（写 `completed_at`）；项目下**任一任务回到未完成**、或新增未完成任务时，项目自动回到 `todo`（清空 `completed_at`）；
- **空项目**（无成员任务）恒为 `todo`，不显示"已完成"；
- **端上不提供**手工「完成项目 / 恢复项目」按钮与勾选框（与 PRJ-04/PRJ-05 一致）；项目状态徽标为只读展示；
- **一致性要求**：项目状态变化与成员任务状态变化在**同一事务**内完成，不允许出现"成员全完成但项目仍进行中"或反之的中间可见状态；
- 原 4010（完成项目需级联确认）与端上级联确认交互在本口径下**失去触发面**（编号保留，见 4.6）。

### 4.8 存量数据处置（迁移 014）

**迁移文件**：`014_project_extract.sql`（单迁移单事务，**幂等、可重复执行**，沿用现有迁移机制）。

**步骤（顺序不可颠倒）**：

1. 建 `projects` 表与索引；
2. **搬迁项目行**：把 `tasks` 中 `task_type='project'` 的行按 id、user_id、title→name、note、status、completed_at、source、时间戳写入 `projects`（**保留原 id（决议 3 已批准）**）；同步把序列推进到 `max(id)`；
3. **改写成员关系**：`UPDATE tasks SET project_id = parent_id WHERE parent_id IS NOT NULL`（此时父行均为原项目行，且项目 id 已直通）；
4. **项目关联日程处置（决议 5 已批准）**：原项目 id 上存在 `event_type='task'` 的日程时，**转为普通日程**（`task_id` 置空、`title` 取项目名，保留用户数据）。迁移需输出/记录处置条数；
5. **删除被搬迁的项目行**（`DELETE FROM tasks WHERE task_type='project'`）——先删父行前必须已保证成员任务的 `parent_id` 引用已改写，避免级联删除成员任务；**实施顺序必须是"先改写成员任务再删项目行"**；
6. 删除 `tasks.task_type`（约束、索引、列）与 `tasks.parent_id`；创建 `project_id` 外键与索引；
7. **校验**：迁移结束执行断言——（a）不存在 `project_id` 指向不存在项目的任务；（b）项目数 = 迁移前 `task_type='project'` 行数；（c）成员任务数 = 迁移前 `parent_id IS NOT NULL` 行数；（d）任务/日程/备注/优先级/截止时间零丢失（除项目自身的 priority/due_at 与第 4 步处置项）。

**演练要求**：

- 在 v0.7.0 类生产存量库快照上演练通过，覆盖：含项目的用户（多项目、多成员）、项目下任务带任务日程、项目自身带任务日程（历史允许）、已完成项目与已完成成员任务、无项目的用户、异常数据（成员指向不存在父行）；
- 演练需输出"迁移前后对照表"：任务数、项目数、成员关系数、任务日程数、项目日程处置数、被删除的字段值（项目优先级/截止时间）清单。

### 4.9 边界与异常

- **项目名重复**：允许重名（沿用 v0.7.0 无唯一约束的口径）；
- **成员上限**：单项目成员任务数沿用配置项上限（现 `TASK_TREE_MAX_NODES`，默认 200；v0.8.0 语义为"单项目成员上限"，建议随模型改造重命名为 `PROJECT_MAX_MEMBERS`，旧变量保留兼容或直接更名由 SDD 定稿），超限返回参数错误并提示；
- **并发**：同一项目并发添加成员、并发完成项目下任务时，进度与项目状态派生结果必须一致（不得出现进度回退或状态抖动）；
- **越权**：所有项目/任务操作校验归属；跨用户返回"不存在"；
- **已删除项目**：成员任务的"所属项目"跳转入口失效时，任务详情不展示该行；从项目详情返回的任务页不得出现死链。

## 5. 功能需求二：任务页（TASK-01 / TASK-02）

### 5.1 任务页展示全部任务（TASK-01）

- **列表数据范围变更**：由"根普通任务（`task_type=normal` + `root_only`）"改为**全部任务**（含项目下的任务）；不再传 `root_only`；
  - 现状（`src/web/src/views/tasks/TaskHomeView.vue:67-74`）固定传 `task_type:'normal'`、`root_only:true`、`page:1`、`page_size:50`；
- **列表项**：在既有行（勾选框/标题/优先级/截止时间）基础上，**项目下的任务增加"所属项目"标识**（项目名 chip 或副行）；点击该标识**直达项目详情**（不触发进入任务详情）；
- **保留**：状态分段（全部/未完成/已完成）、排序（截止时间升序 / 创建时间倒序）、搜索入口、下拉刷新、行内左滑（完成/删除）、`?highlight=` 高亮；
- **空态**：无任务 → "还没有任务"；筛选态无任务 → 按筛选条件区分文案（含"该项目下还没有任务"）；
- **不做分页**：仍为首页 50 条口径（见 1.3）。

### 5.2 项目筛选器（TASK-01）

- **位置**：任务列表**左上方**，与既有排序胶囊同一行（左：项目筛选器；右：排序），状态分段保留在其上方/下方（建议沿用 v0.7.0 层级：状态分段在下、筛选+排序在上，最终由 UXUI 定稿）；
- **形态**：胶囊按钮（显示当前值，如「项目：全部」），点击打开选择弹层（`AppActionSheet` 或项目选择弹层，UXUI 定稿）；
- **选项**：
  1. `全部`（默认）——不按项目过滤；
  2. `未归属项目`——仅 `project_id` 为空的任务；
  3. 具体项目——列全部项目（项目名 + 成员计数），项目多时支持搜索/滚动；

## 7. 功能需求四：列表手势冲突修复（GES-01）

### 7.1 现象与复现

- **现象**：在**任务列表**与**项目列表**中，于列表项上**左滑**（露出「完成/删除」等操作）时，页面同时出现**下拉刷新**（刷新提示文案出现、松手后触发刷新）。
- **复现（真机/移动端浏览器）**：
  1. 进入任务页或项目页，确保列表位于**顶部**（`scrollTop = 0`）；
  2. 在某一行上向左滑动、且滑动过程带有**向下的斜向分量**（水平为主、垂直分量累计 ≥ 72px）；
  3. 结果：行左滑生效的同时，下拉刷新被触发（或下拉提示出现）。
- **对照**：纯水平左滑（垂直分量很小）通常不触发；纯垂直下拉正常刷新。

### 7.2 根因分析（基于现有实现）

- **下拉刷新**：监听绑定在列表滚动容器 `.page-body` 上（`src/web/src/views/tasks/TaskHomeView.vue:278-285`、`src/web/src/views/projects/ProjectPageView.vue:314-321`）；`touchstart`（passive）在 `scrollTop === 0` 时记录起点，`touchmove` **只判 `dy > 0`** 即累计 `pullDistance = min(72, dy * 0.5)`（阻尼 0.5、上限 72px），`touchend` 时 `pullDistance >= 36` 即刷新（`TaskHomeView.vue:215-240`、`ProjectPageView.vue:247-272`）；
- **行左滑**：监听绑定在行元素上（`src/web/src/components/TaskListItem.vue:137-148`、`src/web/src/components/tasks/ProjectCard.vue:120-123`），进入拖动的条件是"水平位移 ≥ 8px 且 `|dx| > |dy|`"（`TaskListItem.vue:90-98`、`ProjectCard.vue:66-76`）；
- **根因**：两套手势**没有任何互斥或共享锁**——下拉刷新只按垂直位移判定与累计，既不检查水平位移、也不检查方向主导性，也不感知"行已进入左滑拖动"；两处 `touchstart` 均为 passive、均未 `preventDefault`/`stopPropagation`，事件冒泡同时抵达两个处理器。因此只要左滑伴随较大的向下分量，垂直位移就会被累计到 36px 阈值并触发刷新。理论上（`|dx| > |dy|` 但 `dy` 仍很大）同一手势可同时驱动左滑与下拉。

### 7.3 修复要求（行为级）

1. **方向主导判定（下拉侧）**：下拉刷新仅在**手势为纵向主导**时才允许累计与触发，即要求 `|dy| > |dx| * k`（建议沿用既有方向锁系数 1.5）且水平位移未超过左滑进入阈值（8px）；不满足时本次手势**不产生**下拉位移、不显示刷新提示、松手不刷新；
2. **手势占用互斥（左滑侧）**：一旦任一行进入左滑拖动（水平位移 ≥ 8px 且 `|dx| > |dy|`），立即置位"本次手势已被行内滑动占用"，滚动容器侧的下拉逻辑在整个手势周期内**立即取消并禁止再触发**；反之，一旦下拉累计已开始（纵向主导），行内左滑不再进入拖动；
3. **判定时机**：方向判定应在**位移越过 8px 观察期后第一次确定**（与现有观察期一致），确定后本次手势方向不再改变，避免中途翻转造成的抖动；
4. **不改变既有参数**：阻尼 0.5、上限 72px、刷新阈值 36px、左滑 8px 观察期、左滑吸附规则（`-74` 吸附至 `-148`）、操作区宽度 148px、左滑仅右半区起手等**全部沿用**（本项只加互斥，不调参）；
5. **不引入滚动副作用**：保持 passive 监听与 `overscroll-behavior` 现状，不因互斥逻辑引入滚动卡顿（见 10.1）；
6. **覆盖范围**：任务列表（`TaskHomeView` + `TaskListItem`）与项目列表（`ProjectPageView` + `ProjectCard`）；建议把"方向互斥"实现为可复用逻辑，避免后续列表（如搜索结果）重复踩坑；
7. **状态清理**：手势结束/取消（`touchend`/`touchcancel`）时清理占用标记与位移状态，不得残留导致下一次手势失效。

### 7.4 回归要求

- 纯垂直下拉：与现状一致（阈值、阻尼、文案切换、刷新结果均不变）；
- 纯水平左滑：位移、吸附、按钮可点、勾选/删除后自动收起等行为不变；左滑过程中**不得**出现刷新提示文案；
- 列表已滚动离开顶部时：下拉不触发（现状不变），左滑正常；
- 惯性滚动、列表点击进入详情、勾选完成、`?highlight=` 高亮均不回归。

### 7.5 验收方式（硬要求）

- 在列表顶部，对 10 个不同行执行"带斜向分量的左滑"（垂直分量累计 ≥ 72px）10 次：**0 次**触发下拉刷新，10 次左滑均正常生效；
- 在列表顶部执行标准垂直下拉 10 次：10 次均触发刷新；
- 在列表顶部执行水平左滑 10 次：0 次出现"下拉刷新/松开刷新"提示文案；
- 真机专项（微信 WebView + iOS/Android 浏览器）验证手势无抖动、无卡顿。

## 9. 功能需求六：日程主页折叠/展开缺陷修复（CAL-04）

### 9.1 现象与复现

- **现象 A（折叠延迟）**：日程较多（列表超一屏）时，在列表顶部上滑，日历**不是即时折叠**，而是有明显延迟（形态变化/内容切换滞后）。
- **现象 B（展开需两次）**：折叠态下，在列表中**下划屏幕，日历不自动展开**；往往需要**下滑两次**（第一次只把列表滚回顶部）才展开。
- **复现（真机/移动端浏览器）**：
  1. 进入日程主页，选中某天使日程列表**内容超过一屏**；
  2. 列表顶部上滑（纵向、位移 ≥ 32px）→ 观察折叠是否"跟手、即时"（现象 A）；
  3. 折叠后列表若已被滚动离开顶部，下划一次 → 观察是否展开（现象 B）；
  4. 反复多次，统计"一次手势即生效"的比例。

### 9.2 现状实现要点与根因分析

**现状实现（`src/web/src/views/calendar/MonthView.vue`）**：

- 手势常量：方向锁 8px、形态阈值 32px、方向锁系数 1.5、动画 250ms、**列表顶部容错 2px**（`MonthView.vue:83-88`）；
- 形态手势绑定在列表滚动容器 `.month__body`：`touchstart.passive` / `touchmove.passive` / `touchend` / `touchcancel`（`MonthView.vue:649-656`，容器样式 `779-788`）；
- **起手快照**：`onShapeTouchStart` 中若列表不存在或 `scrollTop > 2` 直接放弃本次手势，否则置 `startAtTop = true`（`MonthView.vue:439-454`）；`onShapeTouchMove` 中 `if (!g.startAtTop) return` 位于折叠/展开两个分支之前（`MonthView.vue:471`）；
- 折叠：`!collapsed && dy <= -32` → `collapseCalendar()`（`MonthView.vue:473-475`）；展开：`collapsed && dy >= 32` → `expandCalendar()`（`MonthView.vue:476-479`）；
- 动画与锁：折叠/展开均置 `animating = true`，250ms 后 `animating = false` 并（折叠时）才把 `renderWeek` 置为单周渲染（`MonthView.vue:394-402`、`405-418`）；动画期间新手势被忽略（`435-438`、`459`）；
- 列表滚动为原生 `overflow-y`（`MonthView.vue:779-788`），折叠位移由 `MonthGrid` 的日期行 `translateY` 承担（`src/web/src/components/calendar/MonthGrid.vue:175-179`），动画时长取自 `--dur-page = 250ms`（`src/web/src/styles/tokens.css:103`）。

**根因（现象 B，可解释性最强）**：展开与折叠**共用同一套"起手必须位于列表顶部"的前置判定**。折叠态下用户往往已把列表滚动离开顶部，此时下划手势的起手 `scrollTop > 2` → `startAtTop = false` → `onShapeTouchMove` 在折叠/展开分支之前 `return`，本次手势**只滚动列表**；等列表被滚回顶部时，手指往往已抬起或位移已被消耗，于是用户必须**再下划一次**才能触发展开——这正是"需要下滑两次才展开"的直接原因。

**根因（现象 A，候选机制，需 SDD 复核确认）**：

1. **形态切换依赖数据加载**：`collapseCalendar()` 在置 `collapsed` 后调用 `loadCollapsed()` 重新拉取"折叠周"的数据，形态虽然切换但列表内容需要等待网络返回；动画 250ms 与请求并行时，用户会感知为"折叠后内容迟迟不更新"；
2. **有效位移被原生滚动先消耗**：手势监听为 passive，手指上滑时浏览器先按原生滚动移动列表；在滚动位置与有效位移叠加的过程中，用户感知的"触发点"晚于手指动作；
3. **单时间点判定**：形态判定只在 `touchmove` 的位移累计上做一次性触发，缺少"是否已到达可折叠状态"的即时反馈（无跟手位移提示）。

**注**：上述 A 的机制需 SDD 在实现层复核定位（例如用时间戳区分"形态切换时刻"与"内容渲染时刻"），本 PRD 只对**行为结果**提要求。

### 9.3 修复要求（行为级）

1. **折叠即时化（现象 A）**：
   - 手势有效位移达阈值（32px、纵向主导）时**立即**进行形态切换，**不得**等待列表数据加载完成后再切换；
   - 折叠后的内容加载与动画**并行**；数据未返回时按占位/骨架呈现，不得留白或停留在旧形态；
   - 量化要求：从"有效位移达阈值"到"形态开始变化"≤ 1 帧（约 16ms）；折叠动画 250ms 内完成；折叠周内容从手势结束到可见 ≤ 300ms（超出则以骨架占位兜底）；
2. **展开一次到位（现象 B）**：
   - 折叠态下，**下划手势改为"持续判定期"**：手势开始后，若列表不在顶部，先让列表正常滚动；当列表滚动**到达顶部**（`scrollTop` 进入容错值）后，**同一次手势**内继续累计向下的有效位移，累计达阈值（32px）即触发展开——**不需要第二次手势**；
   - 展开不再要求"起手时列表位于顶部"；但**折叠仍保留"起手必须位于列表顶部"**（避免用户阅读列表中途被误折叠，保持 v0.7.0 决议）；
   - 已展开态改为从上滑手势亦然：起手不在顶部时只滚动列表（折叠不接管）；
3. **方向与阈值沿用**：方向锁系数 1.5、观察期 8px、形态阈值 32px、动画 250ms、动画期间忽略新手势、一次手势只触发一次（`fired`）全部沿用，不重新调参；
4. **滚动与手势不互抢**：展开触发后，本次手势剩余的向下位移交还列表滚动（不产生回弹、不连续触发布局位移）；滚动过程中不得出现形态抖动；
5. **形态与数据一致性**：折叠态显示"选中周"数据、展开态显示"选中月"数据；形态切换与数据加载的对应关系不得错位（如已展开却仍是折叠周内容）；
6. **状态不残留**：手势结束/取消时清理判定期状态；一次未触发的下划结束后，再次下划应能立即生效；
7. **不改变其余交互**：左右翻月/翻周（绑定在日历区，独立手势）、浮动「今日」、头部三元素、形态与选中日的恢复机制（沿用既有 5 分钟机制）均不变。

### 9.4 回归要求

- **v0.7.0 CAL-03 的修复不得回退**：列表内容超一屏时，从列表顶部上滑 10/10 次折叠成功；列表已滚动到中部时上滑只滚动列表、形态不变；
- 折叠态下划（含"列表先回顶再继续下划"的连续手势）必定展开，且只展开一次、不重复触发；
- 左右滑动：展开态翻月、折叠态翻周、选中日与年月同步、补位日切月均不回归；
- 折叠态跨月周的邻月计数补齐、月格标记点不回归；
- 折叠/展开动画连续（高度过渡）、动画期间忽略新手势、不出现回弹；列表滚动/惯性滚动/`overscroll-behavior: contain` 不变；
- 详情返回的形态/选中日/滚动位置恢复机制不回归；浮动「今日」与头部三元素不回归。

### 9.5 验收方式（硬要求）

- **现象 A**：在"列表内容超出一屏"的场景下，从列表顶部上滑 10 次，10 次均在手指位移达阈值后**即时**开始折叠（主观无"延迟"感知；客观：形态切换时刻 ≤ 1 帧，折叠周内容 ≤ 300ms 可见）；
- **现象 B**：折叠态下，先把列表滚动到中部，再**一次**下划（连续手势，中间不停顿）→ 10/10 次展开成功；连续下划 10 次均只需一次手势；
- **不误折叠**：折叠态下、列表已滚动到中部时，上滑 10 次形态均不变（只滚动列表）；
- **真机专项**（微信 WebView + iOS/Android 浏览器）：手势无跳动、无卡顿、无"需两次"复现；
- **埋点验证**：`calendar_shape_gesture` 中"展开触发"的 `gesture_count_per_expand`（每次展开消耗的手势次数）中位数为 1。

## 10. 非功能性需求

### 10.1 性能

- **列表查询**：任务页（含项目下任务）与项目页列表查询 P95 不劣于 v0.7.0；任务列表按 `project_id` 筛选不得引入 N+1（项目名随查询带出或批量解析）；
- **模型抽离收益**：任务查询去掉 `task_type` 判定与 `parent_id` 语义分支，项目查询不再扫描 `tasks` 表；总体查询路径只减不增；
- **手势响应**：`GES-01` 的方向判定在位移越过 8px 观察期后**一次确定**，判定开销为常数级；保持 passive 监听，不得因互斥逻辑阻塞滚动（真机滚动帧率不低于 v0.7.0）；
- **形态切换**：`CAL-04` 的形态切换不得串行等待网络（见 9.3），折叠/展开动画 250ms 内完成，动画期间不产生布局抖动；
- **迁移**：014 迁移在 v0.7.0 类生产库上的执行时长与锁表窗口需在低峰期可接受（具体阈值由 SDD 在演练中给出）。

### 10.2 兼容性与数据

- **迁移 014**：幂等可重复执行、单迁移单事务、先改写成员任务再删项目行（4.8）；演练通过；
- **数据零丢失**：任务（含标题/备注/优先级/截止时间/完成态/代理执行维度）、项目（名称/备注/状态/时间）、成员关系、任务日程、会话、消息、长期记忆、代理与执行记录均不受影响；仅**项目自身的优先级与截止时间**按需求明确丢弃，项目关联日程按 4.8 决议处置；
- **DTO 与接口变更**：任务 DTO 删除 `task_type/parent_id/subtask_*`、新增 `project` 摘要；项目独立 DTO；`/tasks?task_type=` 参数失效；旧客户端（v0.7.0）在服务端升级后的表现需在发布说明中明确（建议服务端对未知/失效参数明确拒绝并提示，避免静默错数据）；
- **路由兼容**：`/tasks/<原项目 id>` → `/projects/<id>`（项目 id 直通，旧书签与历史消息不报死链）；`/tasks/new?task_type=project` → `/projects/new`；历史对话中的项目卡片按 `/projects/:id` 渲染；
- **回滚考虑**：迁移 014 不可逆（删列）；发布前需完成库快照与回滚演练（回滚 = 恢复快照，不做反向迁移）。

### 10.3 隐私与安全

- 项目与任务的所有接口继续做归属校验，跨用户统一按"不存在"处理；
- 项目/任务正文（名称、备注）不进入日志与埋点（沿用只记 ID 与事件的口径）；
- 代理凭据相关（AGT-07）不引入新的暴露面：凭据仍只存哈希、仅创建/重置时明文返回一次，不进入日志/埋点/错误信息；
- 删除项目的高危操作保持二次确认并明示影响范围（成员任务数与关联日程数）；
- 端上渲染：项目名/任务名/备注按纯文本渲染，防注入（沿用现有 Markdown 净化策略）。

### 10.4 可观测性（新增埋点/日志）

- **模型抽离**：`project_extract_migrated`（迁移结果：项目数、成员关系数、项目日程处置数）、`project_created` / `project_updated` / `project_deleted`（含级联删除的成员任务数与日程数）、`project_status_derived`（派生触发：todo↔completed）；
- **任务页**：`project_filter_open`、`project_filter_apply`（选项类型：全部/未归属/具体项目）、`task_list_with_project_ratio`（列表中带项目的任务占比）；
- **回跳**：`task_create_origin`（来源：task-home/project-detail/search/其它）与 `task_create_landing`（落点：任务页/项目详情），用于验证 TASK-02 的修复效果；
- **已完成任务入口**：`task_detail_completed_entry_hidden`（命中隐藏规则的次数，用于确认"点了才报错"已归零）；
- **列表手势**：`list_gesture_direction_lock`（方向判定结果：vertical/horizontal）、`pull_refresh_suppressed_by_swipe`（因左滑被抑制的刷新次数）；
- **日历手势**：扩展 `calendar_shape_gesture`：增加"展开判定期命中（是否经历 roll-to-top）""每次展开消耗的手势次数"，用于验证 CAL-04；
- **错误日志**：4021/4002 的端上触发数（预期降为 0）、项目不存在/越权访问、迁移 014 的校验断言结果。

## 11. 关键业务流程与验收标准

### 11.1 关键业务流程

**流程一：项目模型抽离与存量迁移**

```
升级发版 → 迁移 014：
  建 projects 表 → 搬迁项目行（id 直通）→ 成员任务写 project_id
  → 原项目关联日程处置（转普通日程/删除，按决议）→ 删原项目行 → 删 task_type / parent_id → 建外键与索引
  → 断言校验（项目数/成员数/任务数/日程数一致）
端上/接口：类型相关参数与字段全部消失；/projects 系列接口上线；/tasks 只服务任务
异常：任一断言失败 → 迁移整体回滚（单事务），不进入半迁移状态
```

**流程二：任务页看全量并按项目筛选**

```
任务页 → 列表加载全部任务（含项目下任务，行内显示所属项目）
  → 点左上「项目」筛选器 → 全部 / 未归属项目 / 指定项目（可搜索）
  → 选"装修项目" → 列表只剩该项目下的任务（状态分段与排序保持不变）
  → 选"全部" → 恢复全量
异常：所选项目已删除 → 回落到"全部"并提示；无项目 → 筛选器仅"全部/未归属项目"可用
```

**流程三：从项目详情新建任务并回到项目**

```
项目详情 → 成员区「更多字段」→ /tasks/new?project_id=<id>
  → 表单预填"所属项目 = 装修项目"（可改选/改为独立任务）
  → 保存成功 → 回到 /projects/<id>，新成员任务在列表中高亮，进度 2/5 → 3/5
异常：来源项目已删除/无权限 → 降级为普通新建并提示；保存失败 → 停留并保留内容
```

**流程四：项目页与项目详情精简后的日常使用**

```
项目页 → 直接看到全部项目（无排序、无状态 Tab，创建时间倒序）
  → 卡片：名称 + 进度 + 成员计数 + 状态徽标（只读）
  → 左滑：仅删除（preview-remove 二次确认，明示成员与日程数）
项目详情 → 头部(名称/状态/备注/来源/时间) → 进度 → 成员列表 → 快速添加成员
  → 底部仅「删除项目」；改名走右上「编辑」
  → 成员全部完成 → 项目自动变为"已完成"（无需用户操作）
```

**流程五：列表左滑与下拉刷新互斥**

```
任务/项目列表（顶部）→ 在行上左滑（即使带较大向下分量）
  → 首次位移越过 8px 观察期 → 判定为水平主导 → 左滑生效，下拉刷新立即取消
  → 松手：行吸附（-148 或 0），页面不发生刷新
对照：标准垂直下拉 → 判定为纵向主导 → 正常出现"下拉刷新/松开刷新"并触发刷新
```

**流程六：已完成任务的详情页**

```
任务已完成 → 进入任务详情
  → 不显示「智能体执行」区、不显示「安排日程」入口
  → 仅信息（标题/优先级/截止/所属项目/备注/时间）+「取消完成」「删除」
  → 用户取消完成 → 刷新后智能体执行区与日程安排分区重新出现（可指派/可排期）
边界：手工完成时在途"待领取"指派自动取消并留痕；"执行中"指派保持不变
```

**流程七：代理凭据区只读与底部重置**

```
代理详情 → 凭据区：凭据前缀 + 接入地址 + 复制凭据/复制接入地址/复制接入配置（无「重置」）
  → 需要换凭据 → 底部「重置凭据」→ 二次确认 → 新凭据明文仅此一次可见（切回一次性凭据卡）→ 旧凭据立即失效
```

**流程八：日程主页折叠与展开（修复后）**

```
日程主页（展开态）→ 选中某天使列表超一屏 → 列表顶部上滑（≥32px、纵向）
  → 日历即时折叠为选中周（形态切换不等数据；内容 <=300ms 可见，否则骨架）
  → 折叠态：列表滚到中部 → 一次下划（连续手势，先回顶再继续下划）→ 日历展开为整月
  → 折叠态列表中部上滑 → 只滚动列表，形态不变（不误折叠）
异常：动画期间的额外手势被忽略；手势取消后判定期状态清理，下一次手势立即生效
```

### 11.2 验收标准

**MDL-01 项目模型抽离**

1. 项目中不再存在优先级与截止时间：新建/编辑项目表单无这两个字段，项目卡片与详情头部不展示，接口不接收这两个字段（携带应被拒绝或忽略，SDD 定稿）；
2. 任务模型不再有类型维度：`task_type` 从表、接口参数、DTO、前端类型与提示词中全部消失；任务与项目分别由 `/tasks` 与 `/projects` 服务，互不重定向；
3. 项目成员关系不变：任务可通过"所属项目"移入/移出；单项目成员上限生效；删除项目级联删除成员任务与相关任务日程，且二次确认明示数量；
4. 项目状态为派生态：成员任务全部完成 → 项目自动"已完成"；任一成员回到未完成或新增未完成任务 → 自动回"进行中"；空项目恒为"进行中"；端上无手工完成/恢复入口；
5. 迁移 014 幂等可重复执行，断言校验（项目数、成员关系数、任务数、任务日程数一致）通过；v0.7.0 类生产库演练通过，任务/项目/成员/日程/备注/优先级/截止时间（任务侧）零丢失；
6. 助手侧：可建项目、可给项目加成员任务（使用真实项目 ID），不再产生"任务类型"表述；助手不得把项目当作可完成/可排期/可指派对象。

**TASK-01 任务页全量 + 项目筛选器**

7. `/tasks` 展示全部任务（含项目下的任务），列表项显示所属项目标识且点击直达项目详情；
8. 列表左上方存在项目筛选器，选项为"全部 / 未归属项目 / 指定项目（含项目名与成员计数、可搜索）"，默认"全部"；
9. 项目筛选与状态分段、排序可叠加；切换筛选不重置其它条件；无项目时筛选器仍可用并有引导文案；
10. 服务端支持 `project_id` 过滤（含 `none`）；筛选后列表条数与内容正确，空态文案区分"该项目下还没有任务"。

**TASK-02 新建任务回跳**

11. 从项目详情「更多字段」进入新建任务页并保存后，**回到该项目详情**且新任务高亮，项目进度即时更新；
12. 无来源来源时保存后回任务页并高亮；编辑态保存返回上一页；来源失效时降级回任务页并提示，无死链；
13. 表单内改选其它项目/改为独立任务时，回跳以最终选择为准。

**PRJ-04 / PRJ-05 项目页与项目详情精简**

14. `/projects` 无排序控件、无「全部/进行中/已完成」Tab，展示全部项目且固定创建时间倒序；卡片无优先级/截止时间/完成勾选；左滑仅"删除"（保留影响范围确认）；
15. 项目详情底部仅有「删除项目」，无「安排日程」「编辑项目」「完成项目」；顶部右上「编辑」可用且能改名/改备注；
16. 项目详情不出现智能体执行区块；项目不可安排日程（`/calendar/task/new?task_id=<项目 id>` 被拒绝并提示）；
17. 项目状态徽标为只读派生态，成员状态变化后即时刷新。

**GES-01 列表手势互斥**

18. 列表顶部执行"带斜向分量的左滑"10 次，0 次触发下拉刷新、0 次出现刷新提示；左滑功能（吸附、按钮、勾选/删除）全部正常；
19. 列表顶部标准垂直下拉 10 次全部触发刷新；列表已滚动离开顶部时下拉不触发（不变）；
20. 方向判定在 8px 观察期后一次确定，无抖动；真机专项通过，滚动帧率不劣于 v0.7.0。

**AGT-06 / AGT-07 入口收敛**

21. 已完成任务详情不显示「智能体执行」区与「安排日程」入口；取消完成后二者恢复显示；
22. 已完成任务在途"待领取"指派被自动取消并留痕，「执行中」指派保持；服务端对已完成任务的指派（4021）与排期（4002）拒绝规则不变，端上触发数（点了才报错）为 0；
23. 代理详情凭据区无行内「重置」按钮；底部「重置凭据」可用，二次确认与"旧凭据立即失效、新凭据仅一次可见"行为不变；`POST /agents/:id/token/rotate` 未被移除。

**CAL-04 日程主页手势修复**

24. 列表超一屏时：顶部上滑 10/10 次即时折叠（形态切换 ≤1 帧、折叠周内容 ≤300ms 可见）；列表中部上滑 10/10 次形态不变（只滚动）；
25. 折叠态下一次连续下划（先回顶再继续下划）10/10 次展开成功，无"需两次"复现；每次展开消耗手势次数中位数为 1；
26. 回归零缺陷：左右翻月/翻周、跨月周计数、形态与滚动位置恢复、浮动今日、头部三元素、列表滚动与惯性滚动均不回归。

**非功能**
