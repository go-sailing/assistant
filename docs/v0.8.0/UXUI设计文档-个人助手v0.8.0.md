## 1. 设计目标与原则

### 1.1 设计目标

1. **模型抽离在界面上表现为"减法"**：项目不再有优先级与截止时间、不再有完成勾选、不再有排序与状态筛选；用户看到的是"更少但更准"的控件，而不是"换了套说法的旧界面"；
2. **任务页成为唯一任务视图**：用户在这里看到全部要做的事（含项目下的任务），列表项自带项目标识，左上角一个筛选器即可聚焦某个项目，不必先绕进项目详情；
3. **上下文不丢**：从项目详情去新建任务，保存后回到项目详情并高亮新任务——"我在给这个项目加任务"的心智全程不被打断；
4. **入口与状态严格一致**：已完成任务的详情页不出现「智能体执行」区与「安排日程」入口；代理凭据区只做"看与复制"，重置入口唯一落在页面底部操作区；
5. **手势一次到位**：列表左滑不再误触发下拉刷新；日程主页上滑折叠**即时**生效、折叠态下划**一次**即展开。

### 1.2 设计原则（v0.8.0 新增/强化）

| 原则 | 说明 |
| --- | --- |
| **一页一对象，一态一入口** | 任务页=全部任务、项目页=全部项目；控件只在该状态下有意义时才出现（已完成任务不给执行/排期入口） |
| **控件能删就删** | 项目无优先级/截止时间即删展示位；无手工完成即删勾选与"完成项目"；无排序需求即删排序胶囊（不为对称保留） |
| **派生态只读** | 项目"已完成"由系统派生，界面上**只展示不操作**：用徽标表达状态，不给勾选框 |
| **回跳跟随来源** | 任何"从 A 进 B、在 B 完成"的流程，落点回到 A（并按需高亮新产物）；只有明确无来源时才回默认页 |
| **手势方向唯一** | 同一次触摸手势只服务一个方向意图：纵向=刷新、横向=行内操作，进入任一方向后另一方向当次失效 |
| **判定在手势内完成** | 形态/刷新切换不跨手势累计（避免"要滑两次"）；数据加载不阻塞形态切换（避免"折叠有延迟"） |
| **修缺陷不改观感** | GES-01 与 CAL-04 只改判定与触发时机；色板、间距、动画时长（250ms）、阈值参数（32px / 1.5 倍 / 36px）与视觉表现零变化 |
| **口径不靠颜色** | 项目标识、筛选器选中态、已完成态均"颜色 + 文字/图标"双通道（沿用 v0.7.0 A11y 基线） |

## 2. 设计基准

### 2.1 沿用基准（v0.1.0~v0.7.0）

- 375pt 基准宽、480px 中栏（`--content-max-width`）、tokens.css 色板与字号阶梯（heading-l 22/30、heading-m 18/26、body-l 16/24、body-m 14/22、caption 12/18）、间距 `sp-1..sp-8`、圆角 card 12 / control 8 / bubble 16、阴影 `--shadow-card`；
- 底部弹层体系（AppModal / AppActionSheet：遮罩 `rgba(26,29,38,.45)`、面板顶部圆角 16、`--safe-bottom`、220ms `translateY`）；
- 通用组件：AppNavBar（44pt 高 + `--safe-top`，一级页渲染汉堡菜单）、SegmentedControl（44pt、激活项主色 + 28×2 下划线）、AppCheckbox（22pt 视觉 / 44pt 热区）、AppButton（primary/secondary/text/danger，44pt；small 32pt）、AppInput（48pt）、StateEmpty / StateError / SkeletonList（300ms 延迟出现）；
- 列表范式：`.page-body` 唯一滚动容器（`overflow-y:auto; -webkit-overflow-scrolling:touch`）、行 `min-height:56px`、左滑 `ACTION_WIDTH=148`（两按钮各 74pt；仅右半区起手可滑；8px 观察期；过半吸附）、下拉刷新（阻尼 0.5、上限 72px、阈值 36px、三态文案）；
- v0.7.0：智能体三页（列表/表单/详情）、任务详情「智能体执行」区、项目页/新建项目页/项目详情（头部 + 进度 + 成员 + MemberComposer）、抽屉 5 项一级入口（日程/任务/项目/智能体/助手）、`MENU_ROUTE_NAMES` 菜单态判定；
- 日历主页：`month__head / month__cal / month__body` 三段式、折叠/展开 250ms（`--dur-page`）、浮动「今日」胶囊、`prefers-reduced-motion` 全局降级。

### 2.2 本版新增设计参考

| 参考对象 | 参考点 | 不参考 |
| --- | --- | --- |
| 任务类 App 的"项目筛选器"（Things / Todoist 的标签/项目过滤胶囊） | 列表顶部左侧的**低权重胶囊 + 弹层**选择、选中值常显、与排序/状态并列不抢视觉 | 多标签与布尔组合、保存筛选视图 |
| Linear 的"项目即容器"心智 | 项目只描述"这组任务在做什么"，不携带排期与优先级；进度由成员驱动 | 项目周期、里程碑、团队协作 |
| iOS 列表的"上下文返回"（从详情进入下一级，完成后回到详情并高亮） | 回跳 + 短暂高亮（2s 后自然衰减） | 模态返回动画、面包屑 |
| 手势互斥的通用做法（同一手势方向锁） | 观察期后一次锁定方向、另一方向当次失效 | 自定义手势库、跟手进度条 |
| 派生态展示（GitHub Issues 的自动关闭、Jira 的进度驱动状态） | 状态徽标只读、变更由数据驱动、无需用户操作 | 手动状态机、状态回滚按钮 |

## 4. 核心用户流程（UX Flow）

### 4.1 任务页看全量并按项目聚焦（TASK-01）

```
进入任务页 → 看到全部任务（含"装修项目"下的 5 个任务，行内带项目标识）
  → 点左上「项目：全部 ⌄」→ 弹层（全部 / 未归属项目 / 装修项目 5 / 季度述职 3 …）
  → 选「装修项目」→ 弹层关闭，胶囊变「项目：装修项目」，列表即时只剩 5 条
  → 状态分段仍为「未完成」、排序仍为「按截止时间」（不被打断）
  → 再次打开筛选器：当前项高亮且滚动定位到它
  → 选「全部」→ 恢复全量
边界：所选项目被删除 → 回落「全部」并 toast 提示；无项目 → 弹层仅两项 + 引导「去项目页新建」
```

### 4.2 从项目详情加任务并回到项目（TASK-02）

```
项目详情 → 成员区「更多字段（备注/优先级/截止时间）」→ /tasks/new?project_id=X
  → 表单打开：「所属项目 = 装修项目」已预填（可改选其它项目 / 改为「无（独立任务）」）
  → 保存成功 → replace 到 /projects/X?highlight=<新任务 id>
  → 项目详情重新加载：新任务在成员列表中出现并高亮约 2s，进度 2/5 → 3/5
边界：来源项目已删除/无权限 → 降级为"普通新建"并提示，保存后回任务页
      保存失败 → 停留本页、保留已填内容、字段级错误提示
```

### 4.3 项目页与项目详情的"减法"（PRJ-04 / PRJ-05 / MDL-01）

```
项目页（升级后第一眼）
  变化前：状态分段 + 排序 + 卡片含优先级/截止/勾选
  变化后：直接是项目列表（创建时间倒序），卡片 = 名称 + 进度 + 计数 + 状态徽标
项目详情
  变化前：底部 [安排日程] [编辑项目] [完成项目] 删除项目
  变化后：底部只剩 删除项目；改名走右上「编辑」
  派生：成员全部勾选完成 → 顶部徽标自动变「已完成」（无任何操作）
```

### 4.4 列表左滑与下拉刷新互斥（GES-01）

```
任务/项目列表位于顶部 → 在行上向左滑（手指略向下偏移，垂直分量累计 72px+）
  → 8px 观察期后判为「水平主导」→ 行跟随左滑，露出 [完成][删除]
  → 全程不出现"下拉刷新/松开刷新"提示，松手不刷新
对照：垂直下拉 → 8px 后判为「纵向主导」→ 正常三态文案与刷新
```

### 4.5 已完成任务不再给无效入口（AGT-06）

```
日程详情（任务已完成）→「查看关联任务」→ 任务详情
  → 页面只有：标题（划线）/ 优先级 / 截止时间 / 所属项目 / 备注 / 时间 + [取消完成] [删除]
  → 不存在「智能体执行」区、不存在「安排日程」按钮
  → 用户点「取消完成」→ 页面即时出现两处入口（可重新指派/排期）
```

### 4.6 代理凭据区只读（AGT-07）

```
代理详情 → 凭据区：「接入凭据」标题 + 凭据前缀 + [复制] + 接入地址 + [复制接入地址] + [复制接入配置]
  → 区内无「重置」按钮
  → 需要换凭据 → 滚到底部操作区「重置凭据」→ 二次确认 → 新凭据仅一次可见（凭据区切回一次性凭据卡）
```

### 4.7 日程主页折叠与展开（CAL-04）

```
日程主页（展开态、某天列表超一屏）
  → 列表顶部上滑 32px → 日历即时折叠为选中周（动画 250ms，不等数据）
  → 折叠态：列表已滚到中部 → 一次连续下划（先回顶、继续下划 32px）→ 展开为整月
  → 折叠态列表中部上滑 → 只滚动列表（不误折叠）
关键：展开不需要"第一次把列表滚到顶、第二次才展开"——同一次手势内完成
```

## 7. 关键交互细则

### 7.1 项目筛选器（TASK-01）

| 场景 | 行为 |
| --- | --- |
| 首次进入任务页 | 默认「全部」；胶囊文案「项目：全部」 |
| 打开弹层 | 遮罩 + 面板自下方滑入（220ms）；当前选中项右侧 `check` 且滚动定位 |
| 选择"未归属项目" | 列表仅显示 `project_id` 为空的任务；空态文案「该项目下还没有任务」不适用（用「当前筛选下没有任务」） |
| 选择具体项目 | 胶囊显示「项目：<项目名>」；项目名过长时胶囊内单行省略（`max-width:140px`） |
| 与状态/排序叠加 | 三者正交；任一变化仅刷新列表，不改动其它两个控件的值 |
| 项目被删除 | 应用启动/刷新时若当前选中项目已不存在 → 回落「全部」+ toast「所选项目已删除」 |
| 无项目 | 弹层仅「全部」（可选）与「未归属项目」（disabled）两项，底部提示「还没有项目，去项目页新建」 |

### 7.2 回跳与高亮（TASK-02）

- 来源判定：表单 URL 携带 `project_id` 即视为"来自该项目"；表单内用户改选后以**最终值**为准；
- 落点高亮：`/projects/:id?highlight=<taskId>` 由项目详情的成员列表消费（高亮 2s 后清除 query，避免刷新重复高亮）；
- 降级：进入表单时若来源项目不可用 → 清空「所属项目」并顶部轻提示；保存后回任务页并高亮；
- 权限：来源项目不属于当前用户时按"不存在"处理（同降级路径）。

### 7.3 列表手势互斥（GES-01）

| 阶段 | 纵向（刷新） | 横向（行内左滑） |
| --- | --- | --- |
| `touchstart`（列表顶部） | 记录起点，进入待判定 | 记录起点（仅行右半区），进入待判定 |
| 位移 < 8px | 不累计、不显示提示 | 不移动 |
| 8px 观察期后判定 | 纵向主导（垂直位移 > 水平位移 × 1.5，且水平位移 < 8px）→ 锁定**纵向** | 横向主导（水平位移 ≥ 8px 且大于垂直位移）→ 锁定**横向**并置"手势已占用" |
| 斜向未达任一主导 | 例：水平 12px / 垂直 90px → 判定为 `null`：不累计、不显示提示 | 同一手势内行也不进入拖动；本手势**仅滚动列表**（既不刷新也不左滑） |
| 锁定后 | 累计 `min(72, dy×0.5)`，显示三态文案 | 行跟随位移，钳制 `[-148, 0]`（项目卡 `[-74, 0]`） |
| 另一方向 | 横向锁定后：**立即取消下拉**，本次手势内不再累计、不显示提示、松手不刷新 | 纵向锁定后：行不进入拖动 |
| 松手 | ≥36px → 刷新；否则归零 | 过半吸附（-148 / -74），否则回 0 |
| 结束/取消 | 清理方向与占用标记 | 清理位移与占用标记 |

- 文案侧硬要求：横向锁定后**不得**出现「下拉刷新 / 松开刷新 / 正在刷新…」任一文案；
- 参数零变化：阻尼、上限、阈值、左滑宽度、起手区域规则全部沿用（§6.2）。

### 7.4 已完成任务入口隐藏（AGT-06）

| 任务状态 | 智能体执行区 | 日程安排分区 | 其它 |
| --- | --- | --- | --- |
| `todo` | 渲染（可指派/更换/取消/重试） | 渲染（可安排日程） | 不变 |
| `completed` | **不渲染** | **不渲染** | 标题划线 + 完成时间；操作区「取消完成」「删除」 |
| `completed` → 点「取消完成」 | 即时出现 | 即时出现 | 无 toast 要求（沿用既有成功反馈） |

- 不提供灰态按钮、不提供说明文案；隐藏即为唯一表达（PRD 决议 12）；
- 已完成态若历史存在"执行中（代理已删除）"等数据，按本规则同样不展示（执行记录可在取消完成后查看）。

### 7.5 凭据区只读（AGT-07）

- 凭据区不再有重置按钮；「重置凭据」在底部操作区（第 2 行，`chevron-right`），点击后弹既有 `AppModal`（danger，标题「重置凭据？」，正文「旧凭据将立即失效，已接入的工具需要更新配置」，确认「重置」）；
- 重置成功后凭据区切回一次性凭据卡（警示条 + 明文 + 两个 `CopyField` + 「复制接入配置（含凭据）」）；
- 复制反馈沿用 `CopyField`：按钮切 `check` + 「已复制」800ms，并 toast「已复制」。

### 7.6 日程主页折叠与展开（CAL-04，设计侧定稿）

**行为要求（不含视觉新增）**

| 场景 | 期望行为 |
| --- | --- |
| 展开态 + 列表顶部上滑 ≥32px | **即时**折叠为选中周；形态切换不等待列表数据（内容未到用骨架占位） |
| 展开态 + 列表已离开顶部上滑 | 只滚动列表，**不折叠**（保留 v0.7.0"起手须在顶部"） |
| 折叠态 + 列表顶部下划 ≥32px | 展开为整月 |
| 折叠态 + 列表已离开顶部下划 | 先将列表滚到顶部；**同一次手势**内继续累计下划位移，达阈值即展开（不需要第二次手势） |
| 动画进行中再次手势 | 忽略（250ms 内） |
| 一次手势 | 只触发一次形态切换，剩余位移交还列表滚动，不回弹 |

**设计侧约束**

1. 折叠"延迟"的消除限定在**触发时机与渲染顺序**上，视觉（高度过渡、日期行位移、250ms、缓动 `ease-out`）与 v0.7.0 完全一致；
2. 折叠后的列表内容不得出现"空白等待"：数据未返回时以 `SkeletonList`（既有 3 行骨架）呈现；
3. 不新增跟手位移/进度反馈（与 PRD 1.3 非目标一致）；
4. 展开的"持续判定期"不得影响左右翻月/翻周手势（两者分别绑定日历区与列表区，互不共用）。

## 8. 可访问性（A11y，增量）

- **项目筛选器**：按钮 `aria-haspopup="listbox"`、`aria-expanded`；弹层 `role="listbox"`、选项 `role="option"` + `aria-selected`；打开后焦点进入当前选中项，`Esc`/返回键关闭并归还焦点；
- **项目标识 chip**：作为可点击元素需满足 44pt 热区（视觉 20pt + `::after` 扩热区），`aria-label="查看项目 <名称>"`，与"进入任务详情"的行点击语义区分；
- **颜色非唯一通道**：项目标识、筛选选中项、项目状态均带图标或文字（`folder`/`check`/状态文案）；
- **隐藏入口的可发现性**：已完成任务不再有执行/排期入口，端上以"[取消完成] 后可指派/安排日程"的**空态说明**替代（仅在"该任务曾有过日程或指派"时展示一行 `caption` 提示，避免用户误以为功能丢失；无历史则完全不展示）；
- **手势可达性**：左滑操作均提供等价的长按/详情页入口（任务详情/项目详情内的操作按钮），手势不作为唯一路径；下拉刷新非唯一刷新手段（进入页面即自动加载）；
- **动效降级**：`prefers-reduced-motion: reduce` 下，折叠/展开与弹层动画压到 0.01ms（既有权衡不变）；
- **对比度**：新增 chip 与胶囊的文字/底色对比度 ≥ 4.5:1（`primary` on `primary-light` 满足）。
