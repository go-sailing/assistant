## 1. 设计目标与原则

### 1.1 设计目标

1. **减法后界面依然"完整"**：删掉任务/项目/智能体后，日程主页、日程详情、日程编辑、对话、抽屉、设置各处**看不到缺口、空洞占位或半残控件**——用户感知不应是"少了几块"，而是"本来就长这样"；
2. **入口与路由零死链**：抽屉只剩「日程 / 助手」两项；所有被删路由静默重定向 `/calendar`，书签/历史/深链均不报错、不闪中间态；
3. **存量内容零丢失的视觉承诺**：升级后日历上原先的"任务日程"仍在（已转为普通日程，标题一致），列表不再有完成删除线、不再有类型标签；用户感知是"我的安排都还在"；
4. **对话口径诚实且有用**：用户提到"任务/项目/代理"时，助手如实说明能力已下线，并**给出日程替代方案**（"明天交报告"→建普通日程；"每周五交周报"→建循环日程），不装傻、不报错；
5. **折叠/展开真正跟手**：消除"展开态上滑要先滚一点点才折叠"（问题 A）与"折叠态下拉必须先滚到顶才能展开"（问题 B/C）；手指一动日历就动，双向连续、无缝衔接列表滚动；
6. **改手感不改观感**：头部三元素、浮动「今日」、月格视觉、列表行、全天分组视觉全部不变；本版只改折叠/展开的**手势过程与起手区域**，不新增任何控件、把手、气泡或进度指示。

### 1.2 设计原则（v0.8.0 新增 / 强化）

| 原则 | 说明 |
| --- | --- |
| **删干净，不留影** | 下线要连"文字残留"一起清：入口、筛选、表单行、卡片副行、空态文案、对话卡片、确认文案、错误码提示、埋点与死代码全清。允许"任务/项目/代理"字样仅出现在**历史聊天消息正文**与代码注释/文档中，界面文案零命中（见 7.6） |
| **减法不做替代品** | 日程是唯一的时间事务载体；不引入"轻待办/提醒/打卡"，不做"任务日程 → 只读标签"过渡态，不给迁移引导弹窗 |
| **静默兼容，不打扰** | 旧链重定向无 toast、无文案、无中间态闪烁；历史卡片灰态占位，不弹"该功能已删除"弹窗 |
| **跟手优先，滚动其次** | 形态手势一旦接管，日历形态由手指位移连续驱动；接管期间列表不滚动，到位后无缝交还列表滚动——"拖日历就是拖日历，滚列表就是滚列表" |
| **日历区即拖拽区** | 日历区（含折叠态周行）是天然的可拖拽表面。起手区域从"列表顶部"扩展到 **日历区 ∪ 列表顶部**，使折叠态下拉展开无需先滚到顶 |
| **两端吸附，中间跟手** | 手势中段 1:1 跟手；接近两态端点时轻阻尼（×0.4）软化手感；抬手按"行程过半或速度足够"吸附，杜绝半开残留 |
| **改过程不改结果** | 折叠态视觉、展开态视觉、两态高度、选中周呈现均保持 v0.6.0 / v0.7.0 基线；本版只改"从一态到另一态"的过程 |

### 1.3 本版设计边界（不做）

- 不新增/恢复折叠开关行、拖动把手、手势提示气泡、折叠进度指示；
- 不做跨月/跨年拖拽展开（只在"整月 ↔ 选中周"两态间吸附，松手必落两态之一）；
- 不做深色模式、字号调节、多语言、PC 端专门适配；
- 不做日程主页以外的布局/视觉改造（头部三元素、月格视觉、列表分组与视觉均不变）；
- 不复刻旧任务/项目/代理的任何视觉元素作为"纪念/入口"；历史卡片仅灰态占位；
- 不提供"删除我的任务数据"入口，不做任务/项目/代理的历史数据可视化或导出。

## 2. 设计基准

### 2.1 沿用基准（v0.1.0 ~ v0.7.0）

- 375pt 基准宽、480px 中栏（`--content-max-width`）、tokens.css 色板与字号阶梯、间距/圆角/阴影；
- 底部弹层体系（AppModal / AppActionSheet / 各 Sheet 的 grabber + `--safe-bottom`）；
- v0.5.0：状态条/胶囊条、卡片折叠条（`CardsCollapse` 对象数 >10 折叠）、StateEmpty / StateError / SkeletonList 三态组件；
- v0.6.0：日程主页三段式固定布局（头部 44 + 月历 + 列表独立滚动）、浮动「今日」胶囊、无列表标题行、折叠态 `renderWeek` 单周渲染、抽屉菜单按钮体系（`MENU_ROUTE_NAMES`）；
- v0.7.0：左滑操作、44pt 热区、微信 WebView 适配、`prefers-reduced-motion` 降级、日历手势的 8pt 观察期 / 1.5 方向锁 / 250ms 动画互斥；
- 日程领域全部既有视觉：冲突提示（图标 + 文字 + 橙色三重编码）、全天分组置顶、循环实例「已调整 / 已取消」胶囊、农历副字与休/班角标、月格标记点（单次实心点 / 循环空心环 / 环心点）。

### 2.2 本版新增设计参考

| 参考对象 | 参考点 | 不参考 |
| --- | --- | --- |
| iOS 通知中心/控制中心的下拉跟手 | 连续映射、抬手吸附、中段 1:1 | 加速度与弹簧过冲、多段停靠 |
| Android 底部抽屉（`BottomSheetBehavior`） | 起手区域与滚动嵌套（列表在顶才让位）、吸附阈值（过半/速度）、无缝交还滚动 | 中间停靠态、拖拽把手 |
| 地图类 App 的底图/面板连续收放 | 高度连续驱动、端点阻尼、"手指一动面板就动" | 惯性甩动、飞入动画 |
| 主流 App 的"空能力归档"处理 | 历史卡片灰态、不可点、不报错 | "该功能已移除"引导弹窗、数据导出入口 |
| 极简日历类 App 的折叠 | 折叠态只留一周、跨月周补齐 | 折叠态保留小月历缩略 |

## 4. 核心用户流程（UX Flow）

### 4.1 升级后的"减法"体验（DEL-01 ~ DEL-05）

```
用户升级到 v0.8.0（无引导弹窗、无迁移提示，界面一次性变为新形态）：
  抽屉：只剩「日程」「助手」
  日程主页：原先的任务日程仍在日历上（已转为普通日程，标题一致）
           → 列表不再有任务完成删除线；日期格不再有紫点；列表行不再有「普通日程/任务日程」标签
  日程详情：只有日程自身信息（标题、时间、全天、地点、备注、重复、冲突）+ 编辑/删除
  对话：说「建个任务/待办」→ 助手如实说明能力已下线，建议改用日程
        说「放到 XX 项目」→ 同样说明并建议用日程表达
        说「交给某代理」→ 同样说明（助手已无代理概念）
  设置：无「默认启动页」行；关于版本号 v0.8.0
数据侧（用户不可见）：任务日程逐条转普通日程；任务/项目/代理表与数据保留在库、停止读写
```

### 4.2 对话口径收敛（DEL-05）

```
用户：帮我建个任务，明天交报告
助手（文字）：任务能力已下线。我按「明天 09:00 交报告」建了一个日程，可以吗？   ← 如实说明 + 给出替代
  → 用户确认 → 创建普通日程（唯一写路径）

用户：每周五交周报，建个任务
助手（文字）：任务能力已下线。我按「每周五交周报」建了循环日程，重复 12 次。

用户：我的项目进度怎么样 / 帮我把任务派给工作机-CC
助手（文字）：项目与智能体能力已下线，我这边现在只能管理日程与记忆。
     需要的话，我可以把相关安排建/改到日程上。

边界：
  不装傻（不说"我不明白"）、不报错、不产生任何任务/项目/代理卡片；
  冲突、危险操作、作用域、方案化、相对时间解析等既有门控规则全部保留。
```

### 4.3 跟手折叠（CAL-04，展开态 → 折叠态，修复问题 A）

```
展开态，手指落在「日历区任意位置」或「列表区顶部」
  → 越过 8px 观察期，纵向占优（|dy| > 1.5|dx|）→ 锁定为形态手势
  → 手指向上移动：日历高度随手一起收（1:1，无死区、无"列表先滚"停顿）   ← 问题 A 修复
       · 日历内容同步上移，把选中周滑向可视区顶部（连续、不跳变）
       · 跟手期间列表不滚动
  → 抬手：
       · 行程 ≥ 50% 或 释放速度 ≥ 0.3px/ms（向上）→ 吸附折叠（≤250ms ease-out）
       · 否则 → 回弹到展开
  → 吸附到折叠态后本次手势若仍在继续：剩余上滑位移无缝转为列表滚动
```

### 4.4 无需到顶的跟手展开（CAL-04，折叠态 → 展开态，修复问题 B / C）

```
折叠态，列表很长已滑到中部（scrollTop 很大）
  → 直接在「日历周行」（始终可见）向下拖                                   ← 问题 B/C 修复（无需先滚回顶部）
  → 越过 8px 观察期，纵向占优 → 锁定为形态手势
  → 手指向下移动：先恢复整月渲染，日历高度随手展开（1:1）
  → 抬手吸附展开；继续下拉 → 无缝转为列表回滚/回弹

对照（重要，防误触回归）：
  在列表中部下拉（不经过日历区）→ 只滚动列表，形态不变
  在列表中部上滑 → 只滚动列表，形态不变
```

### 4.5 列表中部滑动不误触

```
展开态或折叠态，列表已滚动到中部（scrollTop > 2）
  → 上滑：只滚动列表（内容上移、看更晚的日程）
  → 下拉：只滚动列表（内容回滚、看更早的日程）
  → 日历形态全程不变（保留 v0.7.0 的正确行为）
说明：起手是否接管形态手势，以「起手瞬间手指落在哪个区域」为准——
      落在日历区或列表顶部才接管；落在列表中部的滚动区不接管。
```

### 4.6 历史聊天卡片占位（DEL-06 / 决议 #8）

```
用户打开历史会话（含升级前产生的任务卡、子任务组、项目结果组、任务候选）：
  → 不改写历史消息正文；
  → 渲染层将上述卡片统一替换为「该能力已下线」灰态占位：
       · 灰底（--bg-page）+ 灰字（--text-disabled）+ 左侧灰条
```

## 7. 关键交互细则

### 7.1 跟手联动模型（CAL-04 核心定稿）

**设计模型**

> 折叠/展开不是"滑够距离后播一段动画"，而是**日历形态由手指纵向位移连续驱动**；一次手势在"形态变化"与"列表滚动"之间无缝衔接；日历区（含折叠态周行）就是天然的可拖拽区。

- 引入连续量 **`p ∈ [0, 1]`**（`p = 1` 完全展开整月，`p = 0` 完全折叠选中周）；
- 日历高度：`H(p) = H_week + p × (H_exp − H_week)`；
- 日历内容位移：`T(p) = (1 − p) × weekIndex × cellH`（选中周连续滑向可视区顶部）；
- 跟手映射：`p ← clamp(p₀ − Δy / (H_exp − H_week), 0, 1)`，`Δy` 为相对起手点的纵向位移（向上为负）；
  - 展开态上滑 `Δy < 0` → `p` 减小 → 收；
  - 折叠态下拉 `Δy > 0` → `p` 增大 → 展；
- 端点阻尼：当 `p` 落在 `[0, 0.15]` 或 `[0.85, 1]` 时，映射增量乘 **0.4**，让接近两态时的位移变"软"；
- 跟手期间 **`transition: none`**，`H(p)` 与 `T(p)` 逐帧直写，保证 1:1。

**手势状态机**

```
        touchstart(日历区/列表顶部)
                │
                ▼
        ┌───────────────┐   位移<8px 或 未判向
        │   observe     │ ─────────────────────────┐
        │  (观察期 8px) │                          │
        └───────┬───────┘                          │
    纵向占优 │               横向占优                │
   |dy|>1.5|dx|                │                    │
                ▼              ▼                    ▼
        ┌───────────────┐  ┌──────────┐      （维持/滚动）
        │  drag(跟手)   │  │ 交还横滑 │
        │ p 随 Δy 变化  │  │ 翻月/翻周│
        │ 阻止列表滚动  │  └──────────┘
        └───────┬───────┘
           touchend
                ▼
        ┌───────────────┐  行程≥50% 或 速度≥0.3px/ms
        │   settle      │ ──────────────► 吸附目标态 (≤250ms)
        │ (吸附/回弹)   │ ──────────────► 或 回弹起始态 (≤250ms)
        └───────┬───────┘
                │ 动画结束且本次手势仍继续
                ▼
        ┌───────────────┐
        │   handoff     │  剩余位移交还列表滚动（展开态继续上滑→列表上滚；
        │ (无缝交还)    │  折叠态继续下拉→列表回滚/回弹）
        └───────────────┘

  中断（多指/路由切换/系统手势）：任何状态 → 复位到最近一次已吸附的合法态
```

### 7.2 手势分区与起手规则

| 起手区域 | 展开态 | 折叠态 |
| --- | --- | --- |
| **日历区**（`.month__cal`，含周行，任意位置） | 上滑 → **跟手折叠** ★ | 下拉 → **跟手展开** ★（新增，问题 B/C 修复关键） |
| **列表区顶部**（`scrollTop ≤ 2`） | 上滑 → **跟手折叠** | 下拉 → **跟手展开** |
| **列表区中部**（`scrollTop > 2`） | 只滚列表（形态不变） | 只滚列表（形态不变） |

补充规则：

1. **方向锁**：`|dy| > 1.5 × |dx|` 判纵向并进入形态手势；否则交还（横滑 → 翻月/翻周，点按 → 选日期）；
2. **观察期**：位移 < 8px 不锁定方向、不进入形态手势（沿用）；
3. **起手快照**：是否接管以"起手瞬间所在区域"为准，手势进行中不再因列表滚动位置变化而取消判定（沿用 v0.7.0 的 `startAtTop` 思路）；
4. **反向位移不驱动形态**：展开态在日历区下拉、折叠态在日历区上滑，均不改变形态（保持当前态），也不产生跳变；
5. **日历区横滑/点按零回归**：纵向锁定前，日历区横滑仍翻期、点按仍选日期。

### 7.3 吸附判定与无缝衔接

| 项 | 规格 |
| --- | --- |
| 吸附目标 | 抬手时 **位移行程 ≥ 50%** 或 **释放速度 ≥ 0.3px/ms（方向一致）** → 吸附到目标态 |
| 回弹 | 不满足上述条件 → 回弹到起始态，形态不变 |
| 速度采样 | 最近 100ms 的位移换算（SDD 定稿具体窗口） |
| 吸附/回弹动画 | `≤ 250ms`，`--dur-page` ease-out |
| 一次一手势 | 一次手势只切换一次形态；吸附到位后剩余位移交还列表滚动，**不再二次触发** |
| 跟手期间列表 | **不滚动**（形态手势接管后消化纵向位移，阻止原生滚动；实现方式由 SDD 定稿） |
| 到位后无缝衔接 | 展开态吸附到位后继续上滑 → 列表正常上滚；折叠态吸附到位后继续下拉 → 列表正常回滚/回弹；**不得出现停顿、回弹或内容跳变** |
| 列表中部 | 起手在列表中部 → 只滚动列表，形态不变（保留 v0.7.0 正确行为） |
| 边界越界归形态 | 列表已在顶部（展开态）时，上滑的越界位移用于折叠；列表已在顶部（折叠态）时，下拉的越界位移用于展开；**此时不同时出现列表橡皮筋与形态变化** |
| 惯性滚动 | 松手后的列表惯性滚动（momentum）**不**触发形态手势 |
| 动画互斥 | 吸附/回弹动画期间（≥200ms、≤250ms）忽略新手势（沿用 v0.6.0 策略） |
| 空/短列表 | 列表内容不足一屏（无滚动）时，两方向均可在任意位置（日历或列表）触发，且不影响列表（无滚动可言） |

### 7.4 渲染切换与动效

| 项 | 规格 |
| --- | --- |
| 跟手期间渲染 | **保持整月渲染（`mode='month'`）并整体裁剪收缩**（`.month__cal { overflow: hidden }`），避免中途从整月切单周造成跳变 |
| 折叠到位渲染 | 吸附到折叠态（`p=0`）**动画结束后**再切换为"只渲染选中周"（`renderWeek=true`，沿用 v0.6.0 思路），切换瞬间不再 animate |
| 展开方向渲染 | **起手即恢复整月渲染**（`renderWeek=false`），再随 `p` 展开，避免跳变 |
| 跟手动画 | 无（逐帧直写） |
| 吸附/回弹动画 | 高度 + 内容位移同步 `≤250ms` ease-out，二者严格同帧，避免"日历在动、内容脱节" |
| 视觉不变 | 不新增控件、不新增手势提示、不改折叠态一周视觉与月份标题、浮动今日、头部三元素 |
| 无障碍降级 | `prefers-reduced-motion: reduce` 下吸附动画缩短/取消（即时到位），但**形态与跟手功能不缺失** |

### 7.5 边界与异常

| 场景 | 规格 |
| --- | --- |
| 横滑与点按 | 日历区横滑仍翻月/翻周、点按仍选日期；跟手只在纵向锁定时接管 |
| 折叠态跨月周 | 邻月计数补齐、月格标记点逻辑不变（`weekMonthKeys` 机制保留） |
| 形态与滚动位置恢复 | 从日程详情返回（5 分钟内）恢复"选中日 + 列表滚动位置 + 日历形态"；页面重建回到"默认展开"（不按条数自动定型） |
| 浮动「今日」 | 显隐与行为不变（选中日 ≠ 今天时显示；点击回今天且**不改变形态**） |
| 中断复位 | 手势中途被系统手势/来电/切前后台打断 → 复位到最近一次已吸附的合法态，**不残留半开** |
| 与左右翻期并发 | 跟手进行中不翻期；翻期进行中不进入跟手 |
| 多指 | 手势中插入第二指 → 取消本次形态手势并复位 |
| 数据加载 | 折叠/展开切换沿用"同一日期不重复请求"缓存；跨月周邻月计数失败静默（该月格子只缺点） |
| 极端高度 | 页面高度不足以同时容纳头部 + 月格下限 + 列表下限时，沿用 v0.4.0 的月格压缩（`--grid-cell-min`），不退化为整页滚动 |

**C. 手势（CAL-04）**

- [ ] **无死区（问题 A）**：展开态列表顶部上滑，手指移动 ~16px 内即可观察到日历高度开始变小，**无"列表先滚动"的位移**；连续 10/10 折叠成功；
- [ ] **日历区上滑**（新增起手区）：展开态在日历区上滑同样连续 10/10 折叠成功；
- [ ] **无需到顶（问题 B/C）**：折叠态、列表已滚到中部，直接在日历周行下拉可跟手展开，**无需先滚回顶部**；连续 10/10 成功；
- [ ] **跟手性**：手指 1px ↔ 日历高度变化约 1px（误差 ≤ 2px）；无跳变、无回弹抖动、≥55fps；
- [ ] **吸附正确**：行程过半或速度足够 → 吸附目标态；不足 → 回弹原态；吸附动画 ≤250ms；
- [ ] **无缝衔接**：形态到位后继续上滑/下拉，列表能无缝滚动/回滚，无停顿或跳变；惯性滚动不触发形态；
- [ ] **列表中部不误触**：列表中部上滑/下拉 10 次，形态均不变（只滚动）；
- [ ] **横滑/点按零回归**：日历区横滑仍翻月/翻周、点按仍选日期；跟手只在纵向锁定时接管；
- [ ] **端点阻尼**：接近两态时手感变软（×0.4），无生硬越界；
- [ ] **中断复位**：多指/切前后台打断后无半开残留；
- [ ] **降级**：开启系统"减弱动态效果"，吸附动画缩短/取消但形态与跟手可用；
- [ ] **真机专项**：微信 WebView + iOS Safari + Android Chrome 上滑折叠 / 日历区下拉展开 / 列表中部滚动均无卡顿投诉。
