### 3.1 关键通过项（摘要）

**迁移与模型（MDL）**
- 迁移 014 由 `migrate.ts` 正常执行并登记；**重复执行为 no-op**（14 个迁移全部 skipped，数据快照 `13/21/3/16/14` 前后一致）；全新库首次安装路径 14 个迁移一次通过。
- 结构：`projects` 列清单与约束正确、无 `priority/due_at` 等冗余列；`tasks` 已无 `task_type/parent_id`，旧约束与索引清除，新增 `fk_tasks_project ... ON DELETE CASCADE` 与两个新索引。
- 守恒：项目数 4=4、成员关系 3（装修项目）+1（季度述职）=4、任务总数 12→8（减少量=项目数）、`task` 类型日程 3→1 且 `normal` 0→2；**孤儿成员与遗留多层行不写入 `project_id`**；超长项目名转正后标题截断至 100。
- 状态归一（TC-MDL-059）：空项目 `completed`→`todo`、成员全完成 `todo`→`completed`、含未完成成员保持 `todo`，与 `recalcStatus` 口径完全一致。
- 接口面：`/projects` CRUD、删除计数与 `preview-remove` 一致、成员接口可用（`page_size=200` 不再被拒）、`priority/due_at/status/task_type/root_only/parent_id` 一律 1001 拒绝、三个下线端点 404。

**任务页/项目页/详情（TASK/FRM/PRJ/DTL/ENTRY）**
- `GET /tasks` 不筛选即返回全部任务（含项目下任务）、`project_id=<id>` 与 `project_id=none` 结果互补、指向不存在项目返回空列表、任务 DTO 无类型字段且带 `project` 摘要。
- 项目派生态：成员全完成 → `completed`（写 `completed_at`）；新增未完成成员 / 取消完成成员 → 回 `todo` 并清 `completed_at`；**并发完成两成员最终一致**。
- 已完成任务：指派 4021、排期 4002（任务原文案）；**手工完成时在途 `pending` 指派自动取消并写入 `unassigned` 留痕**；项目排期返回「项目不支持安排日程」。
- 凭据：`token/rotate` 可用、重置后旧凭据立即失效（401 + `4019`）；凭据区无行内「重置」、底部「重置凭据」为唯一入口（静态断言）。
- 结构性：项目详情无「安排日程/编辑项目/完成项目」按钮、仅保留「删除项目」；项目页无排序与状态 Tab；任务详情已完成态两处入口整块不渲染；`SubtaskGroupCard` 已删除、`project_groups` 已接线。

**代理/MCP 回归（v0.7.0 能力未被模型重构破坏）**
- `claim_agent_task` → `complete_agent_task` 闭环：任务自动完成、`agent_state=succeeded`；`fail_agent_task`：任务保持未完成、`agent_state=failed`；`list_agent_tasks` 可用；用户 JWT 访问 `/mcp` 仍 401。

**安全（SEC）**
- 项目/任务越权 404、未登录 1002、`status` 篡改 1001、关键词注入被参数化转义、清单参数口径不回归（1001）。

**非功能（NFR，冒烟级）**
- 项目列表 median 4ms / p95 6ms；任务列表 median 6ms / p95 7ms；按 `project_id` 过滤 median 5ms / p95 6ms（**数据量仅 ~40 行，属时延冒烟，非 P95 压测**）。
- 并发正确性：两成员并发完成 → 项目 `completed`、计数一致。

**埋点（AUDIT）**
- `project_created`、`project_member_add`、`project_status_derived`（含 `from/to` 与成员计数，状态未变化不产生记录）、`project_member_move_out`、`project_deleted`（含 `deleted_task_count/deleted_event_count`）、`project_extract_migrated`（新增，见缺陷 D-002）均已在运行日志中实测出现。

## 4. 缺陷清单

| # | 级别 | 缺陷 | 影响 | 处置与复测 |
| --- | --- | --- | --- | --- |
| **D-001** | **P1** | **手势方向锁在 8px 观察期内即判定方向**：`TaskListItem.vue`、`ProjectCard.vue`、`TaskHomeView.vue` 三处调用点在位移未过观察期时就调用 `resolveAxis` 并锁定方向（仅 `ProjectPageView.vue` 有守卫） | 手指起手的微小抖动会把整次手势定格为纵向（左滑失效）或横向（下拉刷新被抢占），正是 GES-01 要消除的互斥失效 | 已修复：把观察期守卫**内聚进 `resolveAxis`**（两轴位移均 <8px 时返回 `null`），调用点无需各自守卫；手势单元断言 11/11 通过，`vue-tsc` 0 错误；SDD §12.2 已同步补充说明 |
| **D-002** | **P2** | **迁移埋点 `project_extract_migrated` 缺失**（SDD §16.2 / TC-AUDIT-079 要求） | 迁移期缺少可观测摘要，运维需手工查库 | 已修复：`migrate.ts` 在"本次真正执行 014"时输出该埋点（`project_count`/`member_count`）；全新库实测输出 `project_count=0, member_count=0`；SDD §16.2 字段已与实现对齐 |

> 说明：测试执行中另发现 2 处**文档与代码口径不一致**（非产品缺陷），已回写文档：① `page_size>100` 的行为在 `/projects` 与既有 `/tasks` 一致为**拒绝（1001）**，用例 TC-MDL-034 原写"夹取到 100"已修正；② 斜向手势（dx=12、dy=90）判定为 `null`（既不刷新也不左滑），用例 TC-GES-004 期望已修正。

## 5. 口径澄清（测试期确认，均已落到文档）

| # | 口径 | 结论 |
| --- | --- | --- |
| 1 | `/projects` 列表 `page_size` 超上限 | **拒绝 400 `1001`**（与 `/tasks` 同口径）；合法值正常返回，服务端仅对内部直调做夹取兜底 |
| 2 | 项目成员接口 `page_size` | **不做上限校验**，服务端按 `config.project.maxMembers` 夹取（端上需一次拿全成员；原实现按 100 夹取会导致 >100 成员的项目详情直接报错，已修） |
| 3 | 斜向手势判定 | 未达任一主导 → `null`：本次手势仅滚动列表（不刷新、不左滑） |
| 4 | 迁移期状态归一 | 存量项目状态按派生口径一次性归一（空项目 → `todo`；成员全完成 → `completed`），运行期由 `recalcStatus` 单点维护 |
| 5 | 历史对话卡片 | v0.7.0 已落库的 `subtask_groups` 仍会被端上兼容识别（属预期行为，避免历史卡片消失） |

## 7. 结论与发布建议

1. **自动化可验证范围内全部通过**（131/131，142 条断言 0 失败），未发现阻塞发布的遗留缺陷；
2. 本轮发现的 2 个缺陷（D-001 手势观察期、D-002 迁移埋点）**已修复并复测**，对应文档（SDD §12.2、§16.2）已同步；
3. **发布前必须补跑**：① 真机手势专项（GES 与 CAL 全量，重点验证"左滑不触发刷新""折叠即时、下划一次展开"）；② 浏览器走查（任务页筛选器与 chip、回跳高亮、项目页/详情精简、已完成任务入口隐藏、凭据区只读）；③ 生产级数据量的迁移演练与锁窗口观测；④ v0.1.0~v0.7.0 基线回归全量；
4. 建议在真机专项中重点复核 D-001 的修复效果（起手抖动不再定格方向），可将"斜向手势 0 误触刷新、0 误锁方向"作为验收硬指标（对应 TC-GES-004/005）。
