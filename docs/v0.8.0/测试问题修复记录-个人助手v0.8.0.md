## 2. L-01 修复：端上埋点落地（D-09 / T10 口径）

### 2.1 落地方式（不新增上报通道）

新增 `src/web/src/utils/telemetry.ts`：唯一端上日志通道，`logAppEvent()` 仅在开发期为真时输出一条
结构化 `console.info(event, fields)`。开发期判定语义等价于 Vite 的 `import.meta.env.DEV`，但实现上先取
`import.meta.env` 再取值（`env?.DEV ?? true`），目的是：**无 Vite env 注入的环境**（裸 esbuild / 纯 Node
测试夹具）退化为「按开发期处理」而不抛 `Cannot read properties of undefined`。实测三态：

| 环境 | `import.meta.env` | 日志行为 |
| --- | --- | --- |
| `vite dev` | Vite 注入 `{DEV:true,…}` | 落一条 `console.info`（开发期日志检查可见） |
| `vite build`（生产） | Vite 注入 `{DEV:false}` | 常量折叠为 `false`，日志分支被摇树消除：**生产包内既无 `console.info` 调用也无事件名** |
| 裸 esbuild / Node 夹具（无注入） | `undefined` | 不抛错，按开发期处理（夹具可直接断言） |

模块**无任何 import**、不写 `localStorage`/`sessionStorage`、不发起 `fetch`/`sendBeacon`/`XHR`、不使用 `navigator`/`document`。

字段口径与后端日志一致：只含 ID / 枚举 / 计数 / 路径，**不含标题、备注与对话正文**。

### 2.2 四条事件的触发点与字段

| 事件 | 触发点（实现落点） | 字段 | 频次口径 |
| --- | --- | --- | --- |
| `legacy_route_redirect` | `router/legacyRedirect.ts`：`router.afterEach` 判定 `to.redirectedFrom.meta.retiredLegacy`；标记在 `router/routes.ts` 的 17 条旧链记录上（`/tasks*`、`/projects*`、`/agents*`、`/search`、`/lists`、`/calendar/task/new`、`/calendar/tasks`、`/calendar/:id/edit/task`） | `{ path, target }` | 一次访问一条；`/calendar/day`、`/chat/:id` 等非本版下线的历史重定向不落事件 |
| `calendar_shape_gesture` | `views/calendar/MonthView.vue`：`onShapeTouchEnd` / `cancelGesture`（一次手势结束时结算） | `{ direction, origin, took_over, result, frames, fps, duration_ms }` | 一次手势一条；观察期内抬起（点按/轻触）不计为手势 |
| `calendar_shape_gesture_dropped` | `MonthView.vue`：动画互斥（`beginGesture` 且 `animating`）、方向锁判为横向（观察期结束）、多指打断（`cancelGesture`） | `{ reason, origin }`，`reason ∈ {animating, direction_lock, multi_touch}` | 与实际丢弃次数一致 |
| `legacy_card_placeholder_hit` | `components/chat/MessageBlocks.vue`（`cards.tasks` / `cards.subtask_groups` / `clarify.candidates` 逐项）+ `components/chat/ConfirmBar.vue`（任务类确认条） | `{ object_type, action? }`，`object_type ∈ {task, subtask_group, candidate, confirm}` | 每个占位项渲染一条；同一条消息重复渲染不重复计数 |

> 方向口径：`direction` 为手指位移方向（`up` 上滑 / `down` 下拉 / `none`）；
> 结果口径：`result` 为吸附结果（`collapse` 折叠到位 / `expand` 展开到位 / `rebound` 回弹到起手端 / `none` 未接管未结算）。
> 帧率口径：`frames` 为跟手期间实际写形态的帧数，`fps = frames × 1000 / duration_ms`（未接管记 0），对应 TC-AUDIT-082 的「跟手帧率采样」。

### 2.3 为可复核性做的最小结构调整（不改变行为）

- 路由表从 `router/index.ts` 拆到 `router/routes.ts`（纯路由表，无浏览器 History 依赖），
  重定向观测注册抽到 `router/legacyRedirect.ts`（`observeLegacyRedirects(router)`）；
  `index.ts` 仍负责 `createWebHistory` 与登录守卫，行为不变。
  这样可用 **memory history** 在 Node 中对真实路由表逐条回归重定向与埋点，无需真机。
- `MonthView.vue` 的埋点结算点集中在 `logGesture()`/`logShapeDropped()`，不介入跟手状态机；
  `applyDragFrame()` 增加一行帧采样计数（`frames`），不改变任何样式写入与吸附判定。

## 3. L-02 修复：迁移 014 观测补强

`src/server/src/db/migrate.ts` 增加「迁移观测钩子」（按迁移文件名注册）：

- **迁移前基线**（事务外只读，采集失败仅告警不阻断）：`captureLegacyTaskEventBaseline()` ——
  `task_events`（待转换任务日程条数）、`blank_title`（需兜底标题条数）、`users`（涉及用户数）；
- **迁移提交后汇总**（只读，同样不阻断）：`eventShapeStats()` ——
  `normal_total` / `fallback_titles` / `remaining`（残留，应 0）/ `empty_titles`（应 0）；
- **汇总日志**：`logger.info('migration_014_converted', { file, converted, fallback, users, normal_total, fallback_titles, remaining, empty_titles, attempts, retries, duration_ms })`；
  残留或空标题非 0 时补 `logger.warn('migration_014_residual_rows', …)`；
- **失败与重试**：瞬时故障（`40001/40P01/0800x/57P0x`）最多 3 次尝试，每次重试前落
  `logger.warn('迁移遇到瞬时故障，准备重试', { file, attempts, pg_code })`；非瞬时错误与超限失败落
  `logger.error('迁移失败', { file, attempts, retries, duration_ms, error })` 并抛出。每次尝试都是完整事务（失败已整体回滚），语义与幂等性不变。
- **隐私**：日志只含计数、枚举与耗时，不含标题/备注正文。
