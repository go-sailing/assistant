## 1. 设计概述

### 1.1 系统边界（本版不变）

```
                       ┌────────────────────────────────────────────┐
   移动端 H5（App） ──REST/SSE──▶│  个人助手服务端（Node/Express 单体）        │
                       │                                            │
                       │  ┌───────────────────────────────┐         │
                       │  │ TaskService │ ProjectService  │  ★ 新增  │
                       │  │ EventService│ ChatService     │         │
                       │  │ AgentService│ MemoryService…  │         │
                       │  └───────┬───────────────────────┘         │
                       │          │  领域唯一入口原则                  │
                       │  ┌───────┴──────────────────────────┐      │
                       │  │ REST 路由（/api/v1）│ MCP 接入层（/mcp）│    │
                       │  └──────────────────────────────────┘      │
                       └────────────────────────────────────────────┘
```

- **不新增**对外协议与端点前缀：仅在 `/api/v1` 下新增 `/projects` 资源，并收窄 `/tasks` 的参数面；
- **数据模型变更**是本版唯一"跨层"改动：新增 `projects` 表、`tasks` 去列加列（见 §3）；
- **不做**（见 PRD 1.3）：项目扩展能力（优先级/截止时间/协作/模板/看板）、任务分页、任务页高级筛选、项目手工完成、代理与 MCP 能力变更、日历视觉改造。

### 1.2 设计目标与手段

| 目标 | 手段 |
| --- | --- |
| 项目与任务在模型层分离 | 新增 `projects` 表承接原 `task_type='project'` 行（**id 直通**）；`tasks` 删 `task_type`/`parent_id`、加 `project_id`；删除列与约束一次完成（迁移 014） |
| 类型维度彻底消失 | 后端：去 `normalizeTaskType`、去 `task_type` 过滤与 DTO 字段；LLM：`create_task` 去 `task_type`、新增 `create_project`；前端：去类型参数与类型分支（含对话项目卡片跳转） |
| 项目只保留必要字段 | `projects` 无 `priority`/`due_at`；原项目行的这两个值**在迁移中丢弃**（演练时输出清单） |
| 项目状态派生且一致 | 所有影响成员完成度的写路径（成员创建/完成/取消完成/移入/移出/删除）在同一事务内调用 `ProjectService.recalcStatus`（单条原子 UPDATE） |
| 任务页全量 + 项目筛选 | `GET /tasks` 去掉 `root_only`/`task_type`，新增 `project_id`（数字或 `none`）；任务 DTO 带 `project: {id,name} \| null`；端上新增项目筛选器组件 |
| 回跳跟随来源 | 新建任务页落点由"最终所属项目"决定：有项目 → `/projects/:id?highlight=`；无 → `/tasks?highlight=` |
| 入口与状态一致 | 端上按 `status=completed` 隐藏两处入口；服务端拒绝规则不变（4021/4002），并补"手工完成时待领取指派自动取消"的一致性写 |
| 手势互斥与形态即时 | 前端新增**手势方向锁**（单例）供"列表刷新 × 行内左滑"共用；日历折叠拆为"同步切形态 + 异步取数据"，展开改为"持续判定期" |

### 1.3 核心概念与领域不变量

**概念**

| 概念 | 定义 |
| --- | --- |
| 项目（Project） | 独立实体，任务的容器；字段仅 name/note/status/completed_at/source/时间；**状态为派生只读** |
| 任务（Task） | 只有一种任务；可有 0 或 1 个 `project_id`；可安排日程、可指派代理；有 priority/due_at |
| 项目成员 | `project_id` 非空的任务；仅一层，不可再挂任务；项目删除时级联删除 |
| 派生状态 | 项目 `status`：成员数 > 0 且全部 completed → `completed`；否则 `todo`；空项目恒 `todo` |

**不变量（服务端强制）**

| # | 不变量 | 保障手段 |
| --- | --- | --- |
| I1 | 项目必须是当前用户的独立实体，不携带优先级与截止时间 | `projects` 表无对应列；`ProjectService` 入参 schema 不含 |
| I2 | 任务最多属于 1 个项目，且项目必须属于同一用户 | `tasks.project_id` 单列外键 + 写入前 `assertProjectOwned` |
| I3 | 项目成员不超过上限 | `assertMemberCapacity`（`config.project.maxMembers`，默认 200） |
| I4 | 项目状态 = 成员完成度派生结果，**不接受显式写入** | 唯一写入口 `recalcStatus`；`PATCH /projects/:id` 不接受 `status` |
| I5 | 任务完成状态与代理执行状态正交；已完成任务不可指派/排期 | v0.7.0 规则保留（4021 / 4002），端上隐藏入口 |
| I6 | 删除项目 = 删除其成员任务及其任务日程 | `projects` 删除 + `tasks.project_id ON DELETE CASCADE` + 事务内显式删 events |
| I7 | 项目不可指派代理、不可安排日程、不可手工完成 | 模型上项目不在 `tasks` 表 → 三条路径天然不可达（4002 语义化提示） |
| I8 | 迁移后 `tasks` 不含 `task_type`/`parent_id`，`projects` 与 `tasks` 数量与关系守恒 | 迁移 014 收尾断言（§3.4） |

## 3. 数据模型与迁移（014）

### 3.1 `projects` 表

| 列 | 类型 | 约束/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `INTEGER` | PRIMARY KEY（无默认，迁移显式写入；序列随后推进） | 复用原项目任务 id |
| `user_id` | `INTEGER` | NOT NULL，REFERENCES users(id) ON DELETE CASCADE | 归属 |
| `name` | `VARCHAR(200)` | NOT NULL | 项目名称（承接原 `tasks.title`） |
| `note` | `VARCHAR(2000)` | NULL | 备注 |
| `status` | `VARCHAR(16)` | NOT NULL DEFAULT `'todo'`，CHECK IN ('todo','completed') | **仅由 `recalcStatus` 写入** |
| `completed_at` | `TIMESTAMPTZ` | NULL | 派生为 completed 时写入 |
| `source` | `VARCHAR(16)` | NOT NULL DEFAULT `'manual'`，CHECK IN ('manual','chat') | 来源 |
| `created_at` / `updated_at` | `TIMESTAMPTZ` | NOT NULL DEFAULT now() | 时间戳 |

索引：

- `idx_projects_user ON projects (user_id, created_at DESC)`——项目页固定排序（创建时间倒序）；
- `idx_projects_user_status ON projects (user_id, status)`——保留给内部统计与后续筛选（端上本版不筛选）。

**明确不存在的列**：`priority`、`due_at`、`parent_id`、`task_type`、`list_id`、`agent_*`。

### 3.2 `tasks` 表变更

| 变更 | 说明 |
| --- | --- |
| 删除 `task_type` | 连同 `ck_tasks_task_type` 约束、`idx_tasks_user_task_type` 与部分索引 `idx_tasks_user_project`（`WHERE task_type='project'`） |
| 删除 `parent_id` | 连同 `idx_tasks_parent`（如存在）；其"项目归属"语义由 `project_id` 承接 |
| 新增 `project_id` | `INTEGER NULL REFERENCES projects(id) ON DELETE CASCADE`；写入前校验项目归属与成员上限 |
| 新增索引 | `idx_tasks_user_project_id ON tasks (user_id, project_id)`；`idx_tasks_user_project_status ON tasks (user_id, project_id, status)`（项目详情成员与任务页按项目过滤用） |
| 保留 | `id/user_id/list_id/title/note/status/priority/due_at/completed_at/source/created_at/updated_at` 与 `agent_*` 全部保留 |

> 说明：`list_id` 继续作为内部"默认清单"兜底（清单能力已下线）；本版不改动 `task_lists`。

### 3.3 迁移 014 完整 DDL

文件：`src/server/src/db/migrations/014_project_extract.sql`。**幂等、可重复执行**，**单文件单事务**（沿用 `src/server/src/db/migrate.ts` 机制：`BEGIN → query(sql) → 记录 schema_migrations → COMMIT`，失败整体 ROLLBACK）。

执行顺序（不可颠倒，原因见注释）：

```sql
-- ============================================================
-- 014_project_extract.sql
-- v0.8.0 项目模型抽离：projects 独立建表；tasks 去 task_type/parent_id；
-- 原项目行搬迁（id 直通）；项目关联日程处置；收尾断言。
-- 幂等：IF NOT EXISTS + pg_constraint/列存在性判定 + ON CONFLICT DO NOTHING。
-- 顺序：① 建表 → ② 加 project_id 列 → ③ 搬迁项目行 → ④ 改写成员归属
--      → ⑤ 处理项目关联日程 → ⑥ 删项目行 → ⑦ 删旧列/约束/索引
--      → ⑧ 建外键与新索引 → ⑨ 推进序列 → ⑩ 断言校验 → ⑪ 存量项目状态归一
-- 关键：④ 必须在 ⑥ 之前，否则删项目行会沿 parent_id 级联删掉全部成员任务。
-- ============================================================

-- ① 项目表
CREATE TABLE IF NOT EXISTS projects (
  id           INTEGER PRIMARY KEY,
  user_id      INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  name         VARCHAR(200) NOT NULL,
  note         VARCHAR(2000),
  status       VARCHAR(16) NOT NULL DEFAULT 'todo',
  completed_at TIMESTAMPTZ,
  source       VARCHAR(16) NOT NULL DEFAULT 'manual',
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

COMMENT ON TABLE projects IS
  'v0.8.0 项目：独立实体（无优先级、无截止时间）；status 由成员完成度派生，仅由 ProjectService.recalcStatus 写入';

DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM pg_constraint
    WHERE conname = 'ck_projects_status' AND conrelid = 'projects'::regclass
  ) THEN
    ALTER TABLE projects ADD CONSTRAINT ck_projects_status
      CHECK (status IN ('todo', 'completed'));
  END IF;
  IF NOT EXISTS (
    SELECT 1 FROM pg_constraint
    WHERE conname = 'ck_projects_source' AND conrelid = 'projects'::regclass
  ) THEN
    ALTER TABLE projects ADD CONSTRAINT ck_projects_source
      CHECK (source IN ('manual', 'chat'));
  END IF;
END $$;

CREATE INDEX IF NOT EXISTS idx_projects_user
  ON projects (user_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_projects_user_status
  ON projects (user_id, status);

-- 序列：id 直通场景下由迁移显式写入，需独立序列供后续自增
CREATE SEQUENCE IF NOT EXISTS projects_id_seq;
ALTER SEQUENCE projects_id_seq OWNED BY projects.id;
ALTER TABLE projects ALTER COLUMN id SET DEFAULT nextval('projects_id_seq');

-- ② tasks 增加 project_id（先不加外键：数据尚未一致）
ALTER TABLE tasks ADD COLUMN IF NOT EXISTS project_id INTEGER;

-- ③ 搬迁项目行（id 直通；重复执行安全）
DO $$
BEGIN
  IF EXISTS (
    SELECT 1 FROM information_schema.columns
    WHERE table_name = 'tasks' AND column_name = 'task_type'
  ) THEN
    EXECUTE $sql$
      INSERT INTO projects (id, user_id, name, note, status, completed_at, source, created_at, updated_at)
      SELECT t.id, t.user_id, t.title, t.note, t.status, t.completed_at, t.source, t.created_at, t.updated_at
      FROM tasks t
      WHERE t.task_type = 'project'
      ON CONFLICT (id) DO NOTHING
    $sql$;
  END IF;
END $$;

-- ④ 改写成员归属（必须先于 ⑥）：parent_id → project_id
--    必须同时清空 parent_id：tasks.parent_id 是自引用外键且 ON DELETE CASCADE，
--    若只写 project_id 而保留 parent_id，⑥ 删除项目行时会沿它级联删掉全部成员任务。
--    以 parent_id 列存在为旧模型标记（迁移完成后列已删除），保证重跑为安全 no-op。
DO $$
BEGIN
  IF EXISTS (
    SELECT 1 FROM information_schema.columns
    WHERE table_name = 'tasks' AND column_name = 'parent_id'
  ) THEN
    EXECUTE $sql$
      UPDATE tasks
      SET project_id = COALESCE(project_id, parent_id),
          parent_id  = NULL
      WHERE parent_id IS NOT NULL
        AND parent_id IN (SELECT id FROM projects)
    $sql$;
  END IF;
END $$;

-- ⑤ 项目关联日程处置（决议 T2 已批准）：转为普通日程，保留用户数据。
--    同样以 task_type 列存在为旧模型标记（新模型下 events.task_id 恒指向任务，
--    若不守卫，重跑会把 id 恰好等于某项目 id 的任务日程误转）。
--    events.title 为 VARCHAR(100)，项目名最长 200，此处截断避免迁移失败。
DO $$
BEGIN
  IF EXISTS (
    SELECT 1 FROM information_schema.columns
    WHERE table_name = 'tasks' AND column_name = 'task_type'
  ) THEN
    EXECUTE $sql$
      UPDATE events e
      SET event_type = 'normal',
          task_id    = NULL,
          title      = left(COALESCE((SELECT p.name FROM projects p WHERE p.id = e.task_id), '项目安排'), 100)
      WHERE e.event_type = 'task'
        AND e.task_id IN (SELECT id FROM projects)
    $sql$;
  END IF;
END $$;

-- ⑥ 删除已搬迁的项目行（此时成员已不再引用，安全；守卫同上，保证重跑为 no-op）
DO $$
BEGIN
  IF EXISTS (
    SELECT 1 FROM information_schema.columns
    WHERE table_name = 'tasks' AND column_name = 'task_type'
  ) THEN
    EXECUTE $sql$ DELETE FROM tasks WHERE id IN (SELECT id FROM projects) $sql$;
  END IF;
END $$;

-- ⑦ 删除旧列 / 约束 / 索引
ALTER TABLE tasks DROP CONSTRAINT IF EXISTS ck_tasks_task_type;
DROP INDEX IF EXISTS idx_tasks_user_task_type;
DROP INDEX IF EXISTS idx_tasks_user_project;      -- 原 project 部分索引（依赖 task_type）
DROP INDEX IF EXISTS idx_tasks_parent;
ALTER TABLE tasks DROP COLUMN IF EXISTS task_type;
ALTER TABLE tasks DROP COLUMN IF EXISTS parent_id;

-- ⑧ 外键与新索引
DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM pg_constraint
    WHERE conname = 'fk_tasks_project' AND conrelid = 'tasks'::regclass
  ) THEN
    ALTER TABLE tasks ADD CONSTRAINT fk_tasks_project
      FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE CASCADE;
  END IF;
END $$;

CREATE INDEX IF NOT EXISTS idx_tasks_user_project_id
  ON tasks (user_id, project_id);
CREATE INDEX IF NOT EXISTS idx_tasks_user_project_status
  ON tasks (user_id, project_id, status);

-- ⑨ 推进序列到当前最大 id
SELECT setval(
  'projects_id_seq',
  GREATEST(COALESCE((SELECT MAX(id) FROM projects), 1), 1)
);

-- ⑩ 收尾断言（不满足即抛异常 → 整体回滚）
DO $$
DECLARE
  orphan INT;
BEGIN
  SELECT count(*) INTO orphan
  FROM tasks t
  WHERE t.project_id IS NOT NULL
    AND NOT EXISTS (SELECT 1 FROM projects p WHERE p.id = t.project_id);

  IF orphan > 0 THEN
    RAISE EXCEPTION '迁移 014 校验失败：存在 % 条任务的 project_id 指向不存在的项目', orphan;
  END IF;

  IF EXISTS (
    SELECT 1 FROM information_schema.columns
    WHERE table_name = 'tasks' AND column_name IN ('task_type', 'parent_id')
  ) THEN
    RAISE EXCEPTION '迁移 014 校验失败：tasks 仍存在 task_type 或 parent_id 列';
  END IF;
END $$;

-- ⑪ 存量项目状态归一（新口径：状态完全由成员完成度派生）
--    旧模型允许手工完成项目，存量可能存在「空项目已完成」「成员未全完成但项目已完成」等
--    与派生规则不一致的行；按新口径一次性归一，避免它们在首次写入前显示出错误的完成态。
--    幂等：仅当派生结果与当前状态不同才写（状态一致的行不动 updated_at）。
UPDATE projects p
   SET status = d.status,
       completed_at = CASE
         WHEN d.status = 'completed' THEN COALESCE(p.completed_at, now())
         ELSE NULL
       END,
       updated_at = now()
  FROM (
    SELECT pr.id,
           CASE
             WHEN count(t.id) > 0 AND count(t.id) FILTER (WHERE t.status = 'todo') = 0
             THEN 'completed'
             ELSE 'todo'
           END AS status
      FROM projects pr
      LEFT JOIN tasks t ON t.project_id = pr.id
     GROUP BY pr.id
  ) d
 WHERE d.id = p.id
   AND p.status IS DISTINCT FROM d.status;
```

> **幂等性说明**：③⑦ 通过列存在性判定保护；①⑧ 通过 `IF NOT EXISTS`/系统目录判定保护；④⑤⑥ 的谓词本身幂等（重复执行不再命中）。迁移完成后重跑（如手工执行）为安全 no-op。

### 3.4 迁移前后守恒校验（演练必须输出）

| 校验项 | 迁移前口径 | 迁移后口径 | 期望 |
| --- | --- | --- | --- |
| 项目数 | `SELECT count(*) FROM tasks WHERE task_type='project'` | `SELECT count(*) FROM projects` | 相等 |
| 项目成员数 | `SELECT count(*) FROM tasks WHERE parent_id IS NOT NULL` | `SELECT count(*) FROM tasks WHERE project_id IS NOT NULL` | 相等 |
| 任务总数 | `SELECT count(*) FROM tasks` | `SELECT count(*) FROM tasks` | 减少量 = 项目数 |
| 任务日程数 | `SELECT count(*) FROM events WHERE event_type='task'` | 同口径 | 减少量 = 项目关联日程数（转 normal） |
| 普通日程数 | `SELECT count(*) FROM events WHERE event_type='normal'` | 同口径 | 增加量 = 项目关联日程数 |
| 丢弃数据 | 项目行的 `priority`、`due_at` | — | 演练时逐行导出清单存档 |

### 4.3 项目状态派生（唯一写入口）

单条原子 SQL（在同一事务中执行，避免读改写竞态）：

```sql
UPDATE projects p
   SET status = CASE WHEN m.total > 0 AND m.todo = 0 THEN 'completed' ELSE 'todo' END,
       completed_at = CASE
         WHEN m.total > 0 AND m.todo = 0 THEN COALESCE(p.completed_at, now())
         ELSE NULL
       END,
       updated_at = now()
  FROM (
    SELECT count(*) AS total,
           count(*) FILTER (WHERE status = 'todo') AS todo
      FROM tasks
     WHERE user_id = $1 AND project_id = $2
  ) m
 WHERE p.id = $2
   AND p.user_id = $1
   AND (p.status, p.completed_at) IS DISTINCT FROM (
         CASE WHEN m.total > 0 AND m.todo = 0 THEN 'completed' ELSE 'todo' END,
         CASE WHEN m.total > 0 AND m.todo = 0 THEN COALESCE(p.completed_at, now()) ELSE NULL END
       )
RETURNING p.*;
```

- **幂等**：状态未变化时 `WHERE ... IS DISTINCT FROM` 不命中，不写 `updated_at`（避免无意义变更）；
- **空项目**：`total = 0` → 恒 `todo`；
- **调用点（全部在同一事务内）**：成员任务创建（带 `project_id`）、成员任务完成/取消完成、成员任务移入/移出（旧项目与新项目各一次）、成员任务删除、项目删除前无需调用（整体删除）。

### 4.4 并发正确性

| 场景 | 处理 |
| --- | --- |
| 并发完成同一项目下两个成员 | 两次 `recalcStatus` 均为幂等 UPDATE，行锁串行化，最终态一致（全完成 → completed） |
| 完成成员的同时移入新成员 | 两个事务各自 recalc；后提交者以"当前成员集合"为准，结果一致（存在未完成成员 → todo） |
| 项目行被删除与成员写入并发 | 成员写入前 `assertProjectOwned` 校验 + 外键约束，命中已删除项目 → 404/参数错误 |
| 手工完成任务的队列一致性（I5 补充） | 任务完成写入与"取消 pending 指派"在**同一事务**（见 §8.2） |

### 4.5 级联删除语义（I6）

```
DELETE /projects/:id
  BEGIN
    ① 取成员任务 id 集：SELECT id FROM tasks WHERE user_id=$1 AND project_id=$2
    ② 删这些任务的任务日程：DELETE FROM events WHERE user_id=$1 AND task_id = ANY($ids)
    ③ 删成员任务：DELETE FROM tasks WHERE user_id=$1 AND project_id=$2
    ④ 删项目：DELETE FROM projects WHERE id=$2 AND user_id=$1
  COMMIT
返回值：{ deleted_task_count, deleted_event_count }
```

- 与 v0.7.0 的 `taskService.remove` 语义一致（先删 events 再删 tasks）；
- 二次确认文案由 `previewRemove` 的数量驱动（UXUI 5.7）；
- 任务删除（非项目）仍走 `taskService.remove`：删自身 + 其任务日程，并对其所属项目调用 `recalcStatus`。

```sql

UPDATE tasks SET status='completed', completed_at=now(), updated_at=now()
WHERE id=$1 AND user_id=$2;

   SET agent_id = NULL, agent_state = 'none', agent_queued_at = NULL, updated_at = now()
```

**后果**：左滑若带较大向下分量（`dy` 累计 ≥ 72px），下拉侧照常累计并越过 36px 阈值 → 触发刷新。

### 12.2 修复方案：手势方向锁（单例）

新增 `src/web/src/utils/gesture.ts`：

```ts
export type GestureAxis = 'h' | 'v';
export const GESTURE_LOCK_PX = 8;
export const GESTURE_RATIO = 1.5;

let axis: GestureAxis | null = null;

/**
 * 观察期后判定主导方向：
 * - 观察期内（水平与垂直位移均 < 8px）返回 null —— 守卫放在函数内，任何调用点都不会漏判；
 * - 横向主导 → 'h'；纵向主导 → 'v'；斜向未达任一主导 → null（仅滚动列表）。
 */
export function resolveAxis(dx: number, dy: number): GestureAxis | null {
  const absX = Math.abs(dx);
  const absY = Math.abs(dy);
  if (absX < GESTURE_LOCK_PX && absY < GESTURE_LOCK_PX) return null;
  if (absX >= GESTURE_LOCK_PX && absX > absY) return 'h';
  if (absY > absX * GESTURE_RATIO && absX < GESTURE_LOCK_PX) return 'v';
  return null;
}

/** 由“先判定者”锁定方向；同一手势内不翻转 */
export function lockAxis(next: GestureAxis): boolean {
  if (axis === null) { axis = next; return true; }
  return axis === next;
}

export function currentAxis(): GestureAxis | null { return axis; }
export function isHorizontalLocked(): boolean { return axis === 'h'; }
export function isVerticalLocked(): boolean { return axis === 'v'; }

/** touchend / touchcancel 时复位（由滚动容器统一调用） */
export function resetAxis(): void { axis = null; }
```

> **观察期守卫的位置（测试期修正）**：8px 观察期判定必须内聚在 `resolveAxis` 内返回 `null`。
> 若交由各调用点自行守卫，行组件与滚动容器任一处漏写，手指起手的微小抖动就会把整次手势定格为
> 纵向（左滑失效）或横向（下拉刷新被抢占）。实现即按此内聚，调用点只做"`null` 则不服务任一方向"。

**接入方式**

| 侧 | 改动 |
| --- | --- |
| 列表容器（刷新，`TaskHomeView` / `ProjectPageView`） | `touchmove` 越过 8px 时用 `resolveAxis(dx, dy)` 判定：返回 `'v'` → 锁定纵向并继续累计、显示提示；返回 `'h'` → 本次手势不服务下拉；返回 `null`（斜向但未达任一主导，如 dx=12/dy=90）→ 同样不服务下拉（清零 `pullDistance`、不显示提示、松手不刷新）；每次 `touchmove` 先判 `isHorizontalLocked()` 直接返回；`touchend`/`touchcancel` 调 `resetAxis()` |
| 行组件（左滑，`TaskListItem` / `ProjectCard`） | 越过 8px 判定进入拖动时调 `lockAxis('h')` 成功才拖动；若返回 false（已是纵向）则不进入拖动；`touchend`/`touchcancel` 不单独复位（由容器统一复位，避免顺序问题）；组件内部保留自身 `dragging` 状态与吸附逻辑不变 |
| 参数 | 阻尼 0.5、上限 72、阈值 36、`ACTION_WIDTH` 148（项目卡 74）、8px 观察期、方向系数 1.5 全部**沿用** |

**边界处理**

- 手势在手势区外开始（点在非行区域）→ 行组件不参与，容器按既有逻辑判定方向（仍要求纵向主导）；
- 手势在中途反向（先竖后横）→ 方向锁不翻转，当次只服务首个方向（避免抖动）；
- `touchcancel`（系统打断）→ 容器复位方向锁与 `pullDistance`，行组件收起（既有 `close()` 逻辑）；
- 多指触摸 → 仅跟踪第一个触点（沿用既有实现口径）。

### 13.2 修复方案 A：折叠即时化

1. **拆分形态切换与数据加载**：
   - `collapseCalendar()` 内**同步**执行：`collapsed = true`、`animating = true`、`measureLayout()`（在切换那一帧完成测量）→ 立即开始 250ms 动画；
   - 并行发起 `loadCollapsed()`；新增 `collapsedLoading` 状态，数据未返回时列表区渲染 `SkeletonList :rows="3"`（复用既有骨架与 300ms 延迟策略），**不出现空白停顿**；
   - `renderWeek = true` 仍在动画结束后置位（避免回弹），与数据加载互不阻塞；
2. **展开同理**：`expandCalendar()` 同步切形态并测量，数据并行加载；展开态先渲染缓存/骨架，再以整月数据替换；
3. **时序量化**（测试可断言）：形态切换在 touchmove 命中阈值的那一帧发起（≤1 帧）；`loadCollapsed` 的 promise 不得出现在动画启动之前。

### 13.3 修复方案 B：展开持续判定期

扩展手势状态（`ShapeGesture`）新增 `expandAnchorY: number | null`，`onShapeTouchMove` 的分支改为：

| 状态 | 条件 | 行为 |
| --- | --- | --- |
| 折叠态 · 列表在顶部（`scrollTop <= LIST_TOP_TOLERANCE`） | 起手即在顶部 | `dy = clientY - g.startY`；`dy >= 32` 且方向为纵向 → `expandCalendar()`（与现状一致） |
| 折叠态 · 列表已离开顶部 | `scrollTop > LIST_TOP_TOLERANCE` | **不放弃本次手势**：让列表按原生滚动；把 `g.expandAnchorY = 当前 clientY` 持续更新为"最近一次仍在非顶部时的 Y"；一旦某帧检测到 `scrollTop <= LIST_TOP_TOLERANCE`，则把锚点**冻结**为当帧 `clientY` |
| 折叠态 · 已到顶（锚点已冻结） | `g.expandAnchorY !== null` | `dy = clientY - g.expandAnchorY`；`dy >= 32` 且纵向 → `expandCalendar()`（**同一次手势内完成，无需第二次下滑**） |
| 展开态 | 任意 | 沿用 v0.7.0：`!g.startAtTop` 直接 return（**折叠仍要求起手在列表顶部**，不误折叠） |
| 动画中 | `animating === true` | 忽略新手势；`touchmove` 直接 return |
| 结束/取消 | `touchend` / `touchcancel` | 清空 `shapeGesture`（含锚点），并 `resetAxis()`（与 GES-01 的方向锁共用生命周期） |

**方向与阈值**：方向锁 1.5、观察期 8px、阈值 32px、动画 250ms、`fired` 单次触发、`animating` 忽略新手势——**全部沿用**。

### 13.4 边界与回归分析

| 边界 | 处理 |
| --- | --- |
| 展开触发后剩余位移 | 交还原生滚动；因 `fired=true`，本次手势不再二次触发 |
| 滚到底部继续下划 | `overscroll-behavior: contain` 抑制越界滚动；锚点逻辑不受影响 |
| 折叠态列表不可滚动（`scrollHeight <= clientHeight`） | `scrollTop` 恒 0 → 走"起手在顶部"路径，行为与现状一致 |
| 左右翻月/翻周 | 绑定在日历区（`.month__cal`），与列表手势互不共用；方向锁新增不影响 |
| 浮动「今日」与形态恢复 | 不改动 `goToday()` 与形态/选中日的 5 分钟恢复机制 |
| 动画期间快速反向手势 | 被 `animating` 忽略（现状口径），不产生形态抖动 |

## 15. 关键时序

### 15.1 迁移 014（发布时）

```
服务启动 / npm run migrate
  → migrate.ts 读 schema_migrations（014 未执行）
  → BEGIN
      建 projects + 约束 + 索引 + 序列
      tasks 加 project_id（无 FK）
      搬迁项目行（ON CONFLICT DO NOTHING）
      成员 parent_id → project_id
      项目关联日程 → 普通日程
      DELETE 已搬迁项目行
      删 task_type/parent_id（约束、索引、列）
      建 fk_tasks_project + 新索引
      setval(projects_id_seq)
      断言校验（孤儿成员 / 残留列）→ 失败 RAISE EXCEPTION
      INSERT schema_migrations('014_project_extract.sql')
  → COMMIT（失败则 ROLLBACK 并退出进程）
```

### 15.2 任务页按项目筛选

```
TaskHomeView 挂载
  → 并发：GET /tasks?status=&sort=&page=1&page_size=50
          GET /projects?page_size=100（筛选器候选）
  → 用户选「装修项目」→ projectFilter=42 → 重新 GET /tasks?project_id=42&…
  → 服务端：buildConditions 加 t.project_id=$n → TASK_SELECT JOIN projects 带出 project_name
  → 端上渲染：列表项 chip 用 project.name；无项目项不渲染 chip
```

### 15.3 新建任务回跳

```
项目详情 → 「更多字段」→ /tasks/new?project_id=42
  → 表单：GET /projects/42 预填「所属项目」；GET /projects?page_size=100 供改选
  → 用户保存 → POST /tasks { title, note, priority, due_at, project_id: 42 }
      → 服务端：assertProjectOwned → assertMemberCapacity → INSERT（project_id=42）
                → recalcStatus(42)（成员含未完成 → 项目保持 todo）
  → 端上：router.replace('/projects/42?highlight=103')
  → 项目详情读取 highlight → MemberList 行高亮 2s → 清除 query；进度 2/5 → 3/5
```

### 15.4 项目状态派生

```
成员任务完成（POST /tasks/103/complete）
  → 事务：UPDATE tasks SET status='completed' + 取消 pending 指派（若有）
          → ProjectService.recalcStatus(42)
              → 单条原子 UPDATE：读成员计数 → 全完成则 status='completed', completed_at=now()
  → COMMIT → 响应任务 DTO（带 project 摘要）
  → 端上：项目详情徽标即时变「已完成」（重新拉取项目详情或复用返回的派生结果）
```

### 15.5 列表手势判定（任务列表，顶部）

```
touchstart（.page-body，scrollTop=0）
  → 记录 startX/startY；resetAxis()
touchmove（位移 < 8px）
  → 两个处理器均不动作（观察期）
touchmove（位移 ≥ 8px，dx=12, dy=90）
  → resolveAxis(12, 90) = null（水平位移 ≥ 8 但小于垂直位移；垂直位移 > 1.5×水平 但水平位移 ≥ 8）
  → 行组件：不进入拖动；容器：本手势不服务下拉（清零 pullDistance、不显示提示）
touchmove（dy 继续增大）
  → 容器：非纵向主导 → 不累计、不显示提示
touchend
  → 无刷新；resetAxis()
（对照：dx=3, dy=90 → resolveAxis = 'v' → lockAxis('v') → 正常累计与刷新）
```

### 15.6 日历展开（折叠态、列表已滚到中部）

```
touchstart（.month__body，scrollTop=120）
  → 记录 startY；因 scrollTop > 2，startAtTop=false（折叠分支仍受此约束）
touchmove（下划 20px）
  → scrollTop 减小（原生滚动），未到顶 → 更新 expandAnchorY = clientY
touchmove（列表到顶，clientY=430）
  → scrollTop <= 2 → 冻结 expandAnchorY = 430
touchmove（继续下划至 clientY=470）
  → dy = 470 - 430 = 40 ≥ 32 且纵向 → expandCalendar()
      → 同步：collapsed=false、measureLayout()、启动 250ms 动画；并行 loadExpanded()
  → fired = true，剩余位移交还滚动
touchend → 清理 shapeGesture 与方向锁
```
