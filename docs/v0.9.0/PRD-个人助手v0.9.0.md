## 1. 背景与目标

### 1.1 背景

v0.4.0 ~ v0.7.0 之间，助手沿着"能力做加法"的方向连续扩张：任务 → 子任务 → 项目（任务容器）→ 智能体代理（MCP 派活）。这一路扩张带来三组核心问题：

1. **三重组织维度互相重叠**：任务（待办）、项目（任务容器）、智能体（任务执行方）三者层层叠加，用户要理解"任务属于项目、项目成员也是任务、任务可以指派给代理"这一整条心智链；对一个"个人时间与事务助手"而言，这套结构远超实际需要。多数用户真正会用的仍然是**日程（时间轴上的一件事）+ 对话（一句话安排）**。
2. **维护面与心智负担持续上升**：任务类型分流、项目成员计数、代理执行状态机、MCP 接入面、清单残留字段、错误码 4010 / 4014 / 4017 / 4018 / 4019 ~ 4022 等，都是长期维护成本；v0.7.0 已在做"清单下线"这类减法，说明产品方向需要一次更彻底的收敛。
3. **日程主页的手势仍不流畅**：v0.6.0 把手势化折叠引入日程主页、v0.7.0 修掉了"上滑完全不折叠"的缺陷，但**交互仍是"阈值触发的一次性形态切换"**——用户反馈上滑要"先滚一点点才折叠"（卡顿），折叠态下拉展开又必须"先把长列表滚回顶部"（不连贯）。手势可用但**过程不跟手、起手区域受限**。

v0.9.0 因此做两件事：**一是做彻底的减法**，把任务、项目、智能体三类能力整体下线，产品回到"日程 + 助手（+ 长期记忆 + 账号）"的聚焦形态；**二是把关涉日常使用频率最高的日程主页手势打磨到位**，让折叠/展开跟手、连续、双向无缝。

需求共 2 项，编号与分组如下：

| 分组 | 编号 | 需求 |
| --- | --- | --- |
| 能力下线 | DEL-01 | 任务功能下线：删除任务相关的页面、路由、接口、组件、对话工具、入口与字段 |
| 能力下线 | DEL-02 | 项目功能下线：项目（任务容器）相关的页面、路由、接口、组件、对话工具与级联规则全部删除 |
| 能力下线 | DEL-03 | 智能体代理功能下线：代理管理、MCP 接入面、代理执行链路、相关页面/接口/工具全部删除 |
| 能力下线 | DEL-04 | 日程领域连带改造：任务日程（event_type=task）退场，日程编辑分流收敛，"关联任务"相关交互整体移除 |
| 能力下线 | DEL-05 | 助手（LLM）能力收敛：移除任务/项目/代理类工具与提示词，只保留日程与记忆能力 |
| 能力下线 | DEL-06 | 数据迁移、旧链与兼容：存量任务日程转普通日程，下线路由重定向，DTO 字段清理 |
| 交互优化 | CAL-04 | 日程主页折叠/展开交互优化：改为**跟手联动**，消除"先滚动再折叠"与"必须先滚到顶才能展开"两处卡顿，扩展起手区域到日历区 |

### 1.2 产品目标（v0.9.0）

- **核心目标**：
  1. **产品定位回归聚焦**：助手 = **日程（时间轴）+ 助手（自然语言）**；不再有"任务/项目/智能体"任何用户可见痕迹（页面、入口、文案、对话卡片、字段）；
  2. **能力面与维护面同步收缩**：任务/项目/代理两条 REST 线、MCP 接入面、10 个任务类 + 2 个代理类 LLM 工具、相关错误码与状态机全部退出运行路径；
  3. **存量内容不丢**：升级后用户原先在日历上的**任务日程**自动转为普通日程（标题快照保留），日程内容、循环、农历、冲突提示零变化；
  4. **日程主页手势真正跟手**：展开态上滑**手指一动即开始收**（无 32px 死区、无"先滚动一点点"），折叠态下拉**无需先把列表滚到顶**（可直接在日历周行下拉展开），全程双向连续、无缝衔接列表滚动。
- **成功假设**：
  1. **减法感知**：升级后"任务/项目/智能体"相关入口与文案对用户零可见；"找不到任务页/项目页"类困惑为**升级预期行为**（由版本说明承接），不产生功能性缺陷反馈；
  2. **内容零丢失**：迁移后"任务日程 → 普通日程"转换成功率 100%，用户在日历上看到的日程条数与标题与升级前一致（原任务日程逐条保留，仅失去"关联任务"链接）；
  3. **性能不劣化**：日程主页首屏、翻月/翻周、冲突检测、对话 SSE 的 P95 不劣于 v0.7.0；下线代码后包体与首屏请求数下降；
  4. **手势达标**：上滑折叠成功率 ≥ 99%，折叠态下拉展开成功率 ≥ 99%；"日历折叠卡顿/不跟手/要滚到顶"类投诉归零；
  5. **跟手性**：手势期间日历高度变化与手指纵向位移基本 1:1（误差 ≤ 2px），无明显掉帧（≥ 55fps）。

### 1.3 非目标（v0.9.0 不做）

- **不做任务能力的替代品**：不引入"轻待办/提醒/打卡"等新形态；用户的"要事"统一通过**普通日程 / 循环日程**表达（这正是本版收敛的语义：日程即唯一的时间事务载体）；
- **不做任务日程的"降级降噪"**：不保留任何 `event_type=task` 的用户可见概念；任务日程一律转普通日程，不做"只读标签"之类的过渡态；
- **不做数据物理删除（建议）**：任务、项目、代理的历史数据**保留在库、下线能力**（便于回滚与审计），本版不提供"删除我的任务数据"入口；物理删除与否由评审决议（见 8.2）；
- **不做日程主页以外的布局/视觉改造**：头部三元素、浮动「今日」、月格视觉、列表分组与视觉均不变；本版只改折叠/展开的**手势过程与起手区域**；
- **不新增跟手之外的控件**：不恢复折叠开关行、不加拖动把手、不加手势提示气泡；
- **不做跨月/跨年拖拽展开**：折叠/展开只在"整月 ↔ 选中周"两态间进行，不支持拖到任意高度停留（松手必吸附到两态之一）；
- **不做任务/项目/代理能力的历史数据可视化或导出**；
- **不做深色模式、字号调节、多语言、PC 端专门适配**（延续全版本边界）。

## 2. 目标用户与使用场景

### 2.1 目标用户

延续个人用户，本版尤其面向：

- **只想用"日历 + 一句话安排"的轻量用户**：把事情直接记成日程或循环日程，用对话增删改查，不需要"待办 → 项目 → 派活"的重型工作流；
- **被三重组织维度困扰的用户**：曾因"任务要不要放进项目 / 要不要指派代理"而犹豫，希望页面回归简单；
- **高频使用日程主页的用户**：每天在日程主页看当天安排，对日历收放的手感敏感。

### 2.2 核心使用场景

| 场景 | 描述 |
| --- | --- |
| 升级后的"减法"体验 | 用户升级到 v0.9.0：抽屉只剩「日程」「助手」；打开日程主页，日历上原先的"任务日程"仍在（已变成普通日程，标题一致），只是不再有"关联任务"入口；对话里提到"任务/项目/清单/智能体"时，助手如实说明这些能力已下线，并建议改用日程表达。 |
| 一句话安排一天 | 用户在对话里说"明天上午 10 点开周会""每周一三五晚上 8 点健身，重复 8 次"，助手直接创建普通日程 / 循环日程（不再涉及任务）。 |
| 日程主页上滑收日历（跟手） | 用户看完整月，想给当天列表更多空间：手指落在日历或列表顶部向上滑，日历**随手一起收**，手指一动就能看到它在变小，没有"先滚动一点点"的停顿；抬手后吸附为选中周。 |
| 日程很多时下拉展日历 | 用户在折叠态浏览当天安排，列表很长已滑到中部，想重新看整月：**直接在日历周行上下拉**，日历随手展开，**无需先把列表滚回顶部**。 |
| 列表中部滑动不误触 | 用户想把列表往回翻看更早的日程，在列表中向下拖：列表正常回滚，日历形态不动；上滑同理只滚动列表。 |

## 3. 产品整体说明

### 3.1 产品形态（延续）

- 仍为**移动端 Web（H5）**瘦客户端：日程规则校验、循环展开、农历/工作日历换算、冲突检测、LLM 编排均在服务端完成，端上仅展示与交互；
- 延续全云端架构：日程、循环系列与例外、会话、长期记忆均存云端数据库，端上不缓存；
- 延续单会话、服务端统一 LLM 代理、Function Calling + SSE 流式、模型可在服务端替换；
- **对外形态收缩**：v0.7.0 面向外部智能体新增的 **MCP 接入面整体下线**，服务端只保留面向 App 的 REST（`/api/v1/*`）与聊天 SSE；
- 架构原则"领域唯一入口"继续成立（本版只是把任务/项目/代理三个域移除）。

### 3.4 领域模型收敛（关键，避免误解）

v0.9.0 之后，产品里**只剩一个时间事务载体：日程（events）**。

| 概念 | v0.9.0 处置 |
| --- | --- |
| **普通日程**（`event_type=normal`） | 唯一保留的日程类型：标题、开始/结束、全天、地点、备注，可循环（每天/每周/每月/每年/法定工作日/农历）、可农历创建 |
| **任务日程**（`event_type=task`） | **能力删除**；存量逐条转普通日程（标题取任务标题快照），不再有"关联任务"语义 |
| **任务**（tasks） | **能力删除**：无页面、无接口、无工具、无字段；表与数据保留在库（建议） |
| **项目**（`task_type=project`） | **能力删除**：项目即任务的一种，随任务一并消失；成员/进度/级联规则全部退出 |
| **智能体代理**（agents） | **能力删除**：无管理页、无 MCP 接入面、无执行状态机与记录；表与数据保留在库（建议） |
| **清单**（task_lists） | v0.7.0 已下线，本版维持（不恢复、不删除表） |
| **日程的完成语义** | 原先"日程勾选完成 = 完成关联任务"随任务删除而消失；**日程本身没有完成态**（沿用），列表不再出现删除线 |
| **日程类型标签** | 只剩普通日程后不再有区分意义，「普通日程 / 任务日程」标签整体移除（见 4.5，决议 8.2 #6） |

- **对话口径同步**：助手能处理的写操作只剩日程（新建/改期/改地点/删除/批量/循环作用域）与记忆；用户说"任务/待办/项目/清单/智能体"时，助手如实说明能力已下线，并**建议改用日程**（如"上午把周报写完"→ 建一个普通日程或循环日程）。

## 4. 功能需求一：任务 / 项目 / 智能体能力下线（DEL-01 ~ DEL-06）

### 4.1 下线原则与对象清单

**下线四原则**（本版所有删除动作都遵守）：

1. **用户可见痕迹归零**：页面、路由、入口、按钮、字段、文案、对话卡片、搜索命中，均不得出现"任务/待办/项目/成员/清单/智能体/代理/指派"；

4. **不产生死链与无响应入口**：所有被删路由统一重定向 `/calendar`；旧客户端调用已下线接口返回统一"接口不存在"（1004）。

## 5. 功能需求二：日程主页折叠/展开交互优化（CAL-04）

### 5.1 现状与问题

v0.6.0 引入、v0.7.0 修复的折叠/展开，本质是**"两态 + 阈值触发的一次性切换"**：

- 手势监听绑定在**日程列表容器**（`.month__body`）上，且**只在起手时列表位于顶部（`scrollTop ≤ 2`）**才接管；
- 纵向位移达到 **32px** 阈值后，触发一次 250ms 的高度过渡，在两态之间切换；
- 监听为 `passive`，手势进行中浏览器**原生滚动照常发生**。

用户反馈两类问题（引自 require.txt）：

- **问题 A（上滑不即时、卡顿）**：清单日程较多时，展开态在列表顶部上滑，**日历不会马上折叠**，而是"日程列表先向上滚动一点点，才折叠"——手指前 32px 位移内日历纹丝不动、列表内容却已上移，越过阈值才突然折叠，观感割裂、发卡。
- **问题 B（下拉展开不连贯、必须先滚到顶）**：折叠态下拉展开的**起手区域只有列表且必须在列表顶部**；当日程很多、列表已滚到中部时，下拉只会把列表往回滚，**必须先一路滚回顶部**才能触发展开——体验不连贯、费力。
- **问题 C（隐性）**：用户直觉"**拖日历**"（在日历/周行上下拉）本应能收放日历，但日历区不参与形态手势，拖动无任何响应。

### 5.2 根因分析（基于现有实现）

`src/web/src/views/calendar/MonthView.vue`：

1. **形态切换是离散的、阈值触发的一次性动画**：没有"手指—高度"的连续映射，手势前 32px 是"死区"，此期间只发生原生滚动 → 问题 A 的直接来源；
2. **起手判定绑定列表滚动位置**：`onShapeTouchStart` 仅在 `list.scrollTop ≤ LIST_TOP_TOLERANCE` 时接管，列表在中部时形态手势完全不可达 → 问题 B 的直接来源；
3. **手势表面只有列表容器**：日历区（`.month__cal`）不监听形态手势 → 问题 C 的来源；
4. **`passive` 监听无法 `preventDefault`**：形态手势与原生滚动并行，无法做到"跟手期间不滚动" → 加剧问题 A 的割裂感。

**结论**：要同时消除 A/B/C，必须把交互从"阈值触发的一次性切换"升级为 **跟手联动（drag-linked）**，并把**起手区域从"列表顶部"扩展到"日历区 + 列表顶部"**。

### 5.3 目标交互模型（跟手联动）

**核心原则**：

> 折叠/展开不是"滑够距离后播一段动画"，而是**日历形态由手指纵向位移连续驱动**；一次手势在"日历形态变化"与"列表滚动"之间**无缝衔接**；日历区（含折叠态周行）就是天然的可拖拽区。

- **形态进度**：引入连续量 `p ∈ [0, 1]`（1 = 完全展开整月，0 = 完全折叠选中周），日历高度 `H(p) = weekHeight + p × (expandedHeight − weekHeight)`；
- **跟手**：手势锁定为纵向后，`p` 随手指位移实时变化（`dy < 0` 收、`dy > 0` 展），手指与日历边缘基本 1:1 联动（可加轻阻尼，见 5.6）；
- **吸附**：抬手时按"位移是否过半 / 释放速度"吸附到 `p=0` 或 `p=1` 的最近目标态，剩余距离用 ≤250ms 动画补齐；
- **无缝衔接**：吸附到位后，本次手势若仍在继续，剩余位移**交还列表滚动**（展开态继续上滑 → 列表上滚；折叠态继续下拉 → 列表回滚/回弹）；到位前列表**不滚动**、不产生位移跳变；
- **起手区域扩展**：折叠态下拉展开可在**日历区（周行）**直接起手，因此**无需先把列表滚到顶**（直接解决问题 B/C）。

### 5.4 手势规则

| 项 | 规则 |
| --- | --- |
| 起手观察期 | 8px（沿用）：位移小于 8px 不锁定方向，不进入形态手势 |
| 方向锁 | 1.5 倍（沿用）：纵向位移绝对值 > 1.5 × 横向位移绝对值判为纵向，进入形态手势；否则交还（横滑 → 翻月/翻周，点按 → 选日期） |
| **展开态上滑 → 折叠** | 起手区域 = **日历区任意位置** ∪ **列表区顶部**（`scrollTop ≤ 2`）。锁定纵向且 `dy < 0` 时，`p` 从当前值随 `dy` 递减；列表在中部起手时**不接管**（只滚动列表） |
| **折叠态下拉 → 展开** | 起手区域 = **日历区任意位置（关键新增）** ∪ **列表区顶部**。锁定纵向且 `dy > 0` 时，`p` 随 `dy` 递增；列表中部起手时不接管（只滚动列表） |
| 吸附判定 | 抬手时：位移行程 ≥ 50% **或** 释放速度 ≥ 阈值（建议 0.3 px/ms，SDD 定稿）→ 吸附到目标态；否则回弹到起始态 |
| 一次一手势 | 一次手势只切换一次形态；吸附到位后剩余位移交还列表滚动，不再二次触发 |
| 动画互斥 | 吸附动画期间（建议 ≥ 200ms、≤ 250ms）忽略新手势（沿用 v0.6.0 互斥策略） |
| 惯性 | 松手后的列表惯性滚动（momentum）**不**触发形态手势 |
| 多指/中断 | 手势中插入第二指、或路由/页面切换 → 取消本次形态手势并复位到最近合法态 |

### 5.5 与列表滚动的关系（硬要求）

- **跟手期间列表不滚动**：形态手势一旦接管，需阻止原生滚动（通过 `touch-action` 控制或非 passive 监听 + `preventDefault`，实现方式由 SDD 定稿），避免"日历在收、列表同时在滚"的割裂；
- **到位后无缝滚动**：形态吸附到位后，剩余手势位移交还列表；展开态继续上滑 → 列表正常上滚；折叠态继续下拉 → 列表正常回滚/回弹；两者之间不得出现停顿、回弹或内容跳变；
- **列表中部不误触**：列表已滚动到中部时，上滑/下拉都只滚动列表，形态不变（保留 v0.7.0 的正确行为）；
- **边界越界归形态**：列表已在顶部（展开态）时，上滑的越界位移用于折叠；列表已在顶部（折叠态）时，下拉的越界位移用于展开；此时不得同时出现列表橡皮筋与形态变化；
- **空/短列表**：列表内容不足一屏时，两方向均可在任意位置（日历或列表）触发，且不影响列表（无滚动可言）。

### 5.6 动效与视觉

- **跟手期间无过渡动画**：高度直接跟随手指（可加轻阻尼，阻尼建议在接近两端时启用，系数约 0.4，SDD/UXUI 定稿），确保"手指一动日历就动"；
- **吸附动画**：剩余距离用 `--dur-page`（≈250ms）ease-out 补齐（沿用既有时间轴与缓动）；
- **渲染切换时机**：跟手期间**保持整月网格渲染并整体收缩**（避免中途从整月切换为单周造成跳变）；吸附到折叠态后再切换为"只渲染选中周"（沿用 v0.6.0 的 `renderWeek` 思路）；展开方向先恢复整月渲染再展开；
- **视觉保持不变**：不新增控件、不新增手势提示、不改变折叠态一周的视觉呈现与月份标题、浮动「今日」按钮、头部三元素；
- **无障碍与降级**：保持键盘/读屏可用（如存在），无动画偏好（`prefers-reduced-motion`）下吸附动画可缩短或取消，但形态与跟手功能不缺失。

### 5.7 边界与异常

- **横滑与点按不受影响**：日历区横滑仍翻月/翻周、点按仍选日期；跟手只在纵向锁定时接管；
- **折叠态跨月周**：邻月计数补齐、月格标记点逻辑不变；
- **形态与滚动位置恢复**：从日程详情返回（5 分钟内）恢复选中日 + 列表滚动位置 + 日历形态（沿用 `lastView`）；页面重建回到"默认展开"（沿用，不按条数自动定型）；
- **浮动「今日」**：显隐与行为不变（选中日 ≠ 今天时显示，点击回今天且不改变形态）；
- **中断复位**：手势中途被系统手势/来电/切前后台打断时，复位到最近一次已吸附的合法态，不残留半开状态；
- **与左右翻期并发**：跟手进行中不翻期；翻期进行中不进入跟手。

### 5.8 验收方式（硬要求）

1. **无死区（问题 A）**：展开态、列表顶部，手指向上移动约 16px 内即可观察到日历高度开始变小（无"列表先滚动"的位移）；
2. **跟手性**：手势期间手指每移动 1px，日历边缘高度变化约 1px（误差 ≤ 2px）；无跳变、无回弹抖动、无掉帧（≥55fps）；
3. **折叠成功率**：展开态列表顶部上滑连续 10 次，10 次均折叠成功；日历区上滑同样 10/10；
4. **展开无需到顶（问题 B/C）**：折叠态、列表已滚动到中部，直接在日历周行下拉，可跟手展开，**无需先把列表滚回顶部**；连续 10 次均成功；
5. **吸附正确**：位移过半或速度足够 → 吸附到目标态；不足 → 回弹原态；吸附动画 ≤ 250ms；
6. **无缝衔接**：形态到位后继续上滑/下拉，列表能无缝滚动/回滚，无停顿或跳变；
7. **列表中部不误触**：列表中部上滑/下拉 10 次，形态均不变（只滚动）；
8. **零回归**：左右翻月/翻周、点选日期、补位日切月、折叠态跨月周计数、详情返回形态与滚动位置恢复、浮动「今日」、头部三元素、全天分组、列表滚动与惯性滚动均不回归；
9. **真机专项**：微信 WebView + iOS Safari + Android Chrome 真机验证通过，手势无卡顿投诉。

## 6. 非功能性需求

### 6.1 性能

- **日程主页**：首屏 P95 ≤ 300ms（不劣于 v0.7.0，且因移除任务字段/接口而降）；翻月/翻周、点选日期不引入额外串行请求；
- **手势**：跟手期间保持 55fps 以上，布局不触发重排抖动（优先使用 transform/高度合成友好方案，细节由 SDD 定稿）；列表惯性滚动不劣化；
- **下线收益**：任务/项目/代理/清单相关查询与 JOIN 从热点路径移除；Agent 侧 MCP 长轮询与限流线程退出；端上首屏请求数与包体下降；
- **对话**：SSE 首字节与工具调用不劣化；移除任务/代理工具后工具决策面变小，理论上更稳。

### 6.2 兼容性与数据

- **迁移 015**：幂等、可重复执行、单事务；在 v0.7.0 类生产快照演练通过；覆盖任务日程、项目/成员、代理/执行记录、循环与例外、农历/工作日历；
- **内容零丢失**：任务日程逐条转普通日程（标题快照），条数与标题与升级前一致；普通日程、循环系列与例外、会话、记忆零变化；
- **数据保留**：`tasks`、`task_lists`、`agents`、`agent_task_logs` 表与相关列保留在库（建议），停止读写；不提供物理删除入口；
- **DTO 变更**：日程 DTO 移除 `task`/`task_id`/`event_count`；任务/代理 DTO 不再存在；旧客户端忽略未知/缺失字段即可（端上随版本升级）；
- **路由兼容**：删除路由统一重定向 `/calendar`，书签与历史不报死链；
- **回滚限制**：数据保留使代码回滚可行，但**已转换的任务日程不会自动还原**为任务日程（需在发布说明中明确）。

### 6.3 隐私与安全

- 删除 MCP 接入面与代理凭据后，**对外鉴权面收窄**；已存代理凭据（SHA-256）不再可用；
- 服务端日志不记录日程标题/备注正文与对话正文（沿用只记 ID 与事件）；
- 注销账号级联删除日程、会话、记忆（沿用）；任务/项目/代理数据的清理策略随数据保留策略（决议 8.2 #3）；
- 迁移脚本不输出用户内容明文（仅计数与 ID）。

### 6.4 可观测性（埋点/日志调整）

- **下线观测**：`legacy_route_redirect`（旧链重定向命中：/tasks、/projects、/agents、/search 等，观察残余入口）、`legacy_api_hit`（已下线接口命中，观察旧客户端占比）；
- **迁移观测**：迁移 015 结果（每用户转换的任务日程条数、兜底标题条数、失败与重试）；不得记录标题正文；
- **清理观测**：端上对已下线卡片占位渲染的命中（历史会话）；
- **手势观测（CAL-04）**：`calendar_shape_gesture`（方向、起手区域：日历/列表顶部/列表中、是否接管、吸附结果 collapse/expand/回弹、跟手帧率采样）；`calendar_shape_gesture_dropped`（方向锁/多指/动画互斥导致的丢弃）；
- **保留观测**：日程创建/冲突/循环作用域等既有埋点不变；任务/项目/代理相关埋点全部移除。

## 7. 关键业务流程与验收标准

### 7.1 关键业务流程

**流程一：升级与数据迁移（DEL-06）**

```
升级 → 迁移 015（单事务）：
  ① 任务日程（event_type=task）→ 普通日程（标题=任务标题快照，task_id=NULL）
  ② 解除任务关联使用；代理维度列停止使用（列保留）
  → 校验：转换条数=转换前任务日程条数；普通日程/循环/会话/记忆零变化
  → 发布：旧链 /tasks、/projects、/agents、/search → /calendar
失败：整体回滚，不影响在线数据
```

**流程二：升级后的"减法"体验（DEL-01 ~ DEL-05）**

```
用户升级 → 抽屉只剩「日程」「助手」
  日程主页：原先的任务日程仍在（已为普通日程），无「关联任务」入口
  对话：说「建个任务」「放到 XX 项目」「交给代理」→ 助手如实说明能力已下线，建议改用日程
  对话：说「明天 10 点开会」→ 正常创建普通日程（唯一写路径）
```

**流程三：跟手折叠（CAL-04，展开态 → 折叠态）**

```
展开态，手指落在日历区或列表顶部，向上滑动
  → 越过 8px 观察期，锁定纵向
  → 日历高度随手一起收（跟手，无死区、无"列表先滚"的停顿）   ← 问题 A 修复
  → 抬手：位移过半/速度足够 → 吸附折叠（≤250ms）；否则回弹展开
  → 吸附到位后若继续上滑 → 无缝转为列表滚动
```

**流程四：无需到顶的跟手展开（CAL-04，折叠态 → 展开态）**

```
折叠态，列表很长已滑到中部
  → 直接在日历周行（始终可见）向下拖
  → 日历高度随手展开（跟手）                                ← 问题 B/C 修复（无需先滚回顶部）
  → 抬手吸附展开；继续下拉 → 无缝转为列表回滚/回弹
对照：在列表中部下拉（不经过日历区）→ 只滚动列表，形态不变
```

**流程五：日程能力全量验证（DEL-04 回归）**

```
新建普通日程 / 循环日程 / 农历日程 / 法定工作日日程
  → 冲突检测（定时×定时）+ 确认后保存
  → 月历标记点（单次/循环/混合）+ 农历副字 + 休/班角标
  → 左右翻月/翻周、浮动今日、详情返回恢复形态与滚动位置
  → 对话增删改查日程、循环实例作用域
```
