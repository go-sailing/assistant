## 1. 设计概述

### 1.1 系统边界（收缩）

v0.9.0 在 v0.7.0「App ↔ 服务端 REST + SSE + 对外 MCP」的边界上，**整体摘除对外 MCP 接入面**，服务端收敛为纯 App 后端：

```
                                  ┌──────────────────────────────────────┐
   移动端 H5（App） ──REST/SSE──▶ │  个人助手服务端（Node/Express 单体）    │
                                  │                                      │
                                  │  ┌───────────┐  ┌───────────────┐   │
                                  │  │ Event /   │  │ Chat / Memory │   │
                                  │  │（唯一领域）│  │（LLM 编排）    │   │
                                  │  └───────────┘  └───────────────┘   │
                                  │  ┌────────────────────────────────┐  │
                                  │  │ REST 路由（/api/v1）            │  │
                                  │  └────────────────────────────────┘  │
                                  └──────────────────────────────────────┘

   已移除：TaskService / AgentService / MCP 接入层（/mcp）/ 代理凭据通道 / 任务类 & 代理类 LLM 工具
```

- **对外形态收缩**：不再提供任何 MCP 端点（`POST/GET/DELETE /mcp` 全部移除，命中即 `1004`）；代理凭据通道（`agentAuthMiddleware`）整体删除；`/api/v1/tasks*`、`/api/v1/agents*` 全部下线。
- **保留**：`/api/v1` 下的 auth / events / conversations / chat(SSE) / memories / settings 与 `/healthz`。
- **不做**（见 PRD 1.3）：不引入"轻待办/提醒/打卡"等任务替代形态；不做任务/项目/代理的物理删除与导出；不做折叠/展开以外的日程主页布局改造；不做深色模式、字号、多语言、PC 适配。

### 1.2 设计目标与手段

| 目标 | 手段 |
| --- | --- |
| **任务/项目/智能体能力下线且数据不丢** | 迁移 015 把存量任务日程逐条转普通日程（标题快照）；`tasks`/`task_lists`/`agents`/`agent_task_logs` 表与列**保留在库、停止读写**；被删路由统一重定向 `/calendar` |
| **用户可见痕迹归零** | 端上删页面/组件/API/Store/类型/图标/token；服务端删模块/路由/工具/提示词章节/埋点；保留编号的错误码统一失去触发面 |
| **存量内容零丢失** | 迁移在单事务内完成，任务日程"标题快照 + 解除关联"，普通日程/循环/农历/冲突零变化；提供迁移前后断言 |
| **折叠/展开真正跟手** | 交互从"阈值触发的一次性切换"升级为**位移连续驱动（drag-linked）**：`p ∈ [0,1]` 由手指纵向位移映射；跟手期间阻止列表滚动；两端吸附；到位后无缝交还列表滚动；**起手区域扩展到日历区** |
| **消除两处卡顿** | 取消 32px 死区（问题 A）→ 8px 观察期后即接管、手指一动日历就动；折叠态下拉展开可在日历周行直接起手，无需先滚到顶（问题 B/C） |
| **手感改了、观感不变** | 头部三元素、月格视觉、标记点、农历/休班角标、浮动今日、列表行视觉全部保持 v0.6.0/v0.7.0；不新增控件/把手/提示 |
| **性能不劣化** | 删任务/代理模块后热点查询去掉 JOIN、MCP 长轮询线程退出、包体与首屏请求数下降；手势期间 ≥55fps |
| **删除干净、无残影** | 端上业务代码对 `Task/Project/Agent/Subtask/taskSync/agentToken/api-tasks/api-agents` 引用为 0；界面文案对"任务/待办/项目/成员/清单/智能体/代理/指派"命中为 0（历史消息正文除外） |

### 1.3 核心概念与领域不变量

**概念（v0.9.0 后）**

| 概念 | 定义 |
| --- | --- |
| 日程（event） | 唯一的时间事务载体：标题、起止、全天、地点、备注；可循环（每天/每周/每月/每年/法定工作日/农历）。`event_type` 恒为 `'normal'` |
| 循环系列 / 实例 | 一条 `recurrence IS NOT NULL` 的主记录 + 虚拟展开的实例（`occurrence_key`、`override_state`）；写作用域 `series/this/following` |
| 冲突 | 定时 × 定时时段重叠（`4009` + `details.conflicts`）；全天退出判定 |
| 长期记忆 | 跨会话稳定信息（v0.5.0 起），与日程解耦 |
| 折叠形态 `p` | 日历形态连续量：`p=1` 完全展开整月、`p=0` 完全折叠选中周；手势期间由手指位移驱动，松手吸附到 0 或 1 |

**领域不变量（必须在服务端单点保证）**

| # | 不变量 |
| --- | --- |
| I1 | `events.event_type` 恒为 `'normal'` 且 `task_id IS NULL`（DB CHECK 兜底 + 服务层不再写其他值） |
| I2 | 普通日程 `title` 非空（trim 后非空，DB CHECK 兜底） |
| I3 | `tasks` / `task_lists` / `agents` / `agent_task_logs` 及其列**只保留、不再被应用读写**（无迁移即无访问） |
| I4 | 服务端**不提供任何** `/api/v1/tasks*`、`/api/v1/agents*`、`/mcp` 路径（命中统一 `1004`） |
| I5 | 对话写操作路径只剩日程与记忆；`prompt.ts` 中不含任务/项目/代理/清单语义 |
| I6 | 冲突检测、循环展开、农历/工作日历换算、三种写作用域、月计数补齐、全天降噪全部保持不变（v0.7.0 语义） |
| I7 | 折叠/展开只存在"整月 ↔ 选中周"两态；吸附到位后 `p ∈ {0,1}`；手势中断/多指/路由切换后不残留半开态 |
| I8 | 一次手势只切换一次形态；吸附/回弹动画期间忽略新手势；惯性滚动不触发形态手势 |

## 2. 总体架构（增量）

### 2.1 架构变化

1. **删除 MCP 接入层**：`src/server/src/mcp/`（`mcp.routes.ts` / `jsonrpc.ts` / `protocol.ts` / `tools.registry.ts` / `waiter.ts`）整目录删除；`app.ts` 摘除 `app.use(mcpRoutes)` 与 `app.use('/mcp', mcpErrorHandler)`。
2. **删除代理域**：`src/server/src/modules/agent/` 整目录删除；`middleware/agentAuth.ts` 删除。
3. **删除任务域**：`src/server/src/modules/task/` 整目录删除；`modules/list/` 删除（v0.7.0 仅剩内部兜底的 `getDefaultId/createDefaultList`，随 `tasks` 停用而失去调用方）。

6. **前端大幅减法**：删三组页面/组件/API/Store/类型、抽屉与顶部栏入口收敛、编辑入口收敛为唯一普通表单；`MonthView.vue` 的 CAL-04 跟手联动改造。
7. **数据迁移 015**：新增 `db/migrations/015_retire_task_project_agent.sql`（任务日程转普通日程 + 约束重建 + 索引回收）。

### 2.4 关键技术决策（本版需评审确认的技术项）

| # | 决策点 | 结论 | 理由 |
| --- | --- | --- | --- |
| T1 | 任务/项目/代理数据处理 | **能力下线、数据保留**：表与列不删，只停读写；迁移仅动 `events` | 回滚成本低、审计可查、外键不破；与清单（v0.7.0）一致（PRD 决议 #3） |
| T2 | 任务日程转换 | `event_type='task'` **逐条改写为** `'normal'`（`title` 取 `tasks.title` 快照、`task_id=NULL`）；标题缺失用兜底「（原任务日程）」 | 内容零丢失；任务日程不支持循环，故无循环例外牵连（PRD 决议 #4） |
| T3 | 约束重建策略 | 迁移内**先 `DROP CONSTRAINT IF EXISTS`（旧两条）→ 回填 → 新增两条**（`normal + title`）；`chk_event_time` 保留 | 旧约束（`normal→task_id IS NULL`、`task→title IS NULL`）与转换目标互斥，必须先放宽再收紧（PRD 4.8） |
| T4 | 旧路由策略 | 所有被删路由 `redirect: '/calendar'`（含 `/lists`）；`/calendar/:id/edit/task` → `/calendar/:id/edit`（保留 id） | 无死链、无中间态、无闪烁（PRD 决议 #7） |
| T5 | 旧接口策略 | `/api/v1/tasks*`、`/api/v1/projects*`、`/api/v1/agents*`、`/mcp` 不存在 → 统一 `1004`（`/api/v1/projects*` 为远程 v0.8.0 新增、本版随项目域下线）；请求体携带 `list_id/task_type/agent_*` 等已删参数 → **因路由不存在直接 404**，不单独做参数级拒绝 | 端点整体下线后无参数入口；保留 `rejectListParams` 无意义，随任务域删除 |
| T6 | 配置项残留 | `AGENT_*`、`RATE_LIMIT_MCP_PER_MIN`、`TASK_*` 环境变量与 `config.agent`/`config.task` 一并移除 | 残留无害但违反"删干净"；本版无回滚到 MCP 的需求（PRD 决议 #14） |
| T7 | 手势动画实现 | **跟手期间逐帧直写（rAF 合并、无 CSS transition）**；吸附/回弹用 rAF ease-out 补间（≤250ms） | 保证 1:1 跟手与 ≥55fps；避免 `height` transition 与"移位置零"不同帧导致的脱节 |

## 3. 数据模型与迁移（015）

> **链位说明**：本版迁移**恒位于远程 v0.8.0 的 `014_project_extract.sql` 之后**。014 负责把项目从 `tasks` 抽成 `projects` 独立表、并把「项目关联日程」转为普通日程；015 负责收口**剩余的任务日程**、收紧 events 约束、回收失效索引。因此全新库是 `001→014→015`，v0.8.0 状态库只补 015，v0.7.0 之前的旧库则 014、015 连续应用。

### 3.1 现状约束与目标约束

**现状（`003_events.sql`）**：`events` 有三条 CHECK 与三个索引：

```sql
CONSTRAINT chk_event_task_link CHECK (
  (event_type = 'normal' AND task_id IS NULL) OR
  (event_type = 'task'   AND task_id IS NOT NULL)
),
CONSTRAINT chk_event_title CHECK (
  (event_type = 'task'   AND title IS NULL) OR
  (event_type = 'normal' AND title IS NOT NULL AND btrim(title) <> '')
),
CONSTRAINT chk_event_time CHECK (end_at >= start_at);

CREATE INDEX idx_events_user_time ON events(user_id, start_at, end_at);   -- 冲突检测（保留）
CREATE INDEX idx_events_user_task ON events(user_id, task_id);            -- 任务维度（回收）
CREATE INDEX idx_events_user_type ON events(user_id, event_type);         -- 类型埋点（回收）
```

**v0.9.0 目标**：`event_type` 恒 `'normal'`、`task_id` 恒 `NULL`、`title` 非空；`task_id`/`event_type` 列**保留**（便于可读性与代码回滚），但不再被读写。

> 关键取舍：把 `event_type` 列留下并加 CHECK（`= 'normal'`），而不是 DROP 列。理由——回滚到 v0.7.0 代码时列仍存在（读不报错）；"任务日程不可再创建"由 CHECK 作为数据库级兜底。代价是回滚后 v0.7.0 无法再创建任务日程（会命中新 CHECK）——属"能力已下线"的预期，需在发布说明写明。

### 3.2 迁移 015 完整 DDL

文件：`src/server/src/db/migrations/015_retire_task_project_agent.sql`。幂等、可重复执行；单文件单事务（沿用 `db/migrate.ts` 机制）。

```sql
-- ============================================================
-- 015_retire_task_project_agent.sql
-- v0.9.0 任务 / 项目 / 智能体能力下线（数据侧）。
-- 仅处理 events：存量任务日程 → 普通日程（标题快照），并重建约束、回收失效索引。
-- tasks / task_lists / agents / agent_task_logs / projects 表与列一律保留、停止读写（不删不改）。
-- 其中 projects 表由 v0.8.0 的 014_project_extract.sql 建出（项目模型抽离），本迁移不改其结构，
-- 只随项目域一起退出读写；单文件单事务，顺序执行且仅执行一次。
-- 幂等可重复执行：DROP ... IF EXISTS + 系统目录判定；转换后重跑为 no-op。
-- 执行顺序：① 放宽旧约束 → ② 回填转换 → ③ 收紧新约束 → ④ 回收索引 → ⑤ 注释。
-- ============================================================

-- ① 放宽旧约束（否则无法把 task 日程改写为 normal）
ALTER TABLE events DROP CONSTRAINT IF EXISTS chk_event_task_link;
ALTER TABLE events DROP CONSTRAINT IF EXISTS chk_event_title;

-- ② 存量任务日程 → 普通日程：标题取关联任务标题快照，解除任务关联
UPDATE events AS e
   SET title      = COALESCE(NULLIF(btrim(t.title), ''), '（原任务日程）'),
       event_type = 'normal',
       task_id    = NULL,
       updated_at = now()
  FROM tasks AS t
 WHERE e.event_type = 'task'
   AND e.task_id = t.id;

-- ②b 防御性兜底：非法残留（event_type='task' 但无关联任务）也统一转为普通日程
UPDATE events
   SET title      = COALESCE(NULLIF(btrim(title), ''), '（原任务日程）'),
       event_type = 'normal',
       task_id    = NULL,
       updated_at = now()
 WHERE event_type = 'task';

-- ③ 收紧新约束（系统目录判定，幂等）
DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM pg_constraint
    WHERE conname = 'ck_events_normal_only' AND conrelid = 'events'::regclass
  ) THEN
    -- I1：只剩普通日程，且不再有任务关联
    ALTER TABLE events ADD CONSTRAINT ck_events_normal_only
      CHECK (event_type = 'normal' AND task_id IS NULL);
  END IF;
  IF NOT EXISTS (
    SELECT 1 FROM pg_constraint
    WHERE conname = 'ck_events_title' AND conrelid = 'events'::regclass
  ) THEN
    -- I2：普通日程必须有非空标题
    ALTER TABLE events ADD CONSTRAINT ck_events_title
      CHECK (title IS NOT NULL AND btrim(title) <> '');
  END IF;
END $$;

-- ④ 回收失效索引：event_type 恒为常量、task_id 恒为 NULL，均无选择性
DROP INDEX IF EXISTS idx_events_user_type;
DROP INDEX IF EXISTS idx_events_user_task;

-- ⑤ 注释（口径留档）
COMMENT ON COLUMN events.event_type IS
  'v0.9.0：恒为 normal（任务日程已下线，存量已转为普通日程）。列保留以兼容代码回滚，应用不再写入。';
COMMENT ON COLUMN events.task_id IS
  'v0.9.0：恒为 NULL（任务能力已下线）。列保留以兼容代码回滚，应用不再读写。';
```

> `events.task_id` 的外键（`REFERENCES tasks(id) ON DELETE CASCADE`）与 `idx_events_user_time` 保持不变；`tasks` 表保留，外键不会悬挂。

### 3.3 幂等、正确性与回滚论证

| 关注点 | 结论 |
| --- | --- |
| ① 幂等 | `DROP CONSTRAINT IF EXISTS` 对不存在约束为空操作；重跑不会误删新约束（新约束名不同） |
| ② 幂等 | 转换后不存在 `event_type='task'` 行，`UPDATE ... FROM tasks` 与 ②b 均为零更新，重跑 no-op |
| ② 正确性 | `tasks.title` 非空（应用层 `min(1)`）；标题为空/任务已删时用兜底「（原任务日程）」；任务日程不支持循环，故 `recurrence IS NULL`，无需处理实例例外 |
| ③ 约束顺序 | 先回填满足新谓词，再加 CHECK；加约束时对存量行校验通过（全 `normal` + 全 NULL + 非空标题） |
| ③ 兼容 | `chk_event_time` 不受影响；`end_at >= start_at` 在任务日程转换后仍成立 |
| ④ 索引 | 仅删除无选择性索引；`idx_events_user_time`（冲突检测热路径）保留 |
| 数据零丢失 | 仅改 `events.title/event_type/task_id`；普通日程、循环系列与例外、会话、记忆、账号零变化。转换前的任务日程条数与标题，转换后应逐条一致 |
| 外键 | `event_type` 无枚举约束（仅 CHECK）；`task_id` FK 全 NULL 后无引用；`tasks` 保留 |
| 大库耗时 | 单条 `UPDATE ... FROM tasks` 按任务日程数线性；单事务需演练并记录耗时与锁表现（见 15.4） |
| 回滚限制 | 迁移**不可逆**：已转换的任务日程不会自动还原（回滚后以普通日程存在）；且新 CHECK 会阻止 v0.7.0 代码创建任务日程。需在发布说明明确（PRD 6.2 / 决议 #13） |

**迁移前后断言（演练/上线核对）**

```sql
-- 迁移前快照
SELECT count(*) AS task_events_before FROM events WHERE event_type = 'task';
SELECT count(*) AS normal_events_before FROM events WHERE event_type = 'normal';

-- 迁移后校验（期望：remaining = 0；converted == task_events_before；
--             normal_after == normal_events_before + task_events_before；empty_titles = 0）
SELECT
  (SELECT count(*) FROM events WHERE event_type <> 'normal' OR task_id IS NOT NULL) AS remaining_task_events,
  (SELECT count(*) FROM events WHERE title IS NULL OR btrim(title) = '')            AS empty_titles,
  (SELECT count(*) FROM events WHERE event_type = 'normal')                          AS normal_events_after;
```

### 11.2 目标交互模型

**连续量 `p ∈ [0,1]`**：`p=1` 完全展开整月，`p=0` 完全折叠选中周。

```
H(p) = H_week + p × (H_exp − H_week)                       // 日历容器高度
T(p) = (1 − p) × weekIndex × effectiveCell                 // 日期行上移（选中周滑向顶部）
```

- 展开态：`H_exp = expandedHeight`（含压缩态）、`H_week = weekHeight`（`WEEK_HEAD_H + cellSize + GRID_PAD_BOTTOM`）；
- `weekIndex` 取选中日在其所在月网格中的行号（0..5），`effectiveCell` 为 `compressedCell || cellSize`；
- 跟手映射：`p ← clamp(p₀ − Δy / (H_exp − H_week), 0, 1)`，`Δy` 为相对起手点的纵向位移（向上为负）；
- **端点阻尼**：当 `p ∈ [0, 0.15] ∪ [0.85, 1]` 时，映射**增量**乘 `0.4`。

**两端吸附、中段 1:1、到位交还列表**：见 11.5~11.7。

### 11.3 手势分区与起手规则

| 起手区域（touchstart 快照） | 展开态 | 折叠态 |
| --- | --- | --- |
| **日历区**（`.month__cal`，含折叠态周行，任意位置） | 上滑 → 跟手折叠 ★ | 下拉 → 跟手展开 ★（问题 B/C 修复关键） |
| **列表区顶部**（`scrollTop ≤ 2`） | 上滑 → 跟手折叠 | 下拉 → 跟手展开 |
| **列表区中部**（`scrollTop > 2`） | 只滚列表（形态不变） | 只滚列表（形态不变） |

补充规则（沿用/新增）：

1. **方向锁**：`|dy| > 1.5 × |dx|` 判纵向并进入形态手势；否则交还（横滑 → 翻月/翻周；点按 → 选日期）；
2. **观察期**：位移 < 8px 不锁定方向、不进入形态手势（沿用）；
3. **起手快照**：是否接管以"起手瞬间所在区域"为准，手势进行中不再因列表滚动位置变化而改判；
4. **反向位移不驱动形态**：展开态在日历区下拉、折叠态在日历区上滑，`p` 被 clamp 在端点，不改变形态、不跳变；
5. **日历区横滑/点按零回归**：纵向锁定前，日历区横滑仍翻期、点按仍选日期。

### 11.5 位移映射与阻尼（逐帧实现）

**符号约定（定稿，实现必须一致）**：`dy = t.clientY − startY`（手指向下为正）；`dDy = dy − lastDy` 为相邻两次 move 的增量（向下为正）。目标是**向上滑（`dy` 减小）→ `p` 减小（收）；向下拉（`dy` 增大）→ `p` 增大（展）**，故：

```
p = clamp(p₀ + dy / (H_exp − H_week), 0, 1)          // 绝对式
p_new = clamp(p_old + dDy / (H_exp − H_week), 0, 1)  // 逐帧增量式（等价，实现用这条）
```

> 校验：展开态 `p₀=1`，上滑 `dy=-40` → `p<1`（收）✓；折叠态 `p₀=0`，下拉 `dy=+40` → `p>0`（展）✓。（注：PRD 5.3 的文字公式 `p ← p₀ − Δy/…` 中 `Δy` 以「向上为负」定义，与本文 `dy` 向下为正相反，二者意图一致，实现以本文 `p = p₀ + dy/range` 为准。）

```ts
function progressRange(): number { return Math.max(1, expandedHeight.value - weekHeight.value) }

/** 阻尼映射：中段 1:1，接近两端时增量乘 0.4 */
function mapProgress(p: number, dDy: number): number {
  const delta = dDy / progressRange();
  const damped = (p <= DRAG_DAMP_ZONE || p >= 1 - DRAG_DAMP_ZONE) ? delta * DRAG_DAMP_FACTOR : delta;
  return Math.min(1, Math.max(0, p + damped));
}
```

阻尼只作用于**增量**（非整体重映射），保证跟手过程中手感连续、不会在跨过阻尼区时跳变。

### 11.6 吸附判定与速度采样

| 项 | 规格 |
| --- | --- |
| 吸附目标 | 抬手时 **行程 `|p − p₀| ≥ 50%`** 或 **释放速度方向一致且 `|v| ≥ 0.3 px/ms`** → 吸附目标端；否则回弹到 `p₀` 所在端 |
| 速度采样 | 最近 100ms 位移换算（`v = Δy/Δt`，多帧滑动平均） |
| 吸附/回弹动画 | rAF ease-out（`1 - (1-t)³`）补间，时长 ≤250ms |
| 一次一手势 | 一次手势只切换一次形态；已 commit 后不再二次触发 |
| 动画互斥 | 吸附/回弹期间 `animating=true`，忽略一切新手势（沿用） |

### 11.7 无缝交还列表滚动

- **接管即阻止原生滚动**：`origin ∈ {calendar, list-top}` 且锁纵向时接管；在 `.month__body` 的非 passive `touchmove` 中对本次及后续 move 调用 `e.preventDefault()`；
- **p 触达端点后的残余位移**：若手指继续朝端点方向移动（折叠后继续上滑 / 展开后继续下拉），进入 `handoff`：
  - 记录 `endpointDy`（p 到端点时的 `dy`）与 `handoffBaseScroll`（当时 `scrollTop`）；
  - `scrollTop = clamp(handoffBaseScroll + (endpointDy − dy), 0, scrollMax)`；
  - 折叠方向上滑（`dy` 继续减小）→ `endpointDy − dy > 0` → `scrollTop` 增大（列表上滚）；展开方向下拉（`dy` 继续增大）→ `endpointDy − dy < 0` → `scrollTop` 减小（列表回滚/回弹）；
- **到位后无停顿/跳变**：接管期间只由脚本改 `scrollTop`，原生滚动已禁，故无"日历在收、列表在滚"的并发；
- **惯性滚动不触发形态**：惯性发生在 touchend 之后、无 touchmove，天然不触发；新建 touchstart 会中止惯性并开始新手势。

### 11.8 渲染切换时机

| 阶段 | 渲染 |
| --- | --- |
| 跟手期间 | 保持整月渲染（`mode='month'`，42 格），容器 `overflow: hidden` 整体裁剪收缩；**不做** `renderWeek` 切换 |
| 展开方向起手 | 若当前 `renderWeek=true`（折叠态），**起手即恢复整月渲染**（`renderWeek=false`），再随 `p` 展开，避免跳变 |
| 折叠到位 | `p` 到 0 且 commit 后切换为"只渲染选中周"（`renderWeek=true`、`mode='week'`），切换瞬间位移归零且无 transition |
| 动画 | 跟手期间 `transition: none`；吸附/回弹用 rAF 补间（高度 + 位移同帧） |

> 实现建议：跟手期间**不用 Vue 响应式驱动 42 格重渲染**，改为对 `.month__grid` 直写 `height`、对 `.grid__days` 的 `transform` 直写（通过 CSS 变量 `--shape-shift` 或 ref）。`MonthGrid` 的 `.grid__days { transform: translateY(var(--shape-shift, 0px)) }`，MonthView 在 rAF 中 `gridEl.style.setProperty('--shape-shift', ...)`。仅 commit 时才更新 `mode`/`weekShift` 等响应式状态。

| 路由/页面切换 | `onBeforeUnmount` 取消 rAF 与手势；不持久化半开态 |
| 动画期间 | `animating` 门禁忽略新手势（沿用） |
| 与左右翻期并发 | 跟手进行中不翻期；翻期进行中不进入跟手（手势起点由 lock 唯一决定） |
| `prefers-reduced-motion` | 吸附/回弹动画缩短或即时到位；**跟手功能不缺失** |
| 空/短列表 | 列表不可滚动（`scrollTop` 恒 0）时两方向均可在任意位置触发，且不影响列表 |
| 数据加载 | 折叠 commit → `loadCollapsed()`（当日 + 邻月计数）；展开 commit → `loadExpanded()`；同一日期已加载不重复请求（沿用 `loadedDayKey`） |

const DRAG_DIRECTION_RATIO = 1.5; // 方向锁（沿用）

const SETTLE_MS        = 250;     // 吸附/回弹动画上限（--dur-page）

### 11.12 关键实现骨架（示意，非最终代码）

```ts
type GestureLock = 'none' | 'vertical' | 'horizontal';
type GestureOrigin = 'calendar' | 'list-top' | 'list-mid';

interface ShapeGesture {
  startX: number; startY: number;
  lastY: number; lastT: number; lastDy: number; velocity: number;
  lock: GestureLock; origin: GestureOrigin;
  tookOver: boolean; committed: boolean; handedOff: boolean;
  startP: number; startScroll: number; endpointDy: number; handoffBaseScroll: number;
}

const shapeP = ref(1);          // 连续进度（仅 commit 时同步到渲染状态）
let shapeGesture: ShapeGesture | null = null;
let dragRaf = 0;
let shapeVar = 0;               // --shape-shift 待写值
let heightVar = 0;

function onListTouchStart(e: TouchEvent) {
  const t = e.touches[0]; if (!t) return;
  const top = (listEl.value?.scrollTop ?? 0) <= LIST_TOP_TOLERANCE;
  beginGesture(t, top ? 'list-top' : 'list-mid');
}
function onCalTouchStart(e: TouchEvent) {
  const t = e.touches[0]; if (!t) return;
  beginSwipe(t);                 // 沿用横滑起手记录
  beginGesture(t, 'calendar');
}
function beginGesture(t: Touch, origin: GestureOrigin) {
  if (animating.value) { shapeGesture = null; return }
  shapeGesture = {
    startX: t.clientX, startY: t.clientY, lastY: t.clientY, lastT: performance.now(),
    lastDy: 0, velocity: 0, lock: 'none', origin, tookOver: false, committed: false,
    handedOff: false, startP: shapeP.value,
    startScroll: listEl.value?.scrollTop ?? 0, endpointDy: 0, handoffBaseScroll: 0,
  };
}

function onShapeTouchMove(e: TouchEvent) {
  const g = shapeGesture; if (!g) return;
  if (e.touches.length > 1) { cancelGesture(g); return }     // 多指中断
  const t = e.touches[0]; if (!t) return;
  const dx = t.clientX - g.startX, dy = t.clientY - g.startY;

  // 速度采样（最近窗口）
  const now = performance.now();
  if (now - g.lastT >= 16) { g.velocity = (t.clientY - g.lastY) / (now - g.lastT); g.lastY = t.clientY; g.lastT = now; }

  if (g.lock === 'none') {
    if (Math.abs(dx) < DRAG_OBSERVE_PX && Math.abs(dy) < DRAG_OBSERVE_PX) return;
    g.lock = Math.abs(dy) > DRAG_DIRECTION_RATIO * Math.abs(dx) ? 'vertical' : 'horizontal';
    g.lastDy = dy;                                             // 观察期结束点作为跟手基准
    if (g.lock === 'vertical' && (g.origin === 'calendar' || g.origin === 'list-top')) {
      g.tookOver = true;
      if (renderWeek.value) { renderWeek.value = false; collapsed.value = false }  // 展开方向：起手即恢复整月
    }
    return;                                                    // 本帧不推进 p（观察期内不跟手）
  }
  if (g.lock !== 'vertical' || !g.tookOver) return;          // 列表中部：只滚动，不接管

  if (!g.committed) {
    e.preventDefault();                                     // 跟手期间阻止原生滚动
    const dDy = dy - g.lastDy; g.lastDy = dy;
    shapeP.value = mapProgress(shapeP.value, dDy);
    scheduleFrame(shapeP.value);
    if (shapeP.value <= 0) commitCollapse(g, dy);
    else if (shapeP.value >= 1) { commitExpand(g, dy); /* 展开端点继续下拉 → handoff */ }
    return;
  }
  // 已 commit：残余位移交还列表滚动（脚本滚动）
  e.preventDefault();
  const el = listEl.value; if (!el) return;
  const max = el.scrollHeight - el.clientHeight;
  el.scrollTop = Math.max(0, Math.min(max, g.handoffBaseScroll + (g.endpointDy - dy)));
}

function onShapeTouchEnd() { finishGesture(shapeGesture); shapeGesture = null; }

function finishGesture(g: ShapeGesture | null) {
  if (!g) return;
  cancelAnimationFrame(dragRaf); dragRaf = 0;
  if (g.committed) { animating.value = false; return; }     // 已到位
  const travel = Math.abs(shapeP.value - g.startP);
  const towardCollapse = shapeP.value < g.startP;
  const fast = towardCollapse ? g.velocity <= -SETTLE_VELOCITY : g.velocity >= SETTLE_VELOCITY;
  const target: 0 | 1 = (travel >= SETTLE_RATIO || fast)
    ? (towardCollapse ? 0 : 1)
    : (g.startP >= 0.5 ? 1 : 0);                            // 回弹起始态
  void settleTo(target, g.startScroll);
}

async function settleTo(target: 0 | 1, startScroll: number) {
  animating.value = true;
  if (target === 0) { collapsed.value = true; void loadCollapsed(); } else { collapsed.value = false; void loadExpanded(); }
  await animateP(target, SETTLE_MS);
  shapeP.value = target;
  if (target === 0) renderWeek.value = true;                // 到位后切单周渲染
  applyRender(target, startScroll);                         // 直写 height/shift，归零且无 transition
  animating.value = false;
}
```

> `animateP` 为 rAF ease-out 补间（`prefers-reduced-motion` 下即时）；`scheduleFrame` 用 rAF 合并多次 touchmove 直写 DOM；`commitCollapse/commitExpand` 设定 `committed/handedOff/endpointDy/handoffBaseScroll` 并立即触发数据加载。

| 边界 | 结果 |
| --- | --- |

| 数据加载 | 折叠/展开 commit 才请求；同日期不重复请求；邻月计数失败静默 |

### 12.3 跟手折叠（展开态 → 折叠态，修复问题 A）

```
touchstart（日历区 或 列表顶部；记录 startP=1, startScroll, origin）
touchmove（越过 8px 观察期，|dy|>1.5|dx| → lock='vertical'，tookOver=true）
  → 逐帧：p = clamp(p + dDy/range)，端点阻尼 ×0.4；直写 height 与 --shape-shift
  → preventDefault：列表不滚动
  → p 到 0：commitCollapse → collapsed=true, renderWeek=true, loadCollapsed()
  → 继续上滑（残余位移）→ 脚本滚动列表（无缝交还）
touchend：已 commit → 结束；未到端点 → settle 吸附/回弹（≤250ms）
```

### 12.4 无需到顶的跟手展开（折叠态 → 展开态，修复问题 B/C）

```
折叠态，列表已滚到中部（scrollTop 很大）
touchstart（在日历周行）→ origin='calendar'
touchmove（锁纵向）→ 起手即 renderWeek=false 恢复整月 → p 随下拉增大，日历跟手展开
  → preventDefault：跟手期间列表不滚动
  → p 到 1：commitExpand → collapsed=false, renderWeek=false, loadExpanded()
  → 继续下拉（残余位移）→ 脚本滚动列表（回滚/回弹）
对照：列表中部下拉（不经过日历区）→ origin='list-mid' → 不接管，只滚动列表
```

### 12.5 到位后无缝交还滚动

```
p 到端点（dy = endpointDy, scrollTop = handoffBaseScroll）
  for each further touchmove（同一方向）:
      scrollTop = clamp(handoffBaseScroll + (endpointDy − dy), 0, scrollMax)
  → 无停顿、无回弹抖动、无内容跳变（原生滚动已被 preventDefault 抑制）
```

### 12.6 对话"能力已下线"

```
用户：帮我建个任务，明天交报告
  → 模型无 create_task 工具；按提示词口径：
      text：「任务能力已下线。我按「明天 09:00 交报告」建了一个日程，可以吗？」
  → 用户确认 → present_proposal 或直接 create_event（普通日程）
  → 结果 cards.events（普通日程卡）；无 tasks / subtask_groups 卡
```
